# 天信管业防腐保温智慧平台：现状与开发差距分析

## 1. 结论摘要

本次已在项目根目录完成 CodeGraph 初始化，索引目录为 `.codegraph/`。索引可定位 Java 类、方法、文件及调用关系；例如 `codegraph query "MesProFeedbackServiceImpl"` 可定位 MES 报工实现及其测试。

当前仓库是功能较完整的若依/Txgy 通用企业平台，不是已经交付的“防腐保温行业平台”。它具备可复用的技术底座和若干业务引擎，但附件要求的跨企业行业生态、行业知识与标准库、专家服务、材料批次质量溯源、施工现场闭环、云培训等仍需行业化建模、门户改造、数据治理和业务联调。

**总体判断：**

- **可直接复用：** 统一身份/权限、组织与消息、工作流、CRM/ERP 基础交易、MES 生产、WMS 仓储、HRM 人事考勤绩效、AI 对话/知识库基础、IoT 设备接入。
- **部分满足：** 供应商/客户档案、采购销售订单、库存收发存、生产工单/BOM/工艺路线/报工/质检节点、设备巡检、项目审批、即时通讯、培训相关的人员档案和绩效数据。
- **必须继续开发：** 多企业入驻与数据隔离、行业供需撮合、行业标准/材料参数/工法案例库、专家咨询撮合与结算、行业质量认证与项目级溯源、施工项目全生命周期、云培训学院、招投标专属服务、安全环保合规、行业驾驶舱和跨模块主数据。

## 2. 附件需求归纳（作为需求基线）

三份附件共同提出了五类主体：原材料供应商、生产制造/预制企业、施工安装企业、工程甲方、个人与专家；并要求 PC 管理后台、移动端、统一门户和 AI 能力协同。核心业务可归纳为：

1. 行业资讯、政策、国标行标、材料参数、工艺工法和案例知识服务；
2. 企业/人员/专家入驻、资质审核、信用与业绩档案；
3. 项目、材料、劳务、设备和服务的供需发布、匹配、询报价及订单协同；
4. 原料入库检验、生产巡检、成品检验、第三方检测、不合格闭环和批次溯源；
5. 生产排产、工序报工、仓储物流、施工工序、进度、成本、竣工和维保；
6. 云培训课程、学时监管、考试、证书、讲师直播和上岗资格联动；
7. AI 问答/检索/推荐/预警、招投标辅助、安全环保和运营分析。

附件中关于现有系统、架构和投资的描述属于需求方案/设计建议，不能视为本仓库已经实现的功能；以下判断以代码和 SQL 结构为准。

## 5. 需要继续开发的重点

### P0：先打通平台主链路

1. **多企业/多角色/数据共享模型：** 企业、组织、个人、专家、认证机构、项目成员、数据域和授权策略；明确“公开、企业内、项目内、监管”四级可见性，避免把内部 ERP 数据直接暴露给行业平台。
2. **行业主数据：** 材料、产品型号、单位、工序、质量指标、标准版本、证书、区域、工种、资质和项目编码；建立版本、来源、审核人、更新时间和失效机制。
3. **行业门户与供需撮合：** 企业入驻/实名认证/资质审核、企业黄页、项目/材料/劳务/设备/服务发布、检索匹配、询价报价、洽谈、订单和评价。
4. **项目与质量闭环：** 项目-标段-合同-批次-工序-检验-整改-验收-维保的关联链；移动端拍照/定位/时间留痕，BPM 负责审批而非承载全部业务数据。

### P1：形成行业差异化能力

1. 质量认证与溯源：原料/过程/成品/第三方检测、不合格 CAPA、合格证、报告防篡改和甲方核验二维码。
2. 生产与仓储行业化：危化品台账、效期/批次、配方权限、损耗、产能、物流和质量状态联动。
3. 云培训学院：课程/班级/讲师/直播、学时、题库、考试、证书、证书有效期和“未培训不得上岗”规则。
4. 专家咨询：专家认证、技能标签、排班、预约、工单、文件交付、评价、计费和结算；AI 答案需显示知识来源并支持转专家。
5. 安全环保：风险库、检查清单、隐患整改、VOC/粉尘/危化品/特种作业和事件分析，支持 IoT 告警接入。

### P2：智能化与规模化

1. 标准/材料/案例知识图谱和 RAG 评测集；推荐、质量通病预警、库存预测、投标风险审查。
2. 行业驾驶舱：企业、项目、质量、安全、培训、供需和 AI 调用指标，按角色脱敏聚合。
3. ERP、财务、电子签章、支付、短信、物流、OCR、第三方招投标数据接口；以事件/消息方式解耦，保留重试和审计。
4. 性能与安全：对象存储大文件、异步任务、限流、租户隔离、敏感字段脱敏、上传白名单、提示词注入防护、模型调用审计和备份恢复演练。

## 6. 建议实施顺序与验收口径

**一期（平台可用）：** 统一门户/身份、企业入驻与审核、行业资讯知识库、供需发布、专家咨询 MVP、项目台账、质量批次档案、WMS/MES 关键接口、移动端消息。

**二期（业务闭环）：** 生产检验、项目工序/进度/成本/验收、仓储物流、培训学院、证书与上岗规则、安全环保、甲方监管视图。

**三期（智能运营）：** 知识图谱、AI 推荐与预警、招投标、生态交易结算、IoT 深度接入、驾驶舱和区域复制。

每个模块验收至少应包含：角色与数据权限矩阵、API 参数/返回/异常说明、关键状态机、操作审计、中文/UTF-8 数据、附件与图片留痕、可追溯字段（来源/版本/操作人/时间）、单元测试和基础运行测试。数据库新增表统一使用 `utf8mb4`，禁止用“附件上传成功”替代业务状态闭环验收。

## 7. 代码落点建议

- 新增行业域建议独立为 `txgy-module-industry`（或按实际边界拆分 `industry-platform`、`industry-project`、`industry-quality`、`industry-training`），避免把行业生态逻辑塞入 ERP/MES/WMS。
- 通过 API/事件复用现有 MES、WMS、ERP、HRM、AI、BPM、IM、IoT；跨模块只共享稳定的主数据 ID 和领域事件，不直接依赖对方数据库表。
- 前端新增“行业门户/企业工作台/项目工作台/专家工作台/甲方监管台”，管理后台继续复用现有权限、字典、文件和流程组件。
