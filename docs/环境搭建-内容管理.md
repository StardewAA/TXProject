## 三、数据库初始化（按顺序执行 3 个 SQL）

用 Navicat：连接数据库 → 选中 `ruoyi-vue-pro` 库 → 右键「运行 SQL 文件」，
按顺序执行以下 3 个文件（编码选 **UTF-8**）：

| 顺序 | 文件 | 作用 |
|---|---|---|
| 1 | `sql/cms-schema.sql` | 创建 18 张 cms_* 表（含 DROP TABLE，可重复执行） |
| 2 | `sql/cms_menu.sql` | 导入后台 CMS 菜单（22 条） |
| 3 | `sql/cms-content-data.sql` | 导入内容数据（政策 49 条 + 标准 4 条 + 内容类型字典；用 REPLACE INTO，可重复执行） |

命令行方式（在 `sql/` 目录下，注意库名是 `ruoyi-vue-pro`）：

```bash
mysql -uroot -p --default-character-set=utf8mb4 ruoyi-vue-pro < cms-schema.sql
mysql -uroot -p --default-character-set=utf8mb4 ruoyi-vue-pro < cms_menu.sql
mysql -uroot -p --default-character-set=utf8mb4 ruoyi-vue-pro < cms-content-data.sql
```

> 只需这 3 个文件。`sql/cms-full-db.sql`、`sql/init-content-data.sql` 是早期导出，
> **已废弃不要用**（前者会重复插入整张 system_menu 导致主键冲突，后者缺少字典）。

> 3 个文件都在开发A的实例上实测过：导入后政策 49 条、标准 4 条、CMS 菜单 22 条、
> 内容类型字典 2 条，无报错。

> ⚠️ 编码必须是 utf8mb4，否则中文全部乱码。
> ⚠️ 个人数据库密码、端口等环境配置不要提交到仓库。

## 四、放置 PDF 原件

政策/标准详情页的「查看全文」按钮打开 PDF 原件时，依赖前端静态目录下的文件。

完整 PDF 原件共 36 个、约 139MB，**体积较大未放进 git 仓库**，请从开发A处获取压缩包
`policy-files.zip`，解压后把全部 PDF 放到：

```
txgy-ui-admin-vben/apps/web-antd/public/files/policy/
```

目录不存在就手动创建。**文件名必须保持原样**（`p1.pdf`、`std_GBT232572017.pdf` 等），
因为数据库里存的就是 `/files/policy/xxx.pdf` 这个路径。

本地 `pnpm dev` 模式拷进去即生效；生产构建（`pnpm build`）会把 `public/` 打进 `dist/`。

> 仓库里的 `deploy/content-files/` 只有标准与碳达峰等少量原件，是早期从 Word 里提取的
> 中间产物，文件名与数据库路径不一致，仅供追溯，不要直接拷进前端目录。

> 不拷贝不影响文字内容浏览，但详情弹窗里「查看全文 → 打开 PDF」点击会 404。

## 五、启动 cms 后端

方式一（IDEA，推荐）：

1. 用 IDEA 打开 `txgycloud` 根工程，等 Maven 索引完成
2. 找到 `txgy-module-cms/txgy-module-cms-server` 下的
   `cn.iocoder.txgy.module.cms.CmsServerApplication`
3. 直接运行（确认 Nacos/MySQL/Redis 已启动，且 system 服务在跑）

方式二（命令行）：

```bash
mvn --batch-mode -pl txgy-module-cms/txgy-module-cms-server -am package -DskipTests
java -jar txgy-module-cms/txgy-module-cms-server/target/txgy-module-cms-server.jar
```

启动成功标志：日志输出「项目启动成功！」，端口 **48085**。
cms-server 会自动注册到 Nacos，网关路由 `/admin-api/cms/**` 已在
`txgy-gateway/src/main/resources/application.yaml` 配好。

## 八、常见问题

**Q1：页面一直弹「内部服务器错误」，登录页刷屏？**
Docker/基座重启后前端 nginx 缓存了旧的网关地址。
执行 `docker restart <前端容器名>`，浏览器 Ctrl+F5 强刷后重新登录。

**Q2：菜单是乱码或数据是乱码？**
SQL 执行时编码不对。删除已导入数据后，用 `--default-character-set=utf8mb4`
重新执行 3 个 SQL。

**Q3：登录后左侧没有 CMS 菜单？**
确认 `cms_menu.sql` 已执行，且当前账号是超管或已分配 CMS 菜单权限。

**Q4：详情里「查看全文」打开 PDF 报 404？**
第四章的 PDF 没有放到前端 `public/files/policy/` 目录，补拷即可（注意文件名要和数据库路径一致）。

**Q7：两个内容页面白屏、控制台报 Failed to fetch dynamically imported module？**
浏览器缓存了旧版本的 JS 分片。先 `Ctrl + Shift + R` 强制刷新；仍不行就清空浏览器缓存，
或换无痕窗口重新登录。

**Q5：操作日志里没有 CMS 的记录？**
确认 system 服务已启动（操作日志经 RPC 异步写入 system 库），
且操作成功后才记录（失败操作不记录）。

**Q6：启动 cms-server 报 Nacos 连接失败？**
先启动基座 Nacos（8848），确认 `application-local.yaml` 里的
Nacos 地址与本地环境一致。
