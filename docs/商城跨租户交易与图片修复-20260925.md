# 商城跨租户交易与图片修复（2026-09-25）

## 范围与数据边界

本轮针对用户页面实测：移动端图片缺失、PC 图片间歇失败、H5 下单被误报为拆单异常、科盾商品/店铺计数为 0、订单商品跳转不存在、跨租户取消及文字评价失败。

用户批准短暂停原商城、用隔离库验证后恢复。原商城业务数据只读核查；不得为验收取消、付款、删除或修改截图订单。保留既有文件权限改造，master=4，公开 OSS 配置=36，不关闭 TLS 校验，不公开私有文件。未提交/推送 Git。

## 根因与改动

| 现象 | 根因 | 本轮修复 |
| --- | --- | --- |
| 手机没有图片 | 历史业务图片 URL 含 `127.0.0.1:48080/admin-api/infra/file/...`，手机会访问自己 | PC/H5 对已识别的历史本地文件 URL 使用同源 `/app-api/infra/file/...`，详情富文本也处理；不重写任意外部 URL |
| PC 图片间歇失败 | 历史 config 4 链接解析到已提升的 config 36 文件后，服务器再经 SDK 下载；现场日志出现 OSS TLS 握手失败 | 先执行文件 ACL，只对确认 PUBLIC 且已提升至 OSS 的文件跳转配置中的 HTTPS 公开地址；私有文件不跳转；生成公开 URL 不要求访问密钥 |
| H5 拆单状态异常 | 后端已创建正式子订单并返回 `ALL_UNPAID/UNPAID`，前端仅接受旧草稿状态 | 接受校验后的正式订单响应，明确“订单已创建”，跳转记录继续合并支付；未知响应保留幂等凭据 |
| 科盾计数为 0 | 以首页前 200 条商品样本推算企业总数 | 使用完整店铺列表及其公开商品计数，样本仅用于展示 |
| 订单点击商品不存在 | 平台买家从订单进入单租户 `/goods/` 接口，错误租户下查 SPU | 订单使用平台公开商品 `/products/:spuId`；H5 显式使用 portal 商品模式 |
| 取消、评价、订单项不存在 | 列表已支持平台归属，写操作/订单项查询仍按当前会员租户查询 | 先按登录身份及平台账号关系授权，再到实际订单租户操作；评价会员资料读取使用服务端确定的来源租户 |
| 跨租户付款衔接 | 合并支付商户单号为负的结算 ID，旧收银台/同步逻辑按普通订单号处理 | 验证实际支付关联；支持结算记录及子订单进入同一收银台；支付同步走平台结算逻辑 |

单店铺跨租户取消会先验证并关闭对应合并支付单，然后更新子单/结算状态。已支付订单拒绝取消。多店铺合并支付的单个子单取消明确拒绝，避免误关其他店铺的支付；本轮不宣称已实现多店铺整单取消。

## 验证记录

- 前端相关测试：50 项通过（PC 24，H5 26），包含 URL、富文本、正式结算、支付关联、截止时间与生命周期。
- 后端最终选定回归：8 项通过（公开图片跳转/私有拒绝、OSS 缺省域名、跨租户授权、单子单取消及支付保护）；完整构建成功。
- 隔离接口通过：正式下单、同一凭据重试不重复、订单项读取、其他买家拒绝、未付单取消及支付关闭、模拟付款后同步、已付单取消拒绝。测试订单 4/5，卖家租户 2024，买家来源租户 2009。
- 浏览器实际操作通过：PC 科盾统计（种子为 5 店/35 商品）、平台商品详情；H5 提交订单→成功弹窗→结算记录→合并收银台，以及子订单入口收银台；PC 订单商品点击、取消确认框（测试订单 6）、文字评价提交并返回详情（测试订单 5）。
- 评价前仅将隔离库新建且模拟付款的订单 5 从待发货设置为已完成，作为评价夹具；不算发货/收货链路通过。原库未执行该操作。
- 原环境已恢复运行，五个服务已部署。本轮只读复核：商品接口总数 841；科盾 6 店/36 商品，PC 企业页面断言通过；三笔截图订单状态与停机前相同；master=4、36 非 master。
- 原环境图片：旧 gateway 链接已返回 302，Location 为正确的 OSS HTTPS 对象地址；匿名私有文件 401、无跳转。但宿主机直接 GET 及真实浏览器图片加载未通过，HTTPS 握手失败。DNS（含两个公共 DNS 对照查询）都返回 `198.18.0.57`；怀疑代理/TUN/DNS 路径问题，未确定具体规则。不得把 302 或接口 JSON 200 当作图片加载通过。
- 用户要求“给另一个 AI 测”：停止进一步 OSS 联网测试，交接该项。PC/H5 原环境图片、详情图、Android 真机均未计为通过。只读浏览器脚本停在 PC 图片加载断言，H5 后续步骤尚未执行。
- 原环境图片验证仅为读取既有公开资源，不新增 OSS 上传。

原环境复查曾发现 OSS 配置的 `domain` 为空：SDK 原本会从 bucket/endpoint 派生地址。补丁第二版复用同一派生规则（仍只允许 HTTPS），不要求配置访问密钥或初始化 SDK；新增该配置形态回归通过后部署 infra `cross-tenant-20260925-2`。

网络复验交接见同目录 `OSS图片联网复验交接-20260925.md`。此前联网通过的历史记录不代表当前网络仍然可用。

复现入口：`deploy/mall/verify-cross-tenant.py --allow-demo-writes`、`deploy/mall/tests/cross-tenant-browser.cjs --allow-demo-writes`，仅面向隔离端口 24880/25175/23000；测试账号来自隔离演示种子，不用于原商城。

## 部署与回滚

原服务配置、端口、数据库卷及密钥保持不变，只替换 infra/trade/product/PC/H5 五个镜像。最后叠加 `deploy/docker-compose.mall-cross-tenant-fix.yml`，使用 `up -d --no-deps --no-build infra trade product mall-pc mall-h5`。前三个镜像与隔离环境验收后端相同；原环境前端单独构建，避免带入测试端口，并通过构建 secret 保留地图配置。

叠加顺序：`deploy/docker-compose.yml` → `deploy/docker-compose.mall-rollout.yml` → `deploy/docker-compose.mall-android-rollout.yml` → `deploy/docker-compose.file-acl-rollout.yml` → `deploy/docker-compose.file-acl-frontend.yml` → 本轮覆盖层；项目名 `deploy`。

回滚只去掉本轮覆盖层，针对同样五服务执行上述 `up`，使用保留的上一版镜像。不得 `down -v`、重导原库或清除用户订单。
