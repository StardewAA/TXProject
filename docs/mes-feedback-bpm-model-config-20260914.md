## 一、为什么要做这件事（当前唯一卡点）

MES 报工审批的代码链路已全部完成、编译并部署到位：

- **MES 发起端**：`submitFeedback` 提交报工时按流程 Key「mes-feedback-approval」发起 BPM 流程实例，并把流程实例号回写报工单；
- **BPM 侧转发**：bpm-server 已新增 `MesFeedbackStatusListener`（按流程 Key 过滤），流程结束后把结果 HTTP 转发回 MES；
- **MES 接收与消费**：接收端点 + 审批结果任务表 + 30 秒定时异步消费，全部就位（数据库字段与任务表已建并验证）；
- **前端**：报工列表的直连审批按钮已下线，改为「去 BPM 待办」引导。

**当前唯一卡点**：BPM 流程引擎里没有任何已部署的流程定义（实测 bpm 库 `ACT_RE_PROCDEF` 记录数为 0）。
因此现在提交报工会在「发起流程」这一步直接失败，端到端联调无法开始 —— 缺的就是「在 BPM 管理端新建并发布 `mes-feedback-approval` 流程模型」这一步。

## 三、流程模型规格（必须严格对齐）

### 3.1 基本属性

| 项目 | 取值 | 说明 |
| --- | --- | --- |
| 流程 Key | `mes-feedback-approval` | **必须完全一致、区分大小写**。MES 按此 Key 发起流程，bpm-server 的转发监听器也按此 Key 过滤回写；一旦改动，回写立即失效 |
| 流程名称 | 生产报工审批（建议） | 仅展示用，可自行拟定 |
| 流程分类 | 生产制造（建议） | 可新建或归入现有分类 |

| businessKey | 报工单 id（由 MES 传入） | MES 侧据此定位报工单，不可自行改写 |
| 可见范围 | 建议放开给生产相关人员 | 影响谁能发起 / 查看 |

## 四、三条硬约束（最容易踩的坑，请重点关注）

### 约束 1：驳回必须结束流程，不能「退回某节点等重审」

**原因（已核对源码）**：bpm-server 只在流程实例**完成（completed）**时才会发布状态事件并转发给 MES，
代码位置为 `BpmProcessInstanceServiceImpl#processProcessInstanceCompleted`。
如果驳回后流程仍在运行（例如回到发起人、或退回到上一个审批节点），MES **永远收不到通知**，报工单会一直停在「审批中」。

**因此本期驳回语义 = 直接退回草稿**；报工人修改后重新提交会**发起一个新的流程实例**（businessKey 仍是同一个报工单 id），旧实例自然结束、留痕可查。

### 约束 2：流程 Key 发布后不可修改

MES 发起与回写双向都依赖该 Key。若发布后修改 Key，则新提交的报工发起失败、已发起的报工无法回写。如需变更，请先与我方确认并同步改代码。

### 约束 3：请勿开启「允许撤销/取消流程」（或开启后告知我方）

**风险**：流程被取消时最终状态为 **4（CANCEL）**；而 MES 目前只消费 **2（审批通过）** 与 **3（驳回）**，状态 4 会被忽略 —— 报工单同样会卡在「审批中」。
若团队确实需要取消能力，我方可补充「取消即退回草稿」的处理，约 0.5 天，请在第 6 节一并决策。

> 另：本期不需要子流程 / 多实例会签，单节点审批即可。

## 五、回写链路（帮助理解为什么 Key 与「结束」如此重要）

| 环节 | 实现 |
| --- | --- |
| ① 流程结束 | bpm-server 发布流程实例状态事件（**仅在流程完成时发布**） |
| ② 转发 | `MesFeedbackStatusListener` 按 Key「mes-feedback-approval」过滤，HTTP POST 到 MES 的 `http://mes-server/rpc-api/mes/feedback/on-approval-result` |
| ③ 报文 | `{ id: 流程实例号, processDefinitionKey, businessKey: 报工单id, status: 2=通过 / 3=驳回, reason: 审批原因 }` |
| ④ 落表 | MES 先把结果落「报工审批结果任务表」，规避与提交方事务的时序差 |
| ⑤ 异步消费 | 30 秒定时任务消费：status=2 调 `approveFeedback`（物料扣减 / 产出单 / 数量更新）；status=3 调 `rejectFeedback`（退回草稿） |
| ⑥ 可靠性 | 任务表带 `retry_count` / `next_retry_time`，失败自动重试，超过阈值标记失败并记录原因（沿用项目同步的成熟模式） |

## 七、联调验收步骤（模型发布后我方配合，预计 1.5 天）

| 序号 | 步骤 | 预期结果 |
| --- | --- | --- |
| 1 | 模型发布后，我方查库确认 `ACT_RE_PROCDEF` 中出现该 Key | 流程定义已部署（当前为 0 条） |
| 2 | MES 新建一条报工单并提交 | MES 状态变为「审批中」；BPM「待办任务」出现该审批任务 |
| 3 | 审批人在「工作流程 → 待办任务」中选择通过 | MES 回写：状态为「已完成」或「待检验」；物料扣减与产出单正确 |
| 4 | 再提交一条，选择驳回并填写意见 | MES 状态退回草稿；驳回原因可在 BPM 流程详情查看 |
| 5 | 驳回后修改并重新提交 | 发起新的流程实例；旧实例结束留痕 |
| 6 | 边界验证：重复提交 / 重复回调 | 不产生重复消费（任务表幂等，重试机制生效） |

> 说明：第 3 步中「待检验」是正常分支 —— 关键工序且需检验的报工，审批通过后仍需等待质检完成，BPM 只代表审批环节结束。
