# bidding 后端本地运行与前端联调说明（2026-09-07 实测版）

> 本文记录 bidding-server 本地运行方式、联调入口与本次实测结论（接口时间序列化、脏数据修正、代理链路），供前后端联调与运维参考。

## 1. 运行方式（本地进程；不新增任何容器）
- 前置：MySQL / Redis / Nacos 已在本机映射端口运行（容器 txgy-mysql/txgy-redis/txgy-nacos，127.0.0.1:3306/6379/8848）；JDK 25（JAVA_HOME=D:`Java`jdk-25）；Maven 3.9。
- 打包：`cd txgy-module-bidding/txgy-module-bidding-server && mvn package -DskipTests`，产出 `target/txgy-module-bidding-server.jar`（约 157MB fat jar）。
- 运行（**与其他服务配置方式一致**：仓库 application-local.yaml + 运行 env 覆盖，详见 txgy-module-bidding-server/run-local.cmd）：
  - 对照 deploy/docker-compose.yml 的 `x-backend-service`：容器用 env 注入（SPRING_PROFILES_ACTIVE=local、namespace 置空=public、nacos:8848/mysql:3306/redis、SERVER_PORT=48080）；本地同构注入，仅地址用 127.0.0.1 映射端口、端口用 48110（本机 48080 被网关占用）；
  - env 清单（bash）：`export SPRING_PROFILES_ACTIVE=local SPRING_CLOUD_NACOS_DISCOVERY_NAMESPACE= SPRING_CLOUD_NACOS_CONFIG_NAMESPACE= SERVER_PORT=48110` 后 `java -jar target/txgy-module-bidding-server.jar`（nacos/db/redis 走 127.0.0.1:8848/3306/6379 映射）；
  - 仓库 application-local.yaml 保持与其他服务同构（dev/127.0.0.1），不落盘修改；namespace 等运行差异一律用 env 覆盖（与其他服务的做法一致）；
  - 注意：**Windows 下 jar 运行中会被文件锁，重打包前须先停进程**。
- 健康检查：`GET http://127.0.0.1:48110/actuator/health` → `{"status":"UP"}`。
- 日志：`target/bidding-run.log`（stdout 重定向）；`${user.home}/logs/bidding-server.log`（logback 文件）。
- Nacos：dev namespace 注册服务名 `bidding-server`（实例 IP 为本机网卡，healthy）——注册仅供网关发现，**直连联调不需要注册**。

## 3. 时间序列化约定（实测 2026-09-07）
- **出参**：LocalDateTime 统一序列化为 **epoch 毫秒数字**（如 `publishTime: 1788668723000`），前端按需自行格式化（dayjs 等）；契约表格中的 `yyyy-MM-dd HH:mm:ss` 仅作文义说明。
- **入参**：时间筛选（beginTime/endTime 等）两种格式实测均可解析：ISO 带 T（`2026-09-06T00:00:00`）与空格格式（`2026-09-06 00:00:00`，URL 需编码）。

## 4. 演示数据修正记录（2026-09-07 已在 ruoyi-vue-pro 执行；其它环境请跑通用脚本）
- 零时间回填：4 行 `publish_time=1970-01-01 08:00:00` → `COALESCE(create_time,last_fetch_time,NOW())`（回填为入库时间 2026-09-06 12:25），列表“发布日期/时间倒序”恢复可用；
- `NULL` 字面清洗：4 行 `tender_project_code='NULL'` → `NULL`（采集侧 ORM 脏值；VO 层 `cleanNullable` 保留兜底归一）；
- 通用脚本：`sql/2026-09-10-backfill-external-notice-publish-time.sql`（含零日期预处理步骤说明）。

## 5. 常见问题排查
1. **前端 404**（api.ts 请求 `/bidding-api/bidding/...`，net::ERR_ABORTED 404）：vite dev server 未加载 `/bidding-api` 代理 → 配置写入晚于 dev 进程启动（实测 vite.config.ts mtime 08:56 > 进程启动 08:27）。处理：重启前端 dev（`pnpm dev`），无需改任何文件。
2. **直连 404 “请求地址不存在”**：URL 漏 `/admin-api` 前缀。
3. **keyword 全文检索报 1-060-106-015**：本环境未启用 ES（`bidding.es.enabled=false`），前端隐藏搜索框或提示“检索暂不可用”。
4. **48110 连不上**：服务未启动或端口被占（`netstat -ano | findstr 48110`）；重打包前先停旧进程（Windows jar 文件锁导致 repackage 失败）。
5. **swagger 打开慢/空白**：首次 `/v3/api-docs` 生成较慢，稍候刷新。

## 6. 本地 ↔ 容器服务网络打通（方案 A，2026-09-07 已生效）

- 问题：bidding 本地进程 RPC 调 system-server/infra-server（容器内网 172.20.x:48080）不可达（Windows 宿主到容器网段不通）→ 登录态接口（token 校验）500/超时。
- 方案 A 落地：
  1. 宿主端口映射：`docker compose -f deploy/docker-compose.yml -f ../txgy-module-bidding/deploy-bidding-local.override.yml -p txgy up -d system infra`（system→127.0.0.1:48087、infra→127.0.0.1:48088；override 同时把两容器 namespace 置空=public，与其它服务/本地 bidding 一致）；
  2. bidding 启动参数（已并入 run-local.cmd）：`--spring.cloud.openfeign.client.config.system-server.url=http://127.0.0.1:48087`、`...infra-server.url=http://127.0.0.1:48088`（feign 直连映射端口，绕过容器内网）；
  3. 验证：网关登录 → 直连 48110 调 `/bidding/crawl-parser/list` 与 `/test`（真实样本 multipart：HTML/PDF）均 200，token 校验/错误上报 RPC 全通。
- 注意：override 文件在 txgy-module-bidding/ 下（模块工作区内）；重建容器后 system/infra 注册回 public（nacos），网关路由与既有依赖不受影响。
