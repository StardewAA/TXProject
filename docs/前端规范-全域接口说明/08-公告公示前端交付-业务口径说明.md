# 08 公告/公示前端交付——业务口径说明

> 读者：前端同学。配套接口见 06-bidding前端契约接口完全对照.md §2（notice）与 api/bidding/notice/index.ts。
> 页面位置：招投标(6735) → 公告/公示管理(6753) → 公告列表(6754)，组件 bidding/notice/index。

## 1. 一句话结论

**公告/公示是“招标人（企业）对外发布的法律文书”，管理端负责起草→发布→撤下的全生命周期；大厅只读展示已发布内容。**
管理端页面做的是“发布工作台”，不是普通的文章 CRUD。

## 2. 公告类型（NOTICE_TYPES，四类，别自由扩展）

| code | 名称 | 出现时点 | 说明 |
| --- | --- | --- | --- |
| TENDER_NOTICE | 招标公告 | 招标启动 | 邀请/公开招标的启动文书，含项目、资格要求、获取文件时间地点等 |
| CHANGE_NOTICE | 变更公告 | 招标过程中 | 对已发布公告/文件的澄清、修改、延期等 |
| WIN_CANDIDATE_PUBLICITY | 中标候选人公示 | 评标后 | 公示期 ≥3 日，接受异议；公示期内不能发中标通知书 |
| WIN_RESULT_PUBLICITY | 中标结果公示 | 定标后 | 中标结果对外公布 |

## 3. 状态与生命周期（管理端）

DRAFT(草稿) → PUBLISHED(已发布) → UNPUBLISHED(已撤下) → 可再发布；ARCHIVED(已归档，终态)。
规则（业务原因）：
1. 先建草稿再发布：发布前允许反复编辑；**已发布后不允许直接改正文**——对外文书已生效，改动必须走“撤下→改→重新发布”（留痕），避免公众看到前后矛盾版本。
2. 正文每次修改会追加内容版本（contentVersion），历史版本保留（后端已支持字段）；前端编辑保存时带上最新版本号，避免并发覆盖。
3. 大厅只读接口（/bidding/notice/public/*）只展示 PUBLISHED，且不带管理字段；管理端才能看到草稿/撤下/归档。
4. 撤下≠删除：撤下后仍可再发布；删除仅对草稿/已撤下且无对外引用时允许（业务上后端按状态约束，前端按钮按状态显隐即可，见 notice前端开发指南.md §3.2 行操作矩阵）。

## 4. 其它字段口径

- internalFlag（企业内部公告?）与外发公告并存：false=对外（进大厅/公示），true=仅企业内部可见。本期以对外为主；对外公告建议 internalFlag=false。
- publicLevel：公开范围（如 SOCIAL 全社会），下拉展示即可，实际范围由后端统一；页面不要自行发明级别。
- pdfFileId/pdfSha256/pdfSize：对外公布件（盖章 PDF）优先于富文本正文；若两者都传，以 pdf 为对外最终件，正文用于站内阅读。
- publisherName/publishTime：对外展示署名与时间；发布操作时后端生成/校验。

## 5. 合规提醒（招标公告和公示信息发布管理办法等，docs/法规依据/）

- 依法必须招标项目的招标公告、中标候选人公示等有法定的发布渠道/期限要求（公示期不少于 3 日等）。平台记录发布时间供追溯；
- 前端不必实现期限计算，但展示“发布日期”与“公示期”类字段时不要擅自改时区/裁剪日期，保持原文语义。

## 6. 页面建议与文案模板

- 列表行操作按状态显隐（草稿：编辑/发布/删除；已发布：撤下/查看；已撤下：编辑/再发布/删除；归档：查看）。
- 编辑保存请求体带 contentVersion；保存提示“新版本已追加”。
- 空态/提示模板：
  - 发布确认：“发布后将在招投标大厅对外公示，已发布内容如需修改需撤下后重新发布，是否继续？”
  - 撤下确认：“撤下后大厅将不再展示，历史版本保留；如需再次对外请重新发布。”
  - 类型选择默认：招标公告。

## 7. FAQ（可直接对话术）

- Q：为什么已发布不能直接编辑？A：对外法律文书已生效，直接改会造成版本漂移与审计问题，一律撤下再发。
- Q：发布后发现写错了怎么办？A：撤下→修正→重新发布，新版本号+1，历史可查。
- Q：大厅为什么看不到我刚建的？A：未发布（草稿）只对管理端可见，发布后大厅才展示。
