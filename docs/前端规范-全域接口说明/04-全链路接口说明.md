# bidding 全链路接口说明：公告 / 爬虫 / 个人订阅 / 个人信息录入

> 目的：按业务动线串起四大域的接口（先谁后谁、依赖什么、出错怎么办），供前端联调、测试脚本与演示使用。
> 配套：逐接口字段与设计依据见同目录 01-接口逐一说明与设计依据.md；本文件只讲“链路怎么走”。

## 0. 通用约定
- 入口（三选一）：直连 `http://127.0.0.1:48110/admin-api`；前端代理 `http://localhost:5666/bidding-api`（开发）；网关 `http://127.0.0.1:48080/admin-api`（部署/管理端，需网关含 bidding 路由）。
- 需登录的接口带 `Authorization: Bearer <token>` 与 `tenant-id: 1`；登录：`POST /admin-api/system/auth/login`（admin/admin123，body {"username":"admin","password":"admin123"}）。
- 返回 `CommonResult{code,msg,data}`，code=0 成功；时间字段为 **epoch 毫秒数字**（平台统一，前端 dayjs(Number(v))）。
- 写操作均幂等（按钮 loading 防连点）；权限码见 §6。

## 1. 链路 A：招标人发布公告（主体完善 → 授权 → 备案 → 公告 → 大厅）

| 步 | 端点 | 要点 |
| --- | --- | --- |
| A1 完善主体 | `POST /bidding/subject/profile/save`（body：subjectType=TENDERER + 必填七项） | 未建档先 `GET /bidding/subject/profile/get?subjectType=TENDERER`（data=null 走新建）；USCC 18 位按 GB32100-2015 强校验（错返 1-060-106-035）；保存后 `complete=true`；必填清单见 02-字段枚举 §7.3 |
| A2 平台授权 | `POST /bidding/subject-auth/authorize`（body：tenantId + subjectType=TENDERER） | 管理端动作；重复启用返 106_032；停用后可复用启用 |
| A3 资格自检 | `GET /bidding/subject/profile/eligibility?subjectType=TENDERER` | eligible=true 才可继续；否则 reasonCodes=NOT_AUTHORIZED/PROFILE_INCOMPLETE 并提示 |
| A4 备案（可选前置） | `POST /bidding/filing/submit`（BID-ENT-REG-01；幂等键=类型+项目编号） | 受招标人发布门约束：未授权 106_031 / 未完善 106_034 |
| A5 建公告 | `POST /bidding/notice/create`（body：NoticeSaveReqVO） | 草稿 DRAFT；payload 按权威数据集必填校验（缺项 106_003）；受发布门约束 |
| A6 发布 | `POST /bidding/notice/publish?id=` | DRAFT→PUBLISHED（需正文/PDF 原文件）；再次触发门校验 |
| A7 大厅查看 | `GET /bidding/notice/public/list`、`/public/detail?id=` | PermitAll 免登录；只出 PUBLISHED |
| 管理面 | `GET /bidding/notice/page|get`、`PUT /update`、`POST /unpublish`、`DELETE /delete` | 本企业公告管理；`/exchange/gather-sync` 同步检索、`/exchange/deadline` 查截止 |

示例（A5→A6）：
  POST /admin-api/bidding/notice/create  -> {code:0,data:{id}}
  POST /admin-api/bidding/notice/publish?id={id} -> {code:0}

## 2. 链路 B：爬虫采集（源 → 解析器 → 下载器 → 审核 → 大厅/订阅）

| 步 | 端点 | 要点 |
| --- | --- | --- |
| B1 配置源 | `POST /bidding/crawl-source/create`（body：sourceCode/baseUrl/channelCode=GENERIC/parserCodeDefault/entryUrlsJson/fetchIntervalSeconds） | interval 必须 ≥120（<120 返 106_046）；新建默认停用；`PUT /update` 修改、`POST /enabled` 启停 |
| B2 解析器核对 | `GET /bidding/crawl-parser/list`；`POST /bidding/crawl-parser/test`（multipart） | 7 个内置解析器（HTML/JSON/PDF 通用 + EBIDDING/QYZB_SHCCMG/QYZB_JSON/GX_E_BIDDING）；test 可选 HTML/JSON 文本或 .html/.json/.pdf 文件，出 status/字段/meta/warnings |
| B3 触发采集 | `POST /bidding/crawl-source/run?sourceCode=`（人工）或开启 `bidding.crawl.scheduler.enabled` 定时 | 返回汇总 fetched/ingested/failed（按栏目）；源内条目间隔 1.5s；QYZB 每栏目每轮最新一页；去重：URL 指纹 + ingest origUrlHash 幂等 |
| B4 管理审核 | `GET /bidding/notice-external/manage/page`（NEW 列表）；`GET /manage/get?id=`（预览净化正文/结构化/附件病毒） | approve→ACTIVE（触发关注扇出+索引）；reject 驳回；take-down 下线 |
| B5 大厅展示 | `GET /bidding/notice-external/page`、`/detail?id=`、`/go?url=` | 只出 ACTIVE+SOCIAL；detail 三形态（HTML 净化版/PDF/附件）；外链一律走 go（白名单） |
| B6 运维 | crawl-task/page|get|retry、crawl-job/page|get | 失败任务人工重试（仅 FAILED） |

示例（B3，QYZB 源一轮）：
  POST /admin-api/bidding/crawl-source/run?sourceCode=QYZB
  -> {code:0,data:{sourceCode:QYZB,totalIngested:10,totalFailed:0,categories:[{name:变更公告,fetched:10,ingested:10}]}}

## 3. 链路 C：个人订阅（关注 → 我的关注 → 动态）

> 关注不需要主体信息完善（登录+权限即可），未授权/未完善只影响“投标/发布”动作。

| 步 | 端点 | 要点 |
| --- | --- | --- |
| C1 详情页初始态 | `GET /bidding/notice-follow/status?targetType=&targetKey=` | 公告级 targetType=ANNOUNCEMENT targetKey=公告 id；维度级 PROJECT/TENDER_PROJECT/SECTION targetKey=projectKey/tenderProjectKey/bidSectionKey（外部公告详情接口已下发跟踪键） |
| C2 关注/取关 | `POST /bidding/notice-follow/follow`、`/unfollow`（body：targetType+targetKey） | 幂等；关注已生效公告（外部 ACTIVE / 内部 PUBLISHED）自动种一条已读初始动态（timeline 立即有内容） |
| C3 我的关注 | `GET /bidding/notice-follow/item/page?followType=&followKey=` | followType 四值均可过滤；行含 stageCode/latestDynamicTime/unreadCount/followTime/noticeStatus/available |
| C4 动态 | `GET /bidding/notice-follow/item/{itemId}/timeline` | EXTERNAL 动态跳 origUrl（经 go）；INTERNAL 动态跳 /bidding/notice/public/detail?id=noticeId；available=false 隐藏详情跳转 |
| C5 已读 | `POST /bidding/notice-follow/item/{itemId}/read` | 清未读 |

动态来源：外部公告 approve（EXTERNAL_ACTIVE）、内部公告发布/更新（NOTICE_PUBLISHED/NOTICE_UPDATED，2026-09-07 已接线：发布即扇出、已发布正文实质更新扇出新版本；同版本重发/重放幂等不打扰，见 05-业务核查与修复清单.md §2）。

## 4. 链路 D：个人信息录入与资格（投标人视角）

| 步 | 端点 | 要点 |
| --- | --- | --- |
| D1 建档 | `GET /bidding/subject/profile/get?subjectType=BIDDER` → data=null 时 `POST /bidding/subject/profile/save` | 必填七项；save 幂等（同一租户一类型一档案）；USCC 校验/完善度实时核算 |
| D2 管理端经办用户 | `GET /bidding/subject-auth/user/page`、`POST /user/bind`、`DELETE /user/unbind?id=` | 绑定需 system 用户有效（RPC 校验）；重复绑 106_037 |
| D3 资格查询 | `GET /bidding/subject/profile/eligibility?subjectType=BIDDER`（企业）；`GET /bidding/subject-auth/eligibility?tenantId=&subjectType=`（平台） | 返回 authorized/authStatus/profileComplete/eligible/reasonCodes/missingRequiredNames/授权时间 |
| D4 投标资格门 | （预留）服务端 assertBidderEligible | 本期无投标递交动作；资格=平台授权 ENABLED 且档案必填齐 |

## 5. 跨链路关键数据流

- 外部公告生命周期：ingest 落 NEW → manage 审核 approve → ACTIVE（大厅可见 + 关注扇出）→ take-down INACTIVE → ARCHIVED。
- 订阅与内容联动：详情页（ANNOUNCEMENT/PROJECT/SECTION 键）→ follow 建行 → approve/发布产生事件 → timeline 未读 → read 清零。
- 资格门联动：profile/save 完善度 + subject-auth/authorize 授权 → notice/filing 写操作前置断言（106_031/034）→ eligibility 供前端预检。
- 键的出处：外部公告 detail/page 的 projectKey/tenderProjectKey/bidSectionKeys（跟踪键）→ 前端“跟踪该项目/标段”按钮直接可用。

## 6. 权限码与错误码速查

- 权限：bidding:notice:query|create|update|publish|delete；bidding:notice-external:query|update；bidding:crawl-source:query|create|update|delete；bidding:crawl-task:query|update；bidding:crawl-job:query；bidding:subject:query|update；bidding:subject-auth:query|update；bidding:filing:create|update。
- 高频错误：106_001/002 公告不存在/下线；106_013 采集 payload 非法；106_014 跳转拒绝；106_015 未启用检索；106_031 未授权（发布门）；106_032 重复授权；106_034 信息未完善；106_035 USCC 不合法；106_046 采集间隔 <120s；403=菜单/角色未放行（system 库执行菜单 SQL + system_role_menu 挂载）；500 报表不存在=漏执行 DDL（见 sql/README-完整执行清单.md）。

## 7. 端到端演示剧本（10 分钟走完全链）

1. 招标人：A1 完善 TENDERER → A2 平台授权 → A3 预检通过 → A5/A6 建并发布一条公告 → A7 大厅可见；
2. 订阅者：C1 status=未关注 → C2 关注该内部公告（ANNOUNCEMENT）→ C3 我的关注出现该行（noticeStatus=PUBLISHED、available=true）→ C4 timeline 有已读 NOTICE_PUBLISHED 初始动态 → 发布方再改正文保存 → C4 出现未读 NOTICE_UPDATED（版本+1）→ C5 已读；
3. 平台：B1 建 QYZB 源（interval 180）→ B2 用真实样本测 QYZB_JSON → B3 run（fetched 10/ingested 10）→ B4 manage/page 见 NEW → approve 一条 → B5 大厅外部公告可见（详情含跟踪键）→ 订阅者 C2 关注该外部公告 → 收到 EXTERNAL_ACTIVE 动态；
4. 投标人：D1 完善 BIDDER（故意缺联系人→save 后 complete=false、缺失项提示→补齐）→ D3 eligibility 未授权提示 → 平台 D2 绑定经办用户 + authorize → D3 通过（eligible=true，为后续投标预留）。
