# WMS—ERP 第一阶段主数据与幂等接入设计

## 目标

在现有 ERP—WMS v0.2 接口契约上建立第一条真实、可验证的远程调用链，使 ERP 的物料、客户、供应商和仓库公共数据能够写入 WMS，并让 WMS 成为仓库主数据的权威来源。本阶段同时建立跨模块请求的防重复、版本校验、租户隔离和结果查询基础，为后续库存判断、预留、入出库及 MES 协作复用。

本阶段不实现库存判断、库存预留、入库、退货、协作单 G/B 或 MES 流程，也不把尚未实现的接口伪装为成功。

## 当前基线

- 开发分支：`wms/erp-integration-20260908`。
- ERP 已交付 `WmsIntegrationApi` 及 v0.2 DTO，包含 11 个接口；ERP 具有 mock/remote 两种网关，默认使用 mock。
- ERP 商品、客户和供应商已有提交事务后的同步入口。
- ERP 仓库仍直接维护 `erp_warehouse` 公共字段，仅保存 `wmsWarehouseCode` 映射，尚未成为 WMS 仓库的代理操作入口。
- WMS 主数据表已有部分统一编码、类型、状态和版本字段，但没有 `WmsIntegrationApi` 服务端实现，也没有通用请求处理记录。
- ERP 单据使用 `<materialCode>-DEFAULT` 作为默认 SKU 编码。
- 合并基线使用 JDK 25 运行指定的 14 项 WMS 测试，全部通过。

## 设计原则

1. 继续使用 v0.2 的路径和 DTO，避免 ERP 再次修改调用契约。
2. 公共主数据只有一个权威来源：物料与往来单位来自 ERP，仓库来自 WMS。
3. ERP 同步不能覆盖 WMS 专属字段，也不能修改库存事实。
4. 每个请求必须同时通过认证租户校验、请求幂等校验和数据版本校验。
5. 业务写入与成功请求记录在同一事务中提交。
6. 无法安全推断的存量映射返回明确错误，由迁移清单处理，不按名称自动关联。

## 组件与职责

### WMS RPC 接入层

新增 `WmsIntegrationApi` 的服务端实现，首期开放：

- `PUT /rpc-api/wms/integration/master-data/material`
- `PUT /rpc-api/wms/integration/master-data/partner`
- `PUT /rpc-api/wms/integration/master-data/warehouse`
- `GET /rpc-api/wms/integration/request/{requestId}`

其余 v0.2 接口保留契约，但在对应功能完成前返回明确的“功能尚未启用”业务错误。这样 remote 模式不会得到虚假成功结果。

接入层只负责参数校验、租户一致性检查和调用应用服务，不直接拼装数据库写入。

### WMS 幂等请求服务

新增通用请求记录，至少包含：

- `tenant_id`
- `request_id`
- `operation_type`
- `payload_digest`
- `target_type`
- `target_code`
- `processing_status`
- `business_status`
- `processed_version`
- `response_payload`
- `failure_reason`

唯一键为租户、请求号和未删除标记。请求体按稳定字段序列化后计算摘要。同一请求号和相同摘要重放时返回已保存响应；摘要不同则返回 `INTEGRATION_REQUEST_DUPLICATE_CONFLICT`。并发请求依靠数据库唯一键裁决，发生唯一键竞争后重新读取原记录并执行同样的摘要判断。

失败的业务事务整体回滚，不保存成功状态。可重试的远程失败由 ERP 已有出站记录处理；WMS 仅保存已经接收到并完成裁决的请求结果。

### WMS 主数据同步服务

物料以租户和 `materialCode` 定位。新建时同时创建 `<materialCode>-DEFAULT` SKU；已存在时更新 ERP 公共字段和默认 SKU 的编码、名称、条码等公共映射，保留分类、品牌、长宽高、毛净重、仓储售价、质量报告和库存。若统一编码对应关系不唯一，或现有多规格数据无法确认默认规格，则拒绝同步并报告迁移冲突。

客户与供应商以租户和 `partnerCode` 定位。相同编码可能兼具客户与供应商身份，WMS 应合并为现有枚举支持的“客户/供应商”，而不是创建两条往来企业。更新时保留 WMS 级别等专属字段。

仓库由 WMS 生成或校验 `warehouseCode`。创建请求允许 ERP 不传仓库编号；WMS 返回权威仓库编号。修改请求必须携带仓库编号及 `expectedVersion`，只有版本一致时更新并递增版本，否则返回 `WAREHOUSE_VERSION_CONFLICT`。仓库类型首期限定原料仓和成品仓。

物料和往来单位使用 ERP 的 `dataVersion`：新版本覆盖旧版本；相同版本且内容相同作为幂等成功；相同版本但内容不同或低版本请求返回 `SYNC_VERSION_STALE`。

### ERP 仓库代理服务

ERP 的仓库新增和修改流程调整为：先准备 WMS 请求并在事务提交后调用远程网关，成功后保存 WMS 权威编号及版本。ERP 表继续保存默认仓库、仓库价格、运费价格等 ERP 扩展配置；公共名称、类型、地址、负责人和启用状态由 WMS 返回结果驱动。

为避免 ERP 本地提交成功而 WMS 暂时失败，调用沿用 ERP 出站请求记录和安全重试机制。页面应能看到同步状态及失败原因。在 WMS 确认前，新仓库不能用于需要真实库存的跨模块业务。

## 请求处理流程

```text
ERP 保存主数据
→ ERP 提交本地事务并写出站记录
→ remote 网关调用 WMS
→ WMS 校验认证租户与 tenantId
→ WMS 以 requestId 裁决重复请求
→ WMS 校验统一编码、数据版本及存量映射
→ 同一事务更新主数据和成功请求记录
→ WMS 返回权威编码、状态和已处理版本
→ ERP 更新同步结果或等待重试
```

请求租户必须等于当前认证上下文租户。调用方只传 `tenantId` 不构成跨租户授权。查询请求结果时也必须受当前租户过滤。

## 数据迁移

新增一个可版本管理的升级脚本，包含请求记录表、必要索引和约束。脚本执行前先报告以下存量问题：

- 同一租户内重复的物料编码、企业编码或仓库编码。
- ERP 统一物料编码与 WMS 商品/SKU 无法形成唯一映射。
- WMS 商品有多规格，但不存在或存在多个候选默认规格。
- 空编码、无效类型及不支持的仓库类型。

脚本不得静默合并或删除存量数据。发现冲突时中止约束创建，并输出人工迁移清单。迁移说明需区分全环境通用脚本与租户专属修复脚本。

## 状态和错误

使用现有 v0.2 状态常量和错误码。首期至少覆盖：

- 请求号内容冲突。
- 旧版本或同版本内容冲突。
- 物料类型或仓库类型无效。
- 仓库乐观锁版本冲突。
- 认证租户与请求租户不一致。
- 存量统一编码映射不唯一。
- 尚未启用的库存或单据处理能力。

错误响应不得写入业务成功状态，不得创建半成品主数据。日志记录请求号、租户、操作类型和目标编码，不记录敏感账户信息。

## 测试与验收

### 自动测试

- 幂等服务：首次请求、相同内容重放、不同内容冲突、并发唯一键竞争。
- 版本服务：高版本更新、旧版本拒绝、同版本同内容成功、同版本不同内容拒绝。
- 物料同步：创建默认 SKU、更新公共字段、保留 WMS 扩展字段、复杂存量映射拒绝。
- 往来企业同步：客户、供应商、身份合并及字段保留。
- 仓库同步：WMS 生成编码、带版本修改、版本冲突、类型校验。
- 租户测试：请求租户不一致拒绝，两个租户相同编码互不影响。
- 接口测试：四个首期接口的路径、参数、响应结构和错误格式与 v0.2 一致。
- ERP 测试：mock 模式保持可用，remote 模式正确调用并记录成功/失败；仓库代理保留 ERP 扩展配置。

### 联调验收

1. ERP 创建或修改商品后，WMS 出现同一物料编码及唯一默认 SKU。
2. ERP 创建客户与供应商后，WMS 形成正确的往来企业身份。
3. ERP 仓库页面创建或修改公共字段后，WMS 保存权威仓库，ERP 保存返回编号和版本。
4. 相同请求重复发送不会重复创建；不同内容复用请求号会被拒绝。
5. 旧版本不能覆盖新版本；不同租户无法读写彼此数据。
6. 同步前后 WMS 扩展字段和库存数量保持不变。
7. 切换 ERP 到 remote 模式完成真实接口联调，并保留请求记录、测试日志和数据库升级说明。

## 交付物

- WMS RPC 服务端、主数据同步服务和幂等请求服务。
- ERP 仓库代理及同步状态处理调整。
- 数据库升级与存量检查脚本。
- 单元测试、数据库测试和 ERP remote 联调测试。
- v0.2 接口实施说明、配置切换说明、已知限制及下一阶段入口。

## 后续边界

第二阶段实现可用库存、预留、释放、核销、销售库存判断、审批出库及 ERP 回调；第三阶段实现采购入库、质检、退货和盘点；第四阶段实现协作单 G/B、MES 领料与成品入库、可靠补偿及全链路追踪。本阶段的数据模型和请求服务需能被这些流程直接复用，但不提前实现后续业务。
