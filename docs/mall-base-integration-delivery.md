# 商城与基座组联调交付物

本文是商城组可以独立交付的联调资料。账号、支付沙箱、Token 密钥和基座回调地址仍由基座组填写，不在商城代码中硬编码。

## 权限矩阵

| 角色 | 企业/店铺 | 商品 | 订单 | 退款 | 结算 | 库存 |
|---|---|---|---|---|---|---|
| 平台管理员 | 查询、审核、停用 | 全部 | 全部 | 全部 | 全部 | 查询 |
| 企业管理员 | 本企业查询、建店 | 本企业新增、编辑、提交审核 | 本企业查询 | 本企业发起 | 本企业查询 | 本企业查询 |
| 店铺运营员 | 本店查询 | 本店编辑、上下架 | 本店查询、发货 | 本店售后处理 | 本店查询 | 本店查询 |
| 企业采购员 | 无 | 查询可售商品 | 本企业创建、查询、取消 | 本人订单申请 | 无 | 查询可售库存 |

权限编码：`product:enterprise:*`、`product:shop:*`、`product:spu:*`、`trade:order:*`、`trade:after-sale:*`、`trade:settlement:*`、`wms:stock:query`。后端必须保留 `@PreAuthorize` 校验，前端隐藏按钮不能替代安全控制。

## 禁用通知契约

联调约定基座组向商城发送 `POST /mall/integration/base/status-changed`，商城侧需接入该回调，并按 `requestId` 幂等处理：

```json
{"requestId":"base-20260904-0001","tenantId":1001,"userId":2001,"eventType":"TENANT_DISABLED","enabled":false,"reason":"企业资质过期","effectiveTime":"2026-09-04T10:00:00+08:00"}
```

企业/租户禁用后阻止该租户新建订单、支付和店铺写操作；用户禁用后阻止该用户新建订单和售后写操作；历史订单保留查询权限按基座返回结果执行。重复通知不得重复扣库存或改变订单状态。商城无法接收通知时显示“待同步”，由基座重试。当前仓库已交付契约、字段和验收用例；回调鉴权、签名密钥和基座推送实现需在联调时补齐。

## 验收数据与用例

联调环境至少准备两个租户（1001、1002）、两个企业、两个店铺、平台自营商品、可售/缺货/定制三类 SKU、两个采购员和一个店铺运营员。所有请求记录 `tenantId`、`userId`、`orderNo`、`requestId`。

| 编号 | 场景 | 预期 |
|---|---|---|
| A-01 | 1001 采购员登录 | 只能看到 1001 数据 |
| A-02 | 访问 1002 订单 | 403，不返回数据 |
| A-03 | 关闭采购权限后下单 | 无权限，购物车不清空 |
| A-04 | 禁用租户后下单 | 拒绝创建订单 |
| A-05 | 支付成功重复回调 | 只处理一次 |
| A-06 | 缺货 SKU 下单 | WMS 返回库存不足，不进入待支付 |
| A-07 | 多店铺下单 | 订单项按 `shopId` 分组 |
| A-08 | ERP/WMS 暂停 | 保留待同步状态，可重试 |
