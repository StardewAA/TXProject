# 06 新模块工程结构与实施边界（已按《招投标模块开发规范》对齐）

> 目标：全部系统实现在 **txgy-module-bidding** 模块组内完成，既有平台（txgy-* 各模块）**零改动**。
> ⚠️ 对齐说明（2026-09-03）：本文为早期设计稿，工程落地以《招投标模块开发规范》为**唯一权威**，冲突处一律以规范为准；"内部功能系统（后台 ent / 监管 sup / 大厅 hall / ES 检索）"不再拆成独立 Maven 模块，统一落在 bidding 小模块的 server 内按域分层组织，理由与落点见下文。

## 一、工程结构（txgy 现行，已落地）

小模块聚合结构（与平台兄弟模块同构，如 txgy-module-infra/-im/-hrm）：

- `txgy-module-bidding`（聚合 pom，本小模块根）
  - `txgy-module-bidding-api`：跨模块接口与全量 VO/代码集定义（api/vo、api/enums、api/<domain>/dto，仅依赖 txgy-common，无业务实现）
  - `txgy-module-bidding-server`：业务实现（controller/service/dal/enums/framework），可独立启动打成可执行 jar（`build.cmd`；单体时并入 `txgy-server`）

**内部不再另设 yudao-module-bidding-ent/sup/hall/es 等 Maven 模块**：19 个功能模块（后台-01~08、监管-01~06、大厅-01~05）按《招投标模块开发规范》第 4.1/4.2 章组织为 server 内的包与域——

| 功能系统 | 代码落点 | 说明 |
| --- | --- | --- |
| 企业后台（后台-01~08，含公告/公示管理） | `controller/admin/<domain>`、`service/<domain>`、`dal/...` | 租户数据走 T 轨（TenantBaseDO），权限 `bidding:xxx:yyy` |
| 公共服务大厅（大厅-01~05 的只读部分） | 同一 server 的公开读接口 | `@PermitAll`（SecurityConfiguration 白名单）+ 跨租户读（`TenantUtils.executeIgnore`）+ 公开级别白名单（规范 2.1/3.2/4.8）；只接收社会公开字段，政务字段到边界即拒绝 |
| 监管系统（监管-01~06） | `controller/admin/<domain>` 按域收口（如监管/归集） | 按规范第五章域清单登记域与表；辖区数据权限走平台数据权限 starter |
| ES 检索 | bidding server 的检索组件（`service/<domain>/search`） | 规范 4.6：框架无 ES starter，bidding 侧按需引入客户端并收敛于检索组件，实现 04 文件的公开文档索引/查询接口；启用/降级走配置 |

## 二、依赖规则（只复用，不改动）

1. 可依赖（作为库使用，不改其任何代码）：txgy-common、txgy-framework 各 starter（web/security/mybatis/redis/tenant/job/mq/protection 等）、平台 BOM 的版本管理。
2. 禁止：修改既有模块源码、向 txgy-server 注入本组模块、在既有表中加字段。本小模块独立启动（txgy-module-bidding-server），与既有平台通过接口互通（api 契约 + RPC）。
3. 业务 SQL 一律放本小模块 `sql/` 目录（文件名 `yyyy-MM-dd-<主题>.sql`），建表约定与评审见规范第五章。
4. ES：独立集群或独立索引前缀，不与既有系统共用索引命名空间；客户端依赖只允许出现在 bidding 检索组件内。

## 三、模块内目录约定（遵循《招投标模块开发规范》）

- 代码目录：`controller/admin/<domain>`（含 vo）、`service/<domain>`、`dal/dataobject/<domain>`、`dal/mysql/<domain>`、`enums`、`framework`；跨模块 DTO/接口放 api 模块的 `api/<domain>/dto`。不引入除平台 starter 以外的框架。
- VO 字段：全量交换 VO 用 `api/vo` 的 record（字段名照录规范英文名称，含拼写瑕疵，逐字段 `@PublicLevel`）；页面/内部接口用自建 VO（规范第三章），字段语义与权威数据集一一对应（02 文件映射表为"字段从哪来"的参照）。
- 表：命名/长度/内容表/租户 T·G 轨/索引/评审按规范第五章；错误码按规范 4.7（`1-060-YYY-ZZZ`，先登记后占用，规约测试自动断言）。

## 四、实施顺序（照做）

1. 先建/维护 txgy-module-bidding-api：全量 VO 与代码集（api/vo、api/enums）作为三侧共同契约（已完成 170 VO/125 代码集）；
2. 企业后台（后台-01→08 按顺序），每个功能域完成"先失败用例 → 实现 → 跑绿"（TDD，规范六章）与建表评审；
3. 监管系统（监管-05 专家库、监管-01 备案先做，再 02 投诉、03 检查、04 信用、06 归集与 ES 检索组件）；
4. 公共服务大厅（大厅-01/02/03/04 读检索组件，大厅-05 投诉入口对接监管-02）；
5. 联调三条主线：备案链路（后台→监管）、公开链路（后台/监管→归集→检索组件→大厅）、投诉链路（大厅→监管→回推大厅）；
6. 验收清单：租户隔离抽查、公开级别字段白名单抽查、幂等重放测试、时限锁定测试（20/15/3/5/30 日）、检索不可用降级测试、归档只读测试。
