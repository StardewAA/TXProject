## 五、问题与改进建议

### 缺陷 D1（展示层，轻微）：Excel 导入的学员被标记为「手动添加」

| 项 | 内容 |
| --- | --- |
| 现象 | 通过「批量导入」入班的学员，在参训人员维护列表的「加入来源」列显示为「手动添加」 |
| 证据 | S10：3 名导入学员 `3013/3014/3015` 的 `source` 均为 `1`；`training_class_student.source` 实测 `[3015:1 3014:1 3013:1]` |
| 根因 | `ClassStudentServiceImpl.importStudents()` 组装 `ClassStudentAddReqVO` 后复用 `addStudents()`，而 `addStudents()` 内部恒定 `student.setSource(1)`，导入路径未传递来源标记 |
| 影响 | 不改写入班、建任务等核心逻辑；但管理员无法按来源区分学员，后续按来源统计会失真 |
| 建议 | `addStudents()` 增加 `source` 入参（手动=1、导入=2），或导入分支单独覆写 `source` |

### 观察 O1（数据完整性）：参训人员「部门 / 班组」列恒为空

- `training_class_student.dept_name` 在 `addStudents()` 中未写入，仅写了 `user_name` 快照；主测试班 10/10 条为 `NULL`。
- 影响：列表「部门/班组」列无数据，`deptName` 筛选条件恒返回 0 条。
- 建议：入班时通过 `AdminUserApi` 一并补写 `deptName`（部门/班组）快照。

### 观察 O2（文案准确性）：资格核查合格结论固定包含「复工培训合格」

- `QualificationServiceImpl` 合格分支文案硬编码为「岗前培训合格，复工培训合格，具备上岗资格」。
- 当项目下仅有岗前培训班、并无复工培训班时，仍输出「复工培训合格」，与实际参与情况不符（本次 Q01 即为此场景）。
- 建议：按实际命中的班次类型动态拼接结论文案。

### 说明 O3（非缺陷）：督促记录为追加式留痕

- `remind/record-page` 返回该班**全部历史**督促记录，重复点击「一键督促」会继续累积记录，不做幂等覆盖。
- 符合审计留痕设计，判定正确。测试中观察到 07:01/07:02 的人工点击产生了 30 条历史记录，本次自动化执行新增 9 条。

## 六、总体结论

1. **培训管理 5 个子分支核心链路全部跑通**，42 个用例通过 41 个，唯一的失败项是展示层的来源标记错误，不阻塞任何业务流程。
2. **状态机严谨**：草稿 / 进行中 / 已完成 / 已取消 四态的编辑、删除、开班、结业、取消、学员管理、进度登记、督促均有明确准入校验，越权操作全部被正确拦截并返回可读的业务错误码（`1_061_012_xxx` / `1_061_013_xxx` / `1_061_014_xxx`）。
3. **数据联动正确**：入班自动生成「学员 × 课程」学习任务；移出学员任务随之作废，重新入班可重建；定课冻结与在班人数冗余均实时刷新。
4. **跨模块联动正常**：一键督促调用站内信成功落库；上岗资格核查复用系统用户与培训班数据，对不存在的人员/项目做了降级处理，不抛异常，便于外部系统对接。
5. **遗留优化项**：缺陷 D1 与观察 O1、O2，均为低风险改进项，建议纳入下一轮迭代。
