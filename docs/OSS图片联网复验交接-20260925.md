## 复验结果（2026-09-25 06:10–06:35，只读，未改代码/配置/镜像/库）

### 结论：OSS 图片链路完全正常；此前失败根因是宿主机 Clash 代理，非 OSS/证书/代码问题

**根因定位（环境核对）**
| 项 | 实际结果 |
| --- | --- |
| 代理进程 | 宿主机运行 **Clash Verge**：`clash-verge.exe`(PID 3356) + `verge-mihomo.exe`(PID 4492)，`verge-mihomo` 监听 `127.0.0.1:7897`（HTTP 混合代理） |
| 环境变量 | `HTTPS_PROXY` / `HTTP_PROXY` = `http://127.0.0.1:7897/`，`NO_PROXY=localhost,127.0.0.1,::1`（只排除 localhost，不含 OSS 域名） |
| Windows 系统代理 | 注册表 `ProxyServer=127.0.0.1:7897`，但 **`ProxyEnable=0`（当前已关闭）** |
| 真实 DNS | WLAN 网卡 DNS=`219.244.0.19`（真实运营商 DNS）；`nslookup` 得到 OSS 真实 IP `39.156.231.75`（无 TUN 网卡接管，无 fake-ip） |
| 关键对照 | `curl` 走环境变量代理 → **`schannel: failed to receive handshake`**（SSL 失败，即交接文件所述现象）；`curl --noproxy '*'` 直连 → **HTTP 200** |

> 交接文件里"DNS 均返回 `198.18.0.57`"是 Clash **fake-ip 模式**特征（`198.18.0.0/16` 为 Clash fake-ip 网段）。当前 TUN 未开（网卡列表无 Clash TUN），故 `nslookup` 走真实 DNS 得真实 IP；但**环境变量 `HTTPS_PROXY` 仍在**，任何尊重该变量的客户端（curl、部分 Node 场景）访问 OSS 都会被 Clash 处理而握手失败。之前"浏览器图片加载超时"发生在系统代理开启（`ProxyEnable=1`）时，浏览器走 7897 同样失败。
