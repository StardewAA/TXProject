## 已实现

### 订单物流

- 新接口 `GET /app-api/trade/order/get-logistics?id=订单ID`，校验当前租户和买家本人后才访问缓存或查询服务。
- 返回已知承运商、运单号、查询状态、运输状态、原始状态码、来源、更新时间、刷新等待时间及文字轨迹。时间字段沿用项目的毫秒时间戳序列化。
- 查询状态区分 ERP 等待/拒绝、未发货、缺单号、未开通、暂无轨迹、可用、查询失败、不适用和订单取消；取消状态优先于过期 ERP 等待记录。
- 有 ERP 履约记录时，未确认出库、单号不匹配或模拟 ERP 模式不能调用真实物流服务。兼容无 ERP 记录的历史已发货单，不回填虚构履约记录。
- 旧物流接口保持响应形状与后台权限要求，并共用新的查询保护。
- 轨迹按时间排序、去重并限制条数；不根据描述文字猜测签收。物流签收不会自动确认收货、退款、结算或改库存。
- 双端支持异常提示和重试；页面切换、账号切换或请求已过期时丢弃迟到结果，不显示另一订单/账号的响应。

### 查询安全与外部服务边界

- `txgy.trade.express.query-enabled` 默认 false；本机 Compose 显式配置 `TXGY_TRADE_EXPRESS_QUERY_ENABLED=false`。
- 现有快递 100/快递鸟适配补充状态映射、请求结果匹配与超时处理；本轮只通过模拟 HTTP 响应验证，没有发送真实承运商请求。
- 查询内容按租户、订单、服务商、运单及必要联系方式隔离缓存；同一物理运单的调用冷却共享，但不共享用户私有响应。
- 同单查询间隔为 1800 秒；增加查询锁、全局限流和 Redis 故障拒绝外部调用的保护。必要手机号按承运商白名单发送，缓存键使用摘要。
- 非法上游 JSON 使用静默解析，避免解析失败时把运单、电话、地址等原始响应写进日志；已有日志捕获回归测试。
- 配置文件中历史示例凭据不代表已获得真实权限。启用前仍须核对/替换有效凭据及授权。

### 地址与订单快照

- 会员地址新增可空 longitude、latitude、coordSystem、locationSource、locationPrecision、locationConfirmedAt；订单增加对应 receiver 字段。
- 坐标必须成组合法，精度最多 6 位小数，当前坐标系为 GCJ02；新增或重新确认坐标需明确确认，确认时间由服务端生成。
- 坐标是客户确认的参考点，不是服务端已验证的地理编码、GPS 或承运商送达证明。
- 修改地区/详细地址会清除旧点位；只改联系人、电话或默认地址不会误清坐标；旧客户端不传坐标字段仍可使用。
- 创建订单复制当时的地址点位元数据，后来修改地址不会覆盖历史订单快照；后台修改订单收货地址时清除过时点位。
- 新接口 `GET /app-api/member/address/location-capability` 当前明确返回未开通、允许手工填写；不下发私有地图密钥，不加载外部 SDK，也不请求定位权限。
- PC/H5 增加地图能力提示和参考点信息；地图配置读取失败不阻断手工保存。H5 读取既有地址失败时禁止把空表单误存为新地址。
