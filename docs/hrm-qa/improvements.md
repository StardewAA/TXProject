## P0（阻断正确性或安全）

### I-001 并发入职编制原子化
- **类型**：流程改进
- **关联**：Q-001
- **现状**：`HrmRecruitOfferServiceImpl.onboard` 在 `:542` 校验 `demand` 编制，在 `:566` `increaseOnboardCount`，中间还执行 `createEmployee :561`；两步无同一事务行锁；双候选人同时入职可超编。
- **建议**：将「读编制 → 校验 → 核增」放入同一事务，对 `hrm_recruit_demand` 行 `SELECT ... FOR UPDATE`（或 `UPDATE ... WHERE onboard_count < headcount` 条件更新）；失败返回明确业务码。
- **验收标准**：
  - Given 需求编制=1 且已入职 0 人，When 两个 Offer 并发 `onboard`，Then 仅 1 人成功，另 1 人返回「编制已满」且不产生员工/不增加 onboardCount。
  - 回归：单线程入职仍成功，`onboardCount` 最终 = 实际入职数。
- **价值**：杜绝超编用工与需求看板失真。
- **优先级**：P0 · **涉及面**：后端 · **工作量**：M

### I-002 Offer 有效期语义统一（长期有效）
- **类型**：流程改进
- **关联**：Q-002
- **现状**：`send`（`:335-347`）将 `validUntil==null` 视为不限期；`confirm`（`:439-440`）要求非空否则拒绝。DRAFT 免审批发放为 2026-09-23 业务确认口径，**不改**。
- **建议**：引入显式「长期有效」或允许 `confirm` 接受 null=长期；创建 VO 若强制 `validUntil`，则同步允许长期开关，避免三处口径不一致。
- **验收标准**：
  - Given Offer 长期有效（null 或 FOREVER）且状态=SENT，When 候选人接受/HR 确认，Then 进入 CONFIRMED。
  - Given 固定 `validUntil` 已过期，When 确认/接受，Then 业务错误且状态不变。
  - 回归：DRAFT 直接发放仍按业务口径允许。
- **价值**：长期 Offer 可正常入职，过期仍拦截。
- **优先级**：P0 · **涉及面**：后端+前端 · **工作量**：S

### I-003 门户写接口补齐本人鉴权
- **类型**：流程改进
- **关联**：Q-005、Q-006
- **现状**：`HrmPortalResumeController:41-69`、`HrmPortalResumeVersionController`、`HrmPortalRecruitAgentController:47-85`、`HrmPortalRecruitController` 投递写操作无 `@PreAuthorize`；证件/培训仅 `isAuthenticated()`；代理任务 `getTaskInTenant:137-149` 仅租户校验。
- **建议**：
  1. 所有 portal 写接口加 `@PreAuthorize("@ss.hasPermission('hrm:portal:...')")` 或统一 `hrm:portal:action`；
  2. 一律 `validateEmployeeBySelf(getLoginUserId())` / `applicantUserId` 归属校验；
  3. 代理任务查询增加 `assigneeUserId`/`creator` 过滤。
- **验收标准**：
  - Given 用户 A 的 token，When 请求用户 B 的简历/投递/任务 ID，Then 403/404，不泄露正文。
  - 未登录访问 portal 写接口 → 401。
- **价值**：堵住 IDOR 与简历泄露。
- **优先级**：P0 · **涉及面**：后端 · **工作量**：M

### I-004 工资月表同年月唯一
- **类型**：流程改进
- **关联**：Q-012
- **现状**：`hrm_salary_month_record` 无 `(tenant_id, year, month)` 唯一索引，可重复建月。
- **建议**：补唯一索引 + 创建接口冲突时返回「该月工资表已存在，是否进入？」；历史归档月用状态区分不占唯一时改为 `(tenant_id,year,month,status_bucket)`。
- **验收标准**：同年月第二次创建失败且错误文案含月份；并发创建仅一条。
- **价值**：防止双工资表、核算与发放错乱。
- **优先级**：P0 · **涉及面**：数据+后端 · **工作量**：S

### I-005 生产关闭 actuator/druid 公网
- **类型**：流程改进
- **关联**：Q-008
- **现状**：`SecurityConfiguration:28-31` 对 `/actuator/**`、`/druid/**` permitAll。
- **建议**：网关与服务侧默认 deny；仅内网 profile 放开；至少要求管理角色。
- **验收标准**：匿名请求 actuator/druid → 401/403；健康检查走独立只读探针。
- **价值**：降低信息泄露与攻击面。
- **优先级**：P0 · **涉及面**：后端 · **工作量**：S

## P1（主链路体验与数据正确）

### I-006 管理端请假补录/代提
- **类型**：流程改进
- **关联**：Q-004
- **现状**：`#/hrm/attendance/leave` 无新增按钮，仅导出/审批（`views/hrm/attendance/leave/index.vue`）。
- **建议**：列表头增加「代提请假」：选员工 → 假别/起止/时长/事由/附件 → 可选直接生效或走审批；与员工端 `HrmPortalAttendanceLeaveController` 共用 service。
- **验收标准**：
  - Given HR 权限，在请假列表点「代提请假」，When 必填齐全提交，Then 列表出现新单，状态=待审批/已通过（按配置）。
  - 无 `hrm:attendance:leave:create` 权限时按钮隐藏。
- **价值**：HR 处理补卡/补假不再绕道 SQL 或员工端。
- **优先级**：P1 · **涉及面**：前端+后端 · **工作量**：M

### I-007 职位增加草稿态
- **类型**：流程改进
- **关联**：Q-003
- **现状**：新建职位保存即发布（`form.vue` 文案「保存后直接发布到招聘门户」）。
- **建议**：状态增加 `DRAFT`；默认保存草稿，另「保存并发布」；门户查询仅 `RECRUITING`；支持草稿→发布、招聘中→暂停/关闭。
- **验收标准**：
  - Given 新建职位仅点「保存」，Then 列表状态=草稿，`/portal/recruit` 不可见。
  - 点「发布」后门户可见；已关闭不可直接再发布需复制或重新打开。
- **价值**：避免未审信息对外。
- **优先级**：P1 · **涉及面**：后端+前端 · **工作量**：M

### I-008 核算就绪阻断 + 一键补齐
- **类型**：流程改进
- **关联**：Q-013
- **现状**：未入薪资组/无档案人员静默丢弃或 readiness 提示非阻断（`HrmSalaryMonthRecordServiceImpl:228-232`，`payroll-readiness-alert.vue`）。
- **建议**：点「核算」时弹出不可计薪人员清单（原因：未入组/无档案/停薪）；提供「批量入组」「批量建档」快捷入口；确认后才写核算结果。
- **验收标准**：
  - Given 存在未入组员工，When 点核算，Then 列出姓名+原因，确认前无 COMPUTED 状态。
  - 补齐后再次核算，该员工出现在明细中。
- **价值**：少跑一个月「怎么少人发薪」。
- **优先级**：P1 · **涉及面**：前端+后端 · **工作量**：M

### I-009 需求状态机与编制行锁
- **类型**：流程改进
- **关联**：Q-009
- **现状**：需求状态无转移矩阵；`increaseOnboardCount` check-then-act。
- **建议**：定义状态表（草稿/审批中/招聘中/已完成/已取消）与合法迁移；核增用条件 SQL/行锁（同 I-001）；manual 审批与 BPM 回调加幂等键。
- **验收标准**：非法迁移 API 返回明确错误；编制与入职数一致；重复审批回调不双计。
- **价值**：招聘执行可控。
- **优先级**：P1 · **涉及面**：后端 · **工作量**：M

### I-010 员工转正/异动单入口与互斥
- **类型**：流程改进
- **关联**：Q-010
- **现状**：转正双路径无锁；`applyEmployeeChange` 有 `appliedTime` 但定时离职不阻塞未完成交接。
- **建议**：统一「发起异动」入口；离职生效前校验交接结论（handover CONFIRMED/WAIVED）与薪资结清；并行异动用状态互斥锁。
- **验收标准**：未完成交接无法置已离职；并发转正+调岗仅一生效。
- **价值**：离职闭环不漏项。
- **优先级**：P1 · **涉及面**：后端 · **工作量**：M

### I-011 合同到期自动置 EXPIRED
- **类型**：流程改进
- **关联**：Q-011
- **现状**：有到期预警 Job，但合同状态不自动 EXPIRED。
- **建议**：到期日 Job 置 `EXPIRED`，触发预警通知与续签待办；已终止/已签未生效除外。
- **验收标准**：将系统日期推进到期日后，状态自动变更且列表可筛选「已到期」。
- **价值**：合规台账准确。
- **优先级**：P1 · **涉及面**：后端 · **工作量**：S

### I-012 薪资/社保数据权限
- **类型**：流程改进
- **关联**：Q-007
- **现状**：`HrmDataPermissionConfiguration:48-50` **刻意不注册** salary/insurance/recruit/简历/黑名单（javadoc 写明）；属产品口径而非笔误，但薪酬跨部门可见仍是合规风险。
- **建议**：薪资与社保按部门+角色（仅 HR 薪酬岗/超管）过滤；招聘按用人部门过滤；提供「全公司」显式开关给超管。
- **验收标准**：部门 HR 查看工资表仅本部门；越权 ID 查询 403/空。
- **价值**：薪酬保密。
- **优先级**：P1 · **涉及面**：后端 · **工作量**：L

### I-013 高频台账补导出
- **类型**：体验优化
- **关联**：Q-021
- **现状**：合同签订、证件台账、社保表、薪资档案、发放记录、打卡等无导出。
- **建议**：与员工档案一致的导出组件；默认导出当前筛选；大数据量异步导出中心。
- **验收标准**：任意列表「导出」得到 xlsx，列与表头一致，含当前筛选。
- **价值**：对账/汇报少截图。
- **优先级**：P1 · **涉及面**：前端+后端 · **工作量**：M

## 建议新增功能（让操作更简单）

### I-020 入职向导（Offer→上岗一键）
- **类型**：新增功能
- **关联**：主线 A→B 衔接
- **现状**：入职已写员工/工号/合同草稿，但仍要分头配薪资组、考勤组、社保方案、账号角色。
- **建议**：入职向导页：确认员工信息 → 选薪资组/考勤组/社保方案/角色 → 生成工号与账号预览 → 一键完成；从候选人详情「入职」直达。
- **验收标准**：从 Offer 确认起 ≤3 步完成上岗配置；完成后工资表核算就绪检查通过。
- **价值**：新人第一天可打卡可计薪。
- **优先级**：P1 · **涉及面**：前端+后端 · **工作量**：L

### I-021 待办中心（跨模块审批一条队）
- **类型**：新增功能
- **关联**：Q-004、工作台角标
- **现状**：招聘需求/Offer/请假/异动/绩效分散在各页角标。
- **建议**：工作台「我的待办」聚合 BPM+HRM 待办（请假、转正、调岗、Offer、绩效）；支持一键跳转处理。
- **验收标准**：任一待办在中心出现且与原页角标计数一致；处理后同步消失。
- **价值**：少翻菜单。
- **优先级**：P1 · **涉及面**：前端+后端 · **工作量**：L

### I-022 员工自助「我要」快捷
- **类型**：新增功能
- **关联**：I-006
- **现状**：员工端请假在考勤页深处；证明/用章/转正申请入口分散。
- **建议**：`portal/home` 增加「我要请假 / 开收入证明 / 发起转正 / 更新联系方式」磁贴，直达表单。
- **验收标准**：从工作台 ≤2 次点击到达任一表单。
- **价值**：员工不用记路径。
- **优先级**：P2 · **涉及面**：前端 · **工作量**：M

### I-023 薪资核算差异对比
- **类型**：新增功能
- **关联**：I-008
- **现状**：月度核算后仅看当月；历史需切换。
- **建议**：工资表详情增加「环比上月」高亮增减项；导出对比表。
- **验收标准**：任选两人两月，页面高亮应发/实发差额与变化项。
- **价值**：调薪与异常一眼看出。
- **优先级**：P2 · **涉及面**：前端+后端 · **工作量**：M

### I-024 合同/证件续签到期日历
- **类型**：新增功能
- **关联**：Q-011
- **现状**：合同到期、证件预警、试用期到期分散列表。
- **建议**：HR 工作台月历聚合三色节点（合同/证件/试用期），点击直达处理。
- **验收标准**：当月三类到期项均可在日历点击处理。
- **价值**：避免漏签漏换证。
- **优先级**：P2 · **涉及面**：前端 · **工作量**：M

### I-025 一键「演示数据」与「清场」
- **类型**：新增功能
- **关联**：测试/实施体验
- **现状**：QA/实施造数据靠手工，易脏。
- **建议**：租户超管可见「沙箱数据」工具：按剧本生成需求→候选人→入职→考勤→工资；提供只读沙箱租户或标记 `is_sandbox`。
- **验收标准**：10 分钟内跑通主线 B 最小链路；清场不影响正式数据。
- **价值**：培训与验收更快。
- **优先级**：P2 · **涉及面**：后端 · **工作量**：L
