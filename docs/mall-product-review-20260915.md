## 状态与并发规则

审核状态与上下架状态独立：`NULL` 历史过渡、`0` 草稿、`10` 待审、`20` 通过、`30` 驳回。

`contentVersion` 是经营内容版本；`submissionId` 是每次送审的 UUID。撤回后即使内容版本不变，重新送审也有新 UUID，旧页面不得批准新提交。

- 经营写入、送审、撤回、审批、上下架在租户作用域下锁商品行。期望版本不匹配即拒绝，不自动覆盖。
- 待审内容冻结，先撤回才能编辑。实际修改已上架商品，在同一事务内置下架草稿、递增版本、失效批准；无变化保存不新增版本。
- 审核基于不可变提交快照并校验当前经营内容一致。批准只改变审核状态，不自动上架、不把快照回写到商品或库存。
- SKU 编号、实时库存、销量、ERP/WMS 映射不随经营编辑重建/覆盖。已被 SKU 使用的属性/属性值不能通过字典改名绕过审核。
- 后台新建/复制不得携带既有 WMS 映射；回收站删除公开 API 也必须带 `expectedVersion` 并在行锁内验证。后台当前没有新增永久删除按钮。
- 当前版本维护人/提交人不能自审；已知店铺经营关联后台账号也不能审批本店。记录区分 MEMBER/ADMIN 类型和账号编号，不声称已具备跨账号“同一自然人”识别。
- 非试点后台临时送审/撤回同样要有经营权限和店铺政策允许，仍由独立审核人处理。

## 可见与购买边界

- 商品公开分页、列表及详情、活动公开列表/详情、购物车、新下单商品验证均核对审核可售版本。
- 内部商品 RPC 保留历史业务读取语义，通过新增 `saleable` 明确是否可用于当前展示/购买；新消费者遇到缺失标记按不可售处理。部署顺序必须先商品，再交易/活动。
- 未审经营资料不从失效购物车、收藏、浏览历史中泄露。保留关系 ID 和商品 ID 供删除，显示失效说明，不展示新待审价格、名称、图片。
- 已下单的商品快照、成交价、订单、退款和积分记录不由重审改写。
- 活动查询跨服务批量筛选（每批 100），分页保留筛选后的总数；不保证并发变动中的数据库快照一致性。最多扫描 10000 条、预算 30 秒，超限明确失败不伪造部分总数；首页限量接口凑够即停。不缓存跨租户可售状态。大规模目录应后续改为可靠事件驱动的可售投影。
