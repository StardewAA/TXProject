## 0. 关键口径（需求澄清：无招标方 → 全手动）

- 现阶段没有“招标方/外部报名系统”接入，因此流程全部动作由**登录用户（投标员工）本人手动触发**，包括：报名登记、审核通过/不通过（自我标记，原因必填）、上传标书、取消；
- 未来接入招标方/工作流后，REGISTER/APPROVE 可改为事件或管理员驱动，本契约状态机与事件表保持兼容；
- 状态机采用**轻量枚举守卫**（不引 Spring Statemachine 依赖，规避 3.2.1 版本线与容器环境风险）：Service 内 currentState → target 校验非法转移抛错，事件表落历史，DB 事务内完成。

## 1. 状态与事件（枚举）

| code | 名称 | 说明 |
| --- | --- | --- |
| INTENTION | 意向投标 | 新建流程即进入（对应员工关注/建档） |
| QUALIFICATION_REVIEW | 资质审核 | register 后 |
| PENDING_BID | 待投标 | 审核通过后 |
| BIDDED | 已投标 | 上传标书后 |
| TERMINATED | 流程结束 | 审核不通过 / 取消投标 |

| 事件 | 触发动作 | from → to |
| --- | --- | --- |
| CREATE | 新建意向 | — → INTENTION |
| REGISTER | 报名投标 | INTENTION → QUALIFICATION_REVIEW |
| APPROVE | 审核通过 | QUALIFICATION_REVIEW → PENDING_BID |
| REJECT | 审核不通过 | QUALIFICATION_REVIEW → TERMINATED |
| UPLOAD_DOCUMENT | 上传标书 | PENDING_BID → BIDDED |
| CANCEL | 取消投标 | INTENTION/PENDING_BID → TERMINATED |

## 2. 表结构（修正设计稿 3.1/3.2）

- 主键：**雪花 id**（MyBatis-Plus IdType.ASSIGN_ID，Long 序列化字符串），与既有 crawl/notice 表口径一致（设计稿 AUTO_INCREMENT 废弃）；
- `bidding_process_track`：user_id、follow_item_id（可空，意向来源关注行）、follow_key/follow_type、project_name、project_code（新增，跟踪键）、issuer_name、current_state、review_result（APPROVED/REJECTED）、review_reason、document_id/document_name/document_size、各阶段时间戳（intention/register/review/pending_bid/bidded/terminated_time）、remark、creator/updater 审计；
- `bidding_process_event`：雪花 id、track_id、user_id、event_type、from_state、to_state、operator_id/operator_name、operation_desc、extra_data(json，标书名/原因等)、occurred_at；
- 唯一键建议 (user_id, follow_item_id)（跟随关注行可空时的判重：null 时允许重复建档，业务上仅提示）。

## 3. 接口（管理端登录态，当前用户=操作者）

| 方法/路径 | 权限 | 说明 |
| --- | --- | --- |
| GET `/admin-api/bidding/process-track/page` | `bidding:process-track:query` | 分页我的流程（currentState/userId 恒等于当前登录人；管理员加 adminUserId 可查全部） |
| GET `/admin-api/bidding/process-track/get?id=` | query | 详情（含事件列表） |
| POST `/bidding/process-track/create` | `bidding:process-track:create` | 新建意向：projectName*/projectCode/issuerName/followItemId?/followKey?/followType?/remark |
| POST `/bidding/process-track/register` | `register` | trackId + remark |
| POST `/bidding/process-track/review` | `review` | trackId + result(APPROVED/REJECTED)* + reason* |
| POST `/bidding/process-track/upload-document` | `upload` | trackId + documentName* + documentSize? + fileId?(infra file 上传后回填) |
| POST `/bidding/process-track/cancel` | `review` | trackId + reason |

- 事件查询：GET `/bidding/process-track/events?trackId=`（detail 内联即可）；
- 每条变更在**同一事务**内：校验当前状态合法转移 → 更新 track（current_state/previous_state/阶段时间戳/review_*）→ 插 event 行；
- 越权/非法转移错误码沿用 106 段（106-020 起建议：非本人、非法状态转移、重复报名等），供前端 message 展示。

## 4. 前端现状（先行实现，供对照）

- 页面：管理端 `招投标 → 投标流程跟踪`（component `bidding/processTrack/index`，已并入 6735 菜单）；
- 全手动操作按钮随状态出现：意向→[报名投标]；审核→[审核通过/审核不通过(原因必填)]；待投标→[上传标书]/[取消投标]；已投标/已结束 只读；
- 列表：项目名/编号/发布单位/状态/各阶段时间/最近事件；顶部状态统计 tabs；
- 详情抽屉：流程 Steps（5 段）+ 阶段时间 + 事件时间线 + 标书信息；
- 建档数据源：优先从“我的关注”（`/bidding/notice-follow/item/page`，真实接口）选择项目带入，亦可纯手填（无关注/无招标方数据时）；
- 持久化：当前后端未实现，前端以 localStorage 本地持久演示（页面顶部已标注），后端 3.0 接口上线后切 requestClient 并保留事件合并策略（本地历史可一次性 POST 迁移或弃用）；
- 菜单按钮权限：query(页面) / create / register / review / upload。

## 5. 验收 checklist（后端自查）
