## 0. 本期已对接（前端侧完成，供后端冒烟用）

| 场景 | 端点 | 说明 |
| --- | --- | --- |
| 大厅列表/检索/性质/来源/行业/时间 | `GET /notice-external/page` | keyword(ES)/noticeTypeRaw eq/sourceCode eq/industryFlag eq/时间区间，见上一份清单 R1~R12 |
| 详情三形态 + 结构化正文 | `GET /notice-external/detail?id=` | bodyBlocks(SUCCESS) → contentHtmlSafe 回退；附件/PDF 按 R6 语义 |
| 原文跳转 | `GET /notice-external/go?url=` | 一律走后端中转（白名单） |
| 详情页「＋关注 / 已关注」 | `POST /notice-follow/follow` `unfollow` | targetType=ANNOUNCEMENT, targetKey=公告 id |

## 1. 需要后端处理/确认的条目

### N1（高）管理端列表/审核页前置缺口：没有"管理分页"
- 位置：`notice-external/page`；管理端 approve/reject/take-down/ai-extract/body-structure 端点已存在。
- 现状：公开 `page` 只出 `ACTIVE+SOCIAL`（大厅口径），无 `status`(NEW/INACTIVE) / `auditStatus`(UNREVIEWED…) 维度的管理列表。
- 影响：管理端审核页（03 §3）**无法**依赖公开 page 实现——03 明确"先把需求提给后端，勿直接依赖公开接口做管理页"。前端本期未做管理页。
- 期望：后端开放**管理分页**（如 `GET /bidding/notice-external/manage/page`，入参叠加 status/auditStatus/时间/来源/类型，仅登录 + `bidding:notice-external:update`）；前端随后在管理后台补「列表 + 审核通过/驳回/下线 + AI 抽取 + 正文结构化」按钮（均二次确认 + loading + @Idempotent 语义）。

### N2（高）公告级关注的行快照与"是否已关注"查询
- 位置：`follow` / `item/page`；详情页关注按钮。
- 现状 ①：`follow(targetType=ANNOUNCEMENT)` 建行时 `display_name` 暂存 **targetKey（公告 id）**，须等下一次 EXTERNAL_ACTIVE 扇出才快照标题。用户关注一条已 ACTIVE 公告后，其"我的关注"列表里是一串雪花 id，观感差。
  - 前端绕行：列表遇到 `followType=ANNOUNCEMENT` 且 displayName=followKey 的行，用公开 `detail` 回查补标题/发布单位（已实现）；但这有额外请求且下架公告查不到。
  - 期望：follow 服务端解析 ANNOUNCEMENT 目标并快照（标题/发布单位/原网址）；或 `FollowReqVO` 允许前端带上可选 `displayName/issuerName` 快照（公告 id → 标题在服务端可查，最干净）。
- 现状 ②：无"某目标是否已关注"单点查询。详情页初始态前端只能"公告级关注行分页扫描"探测（<=5 页，粗略）。
  - 期望：提供 `GET /notice-follow/status?targetType=&targetKey=`（登录）返回 `{followed:boolean, itemId?}`；`item/page` 增加可选 `followKey` 过滤参数（也可解决 ① 的列表补名场景，一举两得）。

### N3（中）契约文档勘误：item/page 筛选参数名
- 01 §3 表格写作 `dimensionType 过滤(PROJECT/...)`；**后端 `FollowItemPageReqVO` 实际字段名是 `followType`**（VO schema 注释也只写三类，但服务层对 ANNOUNCEMENT 同样建行）。
- 期望：文档改为 `followType`，并注明可传 `ANNOUNCEMENT`；前端已按 `followType` 对接。文档另建议把 FollowItemRespVO 的 followType 取值注释补上 ANNOUNCEMENT。

### N4（中）契约勘误：时间入参口径（02 §5 与实现不符）
- 02 §5 写"分页筛选入参 beginTime/endTime 请传毫秒"；后端 `NoticeExternalPageReqVO` 实为
  `@DateTimeFormat(pattern="yyyy-MM-dd HH:mm:ss") LocalDateTime`。48110 实测：**字符串格式正常解析；毫秒数字直接 400**。
- 期望：文档口径改为传 `yyyy-MM-dd HH:mm:ss`（仅日期可自动补起止时刻）；或后端放宽（毫秒 + 字符串双兼容）。前端已按字符串实现，无需后端改代码，改文档即可。

### N5（低-中）契约勘误：detail 错误码行文
- 01 §3"详情无数据"与 02/03 多处把错误码写成"1-060-106-002（不存在）/1-060-106-011（已下架）"；与 `ErrorCodeConstants` 不符：
  `106-001=外部公告不存在`、`106-002=外部公告已下线或不可展示`、`106-011=采集产出落库数据不完整`。
- 前端已按 001/002 映射"公告不存在或已下架"（R8）。期望：文档订正；如要更细文案可让 106-002 带 msg 前缀区分。

### N6（低）附件/PDF 签名下载仍未回填
- 详情 `attachments[].downloadUrl`、`pdfDownloadUrl` 依旧为空（`toAttachmentVO` 注释"FileApi 签名接入后回填"）。
- 前端已按空态呈现（"文件服务签名地址暂未回填/暂无真实下载链接"、PENDING/INFECTED 语义）。
- 期望：接入 infra FileApi 签名下载后回填；INFECTED 保持不下发链接（已确认）。

### N7（低）AI 抽取 / 正文结构化 = 管理端按钮，依赖 N1
- `ai-extract`、`body-structure` 端点已实现（管理权限 + @Idempotent），但需要"管理分页选中一条公告"的入口。
- 期望：随 N1 管理列表一起排期后，前端在管理后台补触发按钮并展示返回（extractionStatus/blockCount/tableCount 等）。

### N8（低）门户（员工端）普通用户的关注权限
- follow/read 写 = `bidding:notice-external:update`，读 = `query`。当前登录企业用户在**门户侧**是否已默认拥有这两项权限，
  依赖菜单/角色 SQL 给每个租户默认角色授权（参照 `sql/2026-09-03-notice-menu.sql` 权限点定义）。
- 期望：确认并给租户默认角色放行，否则"我的关注"会 403（前端已做提示文案）。
