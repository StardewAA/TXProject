> 依据：后端 NoticeController + api/vo（事实源）、NoticeTypeEnum/NoticeStatusEnum、NoticePayloadUtils（权威字段全集/必填/公开级别）、NoticeDetailRespVO（两形态说明）、notice 前端开发指南。原则：不改后端；后端未实现部分本文件给出完整契约与业务目标，前端按现状适配 + mock 呈现。

## 一、公告发布表单 — 三端字段对齐表（表格逐项填写，全部必填项齐备）

### 1.1 基础字段（NoticeSaveReqVO ↔ NoticeRespVO/Detail ↔ 表单行）
| 表单行（表格逐项） | 后端接口字段（SaveReqVO/PageReqVO/RespVO/Detail） | 类型/必填/说明 |
| --- | --- | --- |

| 公告类型 * | noticeType | 枚举 4 值：TENDER_NOTICE 招标公告 / CHANGE_NOTICE 变更公告 / WIN_CANDIDATE_PUBLICITY 中标候选人公示 / WIN_RESULT_PUBLICITY 中标结果公示；RespVO 另回 noticeTypeName |
| 项目编号 | projectCode | string 可选（关联招标项目） |
| 项目名称 | projectName | string 可选（快照） |
| 发布单位 | publisherName | string 可选（快照列） |
| 发布时间 | publishTime | datetime 可选（发布未填取当前）；列表筛 publishTimeStart/End |

### 1.2 发布前置校验（前端须拦 + 后端仍断言）
- 状态机：DRAFT→PUBLISHED/ARCHIVED；PUBLISHED→UNPUBLISHED/ARCHIVED；UNPUBLISHED→PUBLISHED/ARCHIVED；ARCHIVED 终态（NoticeStatusEnum.canTransit，非法 1_060_101_002）。
- 发布（publish）必过两关：①招标人发布门（106_031 未授权 / 106_034 未完善——subject 资格双条件）；②正文 content + pdfFileId 均非空（106_101_004/006 系列）。
- create/update/publish 幂等（@Idempotent）→ 前端按钮 loading 防连点。
### 1.3 列表筛选行（PageReqVO）
keyword / noticeType / status / internalFlag(null=全部) / publicLevel / projectCode / publishTimeStart·End + 分页。大厅 public/list 只传 tenderProjectCode?（现实现=notice 域：keyword/noticeType/…，后端固定 PUBLISHED+非内部+SOCIAL）。

## 二、自研公告渲染器（不再依赖外部公告渲染器）
### 2.1 目标
依据 **NoticeDetailRespVO 结构化数据**（payload 规范字段全集 + content 正文版本 + pdfFileId/大小/哈希 + attachments 契约）由前端本地模板生成样式化 HTML 公告页——后端明确“不生成 HTML，只给结构化数据”（NoticeDetailRespVO 注释）。同一渲染器输出三类目标：
| 渲染目标 | 数据源 | 产物 | 状态 |
| --- | --- | --- | --- |
| ① 内部 HTML（本平台公告） | NoticeDetailRespVO（管理端详情 / 大厅 public/detail——公开端已裁剪 SOCIAL 子集） | 公告页 HTML：头部队+元数据表+正文+PDF/附件区 | 本期前端实现 NoticeHtmlView |
| ② 外部公告·适应性 HTML | notice-external detail：bodyBlocks（heading/paragraph/table/list，成功优先）回退 contentHtmlSafe（jsoup 净化）；富文本含 PDF 预览 pdfDownloadUrl 与 attachments 下载 | 门户自适应单栏公告页 | **现状已具备**（portal detail.vue: blocksToHtml/prettyNoticeHtml/PDF iframe/下载行）；本轮仅复核+微调 |
| ③ 外部公告 PDF（版式形态） | pdfFileId / pdfDownloadUrl（文件服务签名） | 浏览器 PDF 查看器内嵌预览 | 现状已具备；公开性=公告公示材料免费查阅（10号令 12 条），URL 由业务系统签发（§四 F-2） |

### 2.2 渲染器结构（NoticeHtmlView.vue，本期实现）
- 输入：{ payload: LinkedHashMap（顺序=数据集声明序）, content, contentVersion, pdfFileId?, pdfSize?, pdfSha256?, attachments?[] }。
- 输出区块：头部（类型/状态/版本/编号/时间）→ 元数据字段表（行：中文标签|值；空值跳过；标签字典未收录键原样展示并高亮待补录）→ 正文（换行保留）→ 文件区（分层：L1 公告 PDF 版式查阅 / L2 附件 / L3 招标文件获取指引，见 §3.3）——不无条件给下载。
- 字段分组启发式：标识/时间（含 _TIME/SEND/START/END 键转 yyyy-MM-dd HH:mm）/资格与条件（QUALI/DEMAND/CONDITION/REQUIREMENT/…) /结果（WIN_/RANKING_/PRICE_/BIDDER_）/其余。
- 标签字典 payloadLabel.ts：规范英文名→中文（节选已核条目；后端字典接口（§四 F-1）落地后替换为动态字典，未知键回退原名）。
- 安全：payload/正文一律文本转义渲染（不 innerHTML 业务文本）；PDF/URL 用白名单协议。

## 三、文件与附件——公开分层与获取规则（修订版，按权威依据）

### 3.0 依据（先看原文再设计，勿一律“公开下载”）
- 电子办法 第9条：平台应允许公众/市场主体**免费获取依法公开的招投标信息**；第18条：资格预审/招标文件应加载平台供**潜在投标人下载或查阅**；第20条：除办法/技术规范规定的注册登记外，不得设置“投标报名”等前置限制下载文件。
- 实施条例 第16条：文件发售期≥5日（发售=可收费）；招标文件可依法收取费用（标书费，数据集字段 NOMINAL_FEE）；第26/58条：投标保证金≤估算价2%、履约保证金≤中标合同金额10%（**不是“公告附件”而是投标阶段义务**）。
- 后台-03-公告与文件.md 视图：招标人/代理=发布/澄清/答复；投标人=**购标/下载/下载登记**；大厅=社会公开。数据集含文件获取字段：FILE_RECEIVE_ADDRESS（领取地点）、DOC_GET_START/END_TIME（获取起止）、TENDER_DOC_GET_METHOD（获取方式）、NOMINAL_FEE（标书费）、QUAL_TYPE/资质要求等。
- 公告附件（ATTACHMENT_CODE 关联、公告 PDF 版式）属于**公告公示材料**，随公告公开性走 10号令 12/13 条（依法公开、免费查阅）。

### 3.1 可见性分层（公告页渲染规则）
| 层 | 对象 | 公开性 | 页面表现 |
| --- | --- | --- | --- |
| L1 公告信息 | 公告正文/结构化字段/公告 PDF 版式（public/detail 的 content+payload+pdfFileId） | 社会公开公告：免登录可查阅/下载（public 端点已裁剪 SOCIAL+生效）；内部公告：登录+本租户 | NoticeHtmlView 正文区 + PDF 版式“查阅/下载”入口（pdfDownloadUrl 业务系统签发后） |
| L2 公告附件 | 随公告公布的附件（ATTACHMENT_CODE 等） | 随公告公开性；病毒扫描 CLEAN 才可下载（外部公告域） | 附件列表行 + 状态提示；URL 由业务系统下发，前端不拼内网地址 |
| L3 招标文件/资格预审文件 | 真正“获取”的对象（购标/下载登记；本域 NoticeSaveReqVO 不含，属后续文件域） | **不随公告页直接公开下载**；按招标文件规定的获取方式（地点/时间/方式/标书费 NOMINAL_FEE、资质要求） | 公告页仅展示获取指引：文件获取时间/地点/方式/标书费行 + “获取招标文件/下载登记”入口（后端文件域立项后接线）；**不得在公告页给招标文件无条件下载按钮** |
| L4 保证金义务 | 投标保证金（估算价2%以内）、履约保证金（合同金额10%以内）等 | 属投标/合同环节，不在公告页下载区 | 元数据展示相关字段；文案注明“按招标文件规定缴纳” |

### 3.2 上传链路（公告 PDF/附件，标准 yudao 文件服务）
1) 前端把公告 PDF 版式/附件经 /infra/file/upload（multipart）→ {id,url,name,size}（url=文件服务地址，仅内部凭据，不直接外发）。
2) 公告保存只携带 file_id 元数据（pdfFileId/pdfSha256/pdfSize；多附件待 F-2 attachments 字段）。
3) 展示期对外 URL：业务系统按可见性分层签发（L1/L2 公开下载/签名；L3 只给指引）——见 §四 F-2。
### 3.3 渲染器文件区设计（对应上表）
- PDF 区：仅当详情带 pdfFileId 且属于 L1（公开公告）→ 显示“版式文件查阅”；url 回填前仅展示 file_id/大小元信息+提示。
- 不出现“招标文件下载”类按钮；若 payload 含 DOC_GET_*/FILE_RECEIVE_ADDRESS/TENDER_DOC_GET_METHOD/NOMINAL_FEE 字段，渲染为“文件获取指引”小节（时间/地点/方式/标书费）并提示以招标文件为准。
- 附件下载仅对 L2 且业务放行（virusStatus=CLEAN）的对象展示。
## 四、后端缺口契约（本期不实现，完整表述）
### F-1 数据集字段字典（元数据驱动渲染/动态表单的根基）
- GET /bidding/notice/meta/fields?noticeType=（权限 query）→ [ {key,label,type,required,publicLevel,group,options?} ]（顺序照数据集）。
- 业务目标：前端标签/必填/分组不再硬编码；渲染器与编辑器表单由该字典驱动，三端字段自动对齐。
### F-2 公告附件/PDF 公开下载与回包
- NoticeDetailRespVO（及 public/detail）增：attachments: NoticeAttachmentVO[]（id,fileId,name,size,sha256,kind=PDF|ATTACHMENT,publicLevel,downloadUrl）；pdfDownloadUrl 或经 GET /bidding/notice/public/attachment?fileId=（@PermitAll，按公告公开性+登录态放行，返回重定向/流）
- 业务目标：社会公开公告 PDF+附件公众可下载；URL 由业务系统签发（可签名/限时），前端零拼接；内部公告该端点按登录+租户限制。
### F-3 归档与版本
- POST /bidding/notice/archive?id=（权限 publish）+ GET /bidding/notice/content/versions?noticeId=；业务目标：终态归档、正文版本留痕查看（规范第五章三§2）。
### F-4 时间与字典稳定
- 出参时间格式统一（ISO vs epoch 择一全局）；noticeType 字典/枚举接口（同 F-1 或字典中心）；keyword 命中高亮片段（检索组件增强后补 highlightFragments）。
