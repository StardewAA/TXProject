## 1. 需后端处理/确认的条目

### R1（高）公告性质值域与列表筛选缺失
- 位置：`page`、列表/详情行 `noticeTypeRaw` 字段。
- 现状：演示库两条 `noticeTypeRaw=null`；传参 `noticeTypeRaw=招标公告` 后 total 不变（**参数被忽略，未过滤**）。
- 期望：①列表行的 `noticeTypeRaw` 按真实值回填（招标公告/资格预审/中标候选人公示/中标结果公示/变更/终止等）；
  ②`page` 提供性质筛选参数（建议 `noticeTypeRaw` 精确匹配；或提供性质字典 + 聚合分类，支持前端“中标公示=中标候选人公示+中标结果公示”合并视图）。
- 影响：大厅“公告性质”行与详情/列表“性质”标签、二期订阅分类均依赖此项。

### R2（高）列表项缺 `sourceCode` / `legalFlag`（详情才有）
- 位置：`page` 返回元素。
- 现状：列表元素仅 12 个字段（含 status/title/contentType/issuerName/publishTime/effectiveFrom/To/origUrl/sourceName/industryFlag/noticeTypeRaw/id），**无 `sourceCode`、`legalFlag`**；详情有二者。
- 期望：列表元素补齐 `sourceCode`、`legalFlag`（Y/N/空），或明确列表不展示这两类信息的口径。
- 影响：列表“依法必招”标签、来源代码相关操作无法在前端列表呈现。

### R3（高）来源站字典与“本站”标识
- 位置：`page` 列表行 `sourceCode`；筛选参数 `sourceCode`。
- 现状：实测 `sourceCode=SAMPLE_HUB` 可筛；来源名“示例交易平台”对应代码 `SAMPLE_HUB`。**“本站”自营公告的 sourceCode 取值未定义**。
- 期望：①明确本站公告（本平台发布）的 `sourceCode` 取值（如 `LOCAL`/空串）及 `sourceName`；
  ②提供来源站枚举（代码+名称）或文档化值域，供前端“来源站”下拉按代码过滤。
- 影响：大厅“来源站”行目前仅“示例交易平台”能按代码过滤，“本站”等未映射项暂不下发该筛参（避免误筛为空）。

### R4（中）`go` 中转白名单需放行公告源站域名
- 位置：`/notice-external/go?url=`。
- 现状：演示 origUrl 为 `https://bulletin.example-corp.com/...`。
- 期望：确认/维护 go 白名单（各接入源站域名），避免“前往原地址查看”被拦截；如白名单按域名通配。
- 影响：仅简略信息形态的“前往原地址查看”按钮。

### R5（高）关键词检索参数与匹配语义不符契约
- 位置：`page`。
- 现状（实测）：`title=炼化`（标题确实以“炼化公司…”开头）→ **0 命中**；`keyword=炼化`、`name=炼化` → 2（无过滤效果，疑似参数未绑定）。
- 契约：文档写“title（前缀）”。
- 期望：确认并修复检索参数（参数名 title？匹配=前缀/包含？大小写与空白处理）；或明确 keyword 待 ES 二期（当前接口不做全文，前端按契约传 title，勿在二期前排期）。
- 影响：大厅关键词搜索在真实库当前无法命中（已按契约传 title，修复后即生效）。

### R6（中）附件字段与下载语义确认
- 位置：详情 `attachments[]`、`pdfDownloadUrl` 等。
- 现状：演示库 `attachments=null`；契约含 name/ext/fileId/sha256/size/downloadUrl/origDownloadUrl/virusStatus。
- 期望：①空附件约定（null 或 []）在文档写明；②下载链接 `downloadUrl` 签名有效期与失效处理（过期是否返回 403/新链接？）；③`virusStatus` PENDING/INFECTED 不下发 downloadUrl 已实现，文档确认；④PDF 形态需可预览的 `pdfDownloadUrl`。
- 影响：详情附件下载区（仅“下载链接”文字）与 PDF 组件。

### R7（中）外站 HTML：永不原样渲染，采用“白名单结构化净化”
- 位置：详情 `contentHtmlSafe` / `contentHtml`；前端渲染链路。
- **决策**：外站抓取内容**不做原样 v-html**（script/iframe/on* 事件/javascript: 链接存在 XSS 注入面，不可上线）。“不原样 = 丑”的根因是当前净化退化成纯文本（结构全丢），正确做法是保留结构的白名单净化。
- 现状：jsoup 净化把结构删成连续文本（实测演示库正文即“h1 + 单段连排”）；前端已做单段长文公文化排版（智能切段+标题去重）兜住观感。
- 期望：① `contentHtmlSafe` 定义为**白名单结构化 HTML**：保留 p/br/h1-h6/table/thead/tbody/tr/th/td/ul/ol/li/a/img/blockquote/hr/strong/b/em/u 等，剥除 script/iframe/object/embed/link/meta/style 与全部 on* 属性，href/src 仅允许 http/https/data:image（或走后端中转）；② 样式不入内联（由前端 class 控制），保留 class/text-align 等极小白名单亦可；③ 长期建议：外站正文解析为结构化 JSON（标题/编号/段落列表/表格对象/图片/附件）下发，前端组件排版——支撑二期搜索/标段/订阅，同时彻底无 HTML 注入面。
- 前端现状：已接入 DOMPurify 二次净化（v-dompurify-html）作为纵深防御；结构化 HTML 走公文 CSS，连续文本走 prettyNoticeHtml 智能排版。
- 影响：外部源公告的还原度（表格/列表/图片）取决于 ① 的白名单宽度；图片防盗链建议后端中转或前端 referrerPolicy=no-referrer 处理。

### R8（低-中）状态与错误码
- 位置：`detail`、`page`；错误码段 1_060_xxx。
- 期望：非 ACTIVE / 已下架公告 `detail` 返回语义（code 404/错误码）与提示文案表；前端据此显示“公告不存在或已下架”。
- 影响：详情页错误态文案准确性。

### R9（低）默认排序与分页
- 现状：未传排序参数；演示库 2 条无法验证默认顺序。
- 期望：文档注明默认按 `publishTime desc`；是否支持 sort 参数与 pageSize 上限。
- 影响：目录排序预期。

### R10（低-中）industryFlag 值域
- 现状：实测 `BELONGS`；`UNCERTAIN` 可传但当前 0 命中。
- 期望：确认值域（BELONGS/UNCERTAIN 之外是否存在“无关”值及其筛选取值），列表未知类公告如何标识。
- 影响：“行业相关”行与“行业未知”标签。

### R11（高）空值以字符串 "NULL" 下发，形态不一致
- 位置：`page`/`detail` 行内可空字段。
- 现状（实测新补 4 条种子）：`bidSectionCodes="NULL"`（字符串而非数组/null）、`projectName="NULL"`；同一批数据 `attachments=null`、`noticeTypeRaw` 却有值。空值表示在 null / [] / "NULL" 间混用，且与契约（bidSectionCodes 为数组）不符。
- 期望：①统一约定可空字段的取值（建议：无值=null；多值无内容=[]；不要下文字串 "NULL"）；②写入层过滤/清洗历史数据（常见因 ORM/拼接把 null 转成字符串 "NULL"）。
- 影响：前端已做兼容归一化（展示正常），但"NULL"字串会污染展示与检索口径，务必根治。

### R12（中）表格型内容需结构化/保结构下发（现被压成纯文本）
- 位置：详情正文（候选人/成交/标段等表格式信息）。
- 现状（实测演示库 4 条）：`contentHtmlSafe` 与 `contentHtml` 中均**无任何 `<table>/<tr>/<td>`**；`contentHtml` 为空。原为表格的字段已被拍平成行文本，例如中标候选人公示：`项目经理工程质量第1名陕西化建工程有限责任公司1.80合同签订之日起...`、`序号 候选供应商名称 中选金额（元）1 河南省宇祯建设有限公司 2,297,150.00`（成交结果公告）。
- 期望：①若源站正文含真 `<table>` → 净化白名单保留 table/thead/tbody/tr/th/td（前端公文表格样式现成，可直接还原）；②若为拍平文本 → 由抓取/解析侧将候选列表、成交结果、标段信息解析为结构化 JSON 数组下发（如 {rank,name,price/下浮率,period,projectManager,quality}），前端组件化渲染；③短期无解析时，至少把这类“每行一条”的拍平行按行保序下发（当前行间信息也粘连），前端可逐行展示。
- 前端现状：连续文本已智能分段；若收到含 table 的净化 HTML 会按公文表格渲染。

## 3. 前端联调开关（供开发自用，非后端内容）
