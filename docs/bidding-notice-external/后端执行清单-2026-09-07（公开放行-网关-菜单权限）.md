## 0. 一句话结论

前端侧两处已全部就绪；当前“门户/管理端联调不可用”的根因全部在后端运行环境与数据配置：

## 1. 实测现象与后端动作

### A（高）bidding-server 公开端点免登放行 —— 当前直接 401

**实测**：`GET http://127.0.0.1:48110/admin-api/bidding/notice-external/page?pageNo=1&pageSize=10`（不带 Authorization、带 `tenant-id: 1` 两种均试）→ `{"code":401,"msg":"账号未登录"}`。
Controller 源码（`NoticeExternalController`）`/page`、`/detail`、`/go` 三个方法均标 `@PermitAll + @TenantIgnore`（G 轨公开），但安全过滤器仍拦截——说明**免登白名单未随本次构建生效**（如 yaml 的 permit-all/ignore-urls 清单未含这三个 URL，或 `@PermitAll` 扫描机制被新构建关闭）。

**期望动作**：把以下 URL 加入该服务 security 免登配置（建议按前缀）并重新构建/启动：

- `GET /admin-api/bidding/notice-external/page`
- `GET /admin-api/bidding/notice-external/detail?id=`
- `GET /admin-api/bidding/notice-external/go?url=`

**验证**：无 token 访问上述三个 URL 均返回 `code:0`（列表/详情正常），且不要求 tenant 头。

### B（高）注册中心/服务间 RPC：system-server 不可达 → 登录态接口 500

**实测**：用网关登录得到的 admin token 调 `follow/status`、`follow`、`item/page`、`manage/page` 全部 `{"code":500,"msg":"系统异常"}`；日志（`C:\Users\离不开牛奶\logs\bidding-server.log`）关键栈：

- `feign.FeignException$ServiceUnavailable: [503] ... [Load balancer does not contain an instance for the service system-server]`
- 调用点：`TokenAuthenticationFilter.buildLoginUserByToken` → `GET http://system-server/rpc-api/system/oauth2/token/check?accessToken=…`

**根因**：bidding-server 直跑在 48110，所在注册中心无 `system-server` 实例，无法完成 token 校验；**与权限无关**（权限检查尚未走到，无 403）。

**期望动作（三选一，由后端定）**：
1. 将 bidding-server 与 system-server 注册进**同一注册中心**（容器/网关联调环境，推荐，与 BR-2 答复一致）；
2. 本地直跑联调时提供**本地 token 校验开关**（不走 Feign，如 mock 校验或直连 system 库）；
3. 仅验证公开门户功能可暂不处理（公开端点不校验 token），但关注/管理功能无法验收。

**验证**：带有效 token 调 `GET /admin-api/bidding/notice-follow/status?targetType=ANNOUNCEMENT&targetKey=<公告id>` → 返回 `code:0`（followed:true/false），不再是 500。

### C（高）网关 48080 注册 bidding 路由

**实测**：`GET http://127.0.0.1:48080/admin-api/bidding/notice-external/page` → `{"code":404,"msg":"No static resource ..."}`（网关未路由 bidding）。

**期望动作**：网关路由表新增 `admin-api → /bidding/**` 转发到 bidding-server（48110）；同时核对 knife4j 网关分组包含该服务（BR-2 备注）。

**验证**：经 `48080/admin-api/bidding/**` 可访问（公开端点 code 0；登录态端点不再 404）；随后管理端前端请求走 `/admin-api/bidding/**` 全通。

### D（高）管理端菜单与权限 seed（system 库）

**实测**：`GET /admin-api/system/auth/get-permission-info`（admin/tenant 1）→ 顶层 14 个菜单（系统管理/基础设施/支付/报表/工作流/会员/商城/公众号/CRM/ERP/WMS/MES/AI/IM）**无“招投标”**；权限集合 1051 项中 bidding 相关**仅 `bidding:notice-external:update` 一条**（缺 `…:query`）。

**期望动作**（可在系统管理→菜单管理中配置，或 SQL seed，参照仓库 `sql/2026-09-03-notice-menu.sql` 既有权限点定义）：

1. 建目录「招投标」（可含图标/排序）；
2. 目录下建菜单「外部公告审核管理」：
   - component = `bidding/noticeExternal/index`（**不带前导斜杠**——与既有 sys_menu 数据、`sql/2026-09-03-notice-menu.sql` 同格式；vben 按 `views/{component}.vue` 匹配页面 key，带前导斜杠会映射失败打不开。前端页面已按此路径就位：`apps/web-antd/src/views/bidding/noticeExternal/index.vue`，vben pageMap 可命中）

3. 该菜单绑定接口权限码 `bidding:notice-external:update`（Controller 的 manage/page、manage/get、approve/reject/take-down/ai-extract/body-structure 均 `@PreAuthorize("...:update")`）；
