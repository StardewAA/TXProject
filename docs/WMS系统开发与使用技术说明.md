# WMS 系统开发与使用技术说明

编写日期：2026年9月8日  
适用项目：天信管业智慧平台  
适用对象：WMS 小组、ERP/MES/CRM/商城对接人员、测试人员及仓库业务人员

本文依据当前工作区 WMS 后端、管理端页面、《存储体系.md》及《ERP-WMS-MES-CRM仓储与审批功能结合方案.md》编写。范围涵盖 WMS 小组的基础资料、仓储作业、库存管理、质检、审批、统计及跨系统协作职责。业务设计代表目标范围，代码存在代表已开发，均不等于已经部署或通过人工验收。当前主数据集成已完成自动化测试，人工操作及实际环境联调尚待完成。

## 一、技术架构

### 1.1 系统定位与职责边界

WMS 是仓库主数据和真实库存的管理中心，负责将仓储单据转化为可追溯的库存变更。ERP 提供采购、销售及主数据，MES 提供生产和领料需求；CRM、商城按各自权限引用相关信息。

| 系统 | 数据与业务职责 | 与 WMS 的关系 |
| --- | --- | --- |
| ERP | 物料、客户、供应商、采购与销售业务 | 同步基础档案；通过代理服务维护仓库；后续提交仓储需求 |
| WMS | 仓库、库存、入出库、移库、盘点、仓储质检与审批 | 维护库存余额及流水，执行仓储作业 |
| MES | 生产工单、生产参数、领料及完工信息 | 规划接收成品缺口协作，申请原料出库、成品入库 |
| CRM | 客户关系、商机与合同 | 规划引用统一主数据与仓库信息，不直接改变库存 |
| 商城 | 商品展示及交易 | 通过 WMS 只读接口获取已绑定商品的规格、售价和现存数量 |
| BPM/系统基础模块 | 流程模型、审批待办、账号、角色及租户 | 为 WMS 提供共享能力，不属于 WMS 独立重建的模块 |

目标约束是由 WMS 统一维护真实库存；ERP/MES 审批通过只产生需求，不能直接视作库存变更完成。目前跨系统库存预留、协作调度和执行回写仍处于后续开发范围。

### 1.2 技术组成

| 层次 | 当前采用的技术 | 用途 |
| --- | --- | --- |
| 管理端 | Vue、TypeScript、Vben 管理框架、Element Plus | 业务表单、列表、详情、打印及统计展示 |
| 接口与服务 | Java 25、Spring Boot、Spring MVC | HTTP 接口、参数校验、业务逻辑及事务 |
| 跨服务通信 | Spring Cloud OpenFeign、Nacos | 服务调用、服务发现与配置加载 |
| 数据访问 | MyBatis-Plus、MySQL | 业务数据、库存余额和流水持久化 |
| 公共基础能力 | Redis、项目权限及租户框架 | 缓存、账号权限和租户上下文 |
| 审批 | 项目现有 BPM 模块 | 出库审批发起、流程处理和结果回调 |
| 验证 | Maven、JUnit、Mockito、H2 | 编译、逻辑测试及数据库测试 |

WMS 服务名为 `wms-server`，当前基础配置端口为 `48092`；实际地址以部署配置为准。管理端通常通过统一网关访问服务。接口文档由 Springdoc/Knife4j 提供，是否开放由环境配置决定。

### 1.4 核心数据模型

| 数据表 | 业务含义 |
| --- | --- |
| `wms_warehouse` | 仓库档案 |
| `wms_item_category`、`wms_item_brand` | 商品分类与品牌 |
| `wms_item`、`wms_item_sku` | 商品和具体规格 |
| `wms_merchant` | 往来企业及客户/供应商身份 |
| `wms_item_quality_report` | 商品质检报告记录 |
| `wms_receipt_order`、`wms_receipt_order_detail` | 入库单头与明细 |
| `wms_shipment_order`、`wms_shipment_order_detail` | 出库单头与明细 |
| `wms_movement_order`、`wms_movement_order_detail` | 移库单头与明细 |
| `wms_check_order`、`wms_check_order_detail` | 盘点单头与明细 |
| `wms_inventory` | 仓库与 SKU 维度的库存余额 |
| `wms_inventory_history` | 库存变更及来源单据记录 |
| `wms_integration_request` | 集成请求幂等账本 |

商品与 SKU 是一对多关系；仓库与 SKU 组合形成库存记录；仓储单据通过明细关联 SKU 和仓库。跨系统使用统一业务编码，不能将 ERP、商城和 WMS 的本地数据库 ID 直接当作同一个标识。

### 1.5 库存、事务和权限机制

库存数量和金额采用 `BigDecimal`。库存服务对涉及的余额记录加锁，校验变更后的库存不能小于零，并在事务中写入余额和流水。盘点会复核账面库存；库存已发生变化时需要重新加载后处理。

通用单据状态为草稿（0）、已完成（4）、已作废（5）。保存草稿不代表库存已经生效；完成操作才触发相应库存变化。出库另外维护审批信息，业务完成状态与审批状态必须分别判断。

管理端依赖登录身份、角色菜单权限和接口权限；集成入口校验请求租户与当前租户一致。数据库租户隔离依赖项目的拦截配置，部署后仍须做跨租户负向测试。自动化测试中的租户上下文不能替代完整的权限验收。

### 1.6 ERP 主数据集成

已实现的接口位于 `/rpc-api/wms/integration`：

| 方法与路径 | 功能 |
| --- | --- |
| `PUT /master-data/material` | 按物料编码同步并维护默认 SKU |
| `PUT /master-data/partner` | 同步客户、供应商及合并身份 |
| `PUT /master-data/warehouse` | 创建仓库或带预期版本更新 |
| `GET /request/{requestId}` | 查询当前租户请求结果 |

写请求包含 `requestId`、`tenantId`、`sourceModule`、`occurredAt` 及业务字段。账本保存操作类型和请求摘要：相同请求号、相同内容可重放；相同请求号、不同内容返回冲突。数据库唯一约束用于并发重复请求竞争，生产数据库上的并发行为还应单独验证。

物料通过 `dataVersion` 拒绝旧版本；默认 SKU 编码为 `<materialCode>-DEFAULT`。客户与供应商分别保存版本，支持 `CUSTOMER`、`SUPPLIER`、`BOTH`。仓库修改要求 `expectedVersion` 匹配，成功后返回递增版本。

ERP 仓库代理在本地事务提交后调用网关，保存 WMS 返回的编码、版本及同步状态；失败写入出站记录。当前已存在失败记录基础，但不能据此宣称自动补偿调度已经完成。

`mock` 只模拟响应，不会真正创建 WMS 商品、企业或仓库。验证真实数据同步必须配置 `txgy.integration.wms.mode=remote`，并启动可访问的 WMS 服务。

### 1.7 当前交付边界与待完善事项

当前已开发主数据接口和基础仓储作业。库存判断、预留释放、采购入库申请、客户退货申请、采购退货申请及两类业务结果查询的集成接口仍返回“功能尚未启用”（错误码 `1060900022`）。这不影响区分：WMS 内部已有基础入出库页面，但 ERP 发起对应单据的完整自动执行链路尚未启用。

需继续完善的重点包括：

- ERP 仓库页面补充类型、同步状态和失败原因展示；后端字段存在不代表页面已经支持。
- WMS 旧仓库表单目前主要维护名称、编号、排序、备注，公共类型及版本的维护规则需统一。
- 真实数据库上的幂等竞争、不同请求号的并发版本更新、租户隔离及事务提交后结果持久化需要联调验证。
- 已有映射不能仅凭编码认定同步成功。现升级脚本对已有 ERP 映射回填版本 1 和成功状态，执行前应逐条核对真实 WMS 记录及版本。
- 商品级质检报告与规划中的单据级质检要求快照、批次验收尚需衔接；不能视为同一功能。

## 二、业务模块说明

### 2.1 WMS 首页与统计

展示入库、出库、移库、盘点单据的数量和状态，提供近期单据趋势、库存总量、商品占比及仓库分布。支持按仓库查看。统计用于运营观察；不同计量单位商品的数量合计应结合单位解释，不能直接等同业务价值或库存金额。

### 2.2 仓库管理

维护实际存放货物的仓库档案，支持查询和基础维护。仓库被库存或业务单据引用时删除受限。集成模型区分原料仓和成品仓，ERP 代理入口保存 WMS 的权威编码和版本。当前旧页面字段与新集成模型存在衔接工作，使用时以已部署页面为准。

### 2.3 商品分类、品牌、商品及规格

分类提供树形组织，品牌提供品牌档案，商品维护名称、单位及仓储扩展信息，SKU 表达规格、条码、售价等具体属性。入出库及库存核算使用 SKU 维度。受引用的数据不应直接删除。

统一主数据模式下，公共物料信息由 ERP 同步，WMS 保留分类、品牌、销售价等扩展字段。现有本地维护入口仍需按照团队约定使用，避免在两边反复修改同一公共字段。存量商品没有唯一默认 SKU 映射时，同步会拒绝，需先确认映射。

### 2.4 往来企业

管理客户、供应商和兼具两种身份的企业，保存联系、银行及地址等资料。ERP 同步按统一企业编码匹配，同一编码可以合并身份，WMS 企业级别作为本地扩展保留。名称相同不代表同一企业，不能仅按名称自动合并。

### 2.5 质检报告

在商品下记录质检状态、图片及备注，并保留报告历史。合格或异常报告要求 1—9 张图片；异常必须填写原因，图片地址支持 JPG/JPEG/PNG。当前入库完成逻辑检查商品当前报告是否合格，未合格时阻止完成入库。

规划中的“按入库申请保存质检要求和报告快照”还需进一步实现和验证；商品当前报告不能替代每个到货批次的独立验收证明。

### 2.6 入库管理

通过入库单记录货物入仓，包含单头及商品明细，提供新增、查询、详情、状态处理和打印。完成入库时校验状态、明细及质检条件，并增加目标仓库 SKU 库存、生成流水。草稿阶段可以调整业务内容，完成后的记录用于追溯。

ERP 采购到货、MES 完工入库属于规划中的来源场景。目前不能将手工入库能力描述为上述跨服务申请已经全面打通。

### 2.7 出库管理与 BPM 审批

通过出库单记录货物出仓。已实现出库审批服务和回调入口：发起 BPM 流程、接收审批终态、校验审批结果，完成出库时检查库存并扣减。审批中的单据限制修改，审批通过与实际出库完成应分别核对。

目标流程为“草稿→提交审批→审批通过→完成出库→库存扣减及流水”。业务页面按钮、审批模型和回调配置需在目标环境验证。出库审批能力不能推广为所有入库、移库和盘点已配置相同多级审批。

### 2.8 移库管理

记录同一货物从来源仓库转至目标仓库，来源与目标不能相同。完成时扣减来源库存、增加目标库存，并生成两侧流水。正常移库不改变同一 SKU 的跨仓合计数量；来源不足时应拒绝操作。

### 2.9 盘点管理

将系统账面数量与实盘数量对比，确认后按差异调整库存并记录盘盈或盘亏流水。盘点过程中发生库存变化时，应重新加载账面数量再核对。无差异项不需要产生库存调整流水。

### 2.10 库存查询与库存流水

库存查询展示仓库、商品及规格对应的现存数量；流水展示变动前后数量、变动量及来源单据，用于核对和追溯。库存应由入出库、移库或盘点改变，不应通过手工改数据库完成业务调整。

业务设计中的“可用库存＝实际库存－已预留库存”属于后续预留体系。当前现存库存查询结果不能直接标记为已经扣除预留的可用或可售库存。

### 2.11 商城只读数据对接

已提供 `GET /admin-api/wms/inventory/sku-summary?itemId=...`，返回商品规格、售价及各仓合计现存数量。价格单位为元，未设置价格可为 `null`；无库存规格返回数量 0。接口不提供扣库存、预留或下单能力。

商城服务端使用专用只读账号并持有 `wms:inventory:query` 权限。WMS 商品/SKU ID 与商城 SPU/SKU ID 必须建立显式绑定，不能按相同数字或名称直接关联。失败时应显示获取失败，不能将接口错误当成零库存。

### 2.12 协作调度与后续职责

| 规划模块 | WMS 小组负责内容 | 当前边界 |
| --- | --- | --- |
| 库存判断与预留 | 判断全部满足、部分满足或不足，建立和释放预留 | 接口契约已有，真实业务入口未启用 |
| 协作单 G | 根据成品缺口生成草稿、审批并发送 MES | 待开发完整 WMS 流程 |
| 协作单 B | 根据原料缺口生成草稿、审批并发送 ERP | ERP 已有部分接收基础，WMS 闭环待完成 |
| MES 领料与完工入库 | 接收申请、仓储验收和执行结果回写 | 待跨系统联调开发 |
| 客户退货与采购退货 | 按来源单验证退回数量、执行入出库并回写 | 集成入口未启用 |
| 低库存预警 | 识别缺口，由人员确认后发起协作 | 规划能力 |
| 失败补偿 | 重试、幂等恢复、版本断档和结果对账 | 已有记录基础，调度闭环待完善 |

## 三、产品操作说明

### 3.1 使用前准备

由部署人员确认数据库结构、服务、菜单角色权限及 BPM 模型已配置，使用测试租户进行人工验收。脚本不能重复整批执行；先检查哪些字段和表已存在，再执行缺失升级。

业务用户登录统一管理后台后进入 WMS。下文菜单为功能名称，实际显示名称由菜单配置决定。看不到菜单或按钮时先核对账号权限；不要用其他租户账号绕过权限。

### 3.2 准备基础资料

1. 进入仓库管理，建立测试仓库 A、B，填写名称、编号、排序及备注。
2. 进入商品分类和品牌，准备需要的分类、品牌。
3. 进入商品管理，建立测试商品及 SKU，填写单位、规格等必要字段。
4. 如果采用 ERP 主数据同步，由 ERP 创建物料；切换到 WMS 核对物料编码和默认规格，再维护 WMS 扩展信息。
5. 进入往来企业，核对业务所需客户、供应商。统一编码应来自约定的 ERP 档案。

不应同时将同一测试物料在 ERP、WMS 独立创建为两份无关联档案。

### 3.3 录入质检报告

进入商品的质检报告入口，选择质检状态，上传图片并填写备注。合格和异常状态上传 1—9 张图片；异常必须写明原因。保存后查看当前报告及历史记录。正式仓储使用应将报告与实际货物核对，不能仅为通过测试而填报合格。

### 3.4 完成一次入库

1. 进入入库管理，新增入库单，选择业务类型、仓库及适用的往来企业。
2. 添加商品规格，填写数量、价格等页面要求的信息，保存草稿。
3. 查看详情和质检报告，核对实物、规格、数量及目标仓库。
4. 执行完成入库操作；质检不满足时先处理质检问题。
5. 进入库存查询，核对数量增加；进入库存流水，找到对应入库单。

预期：保存草稿不增加库存，完成后增加一次，重复操作不应再次增加。

### 3.5 完成一次出库

1. 新增出库单，选择仓库、商品规格及出库数量，先确认库存足够。
2. 保存后按已配置的入口提交出库审批。
3. 审批人员在 BPM 待办中核对信息并处理，发起人在单据中查看审批结果。
4. 审批通过后，仓库人员核对实际发货并执行完成出库。
5. 核对库存减少及出库流水。审批拒绝、审批中或库存不足时不应完成出库。

若部署页面未显示提交入口，需先由开发人员检查页面与流程接线；不要跳过审批直接修改库存。

### 3.6 移库与盘点

移库：新增移库单，选择来源仓库 A、目标仓库 B、SKU 和数量；完成后核对 A 减少、B 增加，同一 SKU 总量不变。

盘点：新增盘点单，加载仓库账面库存，现场清点后填写实盘数量；确认差异后完成盘点。提示库存已变化时重新加载和清点；完成后检查调整流水。完成单据需要纠错时，使用合规的后续调整流程，不直接覆盖历史数据。

### 3.7 查询、打印与统计

在单据列表筛选记录，打开详情核对明细，使用打印入口输出业务凭证。库存页面按仓库或商品查看数量，流水页面用于追踪变动来源。首页用于查看单据状态和趋势，最终对账仍以单据、余额及流水为依据。

### 3.8 验证 ERP 同步

此步骤须在 `remote` 模式下进行。`mock` 模式显示模拟成功，也不代表 WMS 已经收到数据。

1. ERP 新增测试物料，WMS 查询统一编码，确认出现默认 SKU。
2. 修改 ERP 物料名称或单位，WMS 核对同步结果，确认分类、品牌、售价未被清空。
3. 用约定的同一企业编码测试客户、供应商同步，确认 WMS 身份合并。
4. ERP 仓库代理表单适配完成后，新增仓库，核对 WMS 实际记录及 ERP 返回编码、版本。
5. 修改仓库后核对两端数据；页面尚无类型或同步字段时，先由开发人员使用接口验证，不能假定界面已可完整操作。
6. 在测试环境模拟 WMS 不可达，核对失败记录及仓库使用限制，再验证恢复后的处理流程。

### 3.9 最小人工验收示例

使用同一测试 SKU、相同单位，确保初始库存为 0：

| 操作 | 仓库 A 预期数量 | 仓库 B 预期数量 | 核查内容 |
| --- | --- | --- | --- |
| 保存入库 100 的草稿 | 0 | 0 | 不提前改变库存 |
| 完成入库 | 100 | 0 | 入库流水仅生效一次 |
| 审批通过后完成出库 20 | 80 | 0 | 审批与库存扣减均正确 |
| A 向 B 移库 30 | 50 | 30 | 两仓合计仍为 80 |
| A 实盘 48 并完成盘点 | 48 | 30 | 盘亏 2，可追溯 |
| 尝试从 A 出库 49 | 48 | 30 | 库存不足拒绝、余额不变 |

还应验证：无权限账号不能写入；跨租户不能查到测试数据；质检不合格不能完成入库；重复完成不会重复扣增；商城查询不会改变库存。
