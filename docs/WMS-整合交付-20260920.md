## 前端开发启动（5173）

使用 Node.js 24 和仓库指定的 pnpm 11.7.0。项目依赖也支持 Node 22.18+；本次回归命令以 Node 24 验证。

```bash
cd txgy-ui-admin-vben
pnpm install --frozen-lockfile
pnpm dev:antd
```

启动会自动执行 `gen:icons`，访问 `http://localhost:5173`。若需要单独重新生成：

```bash
pnpm --filter @vben/web-antd gen:icons
node --test scripts/wms-runtime.test.mjs
```

不要直接跳过 package script 运行 `vite`，否则新拉取目录可能没有 `public/iconify/ep.json`。验证 `/iconify/ep.json` 的内容是 JSON（包含 `prefix: "ep"`），不能只看 HTTP 200：SPA 回退也可能返回 200 HTML。

本机现有 Docker 前端绑定 `127.0.0.1:5173`，开发服务绑定 IPv6 的 5173，两者能同时存在。先检查监听进程和页面是否包含 `/@vite/client`，再选择所需实例；`http://[::1]:5173` 可明确检查开发服务，`http://127.0.0.1:5173` 可明确检查 Docker 产物。不要自动换成 5666、不要为切换页面盲目停止容器。检查名称更新时重新登录或刷新菜单缓存。

## 后端编译与启动

项目必须使用 JDK 25。沿用团队已有 MySQL、Redis、Nacos、gateway、system、BPM 环境及个人配置，不提交密码、令牌和本机容器配置。

在仓库根目录运行（Windows PowerShell 将 `-D...` 参数加引号）：

```bash
mvn -pl txgy-module-wms/txgy-module-wms-server -am -Dtest=WmsItemBrandServiceImplTest,WmsInventoryReadApiRegressionTest,WmsInventoryReadServiceTest,WmsInventoryReadMapperTest -Dsurefire.failIfNoSpecifiedTests=false test
mvn -pl txgy-module-wms/txgy-module-wms-server -am -DskipTests package
```

WMS 启动入口为 `WmsServerApplication`；可由现有部署流程使用生成的 `txgy-module-wms-server.jar`，或 IDE 启动。不要同时启动重复服务实例。gateway 的现有 WMS 路由及 Nacos 服务名 `wms-server` 应保持一致。

本地需要模拟单据、留痕查询和缺料任务时，将 `deploy/local/wms/application-example.properties` 的三项配置加入个人配置，或使用 `--spring.config.additional-location=file:/绝对路径/application-example.properties` 显式加载。该文件不自动改变生产默认配置。

- `txgy.wms.simulation-enabled=true`：允许模拟 ERP/MES 入出库草稿。
- `txgy.access-log.enable=true`：让留痕功能收到访问日志事件。
- `wms.shortage.sender-enabled=true`：缺料通知自动发送/重试；还需接收方地址和令牌，缺少时保持等待对接。模拟单据不会外发。
- AI 使用个人 `TXGY_AI_SILICONFLOW_API_KEY`；本次不提供密钥，也没有验证模型调用。

ERP 需使用同一源码版本构建/发布的 `txgy-module-wms-api`，通过已有 Feign 租户透传调用。不能仅拉取前端就认为新 RPC 接口已部署。
