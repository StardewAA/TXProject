## 2. 后端代码组织（yudao 风格分层）

### 2.1 模块双工程：`*-api` 与 `*-server`

| 工程 | 内容 | 说明 |
| --- | --- | --- |
| `txgy-module-xxx-api` | RPC 契约接口、DTO、枚举 | 供其他服务 OpenFeign 引用，不依赖 server |
| `txgy-module-xxx-server` | Controller / Service / Mapper / DO / 配置 | 可部署服务，含 `api/` 包实现 RPC 契约 |

例：`txgy-module-mes/txgy-module-mes-api` 暴露 `MesProWorkOrderApi`、`MesQcIpqcApi` 等契约；`mes-server` 的 `api/` 包提供实现，`enums/ApiConstants`、`ErrorCodeConstants` 等也在 api 层共享。

### 2.2 server 内分层调用链

```text
controller/admin/<域>/<功能>/
    ├── XxxController          # @Tag/@RestController/@RequestMapping + 权限注解
    └── vo/
        ├── XxxSaveReqVO       # 创建/更新入参（@Valid 校验）
        ├── XxxPageReqVO       # 分页查询入参（继承 PageParam）
        ├── XxxRespVO          # 出参视图
        └── XxxReviewReqVO 等  # 动作类入参
        ↓
service/<域>/<功能>/
    ├── XxxService             # 接口
    └── XxxServiceImpl         # @Service + @Transactional 领域编排
        ↓
dal/dataobject/<域>/<功能>/XxxDO   # @TableName 实体（标准审计字段）
dal/mysql/<域>/<功能>/XxxMapper   # MyBatis-Plus BaseMapperX + XML（resources/mapper/）
        ↓
MySQL（库 ruoyi-vue-pro）
```

要点：
- 统一返回 `CommonResult<T>`、分页 `PageResult<T>`；VO 与 DO 互转用 `BeanUtils.toBean(...)`；
- 权限：`@PreAuthorize("@ss.hasPermission('mes:set-pollution-check:create')")`，权限标识与菜单 SQL 一致；
- 异常：业务错误抛 `exception(ErrorCodeConstants.XXX, args...)`，错误码集中定义在各模块 `enums/ErrorCodeConstants.java`（api 层）；
- 查询封装：`LambdaQueryWrapperX`（框架扩展，支持 eqIfPresent 等链式条件）；
- 每张业务表带标准列：`id / creator / create_time / updater / update_time / deleted / tenant_id`（多租户 + 逻辑删除 + 审计）。

### 2.3 txgy-framework 技术底座（17 个 starter）

| starter | 职责 |
| --- | --- |
| `txgy-common` | 公共 POJO/工具（CommonResult、PageResult、BeanUtils、ServiceExceptionUtil） |
| `-starter-web` | Web MVC、全局异常、参数校验、API 访问日志（`ApiAccessLogInterceptor`） |
| `-starter-security` | Spring Security、登录认证、`@ss.hasPermission` 权限表达式 |
| `-starter-biz-tenant` | 多租户插件（按 `tenant-id` 头自动过滤/写入 `tenant_id`） |
| `-starter-biz-data-permission` | 数据权限（按部门过滤） |
| `-starter-mybatis` | MyBatis-Plus 集成、分页插件、逻辑删除、字段自动填充 |
| `-starter-rpc` | OpenFeign RPC：跨服务调用 `*-api` 契约，Nacos 发现 |
| `-starter-redis` | Redisson、缓存、分布式锁 |
| `-starter-job` / `-starter-mq` | 定时任务 / 消息队列（RabbitMQ） |
| `-starter-excel` | EasyExcel 导入导出 |
| `-starter-monitor` | Actuator、指标 |
| `-starter-protection` / `-starter-biz-ip` | 限流保护 / IP 解析 |
| `-starter-websocket` | WebSocket 长连接 |
| `-starter-env` / `-starter-test` | 环境变量解析 / 测试支撑 |

### 2.4 网关与跨服务调用

- `txgy-gateway/src/main/resources/application.yaml` 静态路由：`/admin-api/mes/** → grayLb://mes-server`（灰度负载，Nacos 注册发现），并重写 `/admin-api/mes/v3/api-docs → /v3/api-docs` 供 Knife4j 聚合；
- 服务间调用：A 服务依赖 B 的 `*-api`，注入 B 的 RPC 接口（如 HRM 的 `BpmProcessInstanceApi` → bpm-server），由 `-starter-rpc` 经 Nacos 发现目标服务；
- 每个服务的容器端口同为 48080（compose 内部），对外只暴露网关 48080。

### 4.3 wm 单据与环保的联动模式

- 单据服务（如 `MesWmProductIssueServiceImpl`）在发料/出库动作点调用 `pollutionControlService.assertIssueAllowed(batchNo)` / `assertOutboundAllowed(batchNo)` 做门禁；
- 单据创建/更新时调用 `purgePendingByBizNo(stage, code)` 清理该单悬挂的未复核判定（判定记录跟随真实单据走，不留孤儿）；
- 前端在单据页内嵌 `judge-modal` 弹窗（`useVbenModal` + `bizNo/batchNo` 透传），做到"在真实业务单据上直接做环保判定"。

## 5. 前端代码说明（txgy-ui-admin-vben）

### 5.1 monorepo 结构

- `apps/` 下保留 web-antd、web-antdv-next、web-ele、web-naive、web-tdesign 五套 Vben 应用，**实际定制开发只用 `apps/web-antd`**；
- 公共能力在 `packages/@core/*`、`internal/*`（vite-config、node-utils、lint-configs 等），`scripts/`（vsh、turbo-run）；
- 包管理 pnpm（store `D:\.pnpm-store`），启动：`pnpm -F @vben/web-antd run dev`（dev 端口 5666，API 直连 `http://localhost:48080/admin-api`）。

### 5.2 web-antd/src 目录

| 目录 | 职责 |
| --- | --- |
| `api/` | Axios 封装：`request.ts`（requestClient）+ `<模块>/<功能>/index.ts`（namespace + interface 定义请求/响应类型） |
| `views/<模块>/<域>/<功能>/` | 页面：`index.vue`（列表）+ `modules/`（表单/详情/弹窗），如 `views/mes/safetyEnv/pollutionCheck/` |
| `router/` | `routes/modules/*.ts` 只放二级隐藏页；**主菜单由后端菜单表下发、动态生成路由** |
| `store/` | Pinia：用户、权限、字典、租户等状态 |
| `layouts/`、`components/`、`plugins/`、`locales/` | 布局、通用组件、插件、国际化 |

### 5.3 路由机制（重要）

- 后端 `system_menu` 表驱动：菜单记录携带 `component` 路径（如 `mes/safetyEnv/pollutionCheck/index`）与权限标识；
- 前端 `router/access.ts` 用 `import.meta.glob('../views/**/*.vue')` 构建 pageMap，按菜单 component 路径动态解析组件 → **新增页面只要视图文件落在 `views/` 下 + 菜单 SQL 指向正确路径即可，无需改路由代码**；
- 二级/隐藏 tab 页（如库区设置、甘特图编辑）才写在 `router/routes/modules/mes.ts` 静态路由里（用 `activePath` 挂靠菜单）。

### 5.4 页面开发套路（以 pollutionCheck 为例）

1. `api/mes/safetyEnv/pollutionCheck/index.ts`：namespace `MesSetPollutionCheckApi`，定义 `PollutionCheck` 等 interface + 每个接口函数（`requestClient.post('/mes/safety-env/pollution-check/create', data)`）；
2. `views/…/index.vue`：Vben `useVbenVxeGrid` 表格 + `data.ts`（列定义/搜索表单）+ `modules/form.vue`（`useVbenModal`）等；
3. 权限按钮用 `auth: ['mes:set-pollution-check:create']` 与后端 `@PreAuthorize` 标识一一对应；
4. 字典/枚举前端映射定义在 `data.ts`（如环节、复核结果的 label/value）。

## 6. 数据库与配置体系

### 6.1 数据管理

- 库：`ruoyi-vue-pro`（MySQL，root/root）；
- `deploy/mysql/init/`：按编号初始化脚本（0052–0055 为 MES 源码库）；`deploy/mysql/upgrade/`：增量升级（如 `20260902-mes-pro-project*`）；
- `sql/00-sql文件/`：业务定制 SQL（环保六件套、HRM 菜单、WMS 质检报告等）；执行统一 `mysql -h127.0.0.1 -uroot -proot --default-character-set=utf8mb4 ruoyi-vue-pro < xxx.sql`；
- 菜单/权限也走 SQL（先插菜单再复制角色授权，见 `pollution-landing` 中 34302 的处理）。

### 6.2 配置加载

- 服务启动读 `application.yaml` → 再加载 `application-local.yaml`（本地）/ `application-dev.yaml` 与 Nacos 配置 `${spring.application.name}-${spring.profiles.active}.yaml`；
- 本机 profile 用 `local`（system/mes/infra 三份 local yaml 的 datasource 密码已改为 root）；
- ⚠️ **实测坑**：本 fork 的属性优先级为 systemEnvironment > application.yaml > application-local.yaml（与官方文档相反），敏感配置（如 DeepSeek api-key）注入点用环境变量（`DEEPSEEK_API_KEY`），yaml 只留 `${DEEPSEEK_API_KEY:}` 占位，key 永不入库。

## 8. 开发约定（新增一个功能的标准路径）

以后端 CRUD + 前端页面为例：

1. **表设计**：标准审计列 + `uk_` 唯一键（注意 `uk_record_no` 这类全库唯一键不带租户的坑）；
2. **SQL**：建表 + 菜单 + 角色授权脚本放 `sql/00-sql文件/`，执行前备份；
3. **后端**：DO → Mapper → Service/Impl（事务 + 状态校验）→ Controller + VO → 权限标识（`模块:域-功能:动作`）→ `enums/ErrorCodeConstants` 补错误码；
4. **RPC（如需跨服务）**：契约放 `*-api`，server 的 `api/` 包实现，消费方依赖 `*-api` 注入；
5. **前端**：`api/<模块>/<功能>/index.ts` → `views/…/index.vue + data.ts + modules/*` → 菜单 SQL 指到组件路径（动态路由自动识别）；
6. **验证**：经网关 `http://localhost:48080/admin-api/…` 实测接口，查 `dev-logs/` 对应服务日志；
7. **留痕风格**：关键业务状态变更写"履历表"（如 `mes_pollution_check_log`），只增不改；
8. 代码作者标记统一 `@author OPENLAB BS`。
