# 主体信息与授权域设计说明（投标人/招标人）

> 范围：本模块主体域（subject）——投标人/招标人信息完善、平台授权、经办用户管理、投标/发布资格门。
> 前置：先精读 docs/法规依据/00-索引与引用说明.md（法规/规范依据对照表）。

## 一、需求与口径

1. 完善投标人、招标人的信息；
2. 管理端应显示已授权的投标人，并支持管理用户；
3. 仅授权尚不充分：被授权投标人仍须进行信息完善；
4. 未完善 → 不能在本项目投标；可关注公告、参与其他项目（关注/订阅/浏览仅需登录+权限）；
5. 管理、关注、订阅等操作不需要信息完善，只要获得权限即可；
6. 需要在本网站所管理项目中投标的，必须完善信息；信息不完整无法获得投标资格。

## 二、设计决策（企业=租户）

- **主体 = 企业租户级**：一企业一租户（system 租户模型），主体档案挂在租户上，不做个人级档案；
  同一租户可同时具备 BIDDER（投标人）/ TENDERER（招标人）两种主体身份（一类型一档案）。
- **授权 = 平台核发**：管理端对“某企业租户具备某主体角色”进行授权（ENABLED/DISABLED，撤销=停用留痕）；
  授权记录 G 轨（跨租户），档案 T 轨（租户自维护），中间靠 tenant_id 关联。
- **资格门 = 授权 + 信息完善**：投标资格 = 已授权(ENABLED) ∧ 档案必填清单全齐；
  招标人发布资格同构：公告 create/update/publish、备案 submit 前断言（招标投标法 第8/16条）。
- **无租户上下文豁免**：平台同步作业/初始化（TenantContextHolder 为空）不设门，防批处理被主体状态阻塞。

## 三、表结构（DDL：sql/2026-09-09-subject.sql）

| 表 | 轨 | 说明 | 唯一键 |
| --- | --- | --- | --- |
| bidding_subject_profile | T | 主体信息档案（租户自维护；必填清单=SubjectCompleteness） | (tenant_id, subject_type, deleted) |
| bidding_subject_auth | G | 平台授权（含 tenant_name 快照、授权/停用时间、操作人） | (tenant_id, subject_type, deleted) |
| bidding_subject_user | G | 主体经办用户绑定（userId + 昵称快照；OPERATOR/CONTACT） | (tenant_id, subject_type, user_id, deleted) |

## 六、错误码（ErrorCodeConstants 106_030~040）

见代码内注释（每条含法规依据）。要点：
- 030 类型不支持（仅 BIDDER/TENDERER）；
- 031 未授权/已停用；032 重复授权；033 授权不存在；034 未完善；
- 035 USCC 校验失败（GB 32100-2015）；036 经办用户非本企业租户（system 侧扩展位）；037 重复绑定；
- 038 绑定不存在；039 载荷格式非法；040 经办用户不存在/禁用。

## 七、权限点（sql/2026-09-09-subject-menu.sql）

- bidding:subject:query / bidding:subject:update —— 企业档案自维护；
- bidding:subject-auth:query / bidding:subject-auth:update —— 平台授权/经办用户管理。
- 资格门只校验“授权+档案完善”，不校验菜单权限（菜单仅控制入口显隐）。

## 八、已知边界与后续

1. 经办用户“归属租户”强校验依赖 system 侧开放租户归属（AdminUserRespDTO 暂未返回 tenantId），当前为 RPC 异常宽松绑定 + 明确无效拒绝；
2. 投标递交（报名/投标文件）流程本期未落地（无假动作），资格门 assertBidderEligible 已就绪，供后续接线；
3. 资质/业绩/证书等扩展数据集（BidderExtVO/PersonSupplierExtVO）入 extJson，随后续资质管理迭代；
4. 附件（营业执照影像）为可选实名凭据，后续可升为必填。

## 附：编写说明（本文档尾部固定段）

### 编写原因
随前端规范文档体系建立（docs/前端规范-全域接口说明/），将主体域设计说明中的接口表升级为「功能+设计依据」逐条口径，并注明与资格门的联动，避免设计与接口实现脱节。

### 编写依据
- 业务需求：Task2 四条（完善信息/管理端授权+管理用户/被授权仍须完善/未完善不能投标但可关注订阅）；
- 法规/规范：招标投标法 第8/16/25/26条、实施条例 第15/19条、电子招标投标办法 第13/24条、10号令 第5条、GB 32100-2015、V2.0 数据规范表89；
- 代码事实源：controller/admin/subject/** 与 service/subject/**（SubjectEligibilityServiceImpl 为资格门唯一入口）。

### 所满足的业务需求内容及其实现方式
- 「完善投标人、招标人的信息」→ 档案 T 轨自维护 + 完善度核算（必填清单 SubjectCompleteness）；
- 「管理端显示已授权投标人并支持管理用户」→ 授权 G 轨 + 经办用户绑定（含昵称快照）；
- 「被授权投标人仍须完善信息；未完善不能在本项目投标，但可关注/订阅」→ 资格门双条件 + 关注域豁免；
- 「信息不完整无法成功获取投标权限」→ 资格接口（6.1.3/6.2.4）与后端硬断言（1-060-106-031/034）双层保障。
