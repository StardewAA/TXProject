## 二、业务流程理解（产品视角）

支付模块的核心链路：

```
① 应用信息（创建支付应用 app + 配置支付渠道：微信/支付宝/模拟）
        ↓
② 业务系统发起支付 → 生成支付订单（支付订单页可查、可跳转收银台）
        ↓
③ 用户支付成功 → 支付渠道异步回调（回调通知页留痕）
        ↓
④ 异常场景：退款（退款订单）、转账（转账订单）
        ↓
⑤ 资金侧：用户钱包（余额 / 充值套餐 / 流水）
```

**使用顺序上，应用信息是入口**：没有支付应用 + 渠道配置，其余页面永远"暂无数据"。这解释了截图空列表的现象。

## 三、缺口分析与开发计划

### 缺口 1：钱包流水独立页面（本次第一个开发的模块）✅

- 现状：`api/pay/wallet/transaction/index.ts` 已存在，但页面仅以"钱包余额 → 详情弹窗"形式呈现，无独立菜单页。
- 目标：新增 `views/pay/wallet/transaction/index.vue`，支持按用户编号/用户类型/钱包编号搜索全量流水，新增"业务分类"列展示（充值/充值退款/支付/支付退款/更新余额/转账）。
- 后端：`/pay/wallet-transaction/page` 已就绪，权限 `pay:wallet:query`，查询参数 walletId/userId/userType。
- 交付物：前端页面 + 菜单 SQL（`docs/sql/pay-wallet-transaction-menu.sql`）。
