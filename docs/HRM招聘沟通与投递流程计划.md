# HRM 招聘沟通与投递流程 — 需求分析与开发计划

> 分析日期：2026-09-12
> 分析范围：`txgy-module-hrm`、HRM 管理端前端、个人登录后的 HRM 应聘网页全部功能（部署优先 `txgy-ui-admin-vben/apps/web-antd`，按需同步 `web-ele`）、HRM SQL/菜单、文档与测试。
> 范围边界：允许修改 HRM 后端、HRM 管理端及个人端招聘应聘页面；不修改云培训学院、招标投标、`txgy-module-im`、BPM/CRM/ERP、公共框架及与 HRM 无关的登录/注册业务。

## 一、现状与缺口

### 1.1 已有能力（HRM 招聘沟通，不是公共 IM 模块）

- 门户已有 `HrmPortalRecruitChatController`、`HrmRecruitChatServiceImpl`，数据表为 `hrm_recruit_chat_conversation`、`hrm_recruit_chat_message`。
- 会话状态当前为 `WAITING(1)`、`QUALIFIED(2)`、`FAILED(3)`；HR 首次回复即获得投递资格，任一方结束会话即失败。
- 门户投递校验 `hasApplyQualification`，管理端代投不校验；候选人详情页尚无沟通 Tab。
- 门户页面 `portal/recruit/messages.vue` 已存在，需要与资格、投递入口及状态提示对齐。

**范围澄清：** 本计划中的“沟通”仅指 HRM 招聘沟通领域对象（`hrm_recruit_chat_*` 表、HRM Controller/Service、个人端招聘页面和 HRM 管理端页面），不涉及 `txgy-module-im`、IM 工作台、IM WebSocket/LiveKit、IM 菜单或 IM 公共消息能力。个人登录后的 HRM 应聘网页（职位浏览、职位详情、求职资料、沟通、投递、应聘记录、面试/Offer/入职展示）属于本计划范围。云培训学院和招标投标完全不属于本计划范围，不得修改其页面、接口、菜单或路由。当前不需要与其它模块联调；若后续需要统一通知、用户关系或 IM 能力，必须另行确认接口和联调范围。

### 1.2 主要缺口

1. 候选人整数状态与应聘字符串状态未形成统一双写规则，流程节点（筛选、面试、Offer、入职）存在漂移风险。
2. 管理端缺少候选人详情内嵌沟通 Tab，以及独立「招聘沟通」列表页和菜单入口。
3. 沟通 DDL 尚未纳入 init-db；测试 H2 表缺资格列；会话缺少业务唯一约束；暂无 Chat 单测。
4. `RECRUIT_APPLICATION_*` 错误码占用 `1_050_200_020~026`，与职位类型、候选人手机号、Offer 错误码碰撞；沟通错误码 `1_050_200_060~066` 可直接使用。
5. 菜单现有招聘顺序为候选人、职位、设置，需要新增菜单并调整为：招聘沟通、候选人、招聘职位、招聘设置；官方 ID 已到 1636，新 ID 从 1637 起。

## 二、目标状态机与双写映射

### 2.1 目标业务状态机

```mermaid
stateDiagram-v2
direction TB
[*] --> 浏览职位
浏览职位 --> 已沟通: 求职者发起沟通
已沟通 --> 等待回复
等待回复 --> 招聘方已回复: 招聘方回复
等待回复 --> 沟通失败: 未回复/结束
招聘方已回复 --> 获得投递资格
获得投递资格 --> 沟通中
沟通中 --> 获得投递资格: 继续沟通
沟通中 --> 沟通失败: 双方结束沟通
获得投递资格 --> 待投递: 进入投递
待投递 --> 已投递: 提交简历
已投递 --> 招聘方查看 --> 筛选中
筛选中 --> 筛选通过
筛选中 --> 简历淘汰
筛选通过 --> 待约面
待约面 --> 已约面: 确认时间
已约面 --> 面试中
已约面 --> 面试取消
已约面 --> 面试缺席
面试中 --> 面试评估
面试评估 --> 下一轮
下一轮 --> 待约面
面试评估 --> 终面通过
面试评估 --> 面试淘汰
终面通过 --> 待发Offer --> Offer已发出
Offer已发出 --> Offer已接受 --> 待入职 --> 已入职
Offer已发出 --> Offer已拒绝
Offer已发出 --> Offer已失效
```

### 2.2 候选人与应聘状态双写

| 业务节点 | 候选人整数状态 | 应聘字符串状态 | 双写时机 |
|---|---|---|---|
| 新候选人/已投递 | `NEW(1)` | `SUBMITTED` | 投递成功（门户需具备资格，管理端代投可跳过资格校验） |
| 招聘方查看、筛选中 | `NEW(1)` | `SCREENING` | 首次查看或进入筛选 |
| 筛选通过、待约面 | `PRIMARY_PASS(2)` | `INTERVIEWING` | 筛选通过 |
| 面试进行/下一轮 | `INTERVIEW(3)` | `INTERVIEWING` | 面试排期或进入面试 |
| 终面通过 | `INTERVIEW_PASS(4)` | `PASSED` | 最终面试评估通过 |
| 待发/审批中 | `INTERVIEW_PASS(4)` | `OFFER_APPROVING` | Offer 发起审批 |
| Offer 已发 | `OFFER_SENT(5)` | `OFFER_SENT` | Offer 发送 |
| Offer 接受、待入职 | `PENDING_ENTRY(6)` | `PENDING_ONBOARD` | 候选人接受 Offer |
| 已入职 | `JOINED(8)` | `ONBOARDED` | 入职转员工成功 |
| 淘汰（筛选/面试/Offer 失效） | `ELIMINATED(7)` | `ELIMINATED` | 任一淘汰终态 |
| 求职者撤回 | 保持/按现状记录 | `WITHDRAWN` | 撤回应聘，不覆盖已入职等终态 |

双写必须在同一事务内完成，禁止只更新一侧；历史数据提供一次性对账脚本/检查 SQL，异常记录进入日志并可重放。

### 2.3 沟通资格与会话生命周期

- `WAITING` 表示尚未获得资格；HR 首次有效回复时原子地写入资格时间、授权来源并转为 `QUALIFIED`。
- `QUALIFIED` 表示当前会话已具备投递资格，不等同于消息发送结束；后续消息仍可继续，结束动作写入结束方、结束时间和原因。
- `FAILED` 表示沟通被明确结束或按超时规则失败。结束会话不自动撤销已经产生的投递资格；资格有效期或职位关闭规则独立处理。
- 会话唯一性建议限定为“同一租户 + 候选人 + 职位的一个未结束会话”；结束后允许重新发起新会话，历史会话保留审计。
- 管理端代投仅跳过资格校验，不跳过重复投递、租户隔离和审计记录。

## 三、产品与页面方案

### 3.1 管理端菜单 SQL

- 在 `sql/hrm_menu.sql` 增加「招聘沟通」目录/页面及查询、回复、结束等按钮权限，新增 ID 从 **1637** 起，避免占用官方 ID。
- 招聘管理子菜单排序固定为：**招聘沟通（sort 10）、候选人（sort 20）、招聘职位（sort 30）、招聘设置（sort 40）**；保留原权限标识兼容已有角色。
- SQL 仅限 HRM 菜单；部署含中文 SQL 时使用 `docker cp` 拷入 MySQL 容器后执行，禁止 PowerShell 中文管道。

### 3.2 沟通入口

- 候选人详情 `apps/web-antd/src/views/hrm/recruit/candidate/detail/index.vue` 内嵌「沟通」Tab：会话摘要、消息时间线、发送/结束、资格状态及跳转投递。
- 新增独立「招聘沟通」列表页：按会话状态、候选人、职位、更新时间筛选，支持进入候选人详情并定位沟通 Tab。
- 个人端 HRM 应聘页面允许完整开发与改造；`web-ele` 仅在需要保持 HRM 功能一致时同步，部署验收以 `web-antd` 为准。
- 门户 `portal/recruit/messages.vue` 增加资格/投递状态展示，沿用现有会话接口，不重复建设 IM 基础能力。

## 六、分阶段里程碑

| 里程碑 | 交付内容 | 验收标准 |
|---|---|---|
| **M1 沟通入口与 DDL** | 菜单 SQL（1637+）、招聘沟通列表、候选人详情沟通 Tab、DDL/init-db/UNIQUE、H2 对齐 | 企业端可查会话、进入详情沟通、DDL 可重复执行且无重复会话 |
| **M2 资格与投递** | 资格授予/失效规则、门户资格校验提示、投递入口与管理端代投豁免 | 首次 HR 回复授予资格；无资格门户不可投；代投可投且记录审计 |
| **M3 筛选面试双写** | 筛选、面试排期/评估、取消/缺席/下一轮流转及候选人/应聘双写 | 合法流转完整，任一失败事务整体回滚，状态对账为零 |
| **M4 Offer/入职** | Offer 审批/发送/接受/拒绝/失效、待入职与入职转员工双写 | Offer 与入职终态、通知和权限走查通过 |
| **M5 走查** | 全链路回归、菜单/权限/租户隔离、前端构建、文档与遗留项清单 | `web-antd` 构建通过，HRM 后端测试通过，确认后再合并发布 |

## 七、执行约束与确认点

- 每个里程碑完成后单独验收再进入下一阶段；个人端 HRM 应聘网页的开发与改造可与管理端同步推进。
- 所有改动限定在 HRM 后端、HRM 管理端前端、个人端 HRM 应聘页面、HRM SQL/菜单、HRM 文档与测试目录；不得触碰云培训学院、招标投标、`txgy-module-im`、BPM/CRM/ERP 和公共框架。
- 登录/注册仅作为 HRM 个人端的既有前置能力使用；如必须调整 HRM 个人端路由守卫，只允许做 HRM 页面范围内的最小改动，不改变通用认证协议或其它业务入口。

## 八、页面布局与交互设计补充

### 8.1 设计参考边界

招聘沟通与投递页面可参考 BOSS 直聘招聘沟通页面的信息组织方式（会话列表、会话详情、职位摘要、输入区的布局关系），但只借鉴布局层级、信息密度和交互可发现性，不复制其品牌视觉、文案或业务功能。

页面所有字段、按钮和状态必须来源于当前 HRM 接口与状态机，不得因为参考站点而新增 HRM 尚未具备的能力。特别是不引入社交动态、推荐算法、语音/视频通话、在线文件预览、企业认证、复杂 IM 扩展或第三方消息能力。

### 8.2 个人端 HRM 应聘页面

#### 招聘沟通页

采用“左侧会话列表 + 右侧当前会话”的双栏结构：

| 区域 | 展示内容 | 允许操作 |
|---|---|---|
| 会话列表 | 职位名称、招聘负责人、最后一条消息、最后更新时间、未读数、会话状态 | 切换会话 |
| 会话头部 | 职位摘要、招聘负责人、沟通状态、投递资格状态 | 返回职位详情；在具备资格时进入投递 |
| 消息时间线 | 文本消息、发送方、发送时间；按时间顺序展示 | 加载历史消息 |
| 输入区 | 文本输入、发送按钮 | 会话未失败时发送消息 |
| 结束提示 | 会话失败原因、结束时间；资格状态单独展示 | 结束后的会话只读 |

个人端现有逻辑保持不变：求职者发起会话后处于等待回复；招聘方首次有效回复后获得投递资格；会话结束进入失败状态，但不以失败状态自动撤销已经产生的投递资格。

#### 职位详情与投递

- 职位详情页保留职位基本信息、招聘要求和沟通入口。
- 未获得有效沟通资格时，投递按钮展示“等待招聘方回复”，并阻止正式投递。
- 获得资格后，投递按钮进入现有简历选择/确认流程。
- 投递成功后展示应聘状态，不增加独立于 HRM 应聘状态机之外的状态。
- 管理端代投仍按现有规则跳过资格校验，但必须保留重复投递校验和审计信息。

### 8.3 企业端 HRM 管理页面

#### 独立“招聘沟通”列表页

采用“筛选区 + 会话列表 + 消息详情”的结构：

- 筛选区：候选人、职位、会话状态、更新时间范围。
- 列表区：候选人、职位、最后消息、更新时间、未读数、资格状态、会话状态。
- 详情区：消息时间线、会话摘要、资格信息、结束原因。
- 操作区：查看消息、回复、结束沟通、跳转候选人详情。

列表页不新增独立聊天账号体系、不接入公共 IM，不提供语音、视频、群聊或消息撤回等当前 HRM 未定义的功能。

#### 候选人详情“沟通” Tab

- 与详细资料、简历版本、面试记录、应聘记录、操作日志并列。
- 默认展示与该候选人相关的 HRM 招聘沟通会话。
- 支持查看消息时间线、回复、查看资格状态和结束原因。
- 跳转投递或应聘记录时使用现有 HRM 页面和接口，不复制一套新的投递流程。

### 8.4 状态与按钮展示规则

| 状态 | 页面文案 | 可用操作 |
|---|---|---|
| `WAITING` | 等待招聘方回复 | 继续发送消息、等待回复 |
| `QUALIFIED` | 已获得投递资格 | 继续沟通、进入投递 |
| `FAILED` | 沟通失败 | 查看历史消息；不可继续发送 |

按钮是否可用必须同时依据会话状态、当前用户身份、资格状态和后端权限判断，前端隐藏按钮不能替代后端校验。

### 8.5 视觉与响应式要求

- 优先适配 `web-antd`，保持现有 HRM 页面卡片、表格、Tabs 和权限按钮风格。
- 个人端在窄屏下将双栏调整为会话列表与会话详情分步显示，不能丢失职位、资格和状态信息。
- 状态使用统一颜色语义：等待为提醒色、已获资格为成功色、失败为中性色；颜色之外必须同时显示文字。
- 不引入新的 UI 框架，不修改公共主题和其它业务模块的布局。
- 开发前先确认本计划书中的状态映射、唯一键维度和菜单排序；如需调整，先更新计划书并重新确认。
