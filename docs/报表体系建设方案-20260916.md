## 一、为什么要做这件事

需求方案的「管控智能化」目标（数据统计、绩效考核、风险研判）目前没有落地载体：

- **设计器已接入，模板为零**：积木报表（JimuReport）后端已集成、设计器入口已在管理后台，但实测 `jimu_report` 表 **0 条模板**——用户打开设计器看到的是空白；
- **大屏入口不可用**：GoView 大屏入口写死了 `VITE_GOVIEW_URL`，该环境变量**在 `.env.development` / `.env.production` 中均未定义**，本地打开即为空 iframe；
- **统计口径散落**：生产、库存、销售、招投标等数据分散在各业务模块的 40+ 个实时聚合接口里，没有统一报表门户，也没有跨域指标；
- **goView 数据层有风险**：`/report/go-view-data/get-by-sql` 允许前端直接传 SQL 到主库执行，无白名单、无行级权限、无性能保护。

本方案要解决的是：**把已有底座用起来，建成一套可复制、有权限、可导出的报表/驾驶舱体系。**

## 三、目标与总体架构

### 3.1 建设目标

1. **模板化**：业务人员/实施人员可在设计器里自助制作报表模板，开发只提供受控数据集；
2. **有权限**：报表可见范围按「菜单权限 + 租户 + 部门数据权限」三层控制；
3. **可导出可订阅**：所有报表支持 Excel 导出，关键报表支持定时生成与预警推送；
4. **驾驶舱**：建立在统一指标口径上的管理驾驶舱（生产/库存/销售/质量/安全/培训/招投标）。

### 3.2 分层架构（在现有底座上补齐，不推翻）

```
展示层    vben 菜单：报表中心（模板分类）＋ 驾驶舱（大屏）
          ├─ 积木报表 iframe（明细/汇总/打印类）   ← 已有入口
          └─ GoView iframe（大屏类）               ← 需配置 VITE_GOVIEW_URL
模板层    积木报表模板（jimu_report）＋ 大屏项目（report_go_view_project）
          └─ 建设重点：分类、命名、参数、权限、导出、订阅
数据集层  【新增】受控数据集：报表数据源从"裸 SQL"改为"命名数据集"
          ├─ SQL 数据集：白名单登记 + 参数化 + 只读账号 + 行数上限
          └─ 接口数据集：调用业务模块统计接口（Feign/HTTP）
数据层    各业务模块统计能力（现状 40+ 接口）＋【新增】预聚合统计表（按需）
权限层    菜单权限（已有）＋ 租户（已有）＋【新增】部门数据权限 / 跨租户汇总
```

### 3.3 关键设计决策（建议）

| 决策点 | 建议 | 理由 |
| --- | --- | --- |
| 明细/汇总/打印报表用什么 | **积木报表** | 已集成、支持复杂表格与打印、模板可自助维护 |
| 大屏用什么 | **GoView** | 已集成、大屏效果成熟；但需先补齐 URL 配置与数据源治理 |
| 裸 SQL 直查是否保留 | **保留但收紧**：登记白名单数据集，只读数据源账号，禁止前端任意 SQL | 当前实现对主库完全开放，属安全与性能风险 |
| 是否自研模板引擎 | **不自研** | 底座已具备，自研成本高、收益低 |
| 预聚合是否必须 | **按数据量分级**：日增万级以下先实时聚合；MES 报工、WMS 收发存优先考虑预聚合 | 复用 mall-statistics 范本 |
| 报表权限粒度 | 菜单权限定"能看哪张报表"，部门数据权限定"能看哪些数据" | 需求方案要求按角色脱敏聚合 |

## 五、模板与数据集规范

### 5.1 命名与分类

- 模板命名：`{域}-{对象}-{口径}`，如 `MES-报工-按工序日汇总`；域取值 `MES/WMS/ERP/CRM/HRM/TRAINING/BIDDING/IOT/FMS/PLATFORM`；
- 分类沿用 `jimu_report_category`，按域建一级分类；
- 大屏项目命名：`驾驶舱-{主题}`。

### 5.2 数据集规范（替代裸 SQL 的关键）

1. **只读账号**：报表数据源使用独立只读数据库账号（当前 `get-by-sql` 走主库可写连接，需改造）；
2. **白名单登记**：数据集以 `名称 + SQL + 参数 + 最大行数 + 责任人` 登记，前端只能引用名称，不能传 SQL；
3. **参数化**：日期区间、仓库、物料等一律走参数，`tenant_id` 由服务端强制注入，禁止前端传入；
4. **行数上限与超时**：单次查询强制 `LIMIT` 与超时，防止大表拖垮主库；
5. **优先接口数据集**：已成熟的统计接口（如 MES 首页 11 个）以接口方式接入，避免重复写 SQL。

### 5.3 权限规范

| 层级 | 控制方式 | 现状 |
| --- | --- | --- |
| 能看哪张报表 | 菜单权限（`report:...`） | ✅ 已有 |
| 能看哪个租户的数据 | MyBatis 租户插件 | ✅ 已有 |
| 能看哪些部门/自己的数据 | `@DataPermission` / 部门数据权限 | ❌ **需新增**（统计接口目前 0 命中） |
| 跨租户汇总（集团看板） | `TenantUtils.execute` 显式切换 + 角色白名单 | ❌ **需新增** |
| 大屏公开分享 | 分享链接 + 有效期 + 脱敏 | ❌ 需设计 |

### 5.4 导出规范

统一走 `ExcelUtils` + 统计专用 RespVO（范本：`TradeTrendSummaryExcelVO`）；导出同样受行数上限与权限约束，超过阈值的导出走异步任务（参考 `jimu_report_export_job` 表能力）。

## 七、风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 裸 SQL 直查主库（现行实现） | 数据泄露、大表拖垮主库 | P0-1 强制改为白名单数据集 + 只读账号 |
| `/jmreport/**` 全 `permitAll` | 未授权访问风险（依赖积木自身 token 校验） | 上线前专项复核安全配置 |
| 实时聚合接口数据量增长 | 报表变慢、影响业务库 | 按数据量引入预聚合（范本：mall-statistics） |
| 指标口径不统一（同一"产量"多算法） | 报表结论互相矛盾 | 先定指标字典（第 9 节问题 3） |
| 跨租户汇总实现不当 | 越权看到其他企业数据 | 白名单 + 显式租户上下文 + 审计日志 |
| GoView 独立工程未嵌入 | 大屏开发与运维割裂 | 明确以 iframe 接入（不合并工程） |

## 八、验收标准

1. 报表中心可按域浏览模板，参数筛选、导出、打印均可用；
2. 每个模板明确「数据来源 + 权限范围 + 刷新时效」三项说明；
3. 数据集白名单可审计：谁、何时、改了什么 SQL；
4. 部门数据权限试点通过：同角色不同部门用户看到的行数不同；
5. 大屏可在管理后台直接打开（`VITE_GOVIEW_URL` 配置生效）；
6. 至少 1 张报表完成「定时生成 + 预警推送」闭环。
