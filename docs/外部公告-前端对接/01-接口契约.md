# 外部公告（notice-external）接口契约

> 上下文前缀：所有管理后台接口走 `/admin-api`（容器/网关环境），服务直连时同上；以下表格只写 controller 内相对路径。
> 返回统一 `CommonResult`：`{code,msg,data}`，`code=0` 成功；分页 data 为 `PageResult{list,total}`。
> 事实源：`/v3/api-docs`；下表若与运行 OpenAPI 冲突，以 OpenAPI 为准。

## 1. 大厅公开（前端展示页，全部 @PermitAll 免登录、免租户）

### 1.1 公开分页 `GET /bidding/notice-external/page`
- 语义：仅返回 **status=ACTIVE 且 public_scope=SOCIAL** 的主档（下架/待审核/归档均不可见），按 publishTime 倒序。
- 入参（`NoticeExternalPageReqVO` 继承 PageParam：pageNo/pageSize）：

| 字段 | 说明 |
|---|---|
| keyword | 全文关键词（标题/项目名/编号/正文），走 ES 索引 bidding-notice-external（需后端 bidding.es.enabled=true；未启用时传该参数报错 1-060-106-015，不会降级为 LIKE）；命中集上限 200 |
| title | 标题（精确匹配筛选） |
| sourceCode | 来源站 code |
| contentType | HTML / PDF / ATTACHMENT / IMAGE / OTHER |
| industryFlag | BELONGS / NOT_BELONGS / UNCERTAIN（防腐保温行业判定） |
| projectCode | 关联项目编号（跟踪维度，大厅一般不传） |
| noticeTypeRaw | 公告类型（外站原文或权威码均可） |
| beginTime / endTime | 发布时间区间 |

- 出参行 `NoticeExternalRespVO`：id、sourceName（来源站名）、title、origUrl、contentType、noticeTypeRaw、industryFlag（BELONGS/NOT_BELONGS/UNCERTAIN）、issuerName（发布单位）、publishTime、effectiveFrom、effectiveTo、status（只会 ACTIVE）。

### 1.2 公开详情 `GET /bidding/notice-external/detail?id=`
- 语义：ACTIVE+SOCIAL 才返回详情。错误码（N5 勘误）：**1-060-106-001=外部公告不存在**、**1-060-106-002=外部公告已下线或不可展示**（前端映射“公告不存在或已下架”即可；契约文档曾误写 002=不存在、011=已下架）。
- 出参 `NoticeExternalDetailRespVO` 按形态给字段：
  - 公共：id、sourceCode、sourceName、title、origUrl（**原网址必带**）、contentType、noticeTypeRaw、legalFlag（Y/N）、industryFlag、issuerName、publishTime、effectiveFrom、effectiveTo。
  - **跟踪维度键（BR-1 新增）**：projectKey/projectName、tenderProjectKey/tenderProjectName（一期恒 null）、bidSectionKeys[]/bidSectionNames[]（一期恒 null/空）、bidSectionCodes（原文）。键存在即前端可显示“跟踪该招标项目/标段”次级关注按钮（follow targetType=PROJECT/TENDER_PROJECT/SECTION，targetKey=对应键）；键为 null=采集未解析到，不展示按钮。
  - 项目名称快照字段名：**projectName**（跟踪键 projectKey 并列下发；与旧版 bidSectionCodes 一起保留）。
  - contentType=HTML：`contentHtmlSafe`（**jsoup 白名单净化版，前端渲染请用此值**）、`contentHtml`（**公开出参恒为 null**：原样 HTML 仅存库留档供抽取/审计，不下发公众客户端，防存储型 XSS 载荷主动下发——安全评审意见）。
  - contentType=PDF：`pdfFileId`、`pdfSha256`、`pdfSize`、`pdfDownloadUrl`（FileApi 签名下载）、`extractionStatus`（NONE/SUCCESS/FAIL_EMPTY/FAIL：抽取的正文文本暂未在 VO 暴露，需要可提后端）。
  - 附件 `attachments[]`（ATTACHMENT 形态或 HTML/PDF 携带附件时）：id、name、ext、fileId、sha256、size、downloadUrl（FileApi 签名）、origDownloadUrl（外站原始链接，溯源用）、**virusStatus（PENDING/CLEAN/INFECTED；INFECTED 的附件后端不下发 downloadUrl，前端遇到 INFECTED 显示"已拦截"即可）**。

### 1.3 外链中转 `GET /bidding/notice-external/go?url=<原网址>`
- 语义：302 跳转到原站。**白名单校验**：url 的 host 必须是启用采集源 base_url 的 host（或其子域），否则拒绝（防开放重定向）。
- 前端约定：**用户点击外部链接一律走后端 go 端点（传 origUrl），不要在前端直接 window.open(origUrl)**——否则脱离白名单管控与防重定向审计。
- 出参：无 body，302 Location。

## 2. 管理端审核（需登录 + 权限 `bidding:notice-external:update`，均 @Idempotent 幂等）

### 2.0 管理分页（N1 新增）`GET /bidding/notice-external/manage/page`
- 语义：审核/运营列表，**不做公开 page 的 SOCIAL+ACTIVE 硬过滤**，可查 NEW/ACTIVE/INACTIVE/ARCHIVED × UNREVIEWED/APPROVED/REJECTED/TAKEN_DOWN 全量；行内含审核/抽取/AI/正文结构化状态，供行内操作选中后执行 approve/reject/take-down/ai-extract/body-structure。
- 权限：登录 + **`bidding:notice-external:update`**（管理列表只对有管理能力的人开放；与 approve 等操作同权限位）。
- 入参（结构化过滤，无 keyword——ES 索引仅含 ACTIVE，管理列表不支持全文，勿传 keyword）：status、auditStatus、sourceCode、contentType、noticeTypeRaw、industryFlag、projectCode、beginTime/endTime（字符串时间）。
- 出参行 `NoticeExternalManageRespVO`：id、sourceCode、sourceName、title、origUrl、contentType、noticeTypeRaw、legalFlag、industryFlag、industryConfidence、issuerName、projectName、bidSectionCodes、status、auditStatus、extractionStatus、aiExtractionStatus、bodyBlocksStatus、bodyParserCode、publishTime、effectiveFrom、effectiveTo、fetchCount、lastFetchTime、createTime、updateTime。

| 端点 | 语义 | 出参 |
|---|---|---|
| `POST /bidding/notice-external/ingest` | **采集回传入库（外部采集服务 → 平台）**：采集侧下载+解析后回传，落 NEW+UNREVIEWED 待审核；同 URL 幂等/内容变更覆盖/驳回重采由后端处理；请求体=采集产出 DTO（origUrl+title 必填，其余见 02 文档样例） | id (Long) |
| `POST /bidding/notice-external/approve?id=` | 审核通过：NEW→ACTIVE；**触发关注提醒扇出 + ES 建索引事件**（成功/失败均不影响审核结果） | Boolean |
| `POST /bidding/notice-external/reject?id=` | 驳回（不展示） | Boolean |
| `POST /bidding/notice-external/take-down?id=` | 下线 ACTIVE→INACTIVE（展示随即消失） | Boolean |

## 3. 关注域（需登录；读=权限 `bidding:notice-external:query`，写=权限 `bidding:notice-external:update`）

| 端点 | 语义 | 入参 |
|---|---|---|
| `POST /bidding/notice-follow/follow` | 关注（幂等） | body `FollowReqVO`：targetType=ANNOUNCEMENT/PROJECT/TENDER_PROJECT/SECTION，targetKey=公告 id 或 项目/招标项目/标段维度代码 |
| `POST /bidding/notice-follow/unfollow` | 取消关注（幂等） | 同上 |
| `GET /bidding/notice-follow/item/page` | 我的关注列表 | **followType**（实参名勘误：契约此前误写 dimensionType）过滤：ANNOUNCEMENT/PROJECT/TENDER_PROJECT/SECTION（空=全部）；可叠加 **followKey**（公告 id/维度代码）精确过滤（N2②，列表补名/详情探测免扫描）+ 分页 |
| `GET /bidding/notice-follow/status` | **关注状态单点查询（N2② 新增）**：详情页关注按钮初始态 | targetType + targetKey → `{followed:boolean, itemId?, displayName?, issuerName?}`（公告级目标已关注且行缺快照时即时补名返回，不落库） |
| `GET /bidding/notice-follow/item/{itemId}/timeline` | 关注项时间线（公告列表+动态） | itemId + 分页 |
| `POST /bidding/notice-follow/item/{itemId}/read` | 标记该关注项已读（清未读，幂等） | itemId |

关注域出参要点（**BR-9 字段名已按真实 VO 订正**）：
- `FollowItemRespVO`：关注行 **id**、**followType**（ANNOUNCEMENT/PROJECT/TENDER_PROJECT/SECTION）、**followKey**（公告 id 或维度代码）、**displayName**（名称快照）、**issuerName**（发布单位）、**stageCode**（进展阶段 PENDING/TENDER/OPEN_BID/EVAL/RESULT/CONTRACT/DONE/UNKNOWN）+**stageName**、**baseJson**（基础信息快照）、**latestDynamicTime**（最近动态时间；**BR-6 起关注已 ACTIVE 公告即被初始动态刷新，不再为空**）、**unreadCount**、**followTime**（关注时间）、**noticeStatus**（公告级行=外部公告状态 ACTIVE/INACTIVE/…；维度行为 null，BR-4 新增）、**available**（平台详情可达性：false=公告已下线/归档，隐藏详情跳转，BR-4 新增）。
- `FollowEventRespVO`（timeline 行）：事件 **id**、**source**（INTERNAL/EXTERNAL）、**eventType**（NOTICE_PUBLISHED/NOTICE_UPDATED/EXTERNAL_ACTIVE/STAGE_CHANGE）、**noticeId**（可空）、**titleSnapshot**、**origUrl**（外部公告原网址）、**occurredAt**、**readFlag**、**noticeStatus**、**available**（BR-4 新增：EXTERNAL 需 ACTIVE、INTERNAL 需 PUBLISHED 才可跳平台详情；否则按源站原文/纯文本）。
- 页面上"外部公告动态"的跳转即用 event.origUrl 走后端 go 端点；内部公告动态（INTERNAL）跳 /bidding/notice/public/detail?id=noticeId（公开详情端点已存在，见 BR-3 答复）。
- **BR-6 初始反馈**：关注已 ACTIVE 的外部公告时，后端种一条已读 EXTERNAL_ACTIVE 初始动态（titleSnapshot=关注时标题），“我的关注”列表按 latestDynamicTime 置顶、timeline 立即有内容；未读角标不受影响。

## 4. AI 结构化抽取与防腐保温行业判定（需登录 + 权限 `bidding:notice-external:update`，@Idempotent）

| 端点 | 语义 | 说明 |
|---|---|---|
| `POST /bidding/notice-external/ai-extract?id=` | 人工触发 AI：结构化抽取 + 防腐保温行业判定 | 需 `bidding.ai.enabled=true`；未启用返回 1-060-106-016 |

- 出参 `NoticeExternalAiExtractRespVO`：`id`、`aiExtractionStatus`（SUCCESS/FAILED）、`metaFieldCount`（结构化字段数）、`fullTextLength`（全文转写长度，无=0）、`industryFlag`（BELONGS/NOT_BELONGS/UNCERTAIN，AI 判定）、`industryConfidence`（0~1 置信度）。
- 判定口径：公告涉及 管道/储罐/装置/设备及附属设施的 防腐蚀、保温、保冷、隔热 的 施工/维修/材料/检测 → `BELONGS`；明显无关 → `NOT_BELONGS`；信息不足 → `UNCERTAIN`。判定理由与命中关键词见 `ai_meta_json`（管理端内部查看，详情 VO 不下发整包）。
- 副作用（SUCCESS）：① `industryFlag`/`industryConfidence` 回写公告权威字段——列表 `page` 即可按 `industryFlag=BELONGS` 筛出"防腐保温相关"公告、详情/列表打标；② 扫描件全文转写（noticeFullText）非空时回写 `extraction_text` 并重放 ES 索引，转写正文随即可被关键词检索命中。
- 失败码：1-060-106-016 未配置 / 017 AI 输出非法 / 018 AI 调用失败 / 019 无可用素材（本地无抽取文本且未接扫描件 PDF 访问）。

## 5. 错误与约定

- 权限不足/未登录：由框架返回统一错误码（前端统一走 code≠0 提示）。
- 状态流转非法等业务错误码段：见 `enums/ErrorCodeConstants.java`（模块段 1_060_xxx），前端映射文案即可，勿硬编码散落。
- 所有写操作加按钮 loading（@Idempotent 保护），防连点重复提交。

## 7. 正文结构化（策略链：常规 HTML 解析 → AI 兜底排版，需登录 + 权限 `bidding:notice-external:update`，@Idempotent）

> 背景：R12② 的"结构化正文块"本期落地。源站正文有真 `<table>` 时常规解析直接块化（HTML_STRUCTURE）；
> 当正文是**拍平粘连文本**（原表格被压成无分隔长段，如候选/标段/金额逐条粘连），常规解析恢复不出表格——
> 运营在管理端对公告点"AI 排版"，AI 兜底把脏正文恢复为结构化块（AI_FALLBACK，走触发者租户自己的 AI 渠道/key）。

| 端点 | 语义 | 说明 |
|---|---|---|
| `POST /bidding/notice-external/body-structure?id=&ai=` | 人工触发正文结构化 | `ai=false`（默认）=常规 HTML 解析 HTML_STRUCTURE；`ai=true`=AI 兜底排版 AI_FALLBACK（需 `bidding.ai.enabled=true`，未启用返回 1-060-106-016） |
| `GET /bidding/notice-external/manage/get?id=`（**BR-7 新增**） | **管理详情预览（审核“读完正文再 approve”）**：全状态返回（NEW/ACTIVE/INACTIVE/ARCHIVED），**不受公开 SOCIAL+ACTIVE 过滤** | 出参 `NoticeExternalManageDetailRespVO`：管理行字段 + `contentHtmlSafe`（净化正文）、`bodyBlocksJson`（结构化块）、`pdfFileId/pdfSha256/pdfSize`、`extractionStatus/extractionSummary`（抽取正文前 200 字摘要）、`aiExtractionStatus/aiMetaFieldCount`、`publicScope`、附件（`virusStatus` 照回，INFECTED 不下发 `downloadUrl`）、跟踪键组。权限同上 `bidding:notice-external:update`，非幂等只读 |

- 出参 `NoticeBodyStructureRespVO`：`id`、`bodyBlocksStatus`（SUCCESS/FAILED）、`bodyParserCode`（HTML_STRUCTURE/AI_FALLBACK）、`blockCount`、`tableCount`、`aiRecommended`（常规解析无表格且存在≥400 字粘连段 → true，提示运营可用 AI 兜底）。
- 素材：HTML 形态取 `content_html`（原文，AI 输入用其文本视图）；PDF 形态无 HTML 时取 `extraction_text`。均无 → 1-060-106-019。
- **content_html 原文留档不动**；结构化产物写 `body_blocks_json`（+ `body_parser_code`/`body_blocks_status`/`body_blocks_at`）。
- AI 兜底输出容错：优先 JSON blocks schema；模型若输出 Markdown（含 md 表格）会被自动转换为同一 blocks schema，不因格式漂移失败。
- 失败：1-060-106-020（AI 兜底异常或输出无法结构化，状态标记 FAILED 可重试；失败不清空上次成功 blocks）。

### 7.1 detail 新增字段（正文块渲染优先）

`GET /bidding/notice-external/detail?id=` 增补：

| 字段 | 说明 |
|---|---|
| `bodyParserCode` | HTML_STRUCTURE / AI_FALLBACK / null（未结构化） |
| `bodyBlocksStatus` | NONE（默认）/ SUCCESS / FAILED |
| `bodyBlocksJson` | JSON **数组**（SUCCESS 时非空；FAILED/未结构化时保留上次成功值或 null） |

- 前端渲染规则：`bodyBlocksStatus=SUCCESS && bodyBlocksJson` 非空 → **按块组件渲染**（见 02 约定 schema）；否则回退 `contentHtmlSafe`（原文净化渲染）兜底。
