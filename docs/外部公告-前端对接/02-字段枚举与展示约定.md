# 外部公告：字段、枚举与展示约定

> 字段真名以 `sql/2026-09-03-external-notice.sql` 与 VO @Schema 注释为准；这里列前端会碰到的。

## 1. 主档关键字段（bidding_notice_external → 展示 VO）

| 概念 | 字段 | 取值/说明 |
|---|---|---|
| 标题 | title | 外站标题（≤512） |
| 来源 | sourceCode / sourceName | 采集源 code / 名称（如"示例交易平台"） |
| 原网址 | origUrl | **必须展示**；点击走 `/go` 中转 |
| 内容形态 | contentType | HTML/PDF/ATTACHMENT/IMAGE/OTHER |
| 类型原文 | noticeTypeRaw | 外站自述类型（展示原文即可） |
| 依法必招 | legalFlag | Y/N（NULL=未知） |
| 行业判定 | industryFlag | BELONGS（防腐保温相关）/ NOT_BELONGS / UNCERTAIN。**来源**：采集回传可先填；管理端执行 AI 抽取（`POST /notice-external/ai-extract`）后由 **AI 判定回写**（含 industryConfidence 置信度）。列表可 `page?industryFlag=BELONGS` 筛"防腐保温相关公告" |
| 发布单位 | issuerName | 快照 |
| 时间 | publishTime / effectiveFrom / effectiveTo | 发布时间/生效起/生效止 |
| 展示状态 | status | 大厅只会返回 ACTIVE |

## 2. 状态与审核（大厅列表不需要，管理端/筛选用）

- 展示状态 status：`NEW` 待审核 → `ACTIVE` 生效中（可展示）→ `INACTIVE` 已失效（超期/源站下线）／`ARCHIVED` 已归档（只读留痕）。管理端操作为 approve（NEW→ACTIVE）/ reject（驳回不展示）/ take-down（ACTIVE→INACTIVE）。
- 审核痕迹 audit_status：UNREVIEWED / APPROVED / REJECTED / TAKEN_DOWN。
- 抽取状态 extractionStatus（PDF 形态）：NONE 未抽取 / SUCCESS 成功（文本+表格已落库）/ FAIL_EMPTY 空结果（扫描件）/ FAIL 失败。

## 3. 展示（渲染）硬性约定

1. **正文**：
   - HTML 形态：渲染 **contentHtmlSafe**（后端 jsoup 白名单净化，已去 `<script>`/`on*` 事件属性/`iframe`/`style` 等）；`contentHtml` 公开出参**恒为 null**（原样仅存库留档），不存在 raw 可用，也禁止期望后端下发原样。注意：净化版**不含原站 class 与外链 CSS**，视觉上是"结构化正文（段落/表格）"，非源站原版排版——如需源站原版观感，正文区放"查看原文"按钮，经 `go?url=origUrl` 跳源站。
   - **表格（联调清单 R12①）**：净化白名单**保留 table/thead/tbody/tr/th/td**；正文含真 `<table>` 的公告（候选人/成交/标段等，演示库已重构重灌）下发即保结构，前端按公文表格样式渲染。表格行/列信息不再拍平粘连。
   - **正文结构化块（R12② 策略链，见 01 §7/§8）**：`detail` 的 `bodyBlocksStatus=SUCCESS` 且 `bodyBlocksJson` 非空时，前端**按块组件渲染**（块 schema 见下），不再渲染 contentHtmlSafe；`NONE`/`FAILED`/null 时回退 contentHtmlSafe。块来源=常规 HTML 解析（HTML_STRUCTURE，保留原表格）或 AI 兜底排版（AI_FALLBACK，把拍平粘连的脏正文恢复成表格/段落）。
   - PDF 形态：用 pdfDownloadUrl 做 `<iframe src>`/`<object>`/新窗口预览（fileId 下载走平台 FileApi）。
   - 抽取正文文本（extractionText）未在 VO 暴露——若详情页要"文字版/全文翻译摘要"再向后端提需求。
2. **附件**：只看 `virusStatus=CLEAN`（或后端已过滤）；`INFECTED` 显示"文件含病毒已拦截"，`PENDING` 显示"扫描中"。下载一律用 downloadUrl（FileApi 签名），不要直连 origDownloadUrl（仅溯源展示，如"查看外站原始附件"）。
3. **外链**：一律经 `GET /bidding/notice-external/go?url=origUrl` 跳转（白名单 host 校验 + 防开放重定向），前端不要直接 window.open 外站。
4. **大厅只读口径**：列表仅 status=ACTIVE + public_scope=SOCIAL；前端展示页不传任何"状态"筛选，页面就是"已审核通过的公开公告"。
*5. **时间格式（实测确认）**：`publishTime / effectiveFrom / effectiveTo` 出参均为 **epoch 毫秒整数**（非 ISO 字符串），前端 `new Date(ms)` 后再格式化（如 dayjs）。分页筛选入参 `beginTime/endTime` 请传毫秒。
6. **noticeTypeRaw 已支持筛选**：`GET /page?noticeTypeRaw=招标公告`（精确匹配外站原文类型；权威码维度后续按 notice_type_code 提供）。

## 4. 正文结构化块 schema（detail.bodyBlocksJson）

`bodyBlocksJson` 为 JSON **数组**，元素（type 决定载荷）：

| type | 载荷字段 | 前端组件 |
|---|---|---|
| `heading` | level（1~6）、text | 标题（如 h2/h3，公文标题样式） |
| `paragraph` | text | 段落（保留换行友好） |
| `table` | caption?（可选）、headers?（列名数组，无表头时缺省）、rows（二维数组） | 公文表格（与 R12① 同款样式）；headers 缺省时首行即数据 |
| `list` | ordered（true/false）、items[] | 有序/无序列表 |

- 示例（候选公告）：`[{"type":"heading","level":2,"text":"一、中标候选人基本情况"},{"type":"table","headers":["排序","中标候选人名称","投标下浮率（%）"],"rows":[["第1名","陕西化建工程有限责任公司","1.80"]]},{"type":"paragraph","text":"…联系方式…"}]`
- 约束：文本均为**纯文本**（无内联标签/无 href，外链跳转仍用公告级 origUrl）；块内容来自净化 DOM 或 AI 兜底排版输出，同样不含脚本/事件属性。
- 回退：`bodyBlocksStatus=NONE/FAILED` 或数组为空 → 按 §3 contentHtmlSafe 渲染。

## 5. 关注域概念（页面提示语用）

- 维度 targetType：ANNOUNCEMENT（公告）/ PROJECT（项目）/ TENDER_PROJECT（招标项目）/ SECTION（标段）。
- 进展阶段 stage：PENDING 前期 / TENDER 招标 / OPEN_BID 开标 / EVAL 评标 / RESULT 中标结果 / CONTRACT 签约 / DONE 完成 / UNKNOWN。
- 事件类型（关注时间线）：NOTICE_PUBLISHED / NOTICE_UPDATED（内部公告发布/更新）、EXTERNAL_ACTIVE（外部公告审核生效——即本模块的"新到外部公告提醒"）、STAGE_CHANGE（阶段流转）。
- 未读数 unreadCount → 列表角标；`POST .../read` 已读后清零。
