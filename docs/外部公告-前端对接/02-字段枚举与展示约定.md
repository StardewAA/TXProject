# 外部公告：字段、枚举与展示约定

> 字段真名以 `sql/2026-09-03-external-notice.sql` 与 VO @Schema 注释为准；这里列前端会碰到的。

## 1. 主档关键字段（bidding_notice_external → 展示 VO）

| 概念 | 字段 | 取值/说明 |
|---|---|---|
| 标题 | title | 外站标题（≤512） |
| 来源 | sourceCode / sourceName | 采集源 code / 名称（如"示例交易平台"） |
| 原网址 | origUrl | **必须展示**；点击走 `/go` 中转 |
| 内容形态 | contentType | HTML/PDF/ATTACHMENT/IMAGE/OTHER |
| 类型原文 | noticeTypeRaw | 外站自述类型（展示原文即可） |
| 依法必招 | legalFlag | Y/N（NULL=未知） |
| 行业判定 | industryFlag | BELONGS（防腐保温相关）/ NOT_BELONGS / UNCERTAIN。**来源**：采集回传可先填；管理端执行 AI 抽取（`POST /notice-external/ai-extract`）后由 **AI 判定回写**（含 industryConfidence 置信度）。列表可 `page?industryFlag=BELONGS` 筛"防腐保温相关公告" |
| 发布单位 | issuerName | 快照 |
| 时间 | publishTime / effectiveFrom / effectiveTo | 发布时间/生效起/生效止 |
| 展示状态 | status | 大厅只会返回 ACTIVE |

## 2. 状态与审核（大厅列表不需要，管理端/筛选用）

- 展示状态 status：`NEW` 待审核 → `ACTIVE` 生效中（可展示）→ `INACTIVE` 已失效（超期/源站下线）／`ARCHIVED` 已归档（只读留痕）。管理端操作为 approve（NEW→ACTIVE）/ reject（驳回不展示）/ take-down（ACTIVE→INACTIVE）。
- 审核痕迹 audit_status：UNREVIEWED / APPROVED / REJECTED / TAKEN_DOWN。
- 抽取状态 extractionStatus（PDF 形态）：NONE 未抽取 / SUCCESS 成功（文本+表格已落库）/ FAIL_EMPTY 空结果（扫描件）/ FAIL 失败。

## 3. 展示（渲染）硬性约定

1. **正文**：
   - HTML 形态：渲染 **contentHtmlSafe**（后端 jsoup 白名单净化，已去 `<script>`/`on*` 事件属性/`iframe`/`style` 等）；`contentHtml` 公开出参**恒为 null**（原样仅存库留档），不存在 raw 可用，也禁止期望后端下发原样。注意：净化版**不含原站 class 与外链 CSS**，视觉上是"结构化正文（段落/表格）"，非源站原版排版——如需源站原版观感，正文区放"查看原文"按钮，经 `go?url=origUrl` 跳源站。
   - **表格（联调清单 R12①）**：净化白名单**保留 table/thead/tbody/tr/th/td**；正文含真 `<table>` 的公告（候选人/成交/标段等，演示库已重构重灌）下发即保结构，前端按公文表格样式渲染。表格行/列信息不再拍平粘连。
   - **正文结构化块（R12② 策略链，见 01 §7/§8）**：`detail` 的 `bodyBlocksStatus=SUCCESS` 且 `bodyBlocksJson` 非空时，前端**按块组件渲染**（块 schema 见下），不再渲染 contentHtmlSafe；`NONE`/`FAILED`/null 时回退 contentHtmlSafe。块来源=常规 HTML 解析（HTML_STRUCTURE，保留原表格）或 AI 兜底排版（AI_FALLBACK，把拍平粘连的脏正文恢复成表格/段落）。
   - PDF 形态：用 pdfDownloadUrl 做 `<iframe src>`/`<object>`/新窗口预览（fileId 下载走平台 FileApi）。
   - 抽取正文文本（extractionText）未在 VO 暴露——若详情页要"文字版/全文翻译摘要"再向后端提需求。
2. **附件**：只看 `virusStatus=CLEAN`（或后端已过滤）；`INFECTED` 显示"文件含病毒已拦截"，`PENDING` 显示"扫描中"。下载一律用 downloadUrl（FileApi 签名），不要直连 origDownloadUrl（仅溯源展示，如"查看外站原始附件"）。
3. **外链**：一律经 `GET /bidding/notice-external/go?url=origUrl` 跳转（白名单 host 校验 + 防开放重定向），前端不要直接 window.open 外站。
4. **大厅只读口径**：列表仅 status=ACTIVE + public_scope=SOCIAL；前端展示页不传任何"状态"筛选，页面就是"已审核通过的公开公告"。
*5. **时间格式（N4 勘误确认）**：出参 `publishTime / effectiveFrom / effectiveTo` 均为 **epoch 毫秒整数**（前端 `new Date(ms)` 后格式化）。**筛选入参** `beginTime/endTime`（公开 page 与 manage/page）传 **`yyyy-MM-dd HH:mm:ss` 字符串**（实测毫秒数字直接 400；仅传日期会自动补起止时刻），勿再传毫秒。
6. **noticeTypeRaw 已支持筛选**：`GET /page?noticeTypeRaw=招标公告`（精确匹配外站原文类型；权威码维度后续按 notice_type_code 提供）。

## 4. 正文结构化块 schema（detail.bodyBlocksJson）

`bodyBlocksJson` 为 JSON **数组**，元素（type 决定载荷）：

| type | 载荷字段 | 前端组件 |
|---|---|---|
| `heading` | level（1~6）、text | 标题（如 h2/h3，公文标题样式） |
| `paragraph` | text | 段落（保留换行友好） |
| `table` | caption?（可选）、headers?（列名数组，无表头时缺省）、rows（二维数组） | 公文表格（与 R12① 同款样式）；headers 缺省时首行即数据 |
| `list` | ordered（true/false）、items[] | 有序/无序列表 |

- 示例（候选公告）：`[{"type":"heading","level":2,"text":"一、中标候选人基本情况"},{"type":"table","headers":["排序","中标候选人名称","投标下浮率（%）"],"rows":[["第1名","陕西化建工程有限责任公司","1.80"]]},{"type":"paragraph","text":"…联系方式…"}]`
- 约束：文本均为**纯文本**（无内联标签/无 href，外链跳转仍用公告级 origUrl）；块内容来自净化 DOM 或 AI 兜底排版输出，同样不含脚本/事件属性。
- 回退：`bodyBlocksStatus=NONE/FAILED` 或数组为空 → 按 §3 contentHtmlSafe 渲染。

## 5. 关注域概念（页面提示语用）

- 维度 targetType：ANNOUNCEMENT（公告）/ PROJECT（项目）/ TENDER_PROJECT（招标项目）/ SECTION（标段）。
- 进展阶段 stage：PENDING 前期 / TENDER 招标 / OPEN_BID 开标 / EVAL 评标 / RESULT 中标结果 / CONTRACT 签约 / DONE 完成 / UNKNOWN。
- 事件类型（关注时间线）：NOTICE_PUBLISHED / NOTICE_UPDATED（内部公告发布/更新）、EXTERNAL_ACTIVE（外部公告审核生效——即本模块的"新到外部公告提醒"）、STAGE_CHANGE（阶段流转）。
- 未读数 unreadCount → 列表角标；`POST .../read` 已读后清零。

## 6. 关键词/全文检索现状

- 本模块公开列表已提供 keyword 全文检索入参（走 ES 索引 bidding-notice-external，匹配标题/项目名/编号/正文，命中集上限 200；不开放业务表 LIKE——红线）。需后端 bidding.es.enabled=true；未启用时传 keyword 报错 1-060-106-015，前端可隐藏搜索框或提示"检索暂不可用"。
## 7. 主体域枚举与展示约定（Task2 新增）

### 7.1 主体类型 subjectType（SubjectTypeEnum）
| code | 中文 | 说明 |
|---|---|---|
| BIDDER | 投标人 | 响应招标、参加投标竞争的法人或其他组织（招标投标法 第25条） |
| TENDERER | 招标人 | 依法提出招标项目、进行招标的法人或其他组织（招标投标法 第8条） |
| AGENCY | 招标代理机构 | 预留未启用（招标投标法 第13~15条）；授权/建档均不接受 |

### 7.2 授权状态 authStatus（SubjectAuthStatusEnum）
| code | 中文 | 说明 |
|---|---|---|
| ENABLED | 已授权 | 可进入后续流程（投标人完善后可投标；招标人完善后可发布） |
| DISABLED | 已停用 | 平台撤销授权留痕；停用即失去投标/发布资格，档案保留 |

### 7.3 档案完善度（SubjectCompleteness 必填清单，投标/发布资格的数据侧）
| 字段 code | 中文名 | 规范字段 |
|---|---|---|
| subjectName | 单位名称 | 表89 LEGAL_NAME |
| uscc | 统一社会信用代码 | 表89 LEGAL_CODE（GB 32100-2015 强校验） |
| legalPersonName | 法定代表人姓名 | 表89 LEGAL_REPRESENT |
| legalPersonTypeCode | 法人机构类别 | 表89 LEGAL_TYPE |
| regionCode | 行政区划 | 表89 REGION_CODE（GB/T 2260） |
| contactName | 联系人 | 表89 LEGAL_CONTACT |
| contactPhone | 联系电话 | 表89 LEGAL_CONTACT_PHONE |

### 7.4 资格状态（SubjectEligibilityRespVO）
| 字段 | 说明 |
|---|---|
| authorized / authStatus | 是否已授权且启用；ENABLED / DISABLED / NOT_AUTHORIZED |
| profileComplete | 档案必填清单是否全齐 |
| eligible | 是否具备资格 = authorized ∧ profileComplete |
| reasonCodes | NOT_AUTHORIZED / AUTH_DISABLED / PROFILE_MISSING / PROFILE_INCOMPLETE（可多值） |
| missingRequiredNames | 缺失必填中文名（未完善时有值） |
| tenantName / authorizeTime / disableTime | 授权快照与时间（企业侧展示“平台已授权、授权时间”） |

### 7.5 主体域错误码（ErrorCodeConstants 106_030~040）
030 类型不支持 / 031 未授权或已停用 / 032 重复授权 / 033 授权不存在 / 034 信息未完善 /
035 USCC 校验失败（GB 32100-2015）/ 036 经办用户非本企业租户（system 侧扩展位）/ 037 重复绑定 /
038 绑定不存在 / 039 载荷格式非法 / 040 经办用户不存在或禁用。
> 前端投标/发布失败时优先引导到 6.1.3（企业资格）+ 6.1.1（缺失项）。

## 8. 跟踪键、可达性与初始动态（BR-1/BR-4/BR-6 落地约定）

- **跟踪键组（外部公告 page/detail 行）**：projectKey/projectName、tenderProjectKey/tenderProjectName（一期 null）、bidSectionKeys[]（bidSectionCodes 拆 ,;）、bidSectionNames[]（一期 null）；键 null/空=未解析到，前端不展示“跟踪该招标项目/标段”按钮。
- **关注行/事件可达性**：noticeStatus（公告展示状态；维度行/无关联公告=null）；available=true 仅 EXTERNAL ACTIVE 或 INTERNAL PUBLISHED；false=公告已下线/归档（隐藏平台详情跳转，EXTERNAL 事件可用 origUrl 走 /go 看源站原文）；null=无公告级状态。
- **关注已生效公告的初始反馈**：follow ACTIVE 外部公告 → 后端种一条已读 EXTERNAL_ACTIVE 初始动态（titleSnapshot=关注时标题），行 latestDynamicTime 被刷新（列表置顶、timeline 非空），未读角标不变；行 followTime 始终可显示“关注于 xx”。
- **事件源跳转**：EXTERNAL → origUrl 经 go 端点；INTERNAL → /bidding/notice/public/detail?id=noticeId（公开详情已存在）。

## 附：编写说明（本文档尾部固定段）

### 编写原因
前端需要统一的字段真名、枚举取值与展示约定；Task2 新增主体域后，把主体类型/授权状态/完善度清单/资格状态/错误码纳入同一约定文档，避免前端各自臆测取值。

### 编写依据
- 代码事实源：enums/SubjectTypeEnum、SubjectAuthStatusEnum、ErrorCodeConstants（106_030~040）、SubjectCompleteness、subject 域 VO；
- 法规/规范：招标投标法 第8/25/26条、电子招标投标办法 第24条、GB 32100-2015、国家/陕西 V2.0 数据规范 表89。

### 所满足的业务需求内容及其实现方式
- 「完善投标人、招标人的信息」→ 7.3 必填清单驱动完善度核算与资格判定；
- 「被授权投标人仍须完善信息」→ 7.2/7.4 授权状态与完善度分离展示（列表行 profileComplete、资格接口双条件）；
- 「信息不完整无法获得投标资格」→ 7.4 eligible=false + reasonCodes + missingRequiredNames 直接可提示。
