# 外部公告（notice-external）前端对接说明与文件索引

> 用途：给「外部公告采集与展示」模块的前端开发（大厅公开展示页 + 管理端审核/关注页）一份"先看哪些文件、以谁为准"的索引。后端代码以本仓库 `notice` 分支为准，字段/接口联调以 OpenAPI（knife4j `/v3/api-docs`）为事实源，本目录只是把参考物汇总。
> 与 docs/notice前端开发指南.md 的关系：那份是**内部公告（notice）**域指南（另一套接口）；**本目录只管外部公告（notice-external）域**，两域页面不同、接口不同、别混用。

## 3. 联调入口

- 运行中服务：本机 `http://127.0.0.1:48110/admin-api/...`（服务本地启动联调用；容器环境走网关统一前缀 `/admin-api`）
- OpenAPI 契约：`GET /v3/api-docs`（knife4j 页面一般 `http://<host>:<port>/doc.html`）
- 公开大厅三个端点（page/detail/go）**无登录**（@PermitAll）；管理端与关注端点需要登录态与权限码（见 01）。
- 公开端点无租户概念（G 轨全局数据）；管理端按当前租户隔离（T 轨关注等表带 tenant_id）。

## 4. 术语速记

- **G 轨**：外部公告主档 `bidding_notice_external`（TenantBaseDO 之外，无租户列，社会公开全局可见）——前端展示读取的就是它。
- **三形态 contentType**：HTML（原文+净化双字段）/ PDF（原文件 JS 预览）/ ATTACHMENT（附件下载）；详情接口统一返回，前端按形态分支渲染。
- 外部公告 ≠ 内部公告：外部 = 从外站采集（示例交易平台/招标平台）；内部 = 本单位发布的 notice 域（见另一份指南）。

## 5. 本地冒烟数据

联调需要数据时可参照：库 `ruoyi-vue-pro` 表 `bidding_notice_external`（ACTIVE + public_scope=SOCIAL 才会出现在公开列表）；来源站 `bidding_crawl_source`（enabled=1 的 base_url 决定 detail 原网址点击 /go 中转是否放行）。
