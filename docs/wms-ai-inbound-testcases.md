### B. 文件识别（`/wms/ai/recognize-file`）

准备这些格式各测一次（内容都是入库清单）：

**B1 — CSV / Excel（标准清单）**

```csv
物料名称,规格,数量,单位,仓库,供应商
玄武岩矿料,20kg/袋,10,袋,上海仓,上海星河商贸有限公司
```

预期：识别到 1 行明细，仓库=上海仓，可进入确认预览。

**B2 — 多行清单**

```csv
物料名称,规格,数量,仓库
玄武岩矿料,20kg/袋,5,上海仓
玄武岩矿料,20kg/袋,5,北京仓
```

预期：识别到 **2 行**，分别对应两个仓库。

**B3 — TXT（非结构化）**

```
今天收到上海星河商贸送来的玄武岩矿料，规格20kg/袋，一共10袋，入上海仓。
```
预期：能解析出物料/SKU/数量/仓库/供应商。

**B4 — PDF 入库单**
上传一张扫描版或文字版入库单 PDF。
预期：能提取文字并识别为入库单；若为纯图片扫描件应提示"无法识别文字"而非编造。

**B5 — 空文件 / 无关文件**
上传一个空 CSV 或一张风景照。
预期：明确提示无有效入库信息，**不编造**任何明细。

## 五、已知限制（测试时请知悉）

### 1. 知识库检索重启后失效

向量库是 `SimpleVectorStore`（**内存**）。重启 `txgy-ai` 后检索返回 0 条，需重建索引：

```bash
curl -X PUT "http://localhost:48080/admin-api/ai/knowledge/segment/reindex?knowledgeId=7" \
  -H "Authorization: Bearer <token>" -H "tenant-id: 1"
```

### 2. 检索精度一般

当前用**本地哈希向量**（词面匹配，非语义）。表现为：
- 「北京仓」「玄武岩矿料」→ 命中准确
- 「危险品」→ 可能命中无关文档

原因：方舟的文本 embedding 模型在本 Key 下始终 404。换真实 embedding 后精度会明显提升。

### 3. 模拟单无法提交审批

「入库管理 → 模拟申请」生成的模拟单**不填验收数量**，而提交审批强制校验：

```
验收数量须非负、最多两位小数，实际数 = 合格数 + 不合格数，且不得超过申请数
```

→ **模拟单只能验证「生成草稿」，不能走审批**。走审批请用真实录入的单据。

## 六、快速命令行回归（可选）

```powershell
# 登录取 token
$body = '{"username":"admin","password":"admin123"}'
$r = Invoke-RestMethod 'http://localhost:48080/admin-api/system/auth/login' -Method Post `
  -Headers @{'tenant-id'='1'} -Body ([System.Text.Encoding]::UTF8.GetBytes($body)) `
  -ContentType 'application/json; charset=utf-8'
$h = @{ Authorization = "Bearer $($r.data.accessToken)"; 'tenant-id' = '1' }

# 用例 A1
$p = @{ text = '采购入库 玄武岩矿料 5 吨 到上海仓' } | ConvertTo-Json -Compress
$res = Invoke-RestMethod 'http://localhost:48080/admin-api/wms/ai/recognize' -Method Post `
  -Headers $h -Body ([System.Text.Encoding]::UTF8.GetBytes($p)) `
  -ContentType 'application/json; charset=utf-8' -TimeoutSec 240
$res.data | Select-Object action, actionName, ready, buildable
$res.data.warehouse, $res.data.items
```
