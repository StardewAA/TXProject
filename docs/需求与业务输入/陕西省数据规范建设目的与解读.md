# 陕西省公共资源交易电子监管系统数据规范（V2.0）建设目的与解读

> 面向对象：项目开发者、数据治理与集成人员。
> 依据文件：《陕西省公共资源交易电子监管系统数据规范（V2.0）》（2024-05-28）、《陕西省公共资源交易电子监管系统数据规范变更记录》（2024-05-28）。
> 说明：本文只从规范原文与其变更清单中梳理"为什么建"，不复述条款细节；字段级合并定义另见项目根目录《VO数据对象规范（国家V2.0+陕西省V2.0合并版）.md》。

## 一、文件基本定位

陕西省这次发布的是一份**"电子监管系统"层的数据规范**，与国家 V2.0（面向公共资源交易平台系统间数据交换共享）在同一坐标系里，但视角不同：国家规范是**平台间**（交易/公共服务/行政监督三平台）的数据通用底座，陕西规范是**监管侧**要求交易系统在与其省级电子监管系统对接时必须遵循的数据接口与保障条款。

规范正文在开篇就把定位说清楚：

- **范围**：为规范陕西省公共资源交易电子监管系统的建设，开放对接第三方依法建设的电子交易系统，促进信息资源开放共享，提高公共资源配置效率和效益，制定本规范。
- **前言**：依据相关法律法规规章及规范性文件，规定了电子监管系统的架构、基本功能、信息资源和技术保障的要求，促进各类信息资源的互联互通，提高交易服务的便捷性、安全性、规范性和统一性。
- **数据项要求（附录A）**：遵循《公共资源交易平台系统数据规范（V2.0）》，并在此基础上根据业务需要进行了调整完善，适用于**工程建设项目招标投标、政府采购、土地使用权、矿业权出让和国有产权交易**五大类电子交易系统与电子监管系统的数据交换。

一句话：**国家 V2.0 定"能对接"，陕西 V2.0 定"能进入陕西监管"。**

## 二、建设背景（上位政策依据）

规范第 2 章"规范性引用文件"列出 30+ 项上位依据，可归为四层：

| 层次 | 代表文件 | 对陕西规范的诉求 |
| --- | --- | --- |
| 顶层整合部署 | 国办发〔2015〕63 号《整合建立统一的公共资源交易平台工作方案》、国办函〔2019〕41 号《深化公共资源交易平台整合共享的指导意见》 | 平台整合、目录管理、互联互通 |
| 营商环境与放管服 | 国办发〔2020〕24 号、发改法规规〔2022〕1117 号 | 降低制度性交易成本、规范主体行为 |
| 电子招标投标法定框架 | 发改委 20 号令、39 号令、10 号令及其配套 | 三平台分工、数据电文效力、公告公示规则 |
| 数据与行业标准 | 发改办法规〔2018〕1156 号（国家 V2.0）、316 号专家分类标准、550 号林权数据规范、752 号基层政务公开指引 | 数据格式、编码、公开范围、专业分类 |

陕西这份规范是上述四层在**省级监管落地**环节的收口文件——把国家平台的通用数据底座，落到陕西省监管系统"能收、能查、能预警、能追责"的具体字段与接口上。

## 三、核心目的（五层递进）

### 目的1：为省级监管系统提供统一、可校验的数据入口

规范第 4 章明确"电子交易系统应与电子监管系统按规定交换信息"，并对接口逐环节做了硬性要求：项目/招标项目/标段环节必须回传**统一交易标识码**；标段环节必须回传**保证金账户信息**；场地申请环节必须回传**开评标场地信息**；公告公示环节必须回传**发布状态**。这些正是"数据归集"的最小闭环，监管系统只有拿到这些字段，才能形成"项目—标段—交易—监管"三码贯通的可追溯链。

### 目的2：让陕西在国家标准之上"管得住"（监管视角的字段补齐）

对照国家 V2.0，陕西规范的调整清单集中体现了"监管刚需"：

- **围串标防控**：开标明细新增文件创建标识码、投标文件制作机器码、解密IP、是否解密、投标人 IP/mac；招标清单新增计价软件锁号（DogNum）。这些字段直接支撑"同机做标、同锁出量、解密异常"三类预警规则的机器识别。
- **责任可追溯**：中标候选人独立为数据模块，增加项目负责人姓名/证件号/证书及编号、水利监督申报责任人；推荐单位一到三的项目负责人字段全部展开，避免"只公示公司名、不知是谁负责"的追责真空。
- **流程透明**：资审文件澄清次数、评标是否回退及回退原因、专家补抽次数与是否补抽——把过去藏在系统内部的过程性动作显性化。
- **交易便利度**：是否不见面开标、开评标场地预约与取消、场地使用类型——为监管掌握"该项目/标段是否现场开标、场地冲突"提供数据支撑。

### 目的3：让省内多业态交易"能归到一张表上"

附录A 覆盖工程招标投标、政府采购、土地、矿业权、国有产权五大领域（不含股权类，另按国家标准执行），并在各领域内做了贴合本地业务的模块化拆分：

- 土地：地块信息 → 交易公告 → 电子竞价 → 成交公示 → 流拍流挂/中止/终止/恢复公告
- 矿权：新增矿区 → 交易公告 → 变更公告 → 挂牌底价 → 报名查看 → 竞得候选人通知书 → 流拍/中止/恢复/终止 → 成交公示 → 电子竞价（13 段生命周期）
- 产权：转让受理 → 普通交易 → 电子竞价 → 交易结束 → 特殊情况

这种"生命周期式"的模块划分，是国家 V2.0 按数据集罗列所不具备的——目的正是让不同交易品种**在同一份规范下能各自闭环**，又能汇聚到统一的字段字典。

### 目的4：完成代码体系与国家的对齐、并预留本地扩展

从"变更记录"更新部分可清晰看到一次**码值系统性对齐**：

| 代码集 | V1.0（陕西旧版） | V2.0（本次） | 动机 |
| --- | --- | --- | --- |
| 1.10.12 资格审查方式 | 0 资格预审 / 1 资格后审 | 1 资格预审 / 2 资格后审 | 去 0 起，与国家/行业代码体系一致 |
| 1.10.13 专家类别 | 0 在库专家 / 1 招标人代表 | 1 在库专家 / 2 招标人代表 | 同上 |
| 1.10.24 资审结果 | 0 通过 / 1 不通过 | 1 通过 / 2 不通过 | 同上 |
| 1.10.25 异常标段类型 | 0/1/2/3 | 0/2/3/5 | 与国家表27 招标异常口径对齐并预留 |
| 1.10.26 异议类别 | 0~4 | 1~5 | 与 20 号令、国家表43 一致 |

同时陕西本地扩展：1.10.20 标段（包）分类二级/三级代码表（在《公共资源交易评标专家专业分类标准》基础上按房建市政/交通组别/交通标段/水利细分）、1.10.30 投诉处理措施（1 项目暂停 / 2 项目终止 / 3 项目流标 / 9 其他）、4.13.3 竞价交易方式新增 250 协议出让/260 申请在先/999 其他、5.6.10 内部决策新增 6 行政会议决议——**给地方特色留口子，但把主键码值向国家靠拢**。

### 目的5：把接口与保障"写死"，避免各建各的

规范第 4、5 章不只讲数据，还讲**接口与运维**：

- **接口方式**：XML 数据交换 + WEB SERVICES；支持同步/异步；数据接口模型由数据结构+数据集+附件集组成。
- **安全**：CA 数字证书覆盖递交投标文件、撤回投标、确认开标记录、发中标通知书、签订合同等**承担法律责任的行为**；等保三级；安全审计系统宜独立部署。
- **性能**：单点响应 <3 秒、支持 5000 同时在线、1000 并发响应 <3 秒。
- **可靠性**：年可用率 ≥99%，平均年故障时间 <1 天，恢复 <30 分钟。
- **技术中立与可溯源**：接口技术保持中立；信息交换应能自动标记输入输出**来源出处**（对应字段级"来源交易系统 FROM_TRADE_PLAT_CODE"）。

这份文件因此不只是数据规范，也兼具**接口规范与运行保障规范**——目的在防止各地市/各交易平台以不同技术路线建出"接不上、看不清、追不回"的孤岛系统。

## 四、V2.0 相对 V1.0 的三块"减法"与三块"加法"

### 减法（把不必要的对外口径剥离）

- 删 1.6.2/1.6.3 的"公示发布时间、公示源URL"：这些是**省公共服务平台对国家的报送字段**，不该回流到监管接口。
- 删 1.4.4 开标工作人员信息模块、1.5.10 合理性检查结果模块、5.4.2/5.4.3/5.4.6 产权价款划转与结算模块：或职责转移，或与省级监管无关，取消后接口更聚焦。
- 删 5.1.1 是否国有资产、企业类型：与主体信息数据集重复。

### 加法（把省级监管真正需要的字段补上）

- 主体：项目主体信息扩展补 LEGAL_CODE；招标代理唯一标识必填化。
- 过程：澄清次数、资审申请时间、评委打分汇总标段编号、评标基准价、清单锁号。
- 风控：围串标防控 4 字段；不见面开标；是否补抽与补抽次数；评标是否回退及原因。
- 服务：场地预约与取消、竞买人信息、投诉撤销。
- 时限：保证金递交截止时间；变更/中止公告原/新时间字段对。

一句话总结：**删的都是"给国家的报送项"，加的都是"给监管看的动作痕迹"。**

## 五、与本项目（招投标 19 模块）的关系

本项目按《电子招标投标办法》三条线建设企业后台、监管、公共服务大厅三个系统。对陕西规范的落地重点在**监管线**与**企业后台向监管推数**的接口层：

- **监管-06 数据归集与预警**是本次陕西规范全部 41 个 VO 的落地入口；围串标、评标回退、清标锁号等新增字段直接构成预警规则的数据源。
- **后台-05 开标、后台-06 评标、后台-07 中标与合同、监管-02 投诉与异议处理**四个模块承载了大部分陕V2.0新增字段的采集侧改造。
- 其余政采/土地/矿权/产权四大领域的 VO 属于**监管归集落地**范畴，企业后台暂不建对应业务模块。

详细字段与来源标注见《VO数据对象规范（国家V2.0+陕西省V2.0合并版）.md》；代码集差异与落地条款见《表设计2新要求（完善版）.md》第五部分与第八章。

## 六、一句话答复"为什么建"

陕西省这套规范是**给省级电子监管系统建的一份"能不能进、进了能不能查、查了能不能追责"的入场与留痕标准**：以国家 V2.0 为数据底座保证互联互通，以生命周期化的模块拆分覆盖五大交易品种，以围串标/责任/过程三类字段补齐实现监管视角，以码值对齐+地方扩展保证与国家体系兼容，最后用接口、安全、性能、运维条款把技术路线钉死，避免各平台以不同实现把"统一"变成口号。
