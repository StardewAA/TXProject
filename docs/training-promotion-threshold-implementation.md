# 云培训学院晋级门槛实现说明

## 数据来源

本模块以《云培训学院-晋级门槛表.xlsx》为基准，固化 5 条晋级路径、40 项硬性门槛：

1. 学徒技师 → 初级工
2. 初级工 → 中级工
3. 中级工 → 高级工
4. 高级工 → 技师
5. 技师 → 高级技师

默认门槛写入 `training_promotion_rule`，`tenant_id=0` 表示平台模板。企业调整门槛时会创建本租户覆盖记录，不会修改其他企业或平台默认值。

## 子模块关联

| 来源 | 指标示例 | 接入方式 |
| --- | --- | --- |
| 课程与成长地图 | 必修完成率、阶段地图完成率 | 从 `training_student_task`、`training_course` 自动计算 |
| 考试与认证 | 分阶段考试成绩、答辩结果 | 调用 `POST /training/analytics/promotion/metric/report` 回传 |
| VR 实操 | 实操通过次数、复杂实操 | 同上 |
| HRM/工时 | 累计工时、本级任职月数 | 任职月数自动计算，工时由 HRM 回传 |
| 质量与安全 | 返工、安全违规、改善提案 | 对应业务模块回传 |
| 项目与技能 | 项目角色、多工种能力 | 对应业务模块回传 |
| 直播与讲师 | 带教学徒及晋级人数 | 讲师体系回传 |
| 知识与专家评审 | 成果输出、评审结论 | 对应业务模块回传 |

指标回传请求示例：

```json
{
  "userId": 1024,
  "ruleKey": "exam_score_entry",
  "metricValue": 86,
  "sourceModule": "EXAM",
  "evidence": "试卷记录 EXAM-20260908-001"
}
```

相同用户、相同 `ruleKey` 会更新为最新值，同时保留来源、凭证和指标时间。没有数据的指标显示“待从某模块同步”，不会把缺失数据当作 0，也不会错误通过“违规次数=0”一类门槛。

## 评估规则

- 支持 `>=`、`<=`、`=` 三种比较符。
- 所有硬性规则都通过时才判定具备晋级资格。
- 进度是当前路径中各规则进度的平均值。
- `POST /evaluate` 会保存一次带完整明细 JSON 的评估快照，用于审计追踪。
- 学员可在“个人学习档案 → 人才成长进度”查看本人差距；管理员在“晋级门槛管理”维护人员档案、同步指标、调整企业门槛和执行评估。

## 部署

执行 `sql/training_promotion_threshold.sql` 建表并导入门槛，再执行 `sql/training_analytics_menu.sql` 增加菜单与权限。本地 Docker 的 `deploy/local/init-db.ps1` 已自动执行这两个幂等脚本。
