## 已核对的前置问题

1. 会员表实际唯一约束为 `(mobile, tenant_id)`，不同租户可保存同手机号；软删除会员仍占用组合唯一值，后续注册需明确兼容和并发冲突处理。
2. 现有短信验证码 DO 标记忽略租户，消费按手机号、场景、验证码查找。仅传 `tenant-id` 或包一层 challengeId 不能提供真正租户隔离；本批不开放跨租户短信注册。
3. 旧会员刷新直接调用通用 OAuth 刷新接口；后者能按 refreshToken 找到原租户，但未在修改令牌前核对请求租户。本批在商城会员层复用现有令牌核验接口，先校验身份与租户，再调用刷新，不修改通用 OAuth 协议。
4. PC/H5 请求、刷新、上传、工作台和部分缓存使用固定租户或全局状态，旧异步结果可能污染新账号。本批增加统一上下文和过期结果保护，仍不开放跨租户交易。
5. H5 目录成功返回空商品时仍回填本地旧商品资料，URL 租户可直接改变本地值；本批纠正真实空态及未获准深链的处理，不用租户 1 的商品填充其他商城。

## 第一批接口契约

### `GET /app-api/member/mall-tenant/config`

匿名入口，不携带会员令牌；只返回专用商城配置，不返回系统全部租户列表或租户联系人、域名、管理员、密钥等资料。

```typescript
interface MallTenantConfig {
  enabled: boolean;
  legacyTenantId: number;
  publicTenantId: number | null;
  tenants: { tenantId: number; name: string; registrationEnabled: boolean }[];
  capabilities: { browseSwitch: boolean; registrationSelection: boolean };
}
```

- `mall.tenant.enabled` 默认 false；禁用时返回旧入口租户、空目录、空公共租户和两个 false 能力，不读取系统租户全列表。
- 配置采用 `mall.tenant.public-tenant-id` 与显式 entries 白名单；公共租户不能猜为 1 或复用历史 3000。目录开启后必须验证配置及租户状态、有效期；缺配置失败，不回落到 1 冒充新公共租户。
- legacyTenantId 延续旧 `mall.registration.platform-tenant-id` 配置的兼容含义，不代表将该租户定义为新公共租户。
- 本批 `browseSwitch`、`registrationSelection` 和返回目录条目的 `registrationEnabled` 始终为 false；即使配置中预置允许注册，也不在本批提前开放能力。
- 新目录没有“列全部租户”的兜底；RPC 故障不伪装为允许切换；未部署新接口的兼容不等于可开启新模式。

### `GET /app-api/member/mall-tenant/session`

仅已登录会员可调用，返回 `{tenantId, userId}`。身份与租户来自已认证会话；请求头与令牌租户冲突、后台身份误用或匿名请求应拒绝，不接受客户端自行指定 userId。

### 认证响应与刷新

原登录／注册／刷新响应新增 `tenantId`，从后端会员或已核验令牌取得，不由浏览器指定。原登录接口和手机号/密码协议保持兼容。

刷新前校验 refreshToken 对应 MEMBER 类型、请求租户与令牌租户一致，以及本租户会员存在且启用；通过后才调用原刷新接口。错误目标租户不能先注销旧 token 再报错。新返回 tenantId 必须沿用已核验账号，不接受当前浏览商城替代账号租户。

## 前端基础与隔离原则

- 为 PC/H5 明确区分旧入口、浏览租户、账号租户和会话代次；本批浏览固定旧入口，没有公开可操作的跨租户切换或注册选择 UI。
- 入口请求匿名；认证请求使用固定目标而不是残留旧会话；账号私有请求使用冻结的账号上下文。未来公开请求可匿名浏览，不能据此放行混合租户交易。
- 旧本地 token 先保留固定旧入口的兼容路径，再由服务端 session 校验；localStorage 中 tenant 数字不构成授权，不能直接升级为可信任意租户。
- 普通请求、刷新、询价独立下载、上传和工作台共用上下文来源。刷新按账号 token／租户／会话代次隔离，旧成功不覆盖新账号，旧失败不退出新账号；业务重放不得偷换成新账号。
- H5 未获准的其他租户深链应明确阻断，不静默用租户 1 展示相同商品 ID，也不为了该链接擅自清除现有账号。
- H5 目录缓存与加载结果带租户范围；成功空结果展示真实空态，失败展示失败，不回填旧商品充当服务端结果。
- 客服、完整页面范围分类、跨租户分享和购物车/结算流转仍需要后续契约与专项，不把基础上下文存在等同全部完成。
