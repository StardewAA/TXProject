# MES 环保模块质优化设计（最终版）

> 版本：最终版（送评审）｜ 2026-09-09
> 范围：mes 安全环保检测模块（34000）+ 既有污染判定/台账 → **危化品·污染物·危废全生命周期数字合规平台**
> 作者：赵梓垚／孟志杰（追溯链+一物一码+四关卡+签字）｜ 基线：v0.3 + 评审意见 + 天信管业对标
> 一句话质变目标：**从"点状判定+台账记录"的记录型模块，升级为"一条实物链贯穿、四条合规主线闭环、称重防篡改、证据可审计"的企业级环保数字合规平台。**

## 1. 质变主张：现在是什么，优化后是什么

| 维度 | 现状（记录型） | 优化后（合规型） | 靠什么质变 |
| --- | --- | --- | --- |
| 对象 | 以"污染判定单/台账行"为中心 | 以**实物码（批次码+容器码）**为中心，一物到底 | §3 对象模型重构 |
| 生命周期 | 4 环节判点 + 台账登记，判完即止 | 危化品→产废→转移→处置→排放 全链可追 | 追溯链 trace_chain |
| 门禁 | 仅领用/出库 2 处拦截，无强制 | 入库冻结→复核→定区 4 步；全程按 type×level 分级拦截 | §4/§6 |
| 记录方式 | 手填，可造假 | 衡器自动采集 + 双人签字 + 拍照证据 + AI 快照留痕 | §7 |
| 闭环 | 拦截无后续 | 每处拦截给后续处置/整改/升级审批，异常必闭环 | §6 |
| 合规锚 | 无 | 按证排污（许可限值/总量红线/执行报告）+ 国标联单五方 + HJ1276 标签 + 应急备案 | §9/§8 |
| 治理设施 | 无 | 活性炭/催化燃烧/布袋台账；换炭即产危废、停运申报 | §8.4 |
| 数据 | 各表孤岛 | 物料衡算闭环：投入≈产物+危废+排放+损耗 | §7.3 |

> 结论：这不是加几个功能点，是**把"环保台账"重构成"以实物码为主键的合规链"**——一次对象模型的质变。

## 3. 对象模型重构（质变的核心）

### 3.1 一个贯穿对象：实物码
- **批次码**（wm 批次）+ **容器码**（一桶一码，危废桶号即容器码，`mes_dg_container`）。
- 追溯链 `mes_set_trace_chain` 记录该实物的全部血缘节点（入→存→领→产→废→移→处置→排放）。

### 3.2 三轴正交属性
- **污染态**（CLEAN/POLLUTED，来自现行判定门禁）—— 管放行不放行。
- **风险类型**（CHEMICAL 危化品 / POLLUTED 污染物 / HAZ_WASTE 危废 / NORMAL）—— 定走哪条规则。
- **危险等级**（A–D + HW 名录码 + 危险特性）—— 定管控深度。
- type 不取代 pollution_status，三轴并存不互斥。

### 3.3 判废依据落真实物（天信）
危化品：异氰酸酯（黑料/MDI·TDI，剧毒·强放热·湿敏）、环氧粉末（静电粉尘易爆）、稀释剂（易燃）。
危废：废包装桶 HW49、废有机溶剂 HW06、漆渣 HW12、废活性炭 HW49、废机油 HW08。
产线：喷涂 VOCs = 活性炭吸附+催化燃烧（换炭→HW49）；抛丸/打磨 = 布袋除尘。

## 5. 主线 A：危化品全生命周期

### 5.1 入库四步冻结（修 v0.2 漏洞：一步到位无复核）
```
到货登记 → 待检区冻结(frozen, 借 MesQcPendingInspect) → AI/人工复核
   → NORMAL 解冻入合格区
   → CHEMICAL/POLLUTED 入隔离区/危化品专区（MSDS 硬挂载）
   → 不符退货
判定状态 PENDING→{CLEAN/POLLUTED/CANCELLED}；复核 CLEAN 只解冻本判定来源。
```

### 5.2 分级储存（落到异氰酸酯级）
| 物料 | 储存实况 | 系统管控 |
| --- | --- | --- |
| 异氰酸酯(黑料) | 专用库+N₂保护/防潮、远离水醇胺（放热剧反应） | 库位禁配(水/醇/胺)；温湿度超限报警；MSDS 必挂 |
| 环氧粉末 | 防静电/防火花/防爆 | 静电接地记录；禁火作业票联动 |
| 稀释剂 | 易燃液体专柜、限量 | 储量上限预警；双人领用 |

### 5.3 五双 + 效期
- 五双：双人收发/保管/双锁/领料/运输，双账号各签一次。
- FIFO + 过期自动冻结（启用 batch.expireDate/produceDate，定时任务扫→冻结→转危废/报废）。
- 领用/投料插桩（现状无单据可插，新建投料扫码）。

## 6. 主线 B：危废全生命周期

### 6.1 委外六步真实节点（对齐国家固废系统）
```
年度危废管理计划备案 → 产生申报 → 资质核验(供应商准入维护,到期预警)
 → 电子联单(产生/运输/接收确认) → 装车转移(逐桶称重·四方会签) → 处置回执归档5年
```
- 电子联单 = 国家固废系统统一运行 → 对齐**五方角色 + 申报时限**；`mes_dg_manifest` 存联单号+五方状态+时限，平台时限**倒排提醒**；**预留 API 对接，当前以格式合规导出/导入+填报确认落地**，接入国家 API 为可选期。

### 6.2 危废标签 HJ 1276-2022
- 系统按规范模板生成（危险特性图形/危废类别/产生单位/批次/重量/日期/**二维码=容器码**），打印贴桶，扫码即查全程；损坏换签留痕；贮存间标志牌入巡检。

### 6.3 治理设施与危废联动
- 台账 `mes_dg_facility`：活性炭吸附/催化燃烧/布袋除尘，关联排放口。
- **活性炭到期更换 → 换下即登记废活性炭 HW49 入桶**（耗材→危废自动转化，杜绝换炭不记危废）。
- 设施停运必须**申报+审批**；停运期在线超标走应急。

## 7. 主线 C：排污合规（按证排污）——把空表落地并串起来

### 7.1 先落地
permit/env/outlet/carbon 四表**已存在须先补代码成模块**（一期；用租户2010 两条许可演示；确认与既有演示数据/租户归属一致，勿覆盖）。

### 7.2 联动
```
排污许可证 permit(no/期限/annual_limits)
 └ 排放口 outlet(挂 no/限值/pollutant_codes/是否重点) 
    └ 在线监测 reading(实测) → 比对限值
        ├ 超限值 → 报警+整改单(异常闭环)
        ├ 超总量(annual累计) → 违法红线+应急(停排/减产)+上报留痕
        └ 排放量回填衡算
执行报告 env_report(周期自动汇总监测/台账,定期上报备案)
```
- 判定"排放/回用" = 是否进治理设施 → 关联 outlet → 是否需 permit 校验。

## 9. 横切机制（四条主线共用）

| 机制 | 要点 | 防什么 |
| --- | --- | --- |
| **称重防篡改** §7 | 电子秤/地磅/汽车衡自动采集 `weigh_record`(衡器号/自动读数/时间/人)；`source=AUTO\|MANUAL`，AUTO 不可改；禁纯手填唯一来源；双人称重 | 称重造假 |
| **电子证据链** | 每步拍照/附件 + 电子签名(sign) + AI 判据快照(ai_source) + 操作人/时间留痕 | 责任不清 |
| **异常闭环** | `dg_exception`：每拦截点给后续（退货/让步/整改/升级审批），结果必填 | 拦截即终点 |
| **物料衡算** | 投入≈产物+危废+排放+损耗，允差预警；危废可由源头工单反推投料批，否则报"无源" | 危废无源/漏记 |
| **AI 预判** | DeepSeek 真实调用预填，人工负责，快照留痕，无 key 可纯人工 | 无 AI 可用 |
| **预警/调度** | 定时任务（过期/资质到期/换炭/联单时限/超限）——**需新建调度底座** | 到期漏管 |
