## 二、关键决策：只覆盖数据，不覆盖表结构

`ERP_202609201615.sql` 与 `MES_202609201615.sql` 都是「整库导出」，其表结构比线上库旧：
线上库有 230 个列是导出文件里没有的（例如 `erp_purchase_order.wms_status`、`business_chain_no`、
`erp_sale_order.wms_shipment_order_no`、若干 `fms_*` / `hrm_*` 字段）。这些列由本仓库的迁移脚本
（`deploy/mysql/repair/`、`sql/*.sql`）补充，运行中的服务代码依赖它们。

因此**没有**直接 `DROP TABLE` + `CREATE TABLE` + `INSERT`，而是：

1. 把导出文件按模块过滤、修正乱码后，先整体导入影子库 `txgy_stage`，逐个文件校验无报错；
2. 线上库只做「数据覆盖」：`DELETE FROM 表; INSERT INTO 表(公共列) SELECT 公共列 FROM txgy_stage.表;`
   （列名按大小写不敏感匹配，例如导出里的 `order_item_Id` 会写入线上正确的 `order_item_id`）；
3. 导出文件里新出现、线上缺失的列，先补进线上表（7 张表 21 列，`crm_after_sale_warranty`、
   `mes_tm_tool*`、`wms_merchant` 等）；
4. 线上表独有的列在覆盖后取默认值（这些是后加的集成/流程字段，原值属于旧演示数据）。

校验：54 张改过注释的表共 1037 个列定义，与导入前备份逐字一致（仅注释文本变化）；
所有模块表的精确行数与来源文件 1:1 相同。

## 三、中文乱码修复

根因：来源文件里的中文不是文件编码问题，而是**双重编码**——
原始 UTF-8 字节被按 CP1252 解码成拉丁字符后，又存成 UTF-8。
例如 `主键`(E4 B8 BB E9 94 AE) 变成 `ä¸»é”®`（含 U+201D 这类 CP1252 特殊字符），
另有少量汉字被写成康熙部首（`⽤` vs `用`）。

处理：导入时对每一行做 CP1252 反向映射 -> UTF-8 重新解码 -> 康熙部首/兼容汉字 NFKC 归一，
并且只在「解出的结果确实是合法 UTF-8」时才替换，避免误伤合法拉丁文本。

结果（全库扫描确认）：

- 乱码数据：0 行（修复前有 `hrm_salary_group`、`system_role` 等条目）。
- 乱码注释：0 条（修复前 4 条表注释 + 156 条字段注释，分布在 54 张表）。
- 脚本：`2026-09-20-fix-mojibake-comments.sql`、`2026-09-20-fix-mojibake-data.sql`（均可重复执行）。

无法还原的部分（源文件本身已损坏，非导入造成）：

- `pay_channel.key_content`：微信支付证书二进制内容，源文件里已是 1088 个 U+FFFD 替换字符。
- MES/ERP 导出里的个别简历文本被截断，各 1142 个 U+FFFD 替换字符。

## 五、复跑方式

```powershell
# 1) 过滤 + 乱码修复，生成模块级导入文件（工具：deploy/mysql/repair/tools/mojibake-repair-filter.js）
node deploy/mysql/repair/tools/mojibake-repair-filter.js --only=crm_   sql/202609201700/CRM_202609201615.sql   out_crm.sql
#    --only=<前缀,前缀>  只保留这些前缀的表
#    --exclude=<前缀>    排除这些前缀的表
#    --drop              为每张表补 DROP TABLE IF EXISTS（源文件没有时）

# 2) 导入影子库做校验
docker exec -i deploy-mysql-1 mysql -uroot -proot --default-character-set=utf8mb4 txgy_stage < out_crm.sql

# 3) 线上库：新增表直接导入；已存在的表用 DELETE + INSERT ... SELECT 覆盖数据
docker exec -i deploy-mysql-1 mysql -uroot -proot --default-character-set=utf8mb4 ruoyi-vue-pro < new_out_training.sql
```

`live_fixcomments.sql`、`live_fixdata.sql`。
