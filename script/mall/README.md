# 商城本机只读就绪检查

在仓库根目录使用 Node.js 22.18 或以上版本（与 PC 项目的最低版本要求一致）：

```powershell
node script/mall/readiness-check.cjs
node --test script/mall/readiness-check.test.cjs
```

默认检查 PC `15175`、H5 `3000`、后台 `5173`、网关 `48080`、租户 `1`。退出码 `0` 表示所有检查通过，`1` 表示接口/页面检查失败，`2` 表示输入配置不合法。

脚本只发匿名 GET，不登录、不取验证码、不修改 Docker/数据库、不访问会增加浏览次数的商品详情接口、不写订单或聊天。结果只保留预定字段、HTTP/业务状态码和固定失败原因，不打印原始响应或异常正文。服务仍可能按原配置记录访问日志，不能将“无业务写入”理解为服务器完全不产生日志。

检查范围：三个 HTML 入口、注册和租户配置、交易配置、简化客服能力，以及私有接口匿名拒绝/内部订单卡不公开。关闭的客服或租户开关会如实报告，并不自动启用。HTML 200 不代表全部页面已渲染，匿名接口通过也不代表已登录账号、真实支付、ERP、物流或客服全链路通过；这些仍需对应的浏览器和授权验收。

可用 `MALL_CHECK_GATEWAY`、`MALL_CHECK_PC`、`MALL_CHECK_H5`、`MALL_CHECK_ADMIN` 更改本机端口，`MALL_CHECK_TENANT` 更改已授权测试租户编号。地址只接受 `localhost`、`127.0.0.1`、`[::1]` 的纯 origin，不接受账号密码、路径、查询参数或非本机地址。脚本禁止 HTTP 重定向，避免匿名诊断意外请求外部站点。

如发现私有接口未正确拒绝匿名访问，先停止对应功能的上线验收并排查，不能将检查条件放宽为“任意非成功都算通过”。此工具不会自动修复配置或修改业务数据。
