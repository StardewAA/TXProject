# PDF 转图片（电子资质证明 → 标书插图）· 调研与技术方案

> 需求：把电子资质证明 PDF（一页或多页）批量转换为图片（PNG/JPG），支持分辨率/尺寸限制、并发批量，
> 供"一键制作投标书"时以图片替换模板占位符（如 docx 模板中的 `{{证书图片}}`）。
> 调研日期：2026-09-02。配套工具：`tools/pdf-to-image/`（README 见同目录）。

---

## 一、场景与输入输出

- 输入：电子资质证明 PDF。来源包括：政务/一体化平台下载的电子证照加注件（OFD/PDF）、扫描件转 PDF、平台生成 PDF。
  ⚠️ 住建部电子证照标准（建办市〔2024〕51号）要求电子证照文件以 **OFD（GB/T 33190）** 承载——**OFD 不是 PDF**，
  本工具一期只做 **PDF→图片**；OFD 需先转 PDF（工具侧说明见 §四"OFD 处理"）。
- 输出：每页一张 PNG（默认，保真、可压缩）或 JPG（体积小），白底、RGB，像素尺寸可被 `dpi × 页面尺寸` 决定并被
  `maxWidth/maxHeight` 二次截断（等比缩小），供模板插入。
- 数量特征：一批证书几十~几百份、每份 1~数页；图像用于排版，过大只会拖慢 Word/PDF 合成与文件体积。

## 二、渲染技术选型（调研结论）

| 方案 | 许可 | 中文/字体 | 保真(扫描件/图章) | 结论 |
|---|---|---|---|---|
| **Apache PDFBox（PDFRenderer）** | Apache-2.0 | 内嵌字体渲染良好；**非内嵌 CID 字体（如 STSong-Light）需字体替换**，否则空白/缺字 | 中上；纯 Java 无系统依赖，缩放走 java.awt | ✅ **主选**：纯 Java、可内嵌到 bidding-server |
| iText（含渲染模块） | AGPL（商用收费） | 好 | 好 | ❌ 许可不适合本项目内嵌 |
| IcePDF / JPedal | AGPL / 商业 | — | — | ❌ 许可或成本 |
| Ghostscript（子进程） | AGPL | 对非嵌入字体/CMYK 最稳 | 最高 | ⚠️ 备用/离线批处理；需服务器装 GS，质量最优、速度慢 |
| PDF.js / Chromium headless | MPL/BSD | 好 | 好 | ⚠️ 服务化偏重，Web 端预览可用，后端批处理不必要 |

**主选 PDFBox 2.0.x 理由**：Apache-2.0 可商用闭源内嵌；API 稳定（`PDFRenderer.renderImageWithDPI(page,dpi,ImageType)`）；
本项目此前（ca-verify、资质管理 e_cert 处理）均为 Java 栈，可直接打成 jar 复用。
**已知坑（须在实现/测试关注）**：
1. PDF 未内嵌中文字体（如 `STSong-Light`、`AdobeSongStd-Light`）时渲染缺字/空白——PDFBox 2.15+ 会用系统字体替换尝试，
   仍失败可注册字体映射（FontMapperImpl 指向本机 ttf）。电子证照 PDF 多数内嵌字体或已扁平化为位图，通常不受影响；
   **验收时用真实证书样本回归**。
2. 渲染结果与 Acrobat 存在 1~2px 级差异，可接受（仅用于排版插图，非司法原件核验）。
3. 扫描件（位图）PDF 渲染无字体问题，重点在 DPI 够不够（见 §三）。

参考：[PDFBox CJK 渲染问题讨论](https://stackoverflow.com/questions/73382606)、[PDF 库对比](https://www.idrsolutions.com/guides/pdf-library-comparison-table)。

## 三、分辨率/尺寸限制的数学约定

- PDF 页面物理尺寸以 pt（1/72 英寸）记录。目标像素：
  `像素宽 = 页宽pt / 72 × DPI`，高同理。
- 常用档位（A4 210×297mm）：72dpi≈595×842；150dpi≈1240×1754；**200dpi≈1654×2339（证书默认推荐，字迹清晰且体积适中）**；300dpi≈2480×3508（印刷级）。
- **限制策略**：先按 `dpi` 渲染，再按 `maxWidth / maxHeight`（默认 2480×3508，0=不限制）等比**只缩小不放大**——
  防止超清证书把 docx/PDF 撑爆；限制值应在模板插图可接受的视觉清晰度与体积间取平衡。
- JPG 质量参数 0.1~1.0（默认 0.9）；白底合成（JPEG 无透明）；PNG 保留像素级还原。
- 单页输出文件尺寸预估：A4@200dpi PNG≈1~3MB（视内容）、JPG≈200~600KB——批量任务应记录总产出大小。
- 建议同时写入图像 DPI 元数据（PNG pHYs / JPEG JFIF），插入 Word 时按"厘米尺寸=像素÷DPI"换算显示大小更可控。

## 四、批量与编排（工作流）

1. **输入扫描**：目录（可递归）或单文件；只认 `*.pdf`（大小写不敏感）；
2. **并发**：线程池（默认 2，可调）逐文件转页，单文件内部逐页串行，失败文件不影响其余；
3. **命名**：`{原文件名}_p{页码}.png`，与证书台账文件一一对应可回溯；
4. **幂等**：默认跳过已存在输出（`--overwrite` 强制重转）；重复执行不产生脏数据；
5. **产物**：输出目录下 `report.json`（工具版本、选项、文件数、成功/失败清单、每页尺寸），供上游"一键制标"任务断言成功后才替换占位符；
6. **与占位符替换的衔接（接口层）**：制标任务先调"转换"产出图片，再调"模板渲染"（Word 模板）把 `{{证书图片:xxx}}` 占位符替换为图片（推荐 [poi-tl](https://blog.gitcode.com/58c73d612b39ad817ff8901e947a708f.html)，Apache-2.0，支持 `addImage` 策略），最后转 PDF 定稿。

**OFD 处理（另案，不在本期代码）**：电子证照为 OFD 时，先经 OFD→PDF 转换（Java 侧可调研 ofdrw 生态的转换工具或服务方转换）再进入本工作流，见 [OFD 转换资料](https://blog.csdn.net/ii950606/article/details/129722521)；或直接由政务平台提供 PDF 加注件。

## 五、接口契约（Java API 与 REST 参考）

Java API（本工具内实现）：

```
PdfToImageRenderer#convert(File pdf, File outDir, PdfToImageOptions options)
    -> List<PageImage>            // 单文件逐页
BatchConverter#convert(File input, File outDir, PdfToImageOptions options)
    -> BatchSummary               // 目录批量 + report.json
PdfToImageOptions: dpi(默认200) / format(PNG|JPG) / jpegQuality(0.9)
                   / maxWidth(2480)/maxHeight(3508) / whiteBackground(true)
                   / recursive(true) / threads(2) / overwrite(false)
```

REST（bidding-server 集成参考，需按模块约定加鉴权/审计；示例 Controller 见 README）：

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| POST | `/admin-api/bidding/pdf-to-image/convert` | multipart：pdf 文件 + options 表单 | `{files:[{name,width,height}]}` |
| POST | `/admin-api/bidding/pdf-to-image/convert-dir` | 服务端目录路径 + options | `BatchSummary` |

建议调用方把"转换结果文件清单"作为制标占位符替换的输入（每个证书条目记录 `pdfPath → 图片路径列表`）。

## 六、验收要点

1. 正样本：真实电子资质证书 PDF（含电子印章/二维码，多专业行 1 页 + 变更记录多页）→ 每页成图、200dpi 清晰、尺寸符合上限；
2. 中文渲染无缺字（非内嵌字体样本单独验证，必要时加字体映射）；
3. 批量 50 份含 3 个损坏 PDF → 47 份全成、3 份在 report 失败清单、进程不中断；
4. 重复执行幂等（skip）与 `--overwrite` 重转；
5. JPG 体积 vs PNG 对比，超限文件自动缩小；
6. 与 poi-tl 模板（含占位符 `{{证书图片}}`）联调：图片正确替换、宽高按限制值显示。
