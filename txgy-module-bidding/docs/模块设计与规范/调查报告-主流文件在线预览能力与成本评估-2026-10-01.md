# 调查报告 · 主流文件在线预览能力与成本评估

- 日期：2026-10-01
- 范围：管理端 + 门户的文件预览能力（PdfPreview.vue 及其 13+ 调用点 / 6 个业务域）
- 结论摘要：**纯前端方案 4~6 人日即可覆盖全部存量文件类型（PDF/图片/docx/csv/txt/zip），后端零改动**；
  老版 .doc/.xls/.ppt 前端做不到、需要后端转换服务（+10~20 人日 + 运维），而**当前库里该类文件为 0**，不建议现在做。

---

## 0. 一句话结论

| 维度 | 现状 | 结论 |
| --- | --- | --- |
| 能预览 | PDF、图片、纯文本（UTF-8） | 已够用，但只覆盖"能打开" |
| 不能预览 | docx / xlsx / csv(表格) / zip / 老版 office | 目前只能「新窗口打开 / 下载」 |
| 真实需求 | 库里 docx 仅 15 个、csv 8 个、txt 35 个，**xlsx/pptx/老格式 0** | 存量 96%+ 是 PDF + 图片，新格式覆盖是"锦上添花"而非救火 |
| 成本 | 纯前端 4~6 人日；后端转换方案 +10~20 人日 | **推荐纯前端分阶段做，后端不动** |

## 1. 现状盘点（代码 + 依赖 + 数据三处实测）

### 1.1 现有预览链路（前端）
- 统一预览组件 `views/bidding/vo/PdfPreview.vue`（13+ 调用点，覆盖 CA 签章、证照文件版本、生命周期佐证、公告版式等 6 个域）：
  - **PDF**：iframe 加载浏览器原生查看器；
  - **图片**：<img> 直接渲染（png/jpg/gif/webp/bmp/svg）；
  - **纯文本**：iframe 走 text/plain 原生渲染（含 .sig.txt 签章凭证）。
  - 其余类型：提示「不支持内嵌预览」+ 新窗口打开 / 下载。
- 取址两条路：调用方给 url（上传回执）→ 直接预览；只给 fileId → 业务受控出口
  `GET /admin-api/bidding/file/download?id=`（内联预览，带 token 查询参数，无需 infra:file:query）。
- 取流底座已具备：`utils/fetchFile.ts` 字节取流（自动带鉴权头 + **HTTP200 错误包体嗅探**，绝不把错误 JSON 当文件字节）——多格式渲染都要走它，现成可用。

## 3. 方案对比

### 方案 A：纯前端统一 FilePreview 组件（推荐 ✅）
- 做法：升级 `PdfPreview.vue`（保持 props 兼容：url / fileId / open / title / fileName）→ 按扩展名分发渲染器：
  字节取流（fetchFileBlob）→ 图片 <img> / PDF iframe 或 pdfjs / 文本(含 GBK) / docx(mammoth) / 表格(SheetJS) / zip(jszip)。
- 优点：**后端零改动**；13 个调用点零迁移或仅补 fileName；离线可用；无数据外发；复用已装依赖（只新增 xlsx 一个）。
- 成本：**4~6 人日**（含 13 调用点回归 + 单测/截图取证）。

### 方案 B：后端转换服务（LibreOffice / OnlyOffice / KKFileView 侧车）
- 覆盖老格式 + 保真渲染，但需要：新服务部署运维、转换队列、鉴权代理、SSRF/免检通道契约——**后端 + 基础设施工作，非前端可独立完成**。
- 成本：10~20 人日起步 + 一台转换容器。当前存量 0，ROI 最低。

### 方案 C：云 Office 在线预览（微软 / Google / WPS 在线查看器）
- 需要把文件 URL 暴露给公网预览服务 —— 现有平台文件地址是 **loopback 内网**（外部服务够不着），且涉及数据外发。
- **不推荐**（与现有"红线 8：URL 即凭据 / 不暴露裸地址"的口径冲突）。

## 5. 风险与边界（如实列出）

1. **SheetJS 授权**：npm `xlsx@0.18.5` 是 CE 最后版本（Apache-2.0）；后续版本转向官方 CDN 收费，**锁定 0.18.5** 不升级。
2. **大文件内存**：xlsx/docx 需全量字节进内存（约 2 份峰值），建议预览上限 30MB、行列截断（如 5000 行）——超出提示「文件过大，请下载查看」。
3. **渲染保真**：mammoth 对复杂 Word 版式有损、SheetJS 不执行公式/宏 → 预览定位为「近似查看」，界面注明「以下载/原文件为准」。
4. **编码**：txt/csv 大概率 GBK（国产系统导出），需 TextDecoder 探测（GB18030 兼容子集），否则乱码。
5. **安全**：html 附件渲染建议加 `sandbox`；不直接 iframe 外链。
6. **兼容面**：PdfPreview props 保持不变；13 个调用点逐一核对 fileName 是否传全（决定扩展名分发准确性）。
7. **门户侧**：portal/bidding/detail.vue 的 PDF 预览已走字节 blob 方案，多格式升级时保持同一渲染器（避免两套）。

## 6. 需要后端做的事

- **纯前端方案：无。**（下载出口已 inline、MIME 正确、鉴权/病毒拦截齐备）
- 若未来确实要支持 .doc/.xls/.ppt/.wps 老格式：另立后端契约（转换服务 + 免检通道 + 鉴权 + 队列），前端再做对接。
