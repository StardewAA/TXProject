用户无法建立"这件事该去哪一页办"的心智模型——这才是"区分有问题"的根因，不是配色问题。

## 一、设计目标与原则

### 1.1 目标形态：三个台账 + 一个平台侧 + 一个设置区

使用方原始意图（"三个台账"）是对的，本次把它作为**唯一基线**：

```
资质与证书管理
├── ① 企业资质台账      ← 企业"持有的资质/许可"这一实体
├── ② 企业证件台账      ← 企业"持有的证照/证件"这一实体
├── ③ 员工证件台账      ← 员工"持有的证件"这一实体
├── ④ 平台审查中心      ← 超管跨租户审查（平台侧唯一入口）
└── ⚙ 设置              ← 主体档案 / 所属企业 / 规则配置 / CA 台账 / 字典
```

### 1.2 划分原则（**这是全文最重要的一张判据**）

> **判据一（主实体原则）**：一个功能归属哪本台账，取决于它**操作的主实体**，与它叫什么名字无关。
> **判据二（就地原则）**：同一实体的所有动作必须能在**同一页**完成，不允许"看在这页、改在那页"。
> **判据三（频率原则）**：页头只放高频动作，低频动作收进「更多」；配置类进「设置」。

三条判据的排序不可调换：判据一决定"归属"，判据二决定"呈现位置"，判据三决定"视觉层级"。

### 1.3 与既有结论的冲突处理（必须显式交代）

`18-页面指标重合度实测与结论-2026-09-14.md` 曾得出 **"不合并页面"**。本次结论与之相反，理由如下：

| | 18 号报告 | 本次设计 |
| --- | --- | --- |
| 测量对象 | 界面**文案标签**的交集 | 用户**任务与实体**的归属 |
| 方法 | 提取中文短标签做集合运算 | 逐功能标注"主实体 + 操作角色" |
| 结论 | 标签重合度低 → 不合并 | 标签不重合**恰恰是问题**：同一实体在不同页被叫成不同名字 |

18 号报告结尾自己留了口子——"页面分工属业务判断，硬编码阈值会把不同实体的同名字段误判成重复"。
本次改用**实体归属**这一业务判断，故 18 号报告的"不合并"结论在信息架构层面**不再适用**；
其在"字段用词分歧"（`validTo` 至/止）上的发现仍然有效并已落地。

### 1.4 设计依据（开源参照）

| 参照 | 借用的部分 | 出处 |
| --- | --- | --- |
| **Ant Design 设计价值观** | 「保持克制：能做，但想清楚了不做」「如无必要，勿增实体」「结果的意义：明确目标，即时反馈」 | <https://ant.design/docs/spec/values-cn> |
| **Ant Design Pro** | 列表页四段式版式（查询区 → 工具栏 → 表格 → 抽屉详情）；ProTable 的"查询与表格分离" | <https://pro.ant.design> |
| **yudao-ui-admin-vue3**（芋道） | 本项目**后端即 yudao 体系**，管理端表格/权限/字典/menu 约定与其保持一致，降低跨模块认知成本 | <https://github.com/YunaiV/yudao-ui-admin-vue3> |
| **vben-admin 5.x** | 本项目**前端框架本身**：页面壳、抽屉、主题令牌（`hsl(var(--card))` 等）均取自其既有能力 | 本仓库 `txgy-ui-admin-vben` |

> 说明：使用方指示"可以直接照抄开源项目的"。以上四项均为**本项目已依赖或已同源**的开源项目，
> 照抄它们的版式与令牌体系不会引入新的技术债；不引入额外 UI 框架。

### 2.5 ⚙ 设置区（新增，收纳"非台账"能力）

**判据**：不管理某个业务实体、而是被三本台账**共同消费**的东西 → 设置。

| 功能 | 理由 | 入口 |
| --- | --- | --- |
| 主体档案（企业自维护） | 回答"我是谁"，三台账共用的 `entId` 来源 | 设置 · 主体档案 |
| 所属企业（本企业 + 子公司名录） | 组织维度字典，非台账实体 | 设置 · 所属企业 |
| 规则配置中心（阈值/版本/灰度/读取审计） | 纯配置，被预警与风险判定消费 | 设置 · 规则配置 |
| CA 签章台账 | 支撑能力（签章记录），业务上服务于各自台账的详情 | 设置 · CA 签章台账 |
| 字典维护 | 归系统字典模块 | 跳转 `/system/dict` |
| 项目关键岗位变更监控 | 主实体是**项目**，不是企业/员工 | **迁往项目域**；本域仅保留只读入口链接 |

> 「项目关键岗位变更」当前挂在安许风险页，复用的是 `bidding:project:query` 权限——
> 这本身就是归属错误的证据（权限码指向项目域）。按判据一，它应回项目域。

### 3.2 版式依据

| 设计动作 | 依据 |
| --- | --- |
| 查询区与表格分离、筛选只留 3–4 项 | Ant Design Pro ProTable：查询表单独立成区，低频条件进「高级筛选」 |
| 详情一律用**抽屉**，不用内联展开、不跳页 | 保留列表上下文与滚动位置，符合"看完即回"的任务节奏；Ant Design「过程的意义：不分散注意力」 |
| 页头只留 1 个主操作 + 刷新 + 更多 | Ant Design「保持克制」；原页面最多 11 个按钮并列，无主次 |
| KPI 卡片可点击联动筛选 | 「结果的意义：明确目标，即时反馈」——数字与明细必须能对上 |
| 完备性结论**下置逐项清单** | 「就地原则」：结论与明细同屏，消灭跨页签核对 |
| 页签承载"同一实体的不同视角" | 页签 = 视图切换，不是功能分区；跨实体的功能不许进页签 |
| 空态给出下一步动作 | 「空屏是行动的邀请」：说明为什么空 + 告诉用户点哪里 |

### 3.3 页头操作分层（统一口径）

| 层级 | 规则 | 例（企业资质台账） |
| --- | --- | --- |
| 主操作（1 个，primary） | 该页最高频的"新建/录入" | 企业资质建档 |
| 次操作（1 个） | 刷新 | 刷新 |
| 「更多 ▾」 | 其余全部低频动作 | 导入 / 导出 / 安许建档 / 预警扫描 / 平台审查中心 / 所属企业 / 配置字典 |
| 「ⓘ 口径」 | 原文案型说明收进气泡，不占版面 | 字典口径、字段来源、未落地项声明 |

**行内操作分层**：列表行只留「查看」+「更多 ▾」（编辑/状态/流程/验真历史等进更多）；
批量动作只在**有选中项时**出现，避免常驻噪音。

## 四、视觉与主题规范

### 4.1 硬约束：禁止硬编码色值

黑夜模式失效的根因是 `cert.css` 内 **53 处硬编码十六进制色值**（`#fff`/`#f4f5f7`/`#dfe3e8` …），
它们不随主题切换。**规范**：本域样式一律走 `--ind-*` 令牌，令牌已在 `src/bid-indust.css` 映射到平台 token。

| 用途 | 令牌 | 映射 |
| --- | --- | --- |
| 页面底色 / 卡片底 | `--ind-paper` | `hsl(var(--card))` |
| 次级底（表头、面板头、筛选条） | `--ind-bone` | `hsl(var(--muted))` |
| 边框（含表格粗线） | `--ind-line` / `--ind-line-soft` | `hsl(var(--border))` |
| 主text / 次text / 弱text | `--ind-ink-text` / `--ind-sub-text` / `--ind-weak-text` | `hsl(var(--foreground))` / `hsl(var(--muted-foreground))` |
| 行悬浮 | `--ind-row-hover` | `hsl(var(--accent))` |

### 5.0 实现范式：「一处实现 + 区块开关」

三项合并都没有复制代码，而是把既有页面变成**可嵌入组件**：

```
safety-risk/index.vue   ← 一份实现
   ├─ embedded + showRiskCard/showWorkbench/showRuleConfig  → ① 企业资质台账 · 页签⑤
   ├─ embedded + showMultiPost/showPersonRisk               → ③ 员工证件台账 · 安许页签
   └─ embedded + showKeyPost                                → 项目台账 · KeyPostPanel

certificate/lifecycle/index.vue ← 一份实现，② 企业证件台账「流程」页签嵌入
components/CompanyManagePanel.vue ← 一份实现，抽屉壳 + 设置·所属企业页共用
```

依据：《接口相似实现归并结论》——同一能力只留一处实现，复制到 N 个宿主必然漂移。
代价：宿主页只见自己那一块，跨块的功能归属由**开关声明**表达（可读、可测）。

### 5.2 菜单 ID 冲突排查（本次拦下的两起同段冲突）

落地过程中做了一次**跨全部 `sql/` 的菜单号段占用扫描**（同一 id 被登记成不同名称即判冲突），
拦下两起会让"后执行者覆盖前者、菜单名与权限静默错位"的冲突：

| 冲突 id | 本方案原计划 | 已占用者 | 处置 |
| --- | --- | --- | --- |
| `60006300/6301` | 设置 · 规则配置（页 + 写按钮） | `2026-09-29-bidding-missing-perm-menus.sql`（主体认证查询/审核） | 让位 → 改用空闲的 `60006500/6501` |

> **口径**：新增菜单前先跑一次号段占用扫描；占用冲突按「先登记再占用」由后到者让位。

## 六、验收标准

1. **归属可判**：随机抽一个功能，能仅凭 §1.2 的判据说出它属于哪本台账，无需查文档。
2. **同页闭环**：任一实体的"看—改—留痕"三步在同一页内完成，不跨页。
3. **黑夜可用**：切到深色主题，页面无"白块/黑字看不清/边框消失"。
4. **无噪音**：页头常驻按钮 ≤ 3 个（主操作 + 刷新 + 更多）；无常驻长文本提示块。
5. **结论可核**：完备性结论与逐项清单同屏，缺失项一眼可数。
6. **端到端**：前端按钮 → 接口 → 数据库，全链路可验证（不停留在"按钮画出来了"）。
