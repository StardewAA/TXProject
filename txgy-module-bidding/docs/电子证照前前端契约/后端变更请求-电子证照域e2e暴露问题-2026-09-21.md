## P1 · 路径命名分叉：安许风险域 14 个 404（需先定口径）

前端（`api/bidding/safetyRisk/index.ts`，其注释自述「本模块后端尚未实现」）调用：

```
GET  /bidding/safety-risk/{page,get,stats,export}
POST /bidding/safety-risk/{assign,handle,scan,alert/batch}
ANY  /bidding/risk-rule/{page,create,update,status,delete}
```

后端**全仓无这两个前缀**（grep 0 命中），同一能力做在：

```
GET  /bidding/safety-permit/risk            → 读安许风险（已有）
POST /bidding/safety-permit/risk/recheck    → 重算（dryRun，已有）
GET  /bidding/safety-permit/risk/history    → 快照含哈希链（已有）
```

**已确认**：`SafetyPermitRiskController` 注入了 `SafetyRiskItemService`，即**服务层在、HTTP 层未暴露**；
且 `RiskItem*Controller` / `RiskRule*Controller` 全仓 0 命中（风险条目 CRUD / 规则实体 CRUD 确实没有控制器）。

**请二选一并书面确认**：
- **方案 A（推荐，改动小）**：后端补 `/bidding/safety-risk/*` 与 `/bidding/risk-rule/*` 两组端点（复用既有 service），前端不动；
- **方案 B**：前端改调 `/bidding/safety-permit/risk*`，但**风险条目分页/指派/处理/规则实体 CRUD 仍需新端点**（后端必须补）。

> 涉及权限码：`bidding:safety-risk:query|assign|handle|alert`、`bidding:safety-risk:scan|rule`（后两个已注册但无实现）。
> 新增端点后需**同时补菜单承载**，否则非超管仍 403。
