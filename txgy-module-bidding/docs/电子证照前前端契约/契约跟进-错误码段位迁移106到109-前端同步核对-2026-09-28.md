# 契约跟进：错误码段位迁移（106 → 109）· 前端同步核对 —— 2026-09-28

> 提出方：前端（电子证照域）· 跟进方：后端同学确认（后端已迁移，前端本轮同步）。
> 依据：_契约精读摘要-2026-09-20.md §5-C26（错误码段位变更）+ 后端 ErrorCodeConstants.java（2026-09-26 迁移实码）。
> 结论先行：**后端证书/资质台账错误码已由 106 段迁至 109 段；前端 CERT_ERR 此前仍是旧 106 段（分支永不命中），本轮已全部迁移并逐项核对**。

---

## 一、背景（精读摘要 C26）

证书与资质台账错误码原为 106 段（1060106xxx），与外部公告/采集域 000~026 整段重叠（同码两义，前端按码分流会误判），
故后端将证书/资质台账整块迁至新登记的 109 段（1_060_109_xxx）。段位规划：

| 段位 | 归属 |
|---|---|
| 1_060_100_xxx | 项目/关键岗位 |
| 1_060_101_xxx | 公告/文件 |
| 1_060_106_xxx | **外部公告域（保留不动）** |
| 1_060_107_xxx | 员工资质/生命周期/材料/安许宽限多岗 |
| 1_060_108_xxx | 规则配置中心与业务字典 |
| 1_060_109_xxx | 证照台账/验真/预警 + 资质台账（迁移目标段） |

## 三、为什么必须同步（影响）

改前前端按 106 段判断：`code === CERT_ERR.OPTIMISTIC_LOCK`（1060106002）永远匹配不到后端返回的 1090109002 →
「数据已被他人修改，请刷新后重试」等分支**永不触发**，用户只能看到通用错误提示，乐观锁冲突时不会自动重载详情。
同理 CERT_NO_DUPLICATE（重复编号字段标红）、CERT_NOT_FOUND（证照不存在刷新）、SAFETY_PERMIT_NOT_EXISTS（安许缺失降级）全部失效。

---

## 四、验收标准

- [ ] 证照建档重复编号 → 表单 certNo 字段标红「该编号已登记」（1090109001）；
- [ ] 并发更新证照 → 提示「数据已被他人修改」并自动重载最新详情（1090109002）；
- [ ] 证照不存在 → 提示并刷新列表（1090109000）；
- [ ] 安许风险读取无安许记录 → 降级提示「该企业没有安全生产许可证记录」（1090109024）；
- [ ] 生命周期审核/生效乐观锁冲突 → 提示并重载最新（107 段不变，行为保持）。
