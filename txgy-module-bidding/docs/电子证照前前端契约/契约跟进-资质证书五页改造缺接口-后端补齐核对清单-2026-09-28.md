## 二、给前端的接线注意（详见《后端变更通知-给前端.md》条目 16~25）

1. **Q1/Q2/Q6 导入入参**：契约写 `{fileId}`，**实现为 multipart `file` 直传**（`GET /import-template` 拿模板，`POST /import` 上传）。行级回执字段为 `successCount/failureCount/failures[{rowNum,message}]`（rowNum 从 2 起）。
2. **Q2 批量验真**：入参 `{certIds:[], verifyChannel?}`（非 `ids`），逐条结果 `results[{certId,success,message}]`。
3. **接口前缀**：安许风险条目一律 `/bidding/safety-permit/risk/*`（前端 api 文件误用 `/bidding/safety-risk/*`，需改）。
4. **权限码**：页面二编辑按钮判 `bidding:qualification:create`（不是 update）；页面五规则面板判 `bidding:rule-config:query/update`（不是 safety-risk:rule）；重扫判 `bidding:qualification:permit:update`（不是 safety-risk:scan）。
5. **Q16 files[] 局限**：evidenceFileIds 无本地版本行时只回 fileId，文件名等字段为空，前端用上传回执/URL 补齐。
6. **字典（第 27 条）**：风险条目状态字典名为 `risk_item_status`（**5 态**，与前端 `RiskStatus` 一致）；证书预警已注册 `alert_level`/`alert_type`；规则条件类型已注册 `risk_rule_cond_type`（前端请删 `COND_TYPE_FALLBACK` 硬编码中文）。
7. **风险条目字段核对（第 28 条）**：`handle` 入参 `status`/`targetStatus` **都接受**（前端无需改）；`assign` 支持回传 `version` 做 CAS（失败报 `DATA_MODIFIED`）；出参已覆盖页面渲染的全部字段（未提供的 `riskType`/`certId`/`handledBy` 页面未渲染，需要时提契约）。

## 五、执行侧修复记录（2026-09-28 追加 · 后端）

### 5.1 Q1/Q6 导入端点 multipart 绑定修复（功能性缺陷）

- **问题**：Q1 `POST /bidding/certificate/import`、Q6 `POST /bidding/qualification/import` 的收件 VO 含 `MultipartFile` 字段，
  但控制器误标 `@RequestBody`：multipart/form-data 请求在进入方法前即被拒（415），导入功能实际不可用；
  框架 `ExcelUtils.read` 亦只接受 `MultipartFile`（无 byte[]/InputStream 重载）。
- **修复**：两端点改 `@RequestParam("file") MultipartFile file`（与 `/bidding/file/upload`、`/bidding/ca/seal` 同一收件口径）；
  **前端口径不变**（通知 17/18 条即 multipart 字段 `file`），无需前端改动。
  > 订正（2026-09-28）：本次曾把失去引用的 `CertificateImportReqVO` / `QualificationImportReqVO` 一并删除，
  > 属越界操作（该二类为电子证照域物件），现已恢复入库（不改动现有 `@RequestParam` 绑定与任何行为）。
  > 若后续要沿用入参 VO 形态，把绑定换成 `@Valid @ModelAttribute <VO>` 即可（已实测可行：multipart 字段 `file` 可正常绑定）。
- **回归**：新增 `CertificateImportVerifyApiContractTest`（4 用例）：用真实 Excel 走通「multipart 绑定 → Excel 解析 → 服务入参」链路，
  并断言行级回执 `{successCount, failureCount, failures[{rowNum, message}]}`、Q2 批量验真
  `{successCount, failureCount, results[{certId, success, message}]}`、三端点权限码与 `@Idempotent`。
  certificate 域回归 35 用例全绿（3+13+15+4）。

### 5.2 Q2 批量验真口径核对（无改动）

- 实现与通知 19 条一致：请求 `{certIds, verifyChannel}`、回执 `{successCount, failureCount, results[{certId, success, message}]}`、
  权限 `bidding:certificate:verify`、写操作带 `@Idempotent`，逐条回执单条失败不影响其余。
