## 1. 代码事实（2026-10-01 实测）

1. **状态机有值域无入口**：QualController（bidding/qualification/**）无 status 端点；
   service#changeStatus 存在但**无任何 HTTP 出口** → LIMITED / REVOKED 永远无法通过界面产生；
   且 PUT /update 对日期推导态**无条件重算**（VALID→EXPIRED 等跳态无校验）。
   企业资质六态（VALID / EXPIRED / EXPIRING_SOON / PENDING_RENEW / LIMITED / REVOKED）中
   后两态当前只能由运维 DML 制造（本轮 e2e 造数即如此，报告 §4.2）。
2. **删除能力不存在**：QualController 无 delete 映射、行操作无删除入口（报告记为 N/A）。
3. **权限点未注册**：bidding:qualification:update 未在 system_menu 注册、admin 不持有 →
   详情页只读态「编辑资质」按钮按 can(bidding:qualification:update) 判权**永不渲染**
   （内联编辑能力本身可用：?mode=edit 直链改备注 PUT /update 返回「已保存」）。
4. 通用证照域先例：证书生命周期 /certificate/lifecycle 已有 POST /…/audit（审批意见必填、驳回留痕）
   与「只删自己造的 e2e 数据」的幂等 DML 口径。

## 2. B1 · 状态机显式入口

```
POST /bidding/qualification/status
Content-Type: application/json
Authorization: Bearer <token>
权限：bidding:qualification:status

request:
{
  "id": 123,                  // 资质 id（必填）
  "targetStatus": "LIMITED",  // 目标态：LIMITED | REVOKED（其余态由流程/扫描推导，不接受直填）
  "version": 7,               // 乐观锁（必填；与 PUT /update 同口径）
  "reason": "串标被行政处罚，责令整改",  // 必填（非流程态必须留原因）
  "remark": "可选补充说明"
}
```

响应：{ code: 0, data: { id, qualStatus, version, updateTime } }

后端职责（对齐证书域 audit 先例）：
- 校验 id 存在且未删除；version 不匹配返回 QUALIFICATION_DATA_MODIFIED（沿用现有码）；
- 校验 targetStatus ∈ {LIMITED, REVOKED}，reason 非空且长度 ≤ 200，否则 QUALIFICATION_STATUS_TRANSITION_INVALID（沿用现有码）；
- **前置校验**：当前态与目标态之间若经过日期推导（如 EXPIRED→VALID 反跳），拒绝并返回原因；
- 落库：qual_status = targetStatus、version+1、update_time 刷新；原因写入留痕
  （现有 remark/留痕表，如无则与 B2 一并补 status_change_log 或复用 lifecycle 表）。

## 3. B2 · 删除能力

```
DELETE /bidding/qualification/{id}?version=7
权限：bidding:qualification:delete
```

- 后端逻辑：逻辑删除（deleted=1、version+1）；查不到 id 返回 {code:404 或既有业务码}（沿用 subject 契约 §0 的 404 形态约定）；
- 幂等语义：重复删除同一 id 返回成功（已删除视为已达成），与通用证照域口径一致；
- 约束：**不级联删绑定证照/文件**（bindedCertId 保留）；仅企业资质行置删。
- 前端行操作补「删除」（confirm + version 回传），仅对已删/终态行禁用——前端配合见 §5。

## 6. 验证（curl 口径，网关 48080，租户 1）

登录取 token（admin/admin123, tenant-id:1）→ data.accessToken

B1：把资质 123 置为 LIMITED
  curl -X POST /admin-api/bidding/qualification/status -H "Authorization: Bearer <token>" -H "Content-Type: application/json" -H "tenant-id: 1"
  -d {"id":123,"targetStatus":"LIMITED","version":7,"reason":"e2e-验证"}    期望 code=0

B2：删除
  curl -X DELETE "/admin-api/bidding/qualification/123?version=8" -H "Authorization: Bearer <token>" -H "tenant-id: 1"
  期望 code=0；重复删除仍 code=0

越界校验：
- targetStatus=VALID → 拒绝（非 LIMITED/REVOKED）
- reason 为空 → 拒绝（原因必填）
- version 不匹配 → QUALIFICATION_DATA_MODIFIED
