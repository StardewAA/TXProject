## 0. 口径（前端已遵守，请后端对齐）

1. 枚举 / 阈值一律取 `GET /bidding/meta/dicts`、`GET /bidding/meta/configs`，前端**不硬编码**（v1.0 §0.5）。
2. **主键口径**：本平台主键为雪花 ID，按 §24 约定以**十进制字符串**传输，前端**原样回传、禁止 `Number()`**（精度会丢）。
   本文所有新增实体的 `id` / 外键均为 `string`。既有实体若仍用 `long`，请在出参兼容期同时下发字符串形态。
3. 写接口：`@Idempotent` + 乐观锁 `version` 回传；失败不自动重试（《规范》§4.5、v1.0 §0.7）。
4. 租户：新增业务表均为 **T 轨**（DO 继承 `TenantBaseDO`，租户条件由拦截器自动拼，业务代码不手写）。
5. 时间：内部 `LocalDateTime`，出参 epoch 毫秒；`LocalDate` 出参 `yyyy-MM-dd` 字符串（v1.0 §0.1）。
6. 新增能力**必须同时注册权限点**（`system_menu` 60005000 段，type=3 按钮型）+ 重生成初始包，
   否则前端按"无权限即隐藏"处理，按钮不可见（本模块既定做法）。

## 2. 新增实体 A：所属企业（`bidding_subject_company`）

### 2.1 业务口径（用户原话要点，请勿误解为租户）

- **「所属企业」不是租户**。租户编号在超管的「全局租户选择」里，属平台级；
- 本实体是**租户自己维护的企业名录**：包含**本企业（SELF）**与其**子公司 / 分公司（SUBSIDIARY / BRANCH）**；
- 用途：把证照 / 资质按"**登记在哪家公司名下**"归集——即页面一/二/三的"所属企业"筛选维度与"持证主体"来源；
- 由此，租户可以管理自己的子公司证照，而不必依赖平台侧的租户切换。

### 2.2 分层与命名（《规范》§3.1 / §4.2）

| 层 | 类 / 文件 | 位置 |
| --- | --- | --- |
| Controller | `SubjectCompanyController` → `/bidding/subject-company` | `controller/admin/subject/` |
| Service | `SubjectCompanyService` / `Impl` | `service/subject/` |
| DO | `SubjectCompanyDO extends TenantBaseDO` | `dal/dataobject/subject/` |
| Mapper | `SubjectCompanyMapper extends BaseMapperX` | `dal/mysql/subject/` |
| VO | `SubjectCompanyRespVO` / `SubjectCompanySaveReqVO` / `SubjectCompanyPageReqVO extends PageParam` | `controller/admin/subject/vo/` |

### 2.3 建表 DDL（按《规范》§5：T 轨 + 长度档位 + version + 唯一键 + 索引）

```sql
CREATE TABLE `bidding_subject_company` (
  `id`                 bigint       NOT NULL COMMENT '主键（雪花 ID）',
  `company_name`       varchar(128) NOT NULL COMMENT '企业名称（对应规范字段「单位名称」；档位 128）',
  `uscc`               varchar(32)  DEFAULT NULL COMMENT '统一社会信用代码（GB32100-2015 18 位；L2）',
  `company_type`       varchar(16)  NOT NULL DEFAULT 'SUBSIDIARY' COMMENT '企业类型 code（字典 subject_company_type：SELF/SUBSIDIARY/BRANCH）',
  `parent_id`          bigint       NOT NULL DEFAULT 0 COMMENT '上级企业 id（顶级为 0；用于"本企业→子公司"从属）',
  `parent_name`        varchar(128) DEFAULT NULL COMMENT '上级企业名称快照（列表展示免联表；源变更不回改）',
  `legal_person_name`  varchar(64)  DEFAULT NULL COMMENT '法定代表人姓名（L3，日志脱敏）',
  `contact_name`       varchar(64)  DEFAULT NULL COMMENT '联系人（L3）',
  `contact_phone`      varchar(32)  DEFAULT NULL COMMENT '联系电话（L3，列表默认掩码）',
  `region_code`        varchar(32)  DEFAULT NULL COMMENT '行政区划代码',
  `industry_code`      varchar(32)  DEFAULT NULL COMMENT '所属行业代码',
  `remark`             varchar(512) DEFAULT NULL COMMENT '备注',
  `enabled`            bit(1)       NOT NULL DEFAULT b'1' COMMENT '是否启用（停用不出现在选择器，不影响历史归属）',
  `version`            int          NOT NULL DEFAULT 0 COMMENT '乐观锁版本',
  `tenant_id`          bigint       NOT NULL DEFAULT 0 COMMENT '租户编号',
  `creator`            varchar(64)  DEFAULT '' COMMENT '创建者',
  `create_time`        datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updater`            varchar(64)  DEFAULT '' COMMENT '更新者',
  `update_time`        datetime     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `deleted`            bit(1)       NOT NULL DEFAULT b'0' COMMENT '是否删除',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_company_uscc` (`uscc`, `deleted`, `tenant_id`) COMMENT '同租户内 USCC 唯一（USCC 为空时后端按名称判重）',
  KEY `idx_company_name` (`company_name`),
  KEY `idx_company_parent` (`parent_id`, `tenant_id`)
) ENGINE = InnoDB COMMENT = '所属企业（租户自维护的企业名录：本企业 + 子公司/分公司）';
```

结构化拆分说明（供评审）：

- **长度档位**按《规范》§5 二：`USCC` 18 位 → `varchar(32)`；单位名称 → `varchar(128)`；短码 → `varchar(16)`。
- **名称快照列** `parent_name` 按《规范》§5 四 2 落（登记时点快照，不回改）。
- **G/T 判定**：本表有租户归属语义（每个租户一份名录）→ **T 轨**，`TenantBaseDO`，由拦截器拼 `tenant_id`。
- L3 字段（法人姓名 / 联系人 / 电话）列表默认掩码、日志脱敏（《规范》§4.8），**进 `Desensitize` 注解口径**。

**入参 / 出参字段（前端已按此实现，务必同名）**

`SubjectCompanyPageReqVO`：`pageNo`、`pageSize`、`companyName`（模糊）、`uscc`（精确）、`companyType`、`parentId`、`enabled`。

`SubjectCompanySaveReqVO`：`id`、`version`、`companyName`（必填）、`uscc`、`companyType`、`parentId`、
`legalPersonName`、`contactName`、`contactPhone`、`regionCode`、`industryCode`、`remark`、`enabled`。

`SubjectCompanyRespVO`：上表全字段 + `parentName`、`tenantId`、`version`、`createTime`、`updateTime`。

**业务校验（请在 Service 落地）**

- `companyName` 必填；同租户内 `companyType = SELF` **只允许一条**（本企业唯一），重复时报错；
- `uscc` 若填，需过 GB32100-2015 校验（复用主体档案既有校验器），且**同租户内唯一**；
- `parentId` 必须指向同租户、且不得形成环（A→B→A）；`parentId` 不能等于自身；
- 删除：若该企业已被证照 / 资质引用（见 §4 DDL 的 `company_id`），**建议拒绝删除并提示改用停用**；
  若允许删除，历史归属会失去对照，请明确口径。

**错误码**：沿用 **104 段（主体/专家）**，新增 `1_060_104_0xx`（请在 `ErrorCodeConstants` 登记，段位已存在无需扩段）。

## 5. 逐页接口清单

### B 组 · 页面一 证照台账（60005100）

| 用途 | 方法 路径 | 入参 | 出参 | 权限点 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| 看板统计 | `GET /bidding/certificate/stats` | 无 | `CertificateStatsRespVO` | `bidding:certificate:query` | P2（**有替代**） |
| 批量导入 | `POST /bidding/certificate/import` | `{ fileId }` | `CertificateImportRespVO` | `bidding:certificate:import` | P1 |
| 批量验真 | `POST /bidding/certificate-verify/verify-batch` | `CertificateVerifyBatchReqVO` | `{ items: CertificateVerifyBatchItemVO[] }` | `bidding:certificate:verify` | P1 |

**`CertificateStatsRespVO`**：`total`、`active`、`expiring`、`abnormal`、`cancelled`、`unverified`、`byStatus`（`Map<String,Integer>`，按 `cert_status` 逐码计数）。

> **P2 说明（重要）**：该接口**不是阻塞项**。前端已用"`certificate/page` 取 `pageSize=1` 并发计数"实现前四类；
> 缺点有二：① 每次加载多 4 次请求；② `page` 的 `certStatus` **只接受单个 code**，无法 `in(...)`，故看板按"每个 tagType
> 取 sort 最小的一个代表码"实现，**暂扣 / 吊销 / 注销进不了卡片**。给出 `stats` 可一并解决。不做也不影响页面一交付。

**批量验真请求**：`{ certIds: string[], verifyChannel?: string }`；
**响应 items 元素**：`certId`、`certName`、`accepted`（本次是否受理成功，**不代表结论为"一致"**）、
`verifyResult`、`verifyChannel`、`message`（失败原因）。

> 前端**不做**"循环调单条 `/verify`"：会真实触发 N 次验真、无事务、无进度、部分失败难回滚，且可能撞上游渠道频控。
> 若上游不支持批量，请后端仍提供统一入口（内部串行 + 限流），返回结构不变。

**批量导入**：文件先经既有 `POST /bidding/file/upload` 拿 `fileId`，再调本接口（**不在业务接口里传二进制**，
符合《规范》§5 三 5"文件不入库、业务表只记 file_id"）。`CertificateImportRespVO`：`totalRows`、`successCount`、
`failCount`、`failures[]{ rowNum, message }`（行号从 2 起，含表头为第 1 行）。建议另给模板下载
`GET /bidding/certificate/import-template`（前端暂未接，可后置）。

**`certificate/page` 入参补充**（高级筛选用）：`companyId`、`validToFrom`、`validToTo`、`validityState`
（`LONG_TERM` / `EXPIRED` / `EXPIRING`）。

- **`page-by-person` 是页面三的 P0 阻塞**：现有 `page` 按**证书**分页，前端先取一批再按人分组会把同一个人的
  证书**切断到两页**，分页失真。故必须后端按人分页：
  - 入参：`pageNo`、`pageSize`、`deptName`、`certType`、`certStatus`、`expiringDays`、`companyId`、`entId`；
  - 出参（人维度一行）：`personId`、`personName`、`personNo`、`deptName`、`certCount`、`nearestValidTo`、
    `certs[]`（**该人在同一筛选条件下**的证书明细，字段同既有 `Cert`）。
- `PersonnelCertStatsRespVO`：`holderCount`（持证员工数，去重人数）、`certTotal`、`expiring`、`expired`、`unverified`。
- **批量续期**：入参优先用 `items[]{ id, version, newValidTo, renewalType }`（逐条各自乐观锁）；
  也可 `certIds[] + newValidTo`。**必须返回逐条结果**（`successCount` / `failCount` / `failures[]{ id, name, message }`），
  单个失败不影响其余——前端据此展示"部分成功"。
- **批量到期提醒 vs 既有 `alert/scan`**：`scan` 是"全量扫描**生成预警记录**"，`notify` 是"**对指定对象推送提醒**"，
  语义不同，请勿合并；`notify` 需幂等（同人同日不重复推送，或明确可叠加）。
- **证书验真**：请明确员工证书**是否走验真**。若**不走**，请回复，前端将去掉该按钮（现按钮已接，
  后端未就绪时点按仅报错，不影响其它功能）。

