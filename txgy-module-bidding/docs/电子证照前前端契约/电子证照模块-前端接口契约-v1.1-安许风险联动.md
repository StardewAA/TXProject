## 12. 安许 A/B/C 三类人员风险联动

**背景（用户口径）**：A/B/C 任一数量不达标→黄色；任一为 0→红色；全为 0→失效；一年预警 ≥4 次→频繁；
法定代表人变更致仅剩 1 名 A 证给 180 天宽限；劳务分包企业 B 证为 0 不触发红色；**企业级与人员级风险标签分离**；
人员 12 个月内更换受聘企业 ≥4 次打“一年异常”标签；同一项目关键岗位频繁变更需监控；兼任 ≥2 岗须持另一岗位考核合格证；
招投标、施工许可、现场监督检查**读同一风险状态**。

### 12.0 本版新增字典与配置（前端先接这里）

字典（`GET /bidding/meta/dicts`，类型名如下；**配色/终态由字典给，不要写死**）：

| 字典类型 | 取值 | 用途 |
| --- | --- | --- |
| `safety_risk_flag` | NORMAL 正常 / YELLOW 黄色预警 / RED 红色预警 / INVALID 失效 / FREQUENT 频繁预警 | 企业风险标签 |
| `person_risk_flag` | NORMAL 正常 / ABNORMAL 一年异常 / FREQUENT 频繁异常 | 人员风险标签 |
| `risk_level` | LOW 低 / MEDIUM 一般 / HIGH 较大 / MAJOR 重大 | 与周检 Job 提前量联动 |

配置（`GET /bidding/meta/configs?group=SAFETY`）：

| ruleKey | 默认 | 前端用途 |
| --- | --- | --- |
| `safety.abc.required` | `{"A":1,"B":1,"C":1}` | 配备看板“要求人数”（**不得写死 1**） |
| `safety.abc.exempt.ent.types` | `{"LABOR_SUBCONTRACT":["B"]}` | 文案：“劳务分包企业 B 证为 0 不触发红色” |
| `safety.abc.grace.legal.person.change.days` | 180 | 宽限表单最大天数 |
| `safety.abc.grace.reason.whitelist` | `["LEGAL_PERSON_CHANGE"]` | 宽限原因下拉选项 |
| `safety.abc.block.flags` | `["INVALID","RED"]` | 阻断档位（**最终以接口 blocked 字段为准**） |
| `personnel.job.change.threshold` / `.window.days` | 4 / 365 | 人员风险说明文案 |
| `project.key.post.change.threshold` / `.window.days` | 2 / 90 | 关键岗位看板阈值与窗口默认值 |

### 12.1 读取安许风险状态（三方共用）

**① 业务目标**：招投标提交、施工许可申报、现场监督检查三个入口都调这一个接口，解决“各页面自己算风险、结论互相矛盾”
（人员流动期间会出现“招投标拦住、现场检查放行”）。返回风险档 + 人数明细 + 宽限状态 + **是否阻断**，
让前端能明确决定“禁用提交”还是“仅提示”。未评估时 `riskFlag=null`，业务侧一律视为不阻断（等价改造前行为）。

**② 契约**

| 项 | 值 |
| --- | --- |
| Method / URL | `GET /bidding/safety-permit/risk` |
| 权限码 | `bidding:qualification:permit:query` |

请求参数：

| 字段 | 类型 | 必填 | 默认 | 业务含义 |
| --- | --- | --- | --- | --- |
| `entId` | number | 是 | — | 企业主体 id |
| `asOf` | string(date) | 否 | 今天 | 基准日（可回填做“以投标截止日预演”） |

响应 `data`：

| 字段 | 类型 | 业务含义 |
| --- | --- | --- |
| `permitId` | number | 安许证主键（未建档为空） |
| `riskFlag` | string 或 null | 风险档 code（**null=未评估，不阻断**） |
| `riskLevel` | string | 等级 code |
| `aCount` / `bCount` / `cCount` | number | 三类有效人数（配备看板直接展示） |
| `graceApplied` | boolean | 是否处于宽限期 |
| `graceExpireAt` | string(datetime) 或 null | 宽限截止（显示倒计时） |
| `graceReason` | string 或 null | 宽限原因 code |
| `blocked` | boolean | **是否阻断业务**（服务端按配置判定） |
| `hitRules` | string(JSON) | 命中规则（“为什么是红”的解释，可展开给用户） |
| `ruleVersion` | string | 规则版本（可复算） |
| `riskEvaluatedAt` | string(datetime) | 最近评估时刻（空显示“未评估”） |

**③ 异常**：401/403 同 v1.0；500 系统异常 → toast + traceId，**风险读取失败不得阻断页面渲染**（降级为“风险未知”）。

**④ 交互与状态约束**

- **阻断文案按档位区分**：INVALID → “三类人员全部为 0，已列失效，无法投标”；RED → “某类人员为 0，请先整改”；
  YELLOW → 仅黄色提示不阻断；FREQUENT → “近一年预警频繁，请关注”（趋势标签，**不阻断**）；
- 宽限期内显示“整改宽限至 {graceExpireAt}，剩余 N 天”；档位已由后端降档，**前端不要自行再降一次**；
- **不要把 riskFlag 映射成中文写死**：用 `safety_risk_flag` 字典的 label/tagType/terminal；
- 三方共用同一份数据：建议同一会话内**缓存 60 秒**（避免同页两处结论不一致），提交前**强制重取一次**。

**⑤ Mock**

```json
// 红色预警 + 无宽限
{ "code": 0, "msg": "", "data": {
    "permitId": 88, "entId": 1, "riskFlag": "RED", "riskLevel": "HIGH",
    "aCount": 1, "bCount": 0, "cCount": 2,
    "graceApplied": false, "graceExpireAt": null, "graceReason": null,
    "blocked": true, "hitRules": "{\"zeroRole\":\"B\"}",
    "ruleVersion": "1", "riskEvaluatedAt": "2026-09-13 02:10:05" } }

// 宽限期内（后端已把档位降为 YELLOW）
{ "code": 0, "msg": "", "data": {
    "permitId": 88, "entId": 1, "riskFlag": "YELLOW", "riskLevel": "MEDIUM",
    "aCount": 1, "bCount": 1, "cCount": 2,
    "graceApplied": true, "graceExpireAt": "2027-03-12 10:00:00",
    "graceReason": "LEGAL_PERSON_CHANGE", "blocked": false,
    "hitRules": "{\"belowRole\":\"A(1/2)\",\"graceApplied\":true}", "ruleVersion": "1" } }
```

### 12.2 重算安许风险（试算 / 排查）

**① 业务目标**：整改后想立刻看结果、或怀疑判定不对时手动重算；`dryRun=true` **只算不落库**，
用于上线前核对判定分布（避免误判直接阻断投标）与单证排查。

**② 契约**： `POST /bidding/safety-permit/risk/recheck`，权限 `bidding:qualification:permit:update`，幂等=是。
请求参数：`permitId`（必填）、`asOf`（可空）、`dryRun`（默认 false）。响应 `data` 同 §12.1。

**③ 异常**：1090109024 安全生产许可证不存在 → 引导建档；重复请求（幂等）→ 按钮已禁用，无需处理。

**④ 交互约束**：按钮 loading + 禁用；`dryRun=true` 时界面**必须显著标注“试算，未保存”**（否则用户以为已生效）。

**⑤ Mock**： `POST /bidding/safety-permit/risk/recheck?permitId=88&dryRun=true` →
```json
{ "code": 0, "msg": "", "data": { "permitId": 88, "riskFlag": "RED", "riskLevel": "HIGH",
  "aCount": 1, "bCount": 0, "cCount": 2, "blocked": true, "hitRules": "{\"zeroRole\":\"B\"}" } }
```

### 12.3 风险快照历史（追溯）

**① 业务目标**：回答“风险什么时候变的、当时为什么这么判”。投标被质疑或监管核查时企业可自证判定依据
（hitRulesJson + ruleVersion 可复算），recordHash/prevHash 提供防篡改证据。

**② 契约**： `GET /bidding/safety-permit/risk/history`，权限 `bidding:qualification:permit:query`。
请求：`permitId`（必填）、`pageNo`/`pageSize`（默认 1/10）。
响应：分页信封，元素含 riskFlag/prevRiskFlag/riskLevel/aCount/bCount/cCount/graceApplied/hitRulesJson/minRequiredJson/ruleVersion/batchNo/evaluatedAt/recordHash/prevHash。

**③ 异常**：同 §12.1。

**④ 交互约束**：渲染为**时间轴**；档位变化用升降级箭头（升红降绿）；哈希链信息折叠展示（不打扰普通用户）；空态“暂无评估记录”。

**⑤ Mock**：
```json
{ "code": 0, "msg": "", "data": { "list": [
  { "id": 90001, "riskFlag": "RED", "prevRiskFlag": "NORMAL", "riskLevel": "HIGH",
    "aCount": 1, "bCount": 0, "cCount": 2, "graceApplied": false,
    "hitRulesJson": "{\"zeroRole\":\"B\"}", "ruleVersion": "1", "batchNo": "RISK-20260913",
    "evaluatedAt": "2026-09-13 02:10:05", "recordHash": "3f2a…", "prevHash": "91bc…" }
], "total": 1 } }
```

### 12.4 登记整改宽限

**① 业务目标**：法定代表人变更等**非主观过错**导致人数临时不足时给整改时间（默认 180 天），宽限期内降一档、不阻断投标；
通过“原因白名单 + 天数上限 + 依据留痕”防止宽限变成逃避整改的后门。

**② 契约**： `POST /bidding/safety-permit/grace`，权限 `bidding:qualification:permit:update`，幂等=是。

| 字段 | 类型 | 必填 | 业务含义 |
| --- | --- | --- | --- |
| `permitId` / `entId` | number | 二选一 | permitId 优先；只给 entId 时按其安许证处理 |
| `reason` | string | 是 | 原因 code（**取自 `safety.abc.grace.reason.whitelist`**） |
| `sourceRef` | string | 否 | 宽限依据（变更单号/决定书号，建议必填） |
| `days` | number | 否 | 天数（留空=配置默认；**不得超配置上限**） |
| `remark` | string | 否 | 备注 |

响应 `data`：`true`。

**③ 异常**

| code | msg | 前端动作 |
| --- | --- | --- |
| 1090109024 | 安全生产许可证不存在 | 引导建档 |
| 1060107025 | 宽限原因不在允许范围内：{原因}（宽限仅限非主观过错情形） | 下拉只给白名单选项；出现即刷新配置 |
| 1060107026 | 宽限天数超出配置上限：最多 N 天 | 输入框用配置上限即时校验 |

**④ 交互约束**：敏感操作 → 二次确认 + 依据；成功后**必须刷新 §12.1**（档位会变）；
页面显示“当前是否已有宽限、到什么时候”，避免重复登记；原因下拉**从配置读取**。

**⑤ Mock**：
```json
// 请求
{ "permitId": 88, "reason": "LEGAL_PERSON_CHANGE",
  "sourceRef": "法定代表人变更登记回执 2026-0001", "days": 180, "remark": "原法人离任，A 证在办" }
// 响应
{ "code": 0, "msg": "", "data": true }
```

### 12.5 多岗兼任合规校验

**① 业务目标**：上岗/配证前校验“兼任两个及以上岗位的必须持另一岗位考核合格证”（如兼任专职安全员需 C 类安考证），
堵住“一人挂多岗但只有一本证”。返回**缺什么证**而不只是通过与否，用户才能立刻行动。

**② 契约**： `POST /bidding/safety-permit/personnel/multi-post-check`，权限 `bidding:personnel:cert:query`，幂等=是。
请求：`personId`（必填）、`primaryPost`（必填）、`secondaryPost`（必填，须与主岗位不同）。
岗位 code（KeyPostEnum）：PROJECT_MANAGER 项目经理 / TECH_LEADER 技术负责人 / SAFETY_OFFICER 专职安全员 / QUALITY_OFFICER 质量负责人 / CONSTRUCTION_ENGINEER 施工员。
响应 `data`：pass、requiredCertType、requiredCertSubType、matchedCertId、failReason、checkedAt。

**③ 异常**：1060107027 主岗位与兼任岗位不能相同（前端先禁用同项）；1060107028 关键岗位 code 不支持；
400 参数校验 → 按 fieldErrors 定位。

**④ 交互约束**：失败时**直接展示 failReason**（已含缺证说明）并禁用“确认上岗”，给“去登记证书”入口。

**⑤ Mock**：
```json
// 请求
{ "personId": 100, "primaryPost": "PROJECT_MANAGER", "secondaryPost": "SAFETY_OFFICER" }
// 通过
{ "code": 0, "msg": "", "data": { "pass": true, "requiredCertType": "SAFETY_ASSESS_CERT",
    "requiredCertSubType": "C", "matchedCertId": 2001, "failReason": null, "checkedAt": "2026-09-13 11:00:00" } }
// 不通过
{ "code": 0, "msg": "", "data": { "pass": false, "requiredCertType": "SAFETY_ASSESS_CERT",
    "requiredCertSubType": "C", "matchedCertId": null,
    "failReason": "缺少兼任岗位要求的证书：专职安全员（需 C 类安全生产考核合格证）",
    "checkedAt": "2026-09-13 11:00:00" } }
```

### 12.6 读取人员级风险

**① 业务目标**：识别“职业化挂靠”人员——12 个月内更换受聘企业 ≥ 阈值（默认 4 次）即打“一年异常”，
用于上岗/配证前拦截。**与企业级风险严格分离**（企业正常不代表人员正常，反之亦然）。

**② 契约**： `GET /bidding/safety-permit/personnel/risk`，权限 `bidding:personnel:profile:query`；
请求 `personId`；响应：personId、personRiskFlag、jobChangeCount12m、jobChangeWindowStart、abnormal、personRiskEvaluatedAt。

**③ 异常**：401/403/500（同 v1.0 §0.4）。

**④ 交互约束**：标签用 `person_risk_flag` 字典渲染；异常时人员列表与详情页均给**红色角标**并提示
“该人员近一年更换单位 N 次，请核实劳动关系”；**不自动拒绝**，系统只提示与留痕，最终由业务判断。

**⑤ Mock**：
```json
{ "code": 0, "msg": "", "data": { "personId": 100, "personRiskFlag": "ABNORMAL",
  "jobChangeCount12m": 5, "jobChangeWindowStart": "2025-09-13",
  "abnormal": true, "personRiskEvaluatedAt": "2026-09-13 03:00:00" } }
```

### 12.7 项目关键岗位变更统计

**① 业务目标**：监控“同一项目同一关键岗位频繁换人”（防挂靠/管理失控），给出各岗位窗口内变更次数、阈值、涉及人员；
让管理方一眼看出“哪个岗位在反复换人”。阈值与窗口全部来自配置。

**② 契约**： `GET /bidding/safety-permit/project/key-post-changes`，权限 `bidding:project:query`；
请求 `projectId`（必填）、`windowDays`（可空，默认取配置 90）；
响应：projectId、windowDays、windowStart、anyExceeded、items[]（postCode/postLabel/changeCount/threshold/exceeded/personIds/lastChangeDate）。

**③ 异常**：401/403/500。

**④ 交互约束**：渲染为**岗位卡片**，超阈值标红并显示“90 天内变更 3 次（阈值 2）”；
personIds 用员工字典补齐姓名（**不要逐行调接口**）；窗口选择器默认取配置值。

**⑤ Mock**：
```json
{ "code": 0, "msg": "", "data": { "projectId": 1024, "windowDays": 90,
  "windowStart": "2026-06-15", "anyExceeded": true,
  "items": [ { "postCode": "PROJECT_MANAGER", "postLabel": "项目经理", "changeCount": 3,
      "threshold": 2, "exceeded": true, "personIds": [100, 101, 102], "lastChangeDate": "2026-09-01" } ] } }
```

## 13. 本版新增错误码

| code | msg | 语义 | 前端动作 |
| --- | --- | --- | --- |
| 1060107025 | 宽限原因不在允许范围内：{原因}（宽限仅限非主观过错情形） | 白名单外原因 | 刷新配置，只给白名单选项 |
| 1060107026 | 宽限天数超出配置上限：最多 {N} 天 | 超上限 | 输入框即时校验 |
| 1060107027 | 主岗位与兼任岗位不能相同 | 岗位重复 | 前端禁用同项 |
| 1060107028 | 关键岗位 code 不支持：{code} | 岗位非法 | 用固定枚举下拉 |
| 1090109024 | 安全生产许可证不存在 | 未建档（**复用既有码**） | 引导建档 |

> 说明：安许风险错误码归入 **107 段（员工资质与证件生命周期）**，紧接 v1.0 已登记的 001~024 之后；
> “安许档案不存在”复用既有 **106 段 1090109024**，不重复定义（避免同码两义）。

5) 契约 v1.0 §0（通用信封/请求头/异常/幂等/动态字典）——直接沿用，不重复。
