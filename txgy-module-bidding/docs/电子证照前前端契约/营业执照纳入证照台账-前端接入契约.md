# 营业执照纳入证照台账 · 前端接入契约 v1.0

> **一句话**：营业执照不再只是"主体档案里的一张照片"，而是**证照台账里的一条正式证照**——
> 立刻获得「多版本影像 + 文件指纹 + 验真 + 到期预警 + 变更留痕」，并且**材料完备性自查会自动认账**。
> 主体档案里那张影像**保留不动**（它承担实名核验职责），两者并存、不冲突。
> 前端**不需要新增任何后端接口**：现有证照台账接口即可完成，本文只说明"怎么接、怎么展示"。

## 一、为什么这么改（三条硬证据）

1. **字典里本来就有这个类型**：`cert_type` 字典第 1 条就是 `ADMIN_LICENSE = 营业执照`（配色 `success`，备注"企业身份证明；材料分类=身份"）。
   即**后端一直支持**把营业执照登记为证照，只是前端没这么用。
2. **主体档案的执照字段承载不了管理需求**：`bidding_subject_profile` 只有 `license_file_id`/`license_file_name` **两个单值字段**
   ⇒ 没有版本历史、没有指纹核验、没有到期日、进不了到期预警。
3. **⚠️ 今天的实际后果：材料完备性里"营业执照"永远是"缺失"**。
   `EnterpriseMaterialTypeEnum.BUSINESS_LICENSE` 声明为 `MaterialSource.CERT` + `certType=ADMIN_LICENSE` + **`mandatory=true`（必备）**，
   且完备性检查是**遍历 `EnterpriseMaterialTypeEnum.values()`** 逐项核验、`fillByCertificate` **只去 `certificate_info`
   按 `cert_type='ADMIN_LICENSE'` 找**（取有效期最晚的一条）——所以只要台账里没有这条记录，**必然判 MISSING**。
   前端目前只填主体档案 → 台账里没有这条证照 → **完备性自查必然报"营业执照缺失"**，用户却明明上传过。
   这不是显示问题，是**数据没进对地方**。

> 业务口径已确认：**一个租户只有一家公司**（不做多主体），所以不需要新增主体概念，只需要"把执照放进台账"。

## 二、怎么接（三步）

### 第 1 步：建档（登记一条营业执照证照）

`POST /bidding/certificate/create`　权限：`bidding:certificate:create`　幂等：是

| 证照字段 | 营业执照取值 | 必填 | 说明 |
| --- | --- | --- | --- |
| `entId` | 当前主体 id | 是 | 企业主体；前端可从主体档案接口拿到 |
| `holderType` | `ORG` | 是 | 字典 `holder_type`（ORG 单位 / PERSON 个人 / EXTERNAL 外部机构） |
| `holderId` | 当前主体 id | 是 | 持证主体 |
| `holderName` | 企业全称 | 是 | 用于列表展示 |
| `certType` | **`ADMIN_LICENSE`** | 是 | 字典 `cert_type` 取值，**不要写死中文**，中文名从字典取 |
| `certName` | `营业执照` | 是 | 证照名称 |
| `certNo` | **统一社会信用代码（18 位）** | 是 | **租户内唯一**；重复会返回 `1090109016`，定位到该输入框提示 |
| `issuingAuthority` | 登记机关（如"XX市市场监督管理局"） | 否 | 建议采集 |
| `issueDate` | 发照日期 | 否 | `yyyy-MM-dd` |
| `validFrom` / `validTo` | 营业期限起 / 止 | 否 | **`validTo = null` 表示长期**；填了到期日，到期预警会自动扫描它 |
| `remark` | 备注 | 否 | — |

### 第 2 步：影像（走文件版本，而不是只存一个 fileId）

1. 走**通用文件服务**上传执照影像 → 拿到 `fileId`；
2. `POST /bidding/certificate/file/register`：登记为**文件版本**（同证同哈希会判重）；
3. `GET /bidding/certificate/file/list?certId=…`：拿版本历史。

> ⚠️ 指纹字段名是 **`fileHash`**（SHA-256），契约别处写的 `sha256` 是笔误（见《后端变更通知-给前端.md》§4.1）。
> 换照（正本换发/补办）时**再登记一个新版本**即可，旧版本自动保留、`isCurrent` 标记当前版本。

### 第 3 步：展示

- 列表：`GET /bidding/certificate/page?certType=ADMIN_LICENSE`（可按类型过滤）；
- 详情：`GET /bidding/certificate/get?id=…`（**带 `version`**，更新时必须回传）；
- **中文名/配色/是否终态一律从 `GET /bidding/meta/dicts` 的 `cert_type` 取，不要写死**；
- 建议在「证照台账」里把营业执照作为一个分组置顶展示（当前版本角标用 `isCurrent`）。

## 三、更新与状态（沿用既有规则，无新约定）

- 更新：`PUT /bidding/certificate/update`，**必须回传 `id` + `version`**（乐观锁 CAS，冲突返回 `1090109002` 让用户刷新）；
  注意 **`certNo`/`certType`/holder 建档后不可改**（业务键）；
- 状态流转：`POST /bidding/certificate/change-status`（如执照被吊销 → 记 `REVOKE`）；
- 验真（可选）：`POST /bidding/certificate-verify/verify`，结果会回填验真状态与官方链接。

## 四、与主体档案的关系（**不要求双写，但要一致**）

| | 主体档案（`bidding_subject_profile`） | 证照台账（`certificate_info`） |
| --- | --- | --- |
| 职责 | **实名核验凭据**（登录/投标主体身份） | **证照管理**（版本、验真、到期、留痕、材料完备性） |
| 这次改不改 | **不改**，字段继续用 | **新增一条** `certType=ADMIN_LICENSE` 记录 |
| 谁读它 | 实名/授权链路 | 材料完备性、到期预警、证照台账页 |

**建议的做法（前端）**：主体档案页的"营业执照"上传控件**保留**（实名需要），同时**在证照台账登记同一条执照**；
如担心两边不一致，可用 `certNo = 统一社会信用代码` 做对账键（两边取同一个值）。
**关于"能不能后端一键生成"（明确答复：不新增这个接口）**：
后端**有意不做**"从主体档案一键生成营业执照证照"的接口，原因有三，且都是本会话反复踩过的坑：
① 它会与 `POST /bidding/certificate/create` 形成**两条写入路径**——同一份数据两个入口，日后必然分叉（本会话已修过多处"两份真相"缺陷）；
② 建档字段里有**必须由人确认的业务判断**（`certNo` 是否就用统一社会信用代码、`issuingAuthority` 取哪个机关、营业期限是"长期"还是具体日期），
   后端替用户拍板等于把这些判断藏起来；
③ 它还要自带幂等/乐观锁/权限设计，**为一个省几次点击的便利增加一条永久维护面**，不划算。
**更好的做法（在前端，零后端改动）**：建档表单**从主体档案预填**（企业全称、统一社会信用代码等），用户确认后提交到**同一个** `/bidding/certificate/create`。
这样既省了输入，又只有一条写入路径。

## 五、接完之后自动获得的能力（不用额外开发）

| 能力 | 说明 |
| --- | --- |
| 材料完备性自动认账 | `fillByCertificate` 按 `cert_type=ADMIN_LICENSE` 命中，营业执照不再误报"缺失" |
| 到期预警 | 填了 `validTo` 就会被 `CredentialAlertJob` 扫描（与其它证照同一套档位/通知） |
| 文件版本与防篡改 | 每次换照留版本 + `fileHash` 指纹 |
| 变更留痕 | 更新走 `cert_change_logs`（谁改了什么、改前改后） |
| 验真留痕 | 验真历史可查（`/certificate-verify/history/page`） |

## 六、错误码（只列本流程会遇到的）

| code | 含义 | 前端处理 |
| --- | --- | --- |
| `1090109016` | 证书编号已存在 | 定位 `certNo` 输入框提示"该统一社会信用代码已登记" |
| `1090109002` | 记录已被他人修改 | 提示刷新后重试（乐观锁） |
| `1090109009` | 文件参数不合法 | 文件登记失败时提示重传 |
| 幂等拦截 | 重复请求 | 提交按钮 loading + 禁用；**不要自动重试写接口** |

> 说明：字段级错误（`data.fieldErrors[]`）后端**当前未实现**，只有整串 `msg`，请把 `msg` 展示在表单顶部/就近位置（见《后端变更通知-给前端.md》§3.1）。

## 七、验收清单

1. 能在证照台账**新建**一条 `certType=ADMIN_LICENSE` 的证照，`certNo` 用统一社会信用代码；
2. 重复登记同一 `certNo` → 返回 `1090109016` 且有明确提示；
3. 上传/换发执照 → `file/list` 能看到**多个版本**、`isCurrent` 正确（指纹字段取 `fileHash`）；
4. 填了 `validTo` 的执照出现在到期预警扫描结果里（可手动补跑 `POST /bidding/certificate-alert-run/scan`）；
5. **材料完备性自查里"营业执照"不再显示缺失**（这是本次改造最有价值的验收点）；
6. 更新记录时带上 `version`；故意用旧 `version` → 得到 `1090109002`；
7. 列表里的中文名/颜色**来自字典**，切换字典配色后前端无需发版。
