## 二、后端变更请求（3 项）

### 2.1 招标项目编号缺省生成（20 位）

`ProjectServiceImpl.saveTenderProject`：当 `reqVO.getTenderProjectCode()` 为空时，按
`BiddingBizNoTypeEnum` 新增类型（如 `TENDER_PROJECT`，前缀沿用 I 段规则扩展至 20 位）生成，
生成后回写入参再走幂等 upsert；**编辑（id 非空 + 编号为空）沿用库内原编号**（同 PROJECT §4.1 口径）。

- 编号结构参考 T08 附录 B：项目编号 17 位 + 招标项目扩展 3 位 = **20 位**；区划/年度分桶规则沿用 bidding_biz_sequence。
- 放宽校验：`TenderProjectSaveReqVO.tenderProjectCode` 由必填改为可选（同 PROJECT 的 `ProjectSaveReqVO.projectCode` 放宽先例）。
- 对外：`save` 成功返回主键 id；前端保存后调 `getTenderProject(id)` 取编号回显。

### 2.2 标段编号缺省生成（23 位）

`ProjectServiceImpl.saveBidSection`：当 `reqVO.getBidSectionCode()` 为空时，按
`BiddingBizNoTypeEnum` 新增类型（如 `BID_SECTION`，前缀规则扩展至 23 位）生成；编辑沿用原号。

- 编号结构参考 T08 附录 B：招标项目编号 20 位 + 标段扩展 3 位 = **23 位**。
- 放宽校验：`BidSectionSaveReqVO.bidSectionCode` 由必填改为可选。
- 注意：`saveBidSection` 已做"所属招标项目必存在"校验（`selectTenderProjectByCode`），编号生成后
  唯一性校验（`BID_SECTION_CODE_DUPLICATE`）沿用，不因放宽受影响。

### 2.3 公告编号确认

`NoticeServiceImpl.generateNoticeCode`（B 段）已实现；界面按用户裁定不显示公告 ID。无需后端改动。
