# 后端 → 前端 变更通知（澄清/修改通知 15 日顺延拦截）

> **用法**：后端给前端的**单向通知文件**。只增不改历史条目；编号越大越新。
> 每条包含：影响范围 → 实际行为（以实现为准）→ 前端需要做什么（若有）。
> 关联设计：《电子招标投标全流程说明书》§4（阶段三标段公告）、§14 附录。
> 更新：2026-09-28（本轮）

## 本轮（2026-09-28）变更：澄清/修改通知发布时强制 15 日顺延

### 影响范围：变更公告（CHANGE_NOTICE）发布接口

**背景**：《实施条例》第 21 条——澄清/修改影响文件编制的，应在投标截止 **15 日前**（资格预审截止 **3 日前**）以书面通知所有获取文件的潜在投标人；不足则截止时间顺延。
说明书 §4.3 第 5 条定位为「澄清时限顺延」自动计算。

**实际行为（后端已实现）**：
- 变更/澄清公告（`noticeType = CHANGE_NOTICE`）在发布时新增强校验 `validateChangeDeadline`：
  - 取 payload 的 `NOTICE_SEND_TIME`（澄清发出时间）→ `BID_END_TIME`（投标/申请截止时间）；
  - 距投标截止不足 **15 日**（payload 含 `QUAL_TYPE` 视为资格预审，不足 **3 日**）→ **拒绝发布**，抛 `1060101019`。
- 语义落地：**拦截「填报的截止时间距澄清发出过近」，强制招标人顺延后再发布**——这是「截止时间顺延（§4.4）」在系统层的可执行实现。
- 缺字段（缺 NOTICE_SEND_TIME 或 BID_END_TIME）/解析失败 → 容错跳过（不误拦存量/外部公告）。

**错误码**：
| code | 文本 |
| --- | --- |
| `1060101019` | 变更/澄清公告距截止时间不足 {} 日（发出 {} → 截止 {}），不得发布（实施条例第21条，应顺延截止时间） |

**新增测试**（NoticeServiceImplTest +3）：招标变更不足 15 日拒绝、满 15 日放行、资格预审不足 3 日拒绝。

**前端需要做什么**：
- 若前端承接「变更公告」发布，发布失败时展示错误码 `1060101019` 的 msg（含应顺延到的最小截止天数），引导招标人调后 `BID_END_TIME` 重新提交。
- 无新增接口/字段；仅发布失败的提示文案变化。
