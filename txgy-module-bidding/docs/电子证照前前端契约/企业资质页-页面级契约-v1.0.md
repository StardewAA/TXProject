## 2. 页面信息架构

```
┌ 顶部：企业主体选择器（entId）＋「材料完备性自查」结论卡片（§3.10）
├ 页签 1 资质台账（默认）：列表 + 行操作（建档/编辑/延续申报/查看要素/查看申报历史）
├ 页签 2 延续申报：申报单列表（按状态分泳道：SUBMITTED / APPROVED / REJECTED / ISSUED）+ 审批通过/退回
├ 页签 3 标准与要素：资质标准（序列/类别/等级 → 人员与业绩要求）＋要素台账（人员配置/业绩/资产）
├ 页签 4 安许证与预警：安许证台账 + 状态流转 + 到期预警清单 + 手动扫描
└ 右下角常驻：预警角标（资质/安许/员工证书三源到期数，点击跳对应清单）
```

**① 状态与交互约束**
- 页签切换不重新拉取"已加载且未过期"的数据；**任何写操作成功后，当前页签与结论卡片必须同时失效重拉**（避免列表已更新、卡片仍是旧结论）；
- 主体选择器切换 → 全页数据重拉（所有列表接口都带 `entId`）；
- 资质状态为 `EXPIRED` / `REVOKED` 的行，行操作只保留"查看"，延续申报按钮置灰并提示原因。

## 3. 今日可联调的接口（后端已实现，11 写 + 1 读）

> 全部走统一信封 `CommonResult{code,msg,data}`（成功 `code=0`）；HTTP 前缀 `/admin-api`；必须带 `Authorization: Bearer` 与 `tenant-id`。

### 3.1 资质建档 `POST /bidding/qualification/create`

**① 业务目标**：为某企业主体登记一条资质（序列/类别/等级/证书编号唯一），并可选绑定证照台账中的影像件，形成"资质主档 ↔ 证照影像"的关联。
**② 契约定义**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `entId` | number | 是 | 关联企业主体 |
| `qualSerial` / `qualCategory` / `qualGrade` | string | 是 | 资质序列 / 类别 / 等级（取值见字典，**不要前端写死**） |
| `certNo` | string | 是 | 资质证书编号（**租户内唯一**） |
| `issuingAuthority` | string | 否 | 发证/许可机关 |
| `issueDate` / `validTo` | string(date) | 否 / 否 | 发证日期；有效期至（`null` = 长期） |
| `approvalScope` | string | 否 | 批准承包/承揽范围 |
| `bindedCertId` | number | 否 | 关联 `certificate_info` 主键（存在性由后端校验） |
| `remark` | string | 否 | 备注 |

出参 `data`：新资质 id（number）。幂等：`@Idempotent`（同参数重复提交只落一条）。
**③ 异常契约**：`1090109016` 资质证书编号已存在 → 定位 `certNo` 提示；`1090109015` 资质主档不存在（编辑场景）；400 字段级错误按 `fieldErrors` 逐项提示；403 无权限；幂等拦截返回"重复请求"。
**④ 前端交互与状态约束**：表单三联动（序列→类别→等级）取值全部来自 §字典（`qual_serial`/`qual_category`/`qual_grade`，见主契约 §1.1 与 §4）；提交按钮点击后立即置 loading 并禁用，**不要自动重试**（幂等窗口内重复提交会命中拦截并被提示）。
**⑤ Mock**

```json
// 请求
{ "entId": 1, "qualSerial": "CONSTRUCTION", "qualCategory": "GENERAL_CONTRACTING", "qualGrade": "FIRST",
  "certNo": "D361123456", "issuingAuthority": "陕西省住建厅", "issueDate": "2024-05-20", "validTo": "2029-05-19" }
// 响应
{ "code": 0, "msg": "", "data": 9001 }
```

### 3.2 延续申报 `POST /bidding/qualification/renew`

**① 业务目标**：在资质到期前发起延续（RENEW）申报，生成申报单并把主档置为 `PENDING_RENEW`，避免"证还在有效期内但没人管续期"。
**② 契约定义**：`qualificationId`(number, 是)、`version`(number, 是 —— 乐观锁，取列表行里的 `version`)、`dueDate`(string(date), 否 预计办结日期)、`remark`(string, 否)。出参：申报单 id。幂等：`@Idempotent`。
**③ 异常契约**：`1090109018` 资质主档已被他人修改（version 不符）→ **自动重拉详情**并提示重新确认；`1090109017` 资质状态流转非法 → 提示并刷新（如已 EXPIRED 不允许延续）；403；幂等拦截。
**④ 前端交互与状态约束**：只有 `VALID` / `EXPIRING_SOON` 的行可发起；提交成功后行状态应显示"延续中"（`PENDING_RENEW`），此时该行的"延续申报"按钮置灰、审批按钮按角色放开。
**⑤ Mock**：`{ "qualificationId": 9001, "version": 3, "dueDate": "2026-03-31", "remark": "到期前 90 天启动" }` → `{ "code": 0, "data": 88001 }`

### 3.3 延续审批通过 `POST /bidding/qualification/approve`

**① 业务目标**：主管部门批复后办结申报单（APPROVED → ISSUED），同时回写主档：状态回 `VALID`、新证书编号、新有效期至 —— 让"申报单"与"主档"始终一致。
**② 契约定义**：`applyId`(number, 是)、`version`(number, 是 申报单版本)、`resultNo`(string, 否 批复文号)、`newCertNo`(string, 否)、`newValidTo`(string(date), **是**)。出参：申报单 id。幂等 `@Idempotent`。
**③ 异常契约**：`1090109020` 申报状态流转非法（非 SUBMITTED 不可批）；`1090109018` 并发修改；400 缺 `newValidTo`（延续必须给新有效期）；403。
**④ 前端交互与状态约束**：审批弹窗必须回显"原有效期 → 新有效期"对比；提交成功后申报单移出待办泳道，主档行的有效期立即刷新。
**⑤ Mock**：`{ "applyId": 88001, "version": 1, "resultNo": "陕建许〔2026〕123 号", "newCertNo": "D361123456", "newValidTo": "2031-05-19" }`

### 3.4 延续审批退回 `POST /bidding/qualification/reject`

**① 业务目标**：批复未通过时退回申报单（→ `REJECTED`）并还原主档为 `VALID`，让企业可补正后重新申报。
**② 契约定义**：`applyId`(是)、`version`(是)、`remark`(string, 是 退回原因)。出参：申报单 id。幂等。
**③ 异常契约**：`1090109020` 状态非法；`1090109018` 并发；400 缺退回原因；403。
**④ 前端交互与状态约束**：退回原因**必填且进备注链**（后端会 append 到主档备注）；退回后该行重新出现"延续申报"按钮，并提示"可补正后重新申报"。
**⑤ Mock**：`{ "applyId": 88002, "version": 1, "remark": "业绩材料缺 2 项，补正后重报" }`

### 3.5 资质标准登记 `POST /bidding/qualification/standard/create`

**① 业务目标**：登记"序列/类别/等级"对应的标准版本（人员配置、业绩、资产等要求），作为达标核查（§3.7）的判定依据；**同标准版本不得重复**。
**② 契约定义**：入参见 `QualificationStandardSaveReqVO`（Swagger `/admin-api/v3/api-docs` 可查全字段：标准版本号、适用范围、要素要求 JSON 等）；出参：标准 id；幂等。
**③ 异常契约**：`1090109023` 同标准版本/适用范围已存在 → 提示换版本号；400 字段级；403。
**④ 前端交互与状态约束**：标准是"可配置数据"而非代码常量 —— 页面上必须能查看当前生效标准与历史版本；登记后触发一次达标核查下拉刷新。
**⑤ Mock**：`{ "serial": "CONSTRUCTION", "category": "GENERAL_CONTRACTING", "grade": "FIRST", "versionNo": "v2026.1", "requirement": { "staff": { "A": 3, "B": 5 }, "assets": 8000000 } }`

### 3.6 要素台账录入（3 个端点，同一权限码 `bidding:qualification:element`）

| 端点 | 业务目标 | 主要入参 |
| --- | --- | --- |
| `POST /bidding/qualification/element/staff` | 登记企业的人员配置（按岗位/细分等级计数），供达标核查比对 | 见 `QualificationElementStaffSaveReqVO` |
| `POST /bidding/qualification/element/performance` | 登记工程业绩（合同额/规模/时间），供业绩项核查与材料完备性引用 | 见 `QualificationElementPerformanceSaveReqVO` |
| `POST /bidding/qualification/element/asset` | 登记净资产/设备等资产要素 | 见 `QualificationElementAssetSaveReqVO` |

**③ 异常契约**：400 字段级；403；幂等拦截。**④ 交互约束**：三张子表的录入入口放在页签 3；录入后"达标核查"按钮由后端重算，**前端不做本地判定**（阈值与规则一律以后端为准）。

### 3.7 达标核查执行 `POST /bidding/qualification/review/run`

**① 业务目标**：按当前生效标准比对要素台账，产出达标结论（通过/风险/不通过）并留痕，作为投标资格审核的依据。
**② 契约定义**：入参见 `QualificationReviewRunReqVO`（企业主体 + 资质主档）；出参：核查记录 id / 结论。幂等 `@Idempotent`。
**③ 异常契约**：`1090109022` 未找到适用资质标准（按序列/类别/等级与生效区间）→ 提示先登记标准；400；403。
**④ 前端交互与状态约束**：结果为三档（通过 / 风险 / 不通过），页面按档位配色；**核查结论必须显示"依据的标准版本号 + 核查时间"**，否则不可作为审核证据。

### 3.8 安许证管理（2 个端点，权限码 `bidding:qualification:permit`）

| 端点 | 业务目标 | 主要入参 | 异常契约 |
| --- | --- | --- | --- |
| `POST /bidding/qualification/permit/create` | 登记安全生产许可证（编号租户内唯一） | 见 `QualificationSafetyPermitSaveReqVO` | `1090109025` 编号已存在 |
| `POST /bidding/qualification/permit/status` | 安许状态流转（VALID / EXPIRING_SOON / EXPIRED / SUSPENDED / REVOKED） | 许可 id + 目标状态 + version | `1090109026` 流转非法；`1090109018` 并发 |

**④ 交互约束**：状态流转按钮由状态机决定可用性（见 §5），**非法目标状态提前置灰**，不要等后端报错；安许证与"安许风险联动页"（600055xx，权限 `bidding:qualification:permit:query|update`）共享数据，流转后风险结论会变化，卡片需重拉。

### 3.9 资质到期预警扫描 `POST /bidding/qualification-alert-run/scan`

**① 业务目标**：手动触发 QUAL_EXPIRY 三源（资质主档 / 安许证 / 员工证书）到期扫描，生成预警记录与通知，**同日幂等**。
**② 契约定义**：无入参；出参：本次新增预警数（number）。幂等：`@Idempotent` + 业务侧同日去重。
**③ 异常契约**：403；500（扫描依赖的字典/阈值缺失时给出可操作提示）。
**④ 前端交互与状态约束**：按钮放在页签 4，点击后 toast 显示"本次新增 N 条"；扫描为**幂等窗口内安全操作**，允许用户稍后重试但按钮点击后禁用 3 秒防连点。

### 3.10 材料完备性自查 `GET /bidding/enterprise-material/completeness`

**① 业务目标**：以企业主体为口径，把"投标需要哪些材料（身份类/资质类/实力类）"逐项对照现有台账（证照/资质/安许/业绩），给出总体结论与缺失、临近到期清单 —— 让企业在报名前就知道"还差什么"。
**② 契约定义**：`entId`(number, 是)、`asOf`(string(date), 否 = 今天)。出参字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `result` | string | 总体结论：`PASS` 齐备 / `RISK` 部分缺失或临近到期 / `FAIL` 必备材料缺失（字典 `material_result`） |
| `requiredCount` / `readyCount` | number | 必备材料总数 / 齐备数 |
| `missingItems` / `expiringItems` | array\<string\> | 缺失清单 / 临近到期清单（名称，或"名称 + 到期日"） |
| `items[]` | array | 逐项明细：`materialType`、`materialLabel`、`category`、`mandatory`、`status`（字典 `material_status`：READY/EXPIRING/MISSING/EXPIRED）、`refId`、`refName`、`validTo`、`message` |

**③ 异常契约**：403；400 缺 `entId`；500。
**④ 前端交互与状态约束**：卡片顶部显示三档结论与配色（`PASS` 绿 / `RISK` 橙 / `FAIL` 红）；逐项明细可从 `refId` 跳转到对应台账页（证照/资质/安许）；**"临近到期"窗口天数由规则配置驱动**（`cert.expiring.window.days` 等），前端不得写死 90/60/30。

### G1 资质台账分页（示例性完整定义，其余同构）

**① 业务目标**：按企业主体与筛选条件分页返回资质主档，支撑列表、角标与导出。
**② 契约定义**

| 查询参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `entId` | number | 是 | 企业主体（页面主体选择器） |
| `qualSerial` / `qualCategory` / `qualGrade` | string | 否 | 字典筛选项 |
| `status` | string | 否 | `QualificationStatusEnum`：VALID/EXPIRING_SOON/EXPIRED/PENDING_RENEW/LIMITED/REVOKED |

## 5. 状态机与并发约束

**资质状态机（`QualificationStatusEnum`，后端 `isTransitionAllowed` 裁决）**
```
VALID ──到期窗口──▶ EXPIRING_SOON ──过有效期──▶ EXPIRED
VALID/EXPIRING_SOON ──发起延续──▶ PENDING_RENEW ──批复通过──▶ VALID（回写新有效期）
PENDING_RENEW ──退回──▶ VALID（还原）
VALID/EXPIRING_SOON/EXPIRED ──限制/吊销──▶ LIMITED / REVOKED（终态，不可回退）
```
**安许状态机（`SafetyPermitStatusEnum`）**：`VALID` ⇄ `EXPIRING_SOON` → `EXPIRED`；`VALID` → `SUSPENDED`（暂扣）→ `VALID`（恢复）或 `REVOKED`（终态）。

**① 前端约束**：目标状态选项由状态机推导，非法项**置灰 + tooltip 说明**；终态行不显示流转按钮。
**② 并发（乐观锁）**：所有写操作必须携带**当前行的 `version`**；收到"已被他人修改"（`1090109018`）时**自动重拉详情/列表并让用户重新确认**，不要静默重试。
**③ 幂等**：写接口均为 `@Idempotent`；命中幂等拦截时后端返回"重复请求，请稍后重试"，前端**不要自动重试**（按钮已在请求期间禁用）。

## 8. 联调自检清单

1. `GET /bidding/meta/dicts` 是否返回本页所需字典；缺哪个就让后端补注册（不要前端写死）；
2. 建档 → 列表出现 → 编辑（带上 `version`）→ 延续申报 → 审批通过 全链路各跑一遍，确认状态与有效期同步；
3. 制造并发：两个窗口同时编辑同一行，确认第 2 个收到"已被他人修改"并能自动重拉；
4. 连点提交按钮，确认命中幂等拦截且页面不产生重复数据；
5. 无权限账号登录，确认按钮隐藏 / 整页 403 占位；
6. `expiringInDays` 与预警窗口改为后台配置值后，前端表现随之变化（证明未硬编码）；
7. 完备性卡片 `FAIL/RISK/PASS` 三态各造一份数据验证配色与跳转。
