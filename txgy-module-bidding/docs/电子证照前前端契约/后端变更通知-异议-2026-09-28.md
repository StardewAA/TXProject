# 后端 → 前端 变更通知（投标异议）

> **用法**：后端给前端的**单向通知文件**。只增不改历史条目；编号越大越新。
> 每条包含：影响范围 → 实际行为（以实现为准）→ 前端需要做什么（若有）。
> 关联设计：《电子招标投标全流程说明书》§6（阶段五资格预审）、§14 附录。
> 更新：2026-09-28（本轮）

## 本轮（2026-09-28）变更：新增投标异议子域

### 影响范围：新增 4 个接口（提出 + 答复 + 查询）

**背景**：《实施条例》第 22 条——资格预审文件异议应在申请截止 **2 日前**提出、
招标文件异议应在投标截止 **10 日前**提出；招标人收到异议后 **3 日内**答复（答复前暂停）。
说明书 §6.3 第 4 条定位为「异议计时器」。

**接口清单**（前缀 `/admin-api/bidding/objection`）：

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| POST | `/propose` | `bidding:objection:propose` | 提出异议（校验提出时限，投标方调用） |
| POST | `/reply` | `bidding:objection:reply` | 答复异议（记录答复时间，招标方调用） |
| GET | `/get` | `bidding:objection:query` | 异议详情 |
| GET | `/page` | `bidding:objection:query` | 异议台账分页（含答复超期标记） |

**关键行为（后端已实现）**：
- **提出时限校验**（条例第22条）：
  - `objectionType = PREQUAL_FILE`（资格预审文件异议）→ 距申请截止不足 **2 日** → 拒绝，抛 `1060118001`；
  - `objectionType = TENDER_FILE`（招标文件异议）→ 距投标截止不足 **10 日** → 拒绝，抛 `1060118001`。
  - 截止时间取已发布公告（招标/变更）的递交截止时间（复用 `getBidDeadline`），缺失/解析失败容错跳过（不误拦）。
- **答复超期标记**：`replyTime` 为空且提出后超 **3 日** → 台账/详情 `replyOverdue = true`（条例第22条 3 日内答复）。
- **答复幂等**：已答复的异议再次答复抛 `1060118002`（不可重复答复）。

**字段说明（以响应字段集合为准，前端只取下列字段）**：
- 请求（propose）6 字段：`tenderProjectCode`、`bidSectionCode`、`objectionType`、`subjectId`、`content`、`remark`。
- 请求（reply）2 字段：`objectionId`、`replyContent`。
- 响应 13 字段：`id`、`tenderProjectCode`、`bidSectionCode`、`objectionType`、`subjectId`、`content`、`proposeTime`、`status`、`replyTime`、`replyContent`、`replyOverdue`、`remark`、`createTime`。
  `replyOverdue`（答复是否超期）：待答复且提出后超 3 日 → true（前端黄色标记提醒）。

**错误码**：
| code | 说明 |
| --- | --- |
| `1060118000` | 异议记录不存在 |
| `1060118001` | 异议提出已超期（资格预审文件 2 日前 / 招标文件 10 日前） |
| `1060118002` | 异议已答复，不可重复答复 |

**前端需要做什么**：
- 菜单/按钮权限码登记：`bidding:objection:propose`、`bidding:objection:reply`、`bidding:objection:query`（3 个）。
- 页面接线：投标方「提出异议」（选标段 + 类型 + 内容）；招标方「异议台账」（`replyOverdue` 黄色标记 + 答复表单）。
- 提出失败时展示错误码 `1060118001` 的 msg（提示已过异议提出时限）。
