## 三、后端落地清单（请后端同学按此修改）

### 3.1 `BiddingProcessTrackController.java`（必需，3 新 1 改）

按 09-18 契约 §5 补 4 个只读接口（前缀 `/admin-api/bidding/process-track`，权限 `bidding:process-track:query`）：

| 接口 | 说明 |
|---|---|
| `GET /page` | **总览分页（项目粒度）**，出参自带公司信息 `ProcessTrackItemVO`（tenantId/tenantName/项目/阶段/负责人/各阶段时间/审核结果/标书名/备注）。入参：pageNo/pageSize/keyword/state/tenantId（仅超管有效）/ownerUserId |
| `GET /stats` | KPI：tenantCount/projectCount/ongoing/bidded/terminated/ownerCount/byState（ongoing=意向+审核+待投标 三态之和） |
| `GET /options` | 筛选项：owners[{value=ownerUserId,label=姓名,extra=公司名}] + tenants[{value,label}]（**超管才下发 tenants**） |
| `GET /get`（改造） | 现 `get` 只有单条：**补 `events[]` 事件史**（eventType/eventName/fromState/toState/operatorName/operationDesc/occurredAt），对齐契约接口 4 |

### 3.2 数据补齐（A3，快照列，可选分两期）

页面展示所需 `tenantName / ownerName / region / amount / deadline`：建议按 09-18 契约 §3 落快照列到 `bidding_process_track`
（对齐本模块既有的 displayName/issuerName 快照习惯，避免列表 N 行 N 次 RPC/联查）。**若本期只交付 page 骨架（可空列），需在验收时明确哪些展示位先为「—」**。

### 3.3 字典对齐（A4）

- 按 09-18 契约 §4.1 注册 `bidding_process_state`（5 条）与 `bidding_process_event`（6 条）；
- 既有 `process_track_status` 冗余处置：可保留（兼容）或重命名，请与组员确认后回落 SQL；
- 前端 `STATE_TEXT` / `EVENT_TEXT` 是棘轮基线在册硬编码（2 处已用满），接口落地后改读字典即可消除。

### 3.4 菜单权限归位（A5）

1. 菜单 6748 `permission`：`bidding:notice-external:query` → 改回 `bidding:process-track:query`；
2. 增补 `bidding:process-track:overview`（仅超管，`system_menu` 挂 6748 下 + `system_role_menu` 绑 super_admin）;
3. 6749-6752（create/register/review/upload 按钮）：页面已全部移除对应入口——撤销或保留为「状态机对外启用后再挂」，请后端与组员确认后同步 SQL。

### 3.5 租户隔离（09-18 契约 §6，硬要求）

- 非超管：`TenantContextHolder` 强制过滤 + `tenantId` 入参忽略；不得「不传就返回全部」；
- 超管：跨租户走 `@TenantIgnore` / `TenantUtils.executeIgnore(...)`，且只出参 §5 字段；
- 超管判定用角色码 `super_admin`（本部署权限码无 `*:*:*`，勿用）。
