> **用法**：后端给前端的**单向通知文件**。只增不改历史条目；编号越大越新。
> 每条包含：影响范围 → 实际行为（以实现为准）→ 前端需要做什么（若有）。
> 关联设计：《电子招标投标全流程说明书》§5（获取招标文件/下载名单）、§6（资格预审）。
> 更新：2026-09-28（本轮）

## 本轮（2026-09-28）变更：新增两个流程域（补齐说明书 §5/§6 断点）

### 2. 🟢 资格预审子域 9 个接口（招标方发起 + 投标方申请 + 资格审查委员会审查）

**背景**：说明书 §6 判定「资格预审」为硬断点（仅注释层面提及条例第19条，无实现）。
本轮补齐资格预审主记录 + 申请 + 审查闭环。

**接口清单**（前缀 `/admin-api/bidding/prequal`）：

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| POST | `/save` | `bidding:prequal:save` | 创建/修改资格预审（草稿态，生成内部编号前缀 P） |
| POST | `/publish` | `bidding:prequal:publish` | 发布（DRAFT→PUBLISHED；校验申请期≥5日，条例第17条） |
| POST | `/close` | `bidding:prequal:close` | 关闭（→CLOSED） |
| GET | `/get` | `bidding:prequal:query` | 资格预审详情 |
| GET | `/page` | `bidding:prequal:query` | 资格预审分页 |
| POST | `/apply` | `bidding:prequal:apply` | 提交资格预审申请（投标方；申请截止前可提交，同一主体幂等） |
| POST | `/review` | `bidding:prequal:review` | 审查申请（资格审查委员会；通过/不通过） |
| GET | `/apply-list` | `bidding:prequal:query` | 申请列表（按预审） |
| GET | `/apply-page` | `bidding:prequal:query` | 申请分页 |

**关键行为（后端已实现）**：
- 申请期校验：发布时强校验「申请开始 → 申请截止 ≥5日」（条例第17条），不足抛 `1060114002`。
- 申请截止锁：申请提交校验当前时间 < applyDeadline，超时抛 `1060114003`。
- 通过者<3家告警：全部申请审查完毕后，通过数<3家记录 warn 日志「应重新招标」（条例第19条），不阻断审查，由招标人决策。

**前端需要做什么**：
- 菜单/按钮权限码登记：`bidding:prequal:save/publish/close/query/apply/review`（6 个）。
- 页面接线：招标方「资格预审发起/发布/关闭/申请列表」、投标方「提交申请」、审查委员会「审查」。

### 1. 🟢 招标文件下载名单 3 个接口（阶段四，澄清/异议定向通知的事实基础）

**背景**：说明书 §5 判定「获取招标文件/下载名单」为硬断点（仅有 ENROLL_MODE 字典，无下载记录）。
本轮补齐下载记录表 + 下载名单查询。

**接口清单**（前缀 `/admin-api/bidding/tender-doc`）：

| 方法 | 路径 | 权限码 | 说明 |
| --- | --- | --- | --- |
| POST | `/record` | `bidding:tender-doc:download` | 记录下载（投标方下载招标文件时调用；同一文件同一用户幂等） |
| GET | `/downloaders` | `bidding:tender-doc:query` | 下载名单（招标方按招标项目/标段聚合查询） |
| GET | `/count` | `bidding:tender-doc:query` | 下载人数统计（按标段） |

**关键行为（后端已实现）**：
- 幂等：同一 fileId + 同一登录用户只记一条下载记录，重复下载返回既有记录。
- 名单倒序：按下载时间倒序，供招标方导出澄清/修改通知名单（条例第21条）。

**前端需要做什么**：
- 菜单/按钮权限码登记：`bidding:tender-doc:download`、`bidding:tender-doc:query`（2 个）。
- 页面接线：投标方「下载招标文件」动作后回调 `/record`；招标方「下载名单」页。
