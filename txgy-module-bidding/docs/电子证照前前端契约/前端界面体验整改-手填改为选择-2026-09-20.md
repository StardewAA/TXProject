   后端 pageSize 是否有上限？超限时前端会静默截断（只显示前 N 条）。建议确认各查询接口 pageSize 允许值。
3. **招标项目/项目编号的关联语义**：标段台账"所属招标项目"下拉直接用招标项目编号（tenderProjectCode）作为
   值并提交；若后端希望提交 id 而非编号，请指出（当前后端接口入参为编号，前端按现状对齐）。
4. **certificate/page 的 certName 模糊检索**：生命周期"作用对象"用其检索证照，是否受当前登录主体/权限限制？
   若是，请说明过滤口径（前端默认按后端返回过滤后的结果展示，无需额外处理）。

## 4. 整改原则（供后端评审前端行为时对照）

- 枚举/码表：一律走 dicts/configs，字典缺失时**禁用 + 中文提示**（不提供手填码值入口）；
- 系统生成的 id/编号/URL：**前端不暴露为输入项**；必须引用时用下拉/检索选择或只读带入；
- 提示文案：中文优先，不出现字段名/配置键名；
- 表格：超长文本列加 ellipsis，宽表保留横向滚动；
- 上传类字段：直接上传收集 fileId，不在界面上要求用户手填文件编号。

## 5. 表格/表单视觉整改（2026-09-20 补充）

用户口径（第 5 点原文要点）："表格长度的不合理——一个元数据明明很短就能写完却占了一行，
或者必须把一行占满才进下一行；一行一行填有成就感，全满会头晕；待填顺序应由 id → 元数据 → 自由文本 →
文件附件，越来越长；要有表格的感觉，表格的线必须明显，不要用太圆滑的样式。"

前端已落实：
- **列宽贴合内容**：登记表单全部改为栅格排布（短字段 span 8 三列、元数据 span 12 两列、自由文本/附件 span 24 全行），
  短字段（id/编号/日期/枚举）不再占满整行；
- **录入顺序**：cert-form / lifecycle-apply / personnel 档案与证书 / bidSection / project / qualification / safety-risk 登记
  均按「id → 元数据 → 自由文本 → 文件附件」由短到长排布，附件（上传）恒为最后一项；
- **表格线强化**（cert.css）：表格加粗实线边框（1.5px）、表头下边线、单元格细分隔线、斑马纹行、圆角降至 2px，
  面板/KPI 圆角 3px——弱化圆滑、突出"格"感；
- 表格超长文本列补 ellipsis 截断，避免行被撑高、全满眩晕。

> 说明：以上为纯前端样式与布局调整，无接口变更。
## 6. 表格化录入改造（2026-09-20 二轮，紧扣用户第 5 点）

用户再述问题（原文要点）：
- 视觉模糊：待填项提示都写在表格里 → 一眼白茫茫；表格外框/界面颜色浅 → 白茫茫；表格太圆 → 白茫茫；
  一行占满 → 界面挤、"徒劳无功"；
- 排版不齐：待填项/表格排版不整齐，不知道要填多少才填完；
- 改进方向：待填项左侧写明"要填什么"；线框直一点，只在拐角微弯、不要纯方正；颜色加深/加阴影、有层次感、
  存在感强；一行不放满，一类一行、关系强的放一起（例：项目编号体系里有多套 ID——项目编号、投资代码、
  审批文号、标段编号、公告编号等，应互相归组）。

前端已落实（纯前端，无接口变更）：
1. **表格式录入组件 .ct-sheet（cert.css 新增）**：
   - 每个待填项 = 一个单元格，**label 写在左侧**（不再堆在上方一行一字段）；
   - 单元格按网格 3 列排布，**短字段不占满整行**，自由文本/附件占整行放最后；
   - 深色外框（1.5px 实线）+ 仅 4px 拐角圆角 + box-shadow 层次阴影，存在感强；
   - 分组标题条（如「编号」「证照信息」「颁发与有效期」），**关系强的字段归组放一行**，一眼看清要填几类；
   - 校验/必填星号/错误提示仍由 a-form-item 承担，规则零改动。
2. **已改造为表格式的登记表单**：
   - 证照建档/更新（cert-form.vue）：证照标识（编号/大类/类型代码）→ 证照信息 → 持证主体 → 颁发与有效期 → 备注；
   - 项目登记（project/index.vue）：编号（项目编号/投资代码/审批文号）→ 项目信息 → 审批与资金 → 自由文本；
   - 标段登记（bidSection/index.vue）：编号（标段编号/所属招标项目/交易码/地区码）→ 标段信息 → 合同与价格 → 要求与说明；
   - 资质建档 / 安许建档 / 资质标准 / 要素录入（qualification/index.vue）：归属与标识 → 资质信息 → 范围与备注；
   - 员工档案 / 员工证书（personnel/index.vue）：归属与身份 → 联系方式与教育 → 任职信息 → 附件与备注；
   - 生命周期发起（lifecycle-apply.vue）：流程申请（对象域/流程类型/申请单号）表格化；
   - 关键岗位任职变更（safety-risk/index.vue）：任职对象 → 任职信息 → 变更原因。
3. **表格/面板层次感**：ct-table、ct-panel 补 box-shadow 微阴影，边框已为深色实线、小圆角（2–4px）。

> 说明：以上为纯前端布局/样式调整；录入顺序均按「id → 元数据 → 自由文本 → 文件附件」由短到长。

## 13. 后端返回值契约核对（用户复核：上传返回 URL/ID、项目编号后端生成）

用户口径："上传/导入文件时后端应返回 URL 或 ID；创建项目时后端应返回 17 位项目编号，
  不该让用户手填或自己造编号。"

核对结论（均已落实）：
1. **文件上传**：契约《11-文件上传与file_id契约-2026-09-10.md》已明确 `POST /bidding/file/upload`
   返回 `{ fileId, url, name, type, size, sha256 }`，fileId 是落库关联键（权威），URL 仅即时预览；
   前端全部上传点（证书文件/履历附件/加注件/佐证材料/要素证据/备案附件）均走 `uploadBiddingFile`
   取 fileId，无手填文件编号交互。
2. **项目编号（17 位）**：契约《25-内部业务编号生成规范-2026-09-15.md》已规定内部项目编号由后端按
   `区划(6)+年度(4)+序列(6)` 生成 I 段 17 位编号（如 `I6101002026000001`），前端新建不带编号提交，
   保存后从详情取回展示。
   - 本轮修正：前端 project/index.vue 原将 projectCode 强制必填（与契约冲突），已去掉 required，
     新建留空由后端生成；提交成功后用 getProject(id) 取回编号展示；编辑沿用原编号不重新编号；
     外部项目（如 E 开头平台编号）仍可手填。
   - 备案回执号同理：submitFiling 返回后端生成的 F 段受理号，自动带入回执登记，不手抄。
> 契约 25 §8 联调实测编号样例：新建内部项目 → `I6101002026000001`，编辑不重新编号。
