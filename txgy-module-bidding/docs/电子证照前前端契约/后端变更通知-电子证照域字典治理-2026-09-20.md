## 二、字典接口（前端唯一取值来源）

```
GET /admin-api/bidding/meta/dicts?dictTypes=cert_status,cert_type,file_category
```

- **字典 = 运维可配置**：运营在后台加一项，前端下拉立即多一项，**不需要前端发版**
- 支持租户级差异化（同租户覆盖平台默认文案）

## 三、证照四类归口（本次新增，前端做二级筛选用）

原先 `cert_type` 的 11 项**平铺**（身份/资质/业绩/资信混在一起），前端只能硬编码分组。现分四类：

| 大类 code | 名称 | 含哪些 cert_type |
| --- | --- | --- |
| `IDENTITY` | 身份类 | ADMIN_LICENSE(营业执照)、LEGAL_PERSON_ID(法定代表人身份证明)、AUTH_LETTER(授权委托书) |
| `QUALIFICATION` | 资质类 | SYSTEM_CERT(体系认证)、SAFETY_PERMIT(安全生产许可证)、PERSON_QUAL(人员资格) |
| `PERFORMANCE` | 业绩类 | PERFORMANCE(业绩证明) |
| `CREDIT` | 资信类 | AUDIT_REPORT(财务审计)、SOCIAL_SECURITY(社保)、HONOR(荣誉)、TAX_CREDIT(纳税信用) |

**用法**：先选大类 → 用 `cert_type_category` 过滤出该大类下的类型 → 再选具体类型。
**注意**：大类归属由字典维护，**可能被运营调整**，所以前端**不要硬编码这个映射表**，应读字典。

## 五、废弃：不要再依赖枚举

后端原有「同一概念既写枚举又写字典」9 组，现治理为**字典唯一权威**：

| 枚举（已废弃） | 改用字典 |
| --- | --- |
| CertificateVerificationStatusEnum | `verification_status` |
| CertFileCategoryEnum | `file_category` |
| CertVerifyChannelEnum | `verify_channel` |
| CertNotifyChannelEnum | `notify_channel` |
| CertificateAlertTypeEnum | `alert_type` |

**保留的 4 个**（有业务逻辑，前端**仍只需读字典**，不直接依赖枚举）：
`CertificateStatusEnum`、`CertLifecycleStatusEnum`、`CertRevokeTypeEnum`、`CertLifecycleTypeEnum`
—— 它们用于后端状态机流转/分支判断，**取值仍以字典为准**（两者当前一致）。

### 7.3 ⛔ 后端请求 R2：`CertificatePageReqVO` 缺 `certCategory` 入参，且 `certType` 的描述写错了

**现象**（读后端源码所见）：

```java
// CertificatePageReqVO
@Schema(description = "证照大类 code", example = "ADMIN_LICENSE")
private String certType;
```

- 描述写的是「**证照大类** code」，但 `example` 给的是 **`ADMIN_LICENSE`（营业执照）—— 这是 `cert_type` 的值**；
  四类归口里 `ADMIN_LICENSE` 属于大类 `IDENTITY`。即**描述与取值域不符**。
- 入参里**没有 `certCategory`**，所以本次新增的四类归口**无法作为服务端筛选条件**。

**影响**：前端只能把「大类」做成**纯前端联动收窄**（选了大类只过滤"类型"下拉的候选，列表本身不会因大类而变），
真正提交后端的仍是 `certType`。用户选了"身份类"却看到列表没变，会以为筛选坏了。

**请后端二选一**：
- **a)（推荐）** `CertificatePageReqVO` 增加 `certCategory` 入参，按 `cert_type_category` 映射把大类展开成 `cert_type IN (...)` 参与查询
  —— 这样大类能真正筛选，前端把 `query.certCategory` 一并提交即可（前端已预留该字段，接上只差一行）；
- **b)** 若不打算支持大类筛选，请**更正该字段的 `@Schema` 描述**为「证照类型 code（字典 cert_type）」，避免下一个接手的人再照抄成"大类"。

> 附带：前端原先那个筛选的标签就是「**证照大类**」但绑的是 `certType`——正是照抄该描述所致；本次已拆成
> 「证照大类（联动收窄）」+「证照类型（提交筛选）」两级，并在代码注释里标注了本缺口。

## 八、兼容性说明（不会破坏现有前端）

- **所有变更都是新增字段/新增字典**，原有 code 字段（`certType`/`certStatus`/`fileCategory`…）**保持不变**；
- 枚举类**保留未删除**（仅标 `@Deprecated`），前端即使暂时不接字典也不会立刻坏；
- 中文名字段在**字典不可用时返回 null**（后端做了容错），前端请回退显示 code。
