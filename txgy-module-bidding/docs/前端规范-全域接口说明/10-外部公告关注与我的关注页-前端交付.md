# 10 外部公告关注与“我的关注/项目跟踪”前端交付（②③：关注入口 + 聚合跟踪页）

> 读者：前端同学（外部公告域的“关注/跟踪”交互与接口契约，含每处业务理由与代码依据）。
> 配套：06 §1/§3（crawlExternal/noticeExternal 接口）、09 §8（跟踪页现状）；本文件把“订阅→动态→已读”闭环的前端缺口补全。

## 0. 为什么补这个（2026-09-09 核查结论）

- 后端订阅引擎已闭环：外部公告审核通过 → followService.handleNoticeActivated 按维度匹配关注者 → 事件/未读落库（版本幂等）；
  内部公告发布/修订同样扇出（08 §8）。但【前端没有发起关注的入口、没有聚合展示页】，业务人员无法订阅与查看动态 → 价值断链。
- 本文件给出 ②（关注按钮）+ ③（我的关注/项目跟踪页）的页面与接口规范；前端已有人负责实现。

## 1. 关注目标与键（最重要，错了收不到动态）

| 目标类型 targetType | targetKey | 含义 | 能否收到后续动态的依据 |
| --- | --- | --- | --- |
| ANNOUNCEMENT | 公告 id（Long 字符串） | 关注单条公告 | 扇出查询 targetKey=公告id（handleNoticeActivated 第二查）→ 必然命中 |
| PROJECT | 项目编号 project_code | 关注整个项目 | 扇出 collectMatchKeys 用公告的 project_code 反查 → **仅当公告带 project_code 才能命中** |
| TENDER_PROJECT | tender_project_code | 招标项目维度 | 同上（按招标项目编号） |
| SECTION | 标段编号（bid_section_codes 拆分） | 标段维度 | 同上（按标段编号） |

**规则（业务依据）**：
1. 公告详情/列表“关注项目”按钮仅在存在 project_code 时展示；缺失则只给“关注此公告”（ANNOUNCEMENT 级，保证必可达）；
   ——否则用户以为关注了项目，实际该公告无项目键，后续同类公告永远等不到（2026-09-09 数据：存量 20 条仅 4 条有 code，① 已做正文推导增强+存量回填，趋势向好但前端仍需兜底）。
2. targetKey 一律用**后端主档字段原值**（公告 id 用字符串、project 用 project_code），不要前端自造键；
   ——扇出匹配是全等比对（in targetKey），键不一致=静默收不到（历史“NULL”字面量脏值教训）。
3. 类型白名单外一律不发（后端 FOLL_target invalid 校验）；可关注类型 = 上面 4 种。

## 2. 接口契约（均已有后端实现，2026-09-09 实测）

基础 URL：/bidding/notice-follow；权限：查询类 bidding:notice-external:query，写操作 bidding:notice-external:update。

| 操作 | 方法/路径 | 请求 | 响应要点 |
| --- | --- | --- | --- |
| 查询关注态 | GET /status | targetType, targetKey | {followed, itemId, displayName?, ...快照}（详情页关注按钮初始态） |
| 关注 | POST /follow | body {targetType,targetKey} | Boolean true；幂等：已关注/退订重关均回 FOLLOWING，不重复插 |
| 取消 | POST /unfollow | body {targetType,targetKey} | Boolean true；幂等：不存在/已取关直接返回成功 |
| 我的关注分页 | GET /item/page | followType/followKey(可空) + 分页 | PageResult<FollowItemRespVO>（后端强制按当前登录人隔离，勿传他人 user） |
| 时间线 | GET /item/{itemId}/timeline | 路径 itemId | 该项目公告+动态（按时间倒序） |
| 已读 | POST /item/{itemId}/read | 路径 itemId | 未读数清零，事件保留 |

字段（FollowItemRespVO，与 06 §5 FollowItem 对应，全部可选）：
id/followType/followKey/displayName（公告级=标题，项目级=名称快照）/issuerName/stageCode/stageName/
baseJson（扩展）/latestDynamicTime（最近动态时间）/unreadCount（未读数，列表红点）/followTime/noticeStatus/available。
id 与 followKey 均兼容 number|string（雪花 Long）；followTime/latestDynamicTime 为后端 LocalDateTime 字符串。

## 3. 页面 ②：关注按钮

- 位置：外部公告公开详情页（公告标题下/正文右上）、公开列表行操作；投标流程跟踪页(6748)新增意向时同样复用。
- 逻辑：进入详情 → GET /status 初始化 → followed ? “已关注（点击取消）” : “+ 关注”。
- 目标键选择：详情优先“关注项目”入口（取详情响应的 projectKey），无 projectKey 时按钮文案变“关注此公告”（ANNOUNCEMENT）。
  - 详情响应跟踪键字段名以 noticeExternal 公开详情契约为准（后端已下发 projectKey/projectName/bidSectionKeys，见 NoticeExternalRespVO）。
- 成功提示：文案建议“已关注，后续变更/公示将出现在“我的关注””；取消失败保持原态，不做本地乐观翻转欺骗。
- 注释理由模板（可直接贴代码）:
  // 关注键必须与后端扇出匹配键一致：公告级=公告id、项目级=project_code；键不一致会导致后续动态静默丢失（见 10-交付文档 §1）

## 4. 页面 ③：“我的关注/项目跟踪”聚合页

- 载体：portal 路由 /bidding/subscription（title：我的关注，hideInMenu 可改显）+ 管理端投标流程跟踪页头部入口（08 语义：跟踪=关注的延伸）。
- 布局：左侧维度切换（全部/公告/项目/招标项目/标段 → followType 过滤）；右侧关注列表 + 底部“查看项目动态”抽屉/子页。
- 列表行：displayName（主）、issuerName、stageName（阶段徽标）、latestDynamicTime、unreadCount>0 红点；未读优先倒序（后端已按用户返回，分页排序以接口为准）。
- 未读数：进入页可对已读项批量调用 read；红点清除只在 read 成功后。
- 行点击 → timeline（GET /item/{id}/timeline）展开该关注对象的公告/动态时间线（含版本幂等语义：同版本不重复）。
- 删除关注：行内取消按钮（unfollow），需二次确认文案：“取消后该项目的后续动态将不再推送（历史记录保留）”。
- 空态文案：“还没有关注；去外部公告大厅浏览并关注感兴趣的项目/公告”。
- 关键注释理由（贴代码用）:
  // A 方案口径（07 §2）：关注/跟踪归属当前登录人账号，不做企业级合并；后端 item/page 已按 getLoginUserId 隔离
  // 展示字段可用 available/noticeStatus 判断失效（撤下/下线），命中后置底或标记“已失效”，勿直接删除行（历史留痕）

## 5. 验收自查清单（评审/联调用）

- [ ] 详情页关注态刷新正确（关注后返回仍是已关注；刷新页面状态一致）；
- [ ] 无 project_code 的公告只出现“关注此公告”，不出现“关注项目”；
- [ ] 关注后对同租户内部公告发布/修订与外部公告审核通过可产生事件（验收依赖后端样例数据或联调桩）；
- [ ] 时间线同版本不重复出现动态；read 后 unreadCount 清零且不丢历史；
- [ ] 换账号登录看不到他人关注（隔离）；个人账号可同时关注多家企业公告（主体域 A 方案允许）。

## 6. FAQ

- Q：为什么必须区分公告级/项目级关注？A：公告级精确到单条；项目级覆盖该编号下后续新公告——扇出按键匹配，两级键不同，语义不同，UI 不可混。
- Q：我关注的项目出现“已失效”？A：available=false 表示公告被撤下/下线；保留记录仍可回看，后续如恢复上线会再激活。
- Q：列表数据会很多吗？A：按人分页+followType 过滤；未读优先展示即可，无需一次性全量。
