## 一、先把 infra 的官方口径查清（避免拍脑袋）

### 1.1 infra 给了两条上传模式（`FileController` 的 `@Operation` 原文）

| 模式 | 端点 | 返回 | 官方描述原文 |
| --- | --- | --- | --- |
| **模式一 后端上传** | `POST /infra/file/upload` | **URL 字符串** | "模式一：后端上传文件" |
| **模式二 前端直传** | `GET /infra/file/presigned-url` + `POST /infra/file/create` | `/create` 返回 **Long（file id）** | "模式二：前端上传文件：**用于前端直接上传七牛、阿里云 OSS 等文件存储器**"；`/create` "**记录上传了上传的文件**" |

### 1.2 下载端点（关键）

```java
@GetMapping("/{configId}/get/**")
@PermitAll            // ← 不需要任何权限
@TenantIgnore
public void getFileContent(...)   // 直接吐字节流
```

**结论**：infra 的下载设计是 **"URL 即凭据"**——URL 里含 `configId + path`，谁持有谁能下载，无需鉴权。
这解释了两件事：
1. 业务库里那些 `pdf_download_url`（`.../infra/file/4/get/bidding/...`）为什么可以直接打开；
2. 为什么《招投标模块开发规范》§5 三-5 要额外规定 "**url 为签名下发/回显快照，不作为一致性依据**"——**规范是在纠正 infra 的默认行为**，要求业务侧不得把 URL 当权威关联键。

### 1.3 infra 的 FileApi 契约（对外 RPC 面）

```java
createFile(FileCreateReqDTO)          // 写：返回 url
presignGetUrl(url, expirationSeconds) // 读：**入参是 url**，返回限时地址
getMetadataByUrl(url)                 // 读：**入参是 url**，返回 {id,name,url,type,size}
```

**注意**：infra-server 内部其实**有** `FileService.getFile(id)` 与 `getFileContent(configId, path)`，
但**都没有暴露进 `FileApi`**——即 **"按 id 取内容"这条路，平台从未对外设计**。

### 1.4 官方"推荐路径"到底是哪条？——模式二

对"前端上传业务附件、业务表要存 file_id"这个场景，infra 的设计意图是**模式二**：
前端直传 OSS → 调 `/create` 登记 → **原生拿到 file_id**。

**为什么本模块不能照搬模式二**（两条硬冲突）：
1. **病毒扫描挂不上**：规范五章三节第 5 款要求"**上传须过病毒扫描与类型白名单**"；模式二下文件不经后端，后端到 `/create` 时才见到元数据，**没有字节可扫**。
2. **本地存储下预签名无意义**：本部署 `config_id=4` 指向**本地文件服务**（非 OSS），`presigned-url` 模式的收益（不占后端带宽）不成立，反而增加前端分片/重试复杂度。

**因此：本模块选模式一 + bidding 侧包装（现状 A 通道）是合理且合规的**，缺的只是"**读/下载**"这一半。

## 二、现状收敛前的全量清点（哪些能用、哪些不能用）

### 2.1 上传（3 条）

| 通道 | 接口 | 返回 | 处置 |
| --- | --- | --- | --- |
| **A** | `POST /bidding/file/upload` | `{fileId,url,name,type,size,sha256}` | ✅ **唯一保留**（业务统一入口） |
| B | `POST /infra/file/upload` | 仅 url（**无 id**） | ⚠️ 限平台组件（头像等），**业务不得使用** |
| C | `POST /bidding/file/register-by-url` | `{fileId…}`（sha256=null） | 🔧 仅历史数据修复通道，**不用于新增** |

### 2.2 下载/预览（3 条 → 收敛为 1 条）

| 通道 | 方式 | 问题 | 处置 |
| --- | --- | --- | --- |
| ① | 出参 `url` + 前端同源化 | 仅"刚上传"时有 url | 保留（上传后即时预览） |
| ② | `GET /infra/file/get?id=` | **需 `infra:file:query`，业务账号没有 → 权限倒挂** | ❌ **废弃** |
| ③ | FileApi 签名 URL | 需先有 url（鸡生蛋） | 🔧 归入新接口内部实现 |
| **④ 新** | `GET /bidding/file/download?id=` | — | ✅ **唯一保留**（后端代理吐字节，url 不出后端） |

### 2.3 更新/替换（4 套语义）——**不收敛为 1 个，统一"语义标注"**

| 模型 | 接口 | 语义 |
| --- | --- | --- |
| 证照版本追加 | `/bidding/certificate/file/{register,void,correct}` | **版本**（只追加，可作废/更正元数据） |
| 通用附件 | `/bidding/attachment/{save,delete}` | **绑定**（解绑重绑） |
| CA 签章 | `/bidding/ca/seal/document` | **重新签章**（产物是新的 fileId） |
| 业务表内嵌 | `evidenceFileIds`/`attachmentFileIds` 覆盖 | ⚠️ **覆盖式**，审计最弱 |

**说明**：四种语义服务四种业务事实，**强行统一会丢语义**（例如"作废"与"解绑"法律含义不同）。
故收敛动作 = **统一审计字段与留痕口径**（谁、何时、用哪种语义换掉了哪个 fileId），**而非合并接口**。

### 2.4 鉴权（3 档 → 收敛为 2 档）

| 现状 | 处置 |
| --- | --- |
| `/bidding/file/*`、`/bidding/attachment/*` = `isAuthenticated()` | ✅ 保留 |
| `/certificate/file/*` = `bidding:certificate:file` | ✅ 保留（业务域权限） |
| `/infra/file/*` = `infra:file:*` | ❌ 业务侧不再依赖 |

## 三、最终收敛口径（一句话版）

> **上传只走 `/bidding/file/upload`；关联只认 `fileId`；取文件只走 `/bidding/file/download?id=`（后端代理，不下发裸 url）；
> 更新按「版本 / 绑定 / 重新签章」三语义选型并统一留痕；病毒统一字段 `virusStatus`，`INFECTED` 一律拒绝下载。**

## 四、后端实施清单（本次落地）

### 4.1 新增：`GET /bidding/file/download?id=`（核心）

```
GET /bidding/file/download?id=1024
  ├─ 校验登录（isAuthenticated）
  ├─ 按 fileId 解析 infra 下载地址（见 4.2）
  ├─ 病毒口径：virusStatus=INFECTED → 抛 1_060_101_021，拒绝下发
  ├─ 后端代取字节（infra 下载端点 @PermitAll，无需 infra 权限）
  └─ 以附件流写回响应（Content-Disposition: attachment; filename=...）
```

- **前端拿不到任何 URL** → 红线 8（不存/不下发裸 url）自然满足；
- **不再需要 `infra:file:query`** → 权限倒挂消除；
- 大文件采用**流式转发**，避免整份读入内存。

### 4.2 fileId → 可访问地址 的解析（不存裸 url、不跨库）

- 上传（A 通道）与按 url 补登记（C 通道）时，响应里的 `url` **本身即含 `configId` 与 `path`**；
  由后端**解析出存储坐标**（`configId` + `path`）并**登记到招投标自有表**（不存裸 url）；
- 下载时按坐标拼 infra 下载端点取字节。
- **为什么不存 url**：url 是"钥匙"（`@PermitAll`，持有即可访问），且存储迁移后会失效；存"坐标"则不是可访问地址。

### 4.3 病毒字段统一（按规范）

- **统一名**：VO `virusStatus` / 库列 `virus_status`，取值 `UNKNOWN / CLEAN / INFECTED`（沿用外部公告附件参考实现）；
- **统一行为**：`INFECTED` → **拒绝下载**（补齐既定义了却从未抛出的错误码语义）；
- 证照域现有 `virusScanStatus`（字典 `cert_virus_scan_status`）**保留兼容但不再新增使用**，读侧以 `virusStatus` 为准。

### 4.4 错误码（101 段「公告与文件」顺延，016~019 已被发售期占用 → 用 020~）

| 码 | 含义 |
| --- | --- |
| `1_060_101_020` | 文件不存在（fileId 无对应登记） |
| `1_060_101_021` | 文件未通过病毒扫描，禁止下载 |
| `1_060_101_022` | 文件存储坐标解析失败（url 非法/非本平台） |
| `1_060_101_023` | 文件内容读取失败（存储侧不可达） |

### 4.5 明确边界（写进类注释）

- `/infra/file/upload`：**业务附件禁用**，仅平台组件（头像/知识库等）可用；
- `/bidding/file/register-by-url`：**仅历史修复**，不用于新增业务。
