## 一、为什么提这个请求（不是"前端偷懒"）

棘轮门禁 `check-hardcoded-enums.js` 把「状态码/枚举值写死成 code→中文映射」冻结成基线（只减不增）。
基线里剩下的 16 处**不是不肯改**，而是**该域字典尚未注册**——前端若纯字典化，在这些字典缺席时
只能直出英文 code（比硬编码更糟）。所以前端当前的形态统一是"**字典优先、映射表兜底**"：
字典一注册、后端下发，页面自动变中文；映射表降级为兜底或直接删除。

本轮已完成的核对（**逐条对照后端权威来源，结论：16 处取值全部一致，未发现错值/漏值**）：

| 前端映射表 | 对照的权威来源 | 结论 |
|---|---|---|
| `QUAL_SERIAL_OPTIONS`(5) | `QualificationSerialEnum`（CONSTRUCTION/SURVEY/DESIGN/SUPERVISION/**TESTING**） | 一致（TESTING 在枚举末行，容易误判为"多出来的值"） |
| `STAFF_ROLE_OPTIONS`(5) | `QualificationStaffRoleEnum` | 一致 |
| `PERFORMANCE_ROLE_OPTIONS`(2) | `PerformanceRoleEnum`（GENERAL/SUB） | 一致 |
| `ASSET_TYPE_OPTIONS`(4) | `QualificationAssetTypeEnum` | 一致 |
| `REVIEW_TYPE_OPTIONS`(3) | `QualificationReviewTypeEnum` | 一致 |
| `RULE_VALUE_TYPE_OPTIONS`(5) | `RuleConfigValueTypeEnum` | 一致 |
| `RULE_STATUS_OPTIONS`(3) | `RuleConfigStatusEnum`（DRAFT/PUBLISHED/GRAY/**ROLLED_BACK**） | 一致——少的那 1 个**是有意排除**（前端注释：「ROLLED_BACK 只能由回滚接口产生，故不在写入选项内」）；注册字典时应**包含**它，由前端按用途过滤 |
| `RULE_HIT_SOURCE_OPTIONS`(4) | `RuleConfigAuditPageReqVO` 字段注释「TENANT / GRAY / PLATFORM / FALLBACK」 | 一致（**无枚举**，仅注释） |
| `TASK_STATUS_MAP`(5) | `CrawlTaskStatusEnum` | 一致 |
| `NOTICE_STATUS_LABEL`(4) | `NoticeStatusEnum` | 一致 |
| `FILING_STATUS_OPTIONS`(3) | `FilingStatusEnum` | 一致（filing_status 字典**已注册**，前端已字典优先） |
| `SUBJECT_TYPE_LABEL`(2) | `SubjectTypeEnum`（另有 AGENCY=扩展位未落地） | 一致（subject_type 字典**已注册**；选项侧有意排除 AGENCY，避免产出后端未支持的数据） |
| `RESULT_FALLBACK`(3) / `STATUS_FALLBACK`(4) | `EnterpriseMaterialResultEnum` / `EnterpriseMaterialStatusEnum` | 一致（命名即口径：仅字典未下发时兜底） |
| `MANUAL_STATUS`(3) | `CrawlParseTestRespVO.status` 注释「SUCCESS/PARTIAL/FAILED」 | 一致（**无枚举**，仅 VO 注释） |

这四类前端只能按现有实现/注释推断，**前端不臆造也不擅自改动**，请后端确认或补枚举后再注册：

## 四、验收口径（字典注册后前端如何验证与收敛）

1. `bidding_dict_data` 存在对应 `dict_type` 且值/文案与上表一致（硬约束：值域可后台调整）；
2. `GET /bidding/meta/dicts` 下发这些类型（**注意与契约 12 的相互作用**：读取面不放开的话，
   注册了字典的页面反而会从"本地映射表中文"退化成"英文 code"——这是两份契约必须一起裁定的原因）；
3. 前端按"字典优先、映射表兜底"切换后，棘轮基线对应条目**逐条删除**（只减不增）；
4. 每个 dict_type 注册后请在本文件回填一行"已注册 + 日期"，便于前端收尾。
