# 29 外部 CA 与身份认证对接清单（2026-09-18）

> 对应需求：最严格环节招投标流程 —— CA 加密、身份认证均对接外部接口（本平台不做自研 CA）。
> 用户将按本清单提供接口资料，我方按资料对接落地。
> 相关库表：bidding_process_track（投标文件加密/签名）、bidding_opening_member（进开标房间身份认证）、bidding_subject_profile（企业 CA 证书映射，待加）。

## 一、对接总览

| # | 接口类别 | 业务场景 | 典型算法/协议 | 对接形态 |
|---|---|---|---|---|
| 1 | **CA 证书登录认证** | 用户持 CA 证书登录平台，核验身份并映射到企业/个人 | 客户端证书 / 证书 DN 解析 | 客户端控件取证书 + 服务端调 CA 验证 |
| 2 | **证书有效性验证** | 进开标房间时二次核验证书（未吊销/未过期/在有效期） | OCSP / CRL / 平台查询接口 | 服务端 API |
| 3 | **数字签名 / 验签** | 投标文件签名（身份绑定+防篡改）；开标/评审验签 | SM2 签名验签（国密） | 服务端 API（必要时客户端控件预签名） |
| 4 | **数据加密 / 解密** | 投标文件加密递交；开标时解密 | SM2 非对称 + SM4 对称（密钥由证书保护） | 客户端加密 + 服务端解密 |
| 5 | **可信时间戳（可选）** | 递交/签名时间固证 | TSA（RFC3161） | 服务端 API |

## 二、逐接口需求详情（需要对方提供的接口）

### 接口 1：CA 证书登录认证（登录 / 进房复用）

- 触发场景：投标人/招标人登录平台（或进开标房间时）
- 我方处理流程：
  1. 前端 CA 客户端控件读取本机证书 → 提交证书序列号 / DN / 公钥
  2. 调外部认证接口验证证书 → 返回身份信息（企业名称、统一社会信用代码、证书有效期）
  3. 映射我方主体库 bidding_subject_profile → 建立会话
- 需要对方提供的接口资料：
  - 认证接口地址 + 协议（HTTP REST / WebService / 双向 TLS）
  - 入参：证书编码（PEM/DER/base64）/ 序列号
  - 出参：企业名称、统一社会信用代码、证书序列号、颁发者、有效期起止、吊销状态
  - 测试环境根证书 / 测试企业证书样例

### 接口 2：证书有效性验证（进开标房间二次核验）

- 触发场景：用户点击「进入开标房间」→ 后端调此接口核验证书状态 → 通过才 AUTHED 进房（bidding_opening_member.auth_result）
- 需要对方提供的接口资料：
  - 验证接口地址 + 协议
  - 入参：证书序列号 / 证书本体
  - 出参：有效/无效 + 原因（吊销/过期/不存在）
  - 或提供 OCSP 地址 / CRL 分发点

### 接口 3：数字签名 / 验签（投标文件）

- 触发场景：
  - 签名：投标人上传投标文件时，对文件 SM3 摘要签名（SM2），签名值存 bidding_process_track.document_signature
  - 验签：开标解密后、评审前，验证签名有效（防篡改 + 身份绑定）
- 需要对方提供的接口资料：
  - 签名接口：入参（待签摘要 hex / 证书序列号 / 私钥会话）→ 出参（签名值 base64）
  - 验签接口：入参（原文摘要 / 签名值 / 证书或公钥）→ 出参（验签结果 bool + 摘要比对）
  - 是否支持服务端持钥签名（或必须客户端控件签名后上送签名值）

### 接口 4：数据加密 / 解密（投标文件）

- 触发场景：
  - 加密：投标人投标文件加密后上传（SM4 对称加密文件 + SM2 公钥加密 SM4 密钥；或平台方分发公钥）
  - 解密：开标时平台持私钥解密投标文件 → 唱标
- 需要对方提供的接口资料：
  - 加密接口（客户端用）：入参（明文文件/密钥）→ 出参（密文 + 加密密钥信封）
  - 解密接口（服务端用）：入参（密文 + 信封）→ 出参（明文）
  - 密钥管理体制说明（谁生成密钥、谁保管私钥、是否有密钥托管/恢复服务）

### 接口 5：可信时间戳（可选，最严格取证）

- 触发场景：投标递交 / 签名固化时间
- 需要对方提供的接口资料：TSA 地址、请求响应格式（RFC3161）、测试时间戳样例

## 5.3 扫码三阶段流程（CA 互认形态：登录/签名/解密）

外部 CA 互认体系为扫码异步形态（非同步返回签名/解密结果）：

| 阶段 | 登录认证 | 签名 | 解密（开标） |
|---|---|---|---|
| 1 生成二维码 | createLoginRequest | createSignRequest(digestHex) | createDecryptRequest(decryptionUserType, orgCode, idCardHash) |
| 2 轮询扫码状态 | queryLoginStatus(tid) | querySignStatus(tid) | queryDecryptStatus(tid) |
| 3 取结果 | fetchAuthInfo(tid) | fetchSignatureValue(tid) | fetchDecryptUserInfo(tid) → uploadDecryptEnvelope(tid, accessToken, envelopes) → fetchDecryptedData(tid) |
| SDK 方法 | SharedLoginRegistration.generateLoginQRCode / queryQRCodeScannedStatus / getUserAuthInfo | MessageSignature.generateMessageSignatureQRCode / queryQRCodeScannedStatus / getMessageSignatureValue | MessageDecrypt.generateMessageDecryptQRCode / queryQRCodeScannedStatus / getDecryptUserInfo / uploadEncryptedKeyDataEnvelope / getDecryptedData |

> 注：扫码状态语义——queryQRCodeScannedStatus 返回 scannedStatus（01 已扫 / 00 未扫）；签名场景「已扫码即已完成签名」（无独立 signed 字段，QueryQRCodeScannedStatusResultDTO 无独立已签名字段），故 querySignStatus.signed = scanned。
