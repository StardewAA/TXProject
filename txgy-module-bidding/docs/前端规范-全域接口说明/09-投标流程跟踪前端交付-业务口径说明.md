# 09 投标流程跟踪前端交付——业务口径说明

> 读者：前端同学。页面：招投标(6735) → 投标流程跟踪(6748)，组件 bidding/processTrack/index。
> 接口现状：唯一真实接口 fetchMyFollowPage → GET /bidding/notice-follow/item/page（bidding:notice-external:query）。

## 1. 一句话结论（v1 现状）

**“投标流程跟踪”v1 = “我的关注/意向”视图：以当前登录人（自然人账号）的关注条目为数据源；阶段跟踪在浏览器本地维护，不落后端。**
后端状态机尚未实现（见 §5），页面不要假设存在任何 process-track 后端写接口。

## 2. 业务口径（与主体域 A 方案一致）

- 跟踪对象 = 外部公告（投标机会），由登录人“关注”产生意向（notice-follow item，user_id 粒度，见 07 §3）；
- 同一企业多个业务员：各自关注各自跟踪，互不合并（对应 A 方案“资格归企业、跟踪归个人”）；
- 页面数据流：加载时调 item/page 拉“我的关注”，其余阶段信息来自 localStorage（key：txgy.bidding.processTrack.v1）。

## 3. 契约类型如何用（避免把本地类型当接口）

- FollowItem：真实后端行。id/followKey/followType/displayName/issuerName/stageCode/stageName/followTime。
- Track / TrackEvent / StateCode / EventCode：前端本地跟踪模型，与后端无对应接口；注释写的是“未来字段对齐”。
- 状态字典（契约）：INTENTION(意向) → QUALIFICATION_REVIEW(资质审核) → PENDING_BID(待投标) → BIDDED(已投标) / TERMINATED(流程结束)；
  事件：CREATE/REGISTER/APPROVE/REJECT/UPLOAD_DOCUMENT/CANCEL。v1 页面用它在本地推进阶段即可。

## 4. 阶段流转预期（后续状态机落地时的同一套语义，前端可先按此做交互）

| 阶段 | 触发 | 说明 |
| --- | --- | --- |
| INTENTION 意向 | 关注公告自动建档 | 有意愿跟进，未报名 |
| QUALIFICATION_REVIEW 资质审核 | 报名（手动标记） | 平台/招标方核资格 |
| PENDING_BID 待投标 | 审核通过 | 等待投标截止，倒计时/提醒 |
| BIDDED 已投标 | 上传标书 | 需登记标书（名称/大小/文件） |
| TERMINATED 结束 | 审核不通过或取消 | 终态，可附原因 |

## 5. 后端状态机为何尚未实现（告知/对齐用）

- 现役“意向”已由关注闭环覆盖（notice-follow，含事件/已读/时间线），无需再造一份意向表；
- 报名/审核/投标文件等能力依赖业务方确认（是否允许在线报名、审核角色、标书存储），设计文档已就绪（docs/前端规范-全域接口说明/投标流程跟踪功能设计方案.md），
  等口径确认后按 bidding_process_track/event 两表实现状态机接口，届时 Track 改为后端数据，前端不再用 localStorage 拼状态。

## 6. 前端易错点清单

- [ ] 不要把 Track 当后端实体调用——后端本期没有 process-track CRUD 端点；
- [ ] 列表必须按当前登录人过滤（后端 item/page 本身就按 user 返回，别做企业级合并）；
- [ ] 关注后阶段从 INTENTION 开始；不产生后端状态变更动作（关注动作在公告详情页的 follow/unfollow，权限 bidding:notice-external:update）；
- [ ] id 兼容 number|string（雪花 Long 序列化）；时间戳用 number(ms)；
- [ ] 页面上“资质审核/上传标书”等操作按钮（菜单 6749-6752 的权限 bidding:process-track:*）本期无后端端点，点击应提示“该能力待上线”，不要静默失败。

## 7. FAQ（对话术）

- Q：为什么我用另一个账号登录看不到同事的跟踪？A：意向与跟踪按个人账号保存（A 方案），企业共享视图属新增需求。
- Q：审核通过/上传标书按钮点了没反应？A：后端状态机尚未上线，按钮为占位；正式能力接入后会同步本说明。
- Q：本地数据会不会丢？A：v1 阶段存在浏览器 localStorage，清缓存会丢；正式状态机上线后以服务端为准。

## 8. 后端约束对照（2026-09-09 实测代码）

| 规则 | 后端是否强制 | 依据 |
| --- | --- | --- |
| 数据按登录人隔离 | ✅ 强制 | item/page、status、timeline、read 全部由后端取 getLoginUserId()，前端无需也不能传他人 userId |
| 关注目标类型白名单 | ✅ 强制 | follow：targetType 仅 ANNOUNCEMENT/PROJECT/TENDER_PROJECT/SECTION，拼写错误直接拒绝 |
| 关注幂等/取消幂等 | ✅ 强制 | 重复关注转 FOLLOWING 不重复插；unfollow 不存在/已取关直接返回 |
| 阶段状态机（报名/审核/上传标书等） | ❌ 后端未实现 | 本期无 bidding:process-track 写端点；本地 Track 为前端维护 |
| 占位按钮（6749-6752 权限 bidding:process-track:*） | ❌ 无对应后端校验 | 前端点击应提示“待上线”，不得静默或伪造状态 |
| 公告变更/发布订阅通知 | ✅ 强制 | NoticeServiceImpl 发布/修订 fanout（NOTICE_PUBLISHED/UPDATED）→ 关注者事件落库（见 08 §8） |
| 时间线/已读 | ✅ 强制 | /item/{id}/timeline、/item/{id}/read（read 标记后未读数更新） |
