# 统一候选接口（options）契约 —— 消灭前端"手输主键"（2026-09-15）

> 规范依据：《招投标模块开发规范》§4.4（菜单/权限码与接口同步）、§5 三-7（枚举以 code 存储）。
> 用户口径 2026-09-15「统一接口」：把散落在各页面的"手输主键"收口成一套接口。
> 同族接口：/bidding/meta/dicts（枚举，见 doc 12）、/bidding/meta/configs（阈值）、/bidding/meta/options（候选，本文件）。
> 相关：《11-文件上传与file_id契约-2026-09-10》（fileId 必须来自上传响应，禁止手填）。
> 后端实现：MetaOptionController + BiddingOptionService(Impl) + BiddingOptionTypeEnum + OptionItemRespVO；单测 BiddingOptionServiceImplTest。

---

## 一、根因（实测，非推测）

前端 views/bidding 下实测 **26 处** 把内部主键做成手输框（`<a-input-number v-model:value="*Id">`）：

| 文件 | 处数 | 字段（行号） |
|---|---|---|
| personnel/index.vue | 12 | recordPersonId:1011、query.personId:1094、boardEntId:1178、countEntId:1243、multiForm.personId:1284、profileForm.entId:1378、trainingForm.fileId:1563、socialForm.evidenceFileId:1610、contractForm.fileId:1654、form.personId:1768、form.entId:1772、form.fileId:1854 |
| qualification/index.vue | 7 | applyQuery.qualId:1502、elemQualId:1598、reviewQuery.qualId:1655、form.bindedCertId:2306（注释已写明 certificate_info id）、staffForm.bindedCertId:2483、permitForm.entId:2591、permitForm.bindedCertId:2617 |
| safety-risk/index.vue | 4 | multiForm.personId:416、personId:465、projectId:503、assignForm.projectId:603 |
| certificate/lifecycle/index.vue | 1 | query.bizId:293（**多态**对象主键，见 §3 备注） |
| certificate/modules/cert-form.vue | 1 | form.holderId:333（关联档案 ID，按 holderType 决定主体/人员） |
| certificate/modules/material-check.vue | 1 | entId:98（企业主体 ID 必填） |

最刺眼的一处：`certificate/modules/lifecycle-apply.vue:445` 的 placeholder 写着
`如 1024,1025（先在「文件版本」上传取得 fileId）`——要求用户去另一个页面把 fileId 抄回来。

危害按严重度排序：

1. **数据污染（最严重）**：主键填错不报错。证照 `holder_id` 写错一位，就静默挂到别的企业/个人名下，
   "谁有什么证"这个事实被污染，事后只能靠人工核对发现。
2. **不可用**：内部雪花 ID 不是给人记的，运营/投标专员被迫到别的页面抄数字；抄不到就只能乱填。
3. **精度风险**：雪花 ID 超过 JS 安全整数（2^53），前端若按 Number 处理会被静默改写（看着是 A、提交成 B）。

根因不是前端"偷懒"：此前后端**没有任何候选接口**（全量检索 GetMapping，无 options/simple-list/list-all 风格端点），
前端拿不到可选值，只能退化成输入框。

## 二、接口契约

### 2.1 端点与参数

`GET /admin-api/bidding/meta/options`

| 参数 | 必填 | 类型 | 说明 |
|---|---|---|---|
| type | 是 | String | 候选类型，见 §2.2 |
| keyword | 否 | String | 模糊匹配该类型的名称/编号列 |
| limit | 否 | Integer | 返回上限：默认 20，最大 50（>50 按 50；<1 按默认值） |

响应：`CommonResult<List<OptionItemRespVO>>`

| 字段 | 类型 | 说明 |
|---|---|---|
| value | String | 主键十进制字符串。**前端必须原样回传，禁止 Number() 转换** |
| label | String | 展示名（名称全空时回落为"未命名"） |
| extra | String / null | 区分同名对象：统一社会信用代码 / 证书编号 / 工号 / 发证机关 |
| disabled | Boolean | true＝置灰但**保留展示**（失效证照、离职人员），前端不要过滤掉 |
| status | String / null | 该行业务状态 code，配合 `/bidding/meta/dicts` 取中文名与标签色 |

type 不支持时返回 `code=400`，message 列出全部可选值；**不返回空列表**
（空列表会让前端误以为"该类型就是没数据"，把参数写错当成业务无数据）。

### 2.2 type 与数据源对照

| type | 数据源表 | label 取 | extra 取 | status 取 | disabled 规则 |
|---|---|---|---|---|---|
| SUBJECT | bidding_subject_profile | subject_name | uscc | — | 永不禁用（主体无可用性状态） |
| PERSONNEL | bidding_personnel_profile | person_name | person_no | personnel_status | 复用 `PersonnelStatusEnum.isUsable`：仅在职可用，离职/停职/退休置灰；字典外状态保守置灰 |
| PROJECT | bidding_project | project_name | project_code | state | 永不禁用（招标阶段不代表对象不可选） |
| CERTIFICATE | certificate_info | cert_name | cert_no | cert_status | 仅 ACTIVE / EXPIRING_SOON 可选 |
| QUALIFICATION | enterprise_qualification | cert_no（缺则 qual_serial） | qual_serial · qual_grade | qual_status | 仅 VALID / EXPIRING_SOON 可选 |
| SAFETY_PERMIT | qualification_safety_permit | permit_no | issuing_authority | permit_status | 仅 VALID / EXPIRING_SOON 可选 |
| PERSONNEL_CERT | personnel_certificate | cert_name | cert_no | cert_status | 同 CERTIFICATE |

一律按 `id DESC`（最新在前）。状态为空（存量/未评估）**不禁用**：不能因为"没填状态"就把可用数据挡在外面。

### 2.3 权限（与 /bidding/meta/dicts 同口径，见 doc 12）

```java
@PreAuthorize("@ss.hasAnyPermissions('bidding:certificate:query', 'bidding:qualification:query', "
        + "'bidding:personnel:profile:query', 'bidding:certificate:lifecycle:query', "
        + "'bidding:qualification:permit:query', 'bidding:subject:query')")
```

理由：候选值是**跨页面前置元数据**，绑死单域权限会让其它域下拉取不到值、又退回手输。
上述 6 个权限码已核对：均已注册在 `system_menu`。

### 2.4 前端三条硬约束

1. 表单里不得再出现绑 `*Id` 的 `a-input-number`（可做静态门禁检查）；
2. `value` 原样回传，不要 `Number()`；
3. `disabled=true` 置灰不过滤。

### 2.5 fileId 不走本接口

文件没有"可枚举候选"语义。`fileId` 必须来自 `POST /bidding/file/upload` 的响应 `fileId`
（doc 11：上传成功必须返回 file_id；前端禁止手填文件 ID）。
因此 26 处中的 4 处 `fileId`（personnel 1563/1610/1654/1854）修复方式是**接上传组件**，不是查候选接口。

## 四、实测记录（2026-09-15，本机 48110 直连 + admin 登录）

- 单测：`BiddingOptionServiceImplTest` 8 用例全绿（含 limit 截断、未命名回落、状态白名单、PersonnelStatusEnum 镜像）；
- 全模块：`mvn -o -pl txgy-module-bidding/txgy-module-bidding-server test` → BUILD SUCCESS；
- 接口实测：
  - `type=SUBJECT` → code=0，1 条：`{value:"182143816674785", label:"西安鸥鹏互联科技有限公司", extra:"91610100MAM94DYHJ0", disabled:false}`（value 为字符串，未丢精度）；
  - `type=CERTIFICATE` → code=0，3 条，含 status=ACTIVE / EXPIRING_SOON，extra 为证书编号；
  - `type=CERTIFICATE&keyword=营业执照` → 2 条（keyword 生效）；
  - `type=PROJECT / PERSONNEL / QUALIFICATION` → code=0，0 条（表内暂无数据，非报错）；
  - `type=FILE` → code=400，msg=「候选类型不支持：FILE（可选：SUBJECT/PERSONNEL/PROJECT/CERTIFICATE/QUALIFICATION/SAFETY_PERMIT/PERSONNEL_CERT）」；
  - `limit=999` → 被截到上限 50；
  - 无 token 直连 → `{"code":401,"msg":"账号未登录"}`（与平台其它 admin 接口一致；HTTP 状态码仍为 200 是本平台约定，非越权）。

## 五、边界与不做

- 不做全量列表：`limit ≤ 50` + keyword，防止大表全表扫描；
- 不做跨租户：数据源 DO 均为 TenantBaseDO，租户过滤由框架拦截器统一处理，本 Service 不手写 tenant_id / deleted 条件；
- 不返回文件 / URL：文件语义见 doc 11；
- 本次**未改任何前端文件**（改造清单见 §3，交前端负责人执行）；
- 未加 BID_SECTION / TENDER_PROJECT：当前 26 处无此需求。扩展成本 = 枚举加一个值 + Service 加一个 loader 方法
  （switch 表达式是穷尽的，漏加 case 会编译报错，不会静默返回空）。
