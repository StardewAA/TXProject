# 前端术语表（招投标域 · 2026-09-14）

- 目的：**同一业务对象只有一个界面名**，且与后端实体名有登记映射；同时把"**看着像不一致、实际是两个对象**"的词固定下来，
  防止下一轮"统一"把它们错误合并（本文件就是为此写的）。
- 测量方式：`node sql/tools/report-terminology.js`（只统计**引号内界面文案**，不看注释与变量名，避免误报）。
- 依据：后端 VO 的 `@Schema(description = "管理后台 - …")`、一键包 SQL 注释、`system_menu.name`、以及各枚举/DDL 注释。

## 二、看着像不一致、**实际是两个对象/两种动作**（禁止合并，已核查）

| 词组 | 为什么不能统一 |
|---|---|
| 项目 / 招标项目 | `ProjectRespVO` 与 `TenderProjectRespVO` 是**两张表两个 VO**（352 处混排是正常业务关系） |
| 资质 / 证照 / 证书 | 资质=企业资格等级（Qualification 域）；证照=电子证照全生命周期（Certificate 域，"证照台账"）；证书=具体证书件（如人员证书编号）——三者有各自的表与状态机 |
| 审核 / 审批 / 复核 / AI 审查 / 人工审查 | 审核=总体审核动作；审批=证书延续等**决定**环节；AI 审查/人工审查=`auditSource` 的两个取值（VO 里就是这两个词）；复核=二次核对。语义不同，且 `auditStageName` 由后端合成、前端原样显示 |
| 抓取 / 采集 / 获取 / 下载 | 采集=领域总称（实体名：采集源/采集批次/采集任务）；抓取=发起请求（"抓取间隔"沿用后端字段口径）；获取=取数动作（界面按钮/提示统一用词）；**下载=原文下载阶段**（受 `CrawlDownloadGate` 限速闸约束）。`crawlExternal/labels.ts` 已把"列表发现/原文下载"两个阶段词固定 |
| ~~爬取~~（**已废弃**） | 2026-09-14 统一：界面动作一律"获取"、领域实体一律"采集"；FE 全仓已清零（`爬虫` 保留，指 CRAWLER 解析器这一技术实体） |
| 任务条 | 控制台刻意的 UI 隐喻（横向条状行），不是"任务"的错别字 |
| 申请延续至 | 动词短语，非"申报"名词的异写 |

## 三、本轮改动

1. `source/index.vue`："新增采集源" → **新增信息源**（同页标题/删除确认都已是"信息源"）；
2. `console/index.vue`：用户可见提示"请在**源配置**里补 baseUrl" → **信息源配置**；配套注释同步；
3. `source-drawer.vue`：抽屉注释「采集源配置」→「**信息源配置**」，并写明后端实体名与表名，避免下次又被当成不一致；
4. `NoticeWorkbench.vue`：**自营公告 → 内部公告**（4 处：头注释、待办注释、KPI 注释、用户可见角标）。

## 四、复跑方式

```bash
cd txgy-module-bidding && node sql/tools/report-terminology.js          # 打印各同义词族的使用分布与"同文件混用"
cd txgy-module-bidding && node sql/tools/report-terminology.js --family 信息源   # 只看某一族
```
该脚本**不设阈值、不进 check-all**：术语属于"人对齐"的范畴，硬编码正则判定容易把合法区别（见第 2 节）误判为缺陷；
它的价值是**让人一眼看到哪一页在同一件事上换了词**。
