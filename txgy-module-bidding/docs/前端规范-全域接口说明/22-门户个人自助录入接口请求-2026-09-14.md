# 契约 22：门户「个人自助录入」需要后端给出自助侧接口/权限

- 提出方：前端（招投标前台）
- 日期：2026-09-14
- 背景：用户在门户里**找不到"个人录自己档案"的地方**。核查结论：门户 `views/portal/bidding/profile.vue` 目前是
  **二期占位页**（页面正文只有一句"二期建设中 —— 展示自身主体信息与办理入口"），而承载真实数据的
  `personnel-profile` / `personnel-certificate` 写入端点**全部是管理端权限**：
  `bidding:personnel:profile:create|update`、`bidding:personnel:cert:create|update|delete`（见 §8.x 契约与菜单 600053xx 段）。
  也就是说：**普通登录人没有任何接口可以录自己的档案/证书**，不是前端没做，是权限面与端点面都缺。

## 1. 期望（前端能接的最小集）

| 能力 | 建议端点 | 权限码（建议） | 说明 |
|---|---|---|---|
| 读自己的档案 | `GET /bidding/personnel-profile/my` | `bidding:personnel:profile:self` | 后端按 `getLoginUserId()` 定位自然人，**不接受 personId 入参**（防越权） |
| 维护自己的档案 | `PUT /bidding/personnel-profile/my` | 同上 | 字段白名单：联系方式/学历/职称/银行卡等**非企业认定项**；企业认定项（在职状态/岗位/工号）只读 |
| 读自己的证书 | `GET /bidding/personnel-certificate/my` | `bidding:personnel:cert:self` | 含 `isCurrent`（现行/历史），与按人查口径一致 |
| 提交/维护自己的证书 | `POST /bidding/personnel-certificate/my` | 同上 | **建议走"提交待企业确认"**：证书属企业资质证据，个人自报后应由企业侧确认才生效 |

## 2. 关键设计问题（需业务先定）

① **个人自报的证书要不要企业确认？** 若要，需新增状态（如 `PENDING_CONFIRM`）与确认动作；
   若不要，个人可直接影响企业资质证据链，合规风险高。
② **档案归属**：自然人可能隶属多个租户（A 方案：资格归企业、操作与跟踪归个人）。"我的档案"是**跨租户一份**还是**租户内一份**？
   这决定端点是否需要租户入参。
③ 身份证等敏感字段：现管理端是"仅提交、回读脱敏"（见 personnel 页口径）。自助侧是否沿用？

## 3. 前端接法（拿到接口即可落地，无需再改结构）

门户「个人中心」（`/portal/profile` 与 `/portal/bidding/profile`）已有路由与入口，接法：
- 页内三块：**我的档案**（可编辑白名单字段）/ **我的证书**（列表 + 新增/编辑 + 现行/历史标记）/ **办理入口**（实名认证等）；
- 复用后台已建的组件与字典（`person_cert_type`/`person_cert_status`/`edu_level`）；筛选与表单统一用平台主题（本轮已把筛选改成前台那种"属性名 + 文字选项"样式）；
- 准入仍走门户已有的 `usePortalCan()`（权限未下发时放行、最终由后端裁决）。

## 4. 前端**不做**的事（避免越界）

- 不在前端"假装"能录：占位页保持明确说明，不做本地暂存（个人档案是权威数据，本地暂存会造成"录了但系统没有"）；
- 不自行放宽权限码：门户复用管理端权限码会等于绕过企业侧确认，属业务决策。
