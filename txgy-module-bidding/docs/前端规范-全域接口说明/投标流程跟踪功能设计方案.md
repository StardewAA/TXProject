# 投标流程跟踪功能 - 详细设计方案

## 一、需求分析

### 1.1 功能概述
在个人登录后的招投标模块中，新增**投标流程跟踪**功能，实现对投标全流程的状态管理和跟踪。

### 1.2 流程阶段
```
意向投标 → 资质审核 → 待投标 → 已投标
   ↓          ↓(失败)
  关注      流程结束
```

### 1.3 状态转换规则
- **意向投标**：员工关注项目后自动进入
- **资质审核**：员工手动报名后（外部系统），手动标记进入审核
- **待投标**：审核通过后自动进入（手动选择通过/不通过）
- **已投标**：上传标书后自动进入
- **流程结束**：审核不通过时结束

## 二、技术方案设计

### 2.1 状态机设计

#### 2.1.1 状态定义（State）
```java
public enum BiddingProcessState {
    INTENTION("意向投标", "员工关注项目"),
    QUALIFICATION_REVIEW("资质审核", "报名后等待审核"),
    PENDING_BID("待投标", "审核通过，准备标书"),
    BIDDED("已投标", "已上传标书"),
    TERMINATED("流程结束", "审核不通过或取消");
}
```

#### 2.1.2 事件定义（Event）
```java
public enum BiddingProcessEvent {
    FOLLOW_PROJECT("关注项目"),           // 触发：意向投标
    REGISTER("报名投标"),                  // 触发：资质审核
    APPROVE("审核通过"),                   // 触发：待投标
    REJECT("审核不通过"),                  // 触发：流程结束
    UPLOAD_DOCUMENT("上传标书"),           // 触发：已投标
    CANCEL("取消投标");                    // 触发：流程结束
}
```

#### 2.1.3 状态转换图
```
[意向投标] --报名投标--> [资质审核]
                            |
                    审核通过 |  审核不通过
                            ↓        ↓
                        [待投标]  [流程结束]
                            |
                        上传标书
                            ↓
                        [已投标]
```

### 2.2 技术选型

#### 方案一：Spring State Machine（推荐）
**优点**：
- Spring 官方支持，集成度高
- 功能完善，支持状态持久化
- 支持状态监听、拦截器
- 可视化配置

**依赖**：
```xml
<dependency>
    <groupId>org.springframework.statemachine</groupId>
    <artifactId>spring-statemachine-core</artifactId>
    <version>3.2.1</version>
</dependency>
```

#### 方案二：轻量级枚举状态机
**优点**：
- 无额外依赖
- 简单轻量
- 易于维护

**适用场景**：状态转换简单、规则固定

## 五、核心功能设计

### 5.1 状态机配置示例（Spring State Machine）

```java
@Configuration
@EnableStateMachine
public class BiddingProcessStateMachineConfig 
    extends StateMachineConfigurerAdapter<BiddingProcessState, BiddingProcessEvent> {

    @Override
    public void configure(StateMachineStateConfigurer<BiddingProcessState, BiddingProcessEvent> states)
            throws Exception {
        states
            .withStates()
            .initial(BiddingProcessState.INTENTION)          // 初始状态
            .states(EnumSet.allOf(BiddingProcessState.class))
            .end(BiddingProcessState.TERMINATED);            // 终止状态
    }

    @Override
    public void configure(StateMachineTransitionConfigurer<BiddingProcessState, BiddingProcessEvent> transitions)
            throws Exception {
        transitions
            // 意向投标 -> 资质审核
            .withExternal()
                .source(BiddingProcessState.INTENTION)
                .target(BiddingProcessState.QUALIFICATION_REVIEW)
                .event(BiddingProcessEvent.REGISTER)
                .action(registerAction())
            .and()
            // 资质审核 -> 待投标（通过）
            .withExternal()
                .source(BiddingProcessState.QUALIFICATION_REVIEW)
                .target(BiddingProcessState.PENDING_BID)
                .event(BiddingProcessEvent.APPROVE)
                .action(approveAction())
            .and()
            // 资质审核 -> 流程结束（不通过）
            .withExternal()
                .source(BiddingProcessState.QUALIFICATION_REVIEW)
                .target(BiddingProcessState.TERMINATED)
                .event(BiddingProcessEvent.REJECT)
                .action(rejectAction())
            .and()
            // 待投标 -> 已投标
            .withExternal()
                .source(BiddingProcessState.PENDING_BID)
                .target(BiddingProcessState.BIDDED)
                .event(BiddingProcessEvent.UPLOAD_DOCUMENT)
                .action(uploadDocumentAction());
    }
}
```

## 十、注意事项和风险点

### 10.1 技术风险
1. **状态机持久化**：需要确保状态机状态与数据库一致
2. **并发控制**：多个操作同时进行时的状态冲突
3. **事务管理**：状态变更和数据库操作需在同一事务

### 10.2 业务风险
1. **手动操作依赖**：依赖员工手动标记审核结果，可能存在遗忘或错误
2. **外部系统集成**：报名操作在外部系统，需要明确对接方式
3. **历史数据迁移**：现有关注项目如何迁移到流程跟踪

### 10.3 优化建议
1. **消息提醒**：在状态变更时发送站内信或短信提醒
2. **自动化审核**：考虑对接外部审核系统，自动更新审核结果
3. **统计分析**：提供流程分析报表，如平均耗时、通过率等
4. **权限控制**：管理员可以查看和管理所有员工的流程
