## 二、组件用法（业务页面接入）

```vue
<SealWorkbench
  v-model:open="sealOpen"
  :document="sealDoc"
  :tools-excludes="['sealValidate', 'sealRemove']"
  @sign-complete="onSigned"
/>
```

**props**

| 属性 | 类型 | 必填 | 说明 |
|---|---|---|---|
| open | boolean | 是 | 弹窗显隐（v-model:open） |
| document | SealDocumentConfig | 是 | 签章文档参数（见下节），fileKey 必填 |
| toolsExcludes | string[] | 否 | 隐藏功能项：sealAddNormal（单页）/sealAddContinued（连续）/sealAddBatch（多页）/sealAddGap（骑缝）/sealAddByWord（关键字）/sealRemove（撤章）/signatureDetail（印章详情）/sealValidate（验章）/completeSeal（完成签章按钮）/viewAttachments（签章历史）/rotateRight/find/download/print/bookMark/thumbnail |
| width / height | string | 否 | 工作台尺寸，默认 100% × 78vh |

**事件**

| 事件 | 说明 |
|---|---|
| @sign-complete | 用户在签章组件点击「完成签章」（官方 signComplete 通道，双兼容） |
| @ready | 工作台初始化完成（iframe 就绪） |

## 三、document 参数（由后端 CA 平台签发，前端不自造）

H5 组件 document 为**数组**（07 号文档 §6.2 / 官方 h5demo），元素字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| awaitingSignatureFilePath | string | 是 | 待签章文件地址（平台上传返回的网络路径） |
| awaitingSignatureFileName | string | 是 | 待签章文件名称 |
| awaitingSignatureFileType | string | 否 | 文件类型：pdf / ofd（默认 pdf；ofd 需装载 web2，当前未装载） |
| signatureFileSavePath | string | 是 | 签章后文件保存地址（平台上传接口） |
| signatureFileName | string | 否 | 签章后文件名称 |
| appId / userId / bizNo / fileKey / token | string | 视平台 | 官方 h5demo 的 JWT 模式字段（与 caShareComponentConfig 二选一由后端定） |
| extDatas | any | 否 | 自定义数据，完成签章上传时原样回传（可用于携带业务单号） |

> **后端依赖（契约待办）**：上述参数需后端对接 CA 互认共享组件后签发（tradingSystemCode、文件上传获取 networkPath、签章回调地址），**前端不产生也不存储 CA 密钥/令牌**（红线：CA 私钥不进浏览器存储）。前端封装已完成，等后端接口就绪即接入业务页面。

## 四、完成签章回调

### 后端接口对接（2026-09-28 更新：后端测试链路全部跑通）

### 八、上传文件 CA 认证检测 + 免扫码签章流程（2026-09-28 后端就绪）

> 演示口径（2026-09-20 修订）：上传 → 检测 → 未认证提示 → 确认 → 原文件预览 + 「生成签名二维码」→
> **二维码可见，旁边放「模拟已扫码（测试）」按钮**（测试阶段未取得官方 key、无法真实扫码）→ 取签名值 → 真实签章 → 返回签章后文件。
> （旧口径为"二维码展示约 2 秒自动关闭"，属盲等，已废弃。）

**新增后端接口**（契约见《后端变更通知-CA签章台账-2026-09-28.md》）：

| 接口 | 说明 |
| --- | --- |
| GET /bidding/ca/seal/check?fileId=&sha256= | 检测文件是否已 CA 认证（台账匹配，返回 caAuthed + 最近签章记录摘要） |
| POST /bidding/ca/seal/document | 文件签章（既有；每次签章直接落库 bidding_ca_seal 台账） |
| POST /bidding/ca/seal/batch | 批量文件签章（多册投标文件统一盖电子章；每份逐页盖章 + 落库台账；批内一个事务） |
| POST /bidding/ca/seal/verify?id= | 验签（既有；真实 SM2 验签回写 PASS/FAIL，演示可点验签看结果） |

**前端接线要点**：
1. 上传回调后调 check；`caAuthed=false` → 提示「该文件未 CA 认证」+ 确认「是否使用 CA 认证功能？」；
2. 确认后预览原文件（networkPath），旁边放「CA 认证」按钮；
3. 点击按钮：调 /bidding/ca/sign/qrcode 生成二维码并展示（测试态后端只下发 tid，前端用 `CaQrCode` 组件按 CA 互认同构地址**本地渲染真实可扫二维码**）；
   点旁边的「**模拟已扫码（测试）**」→ 按真实三阶段拉 `/sign/status` → `/sign/value` 取签名值；
4. 关闭后直接调 document（multipart 上传原文件）→ 返回 sealFileUrl（PDF 带红色公章）+ 签名值/证书号/SM3 指纹（已落库台账）；
5. 展示签章后文件（sealFileUrl 预览/下载）；可选调 verify 验签看 PASS 状态。
