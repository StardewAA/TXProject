# 标书智能体接口契约（A：后台知识库管理 + 智能体管理）

> 版本：2026-09-26 ｜ 归属：招投标模块 `bidagent` 子域 ｜ 面向：前台标书写作/标书审查（B/C 同学）对接
>
> 目标：A 只做"后台调优台"（管资料 / 验召回 / 调智能体）；前台要用的能力在此冻结，B/C 可直接并行开发，不需要再问字段含义。

## 1. 落点与权限

| 项 | 值 |
|---|---|
| 后台菜单 | 一级「招投标」6735 → 「标书智能体」6790 → 知识库管理 6791 / 智能体管理 6792 |
| 接口前缀 | `/admin-api/bidding/bid-agent/**`（后端直连 48110；前端走 vben 代理） |
| 权限码 | `bidding:bid-agent:query / create / update / delete / retrieve / eval / preview` |
| 授权 | 不写 `system_role_menu`：后台两页仅「招投标专员」可见，由管理员在角色界面勾选（super_admin 自动可见） |
| 写接口 | 全部 `@Idempotent`，调用必须带 `idempotency-key` 请求头 |

## 2. 材料与切片（知识库）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/material/page` | 材料分页：`docType / bidSectionCode / indexStatus / name` |
| GET | `/material/get?id=` | 材料详情 |
| POST | `/material/save` | 登记材料并入库：`docType / name / bidSectionCode / fileId / fileUrl / fileName / fileSize / validUntil` |
| POST | `/material/delete?id=` | 删除材料（含本模块切片台账） |
| POST | `/material/reindex?id=` | 重建索引（入库失败或资料更新后的修复入口） |
| GET | `/segment/page?materialId=&pageNo=&pageSize=` | 切片分页（透传底座台账，保证与向量库一致） |

绑定口径（已确认）：**TENDER 必须绑 `bidSectionCode`**；FACT / TEMPLATE 可空（跨标段复用）。
落库口径：`fileId` 是唯一依据；`fileUrl` 仅用于取内容入库与即时预览。
上传通道：沿用 `POST /admin-api/bidding/file/upload`（返回 `fileId` + `url`）。

## 3. 检索（前台写作与前台审查共用）

`POST /bidding/bid-agent/retrieve`

```json
{ "query": "安全生产许可证要求", "docType": "TENDER", "bidSectionCode": "E6100...",
  "topK": 8, "mandatory": ["安全生产许可证"] }
```

```json
{ "code": 0, "data": { "hit": true, "chunks": [
  { "chunkId": "123", "content": "……", "sourceDocName": "招标文件.pdf",
    "chapterPath": "第三章 评标办法", "pageNo": 12, "score": 0.83,
    "matchedBy": "vector", "sourceBlockIds": ["招标文件.pdf#37"] } ] } }
```

**硬约定**：`hit=false` 时前台必须转人工，不得继续生成。

## 4. 智能体配置（前台编排读取）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/agent/list` | 五类智能体列表（含 `editable`：1 后台可编辑 / 0 只读锁定） |
| GET | `/agent/get?taskType=REVIEW` | **前台按任务类型取生效配置**（`systemPrompt / model / temperature / knowledgeRoleList`） |
| GET | `/agent/get?id=` | 按编号取详情（后台编辑页用） |
| POST | `/agent/save` | 保存配置（提示词以后台为唯一事实源；`editable=0` 的项仍被拒绝） |
| POST | `/preview` | 试跑：`taskType + input + withRetrieve` → `promptSource(BID_AGENT/BUILT_IN) + output` |

审查编排取提示词的标准姿势：`GET /agent/get?taskType=REVIEW` → 用 `systemPrompt`；取不到时回退内置基线。

## 5. 精准度测试（golden set）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/eval/case/page` | 用例分页（`name / enabled`） |
| POST | `/eval/case/save` | 用例新增/修改（`query / docType / bidSectionCode / topK / expectKeywords / expectBlockIds / enabled`） |
| POST | `/eval/case/delete?id=` | 用例删除 |
| POST | `/eval/run` | 跑批：`caseIds?`（空=全部启用）+ `topK?` → `totalCount / hitCount / recall / cases[]` |

命中判定：给了 `expectBlockIds` 按溯源块号比，否则按 `expectKeywords` 在命中片段正文里比。
未命中会给 `missReason`，用于区分"资料没入库"与"切片/口径不对"。

## 6. 已知边界（写入契约，避免误期）

1. **切片编辑**：本期只提供"查看 + 重建索引"。在线编辑切片需要与向量库同步改写（删向量→重嵌入），属底座能力，接口预留为下一迭代。
2. **按标段过滤检索**：`bidSectionCode` 目前只在材料台账与用例维度生效；底座检索侧按 `projectId/projectCode` 过滤，编号映射待底座确认后补齐。
3. **检索开关与上云口径（2026-09-16 更新）**：入库/切片/召回/跑批已改为 Java 内闭环（阿里云百炼 embedding/rerank + Qdrant 容器），不再透传 Node 底座。
   `bidding.bid-agent.ai-enabled=false` 时入库会跳过并在台账写明原因、`/retrieve` 返回 `hit=false` 转人工；
   `ai-enabled=true` 但缺 `DASHSCOPE_API_KEY` 时显式报 `1_060_111_070 云端检索不可用`（不做静默降级）。
   检索支持**按标段隔离**：材料登记时选标段（TENDER 必填），召回验证/跑批可传 `bidSectionCode`。
   **关键词通道（2026-09-17 新增）**：召回改为「向量 + 关键词（MySQL FULLTEXT ngram）双通道 → RRF 融合 → rerank → 必检」，
   由 `bidding.bid-agent.retrieve.bm25-enabled`（默认 true，置 false 即回到"仅向量 + rerank"）控制；
   出参不新增字段，`matchedBy` 取值扩展为 `vector` / `bm25` / `hybrid`（双通道召回）/ `rerank`（rerank 开启时最终标记）。
   实测与复现步骤见 `24-标书智能体契约端接口（Agent到Java）-2026-09-16.md` §9。
6. **智能体平台化（2026-09-16）**：智能体管理新增「云端模型（全局一套 + 每智能体覆盖模型名/温度/max-tokens）」「技能（提示词增强包，新智能体按任务类型自动挂载）」「MCP 服务（外部 server 登记 + 连通性自检 + 单次试调）」；试跑已脱离平台 AI 模块，直接走本模块自持的云端模型并把技能片段注入 system prompt。**一键生成标书**（parse→outline→draft→fill，无模板跳过回填）已提供后台页与门户 app-api，对接说明见 `25-标书生成对接说明（前台app-api）-2026-09-16.md`；审查（REVIEW）本期只保留提示词配置、不参与生成。
4. **AI 通道**：试跑复用 `bidding.ai.*`（平台 AI 模块，租户 1 / 角色 20）；`bidding.ai.enabled=false` 时试跑报"未配置"。
5. **契约端（Node 侧 bid-agent-service 直连）**：路径 `/admin-api/bidding/bid-agent/contract/**`，不占用上表权限码——由 `@PermitAll` 免登 + `BidAgentKeyFilter` 校验 `X-Agent-Key`（`bidding.bid-agent.agent-key` 为空＝开发态不校验），且不带 `tenant-id` 头（租户由请求参数/请求体显式传入，`@TenantIgnore` 跳过租户校验过滤器，服务层再 `TenantUtils.execute` 开启过滤）。写方法带 `@Idempotent`，按「方法名+参数」MD5 在 **1 秒**内拦截重复提交（错误码 `REPEATED_REQUESTS`）；该幂等不要求调用方传任何请求头，与上表第 15 行的 `idempotency-key` 不冲突。
