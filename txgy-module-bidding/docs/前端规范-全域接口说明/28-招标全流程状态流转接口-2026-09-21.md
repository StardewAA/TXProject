# 28-招标全流程状态流转接口-2026-09-21

> 契约类型：接口说明（管理后台 admin-api，招投标模块）
> 适用范围：招标全流程状态机（规范 26）的落地服务——事件驱动的状态流转 CRUD，测试模式手动驱动、留痕全量可查
> 关联：`26-招标全流程状态机设计-2026-09-20.md`（状态定义/流转表/双模式）· `27-政府审批接口预留-2026-09-20.md`（审批 stub）

## 一、设计原则（与规范 26 §5 一致）

- **事件驱动**：业务代码禁止直接 `setStatus`；一切状态变更走 `POST /bidding/flow/transition`，内部顺序为
  ① 实体定位（bizType+bizCode）→ ② 事件→目标状态映射 → ③ 状态机 `canTransit` 双保险 → ④ 状态变更 → ⑤ 留痕落表
- **测试/实战双模式**：`bidding.flow.mode`
  - `TEST`（当前）：招标方/平台方/政府审批方点击「下一步/审批通过」手动驱动（本文档端点即测试模式操作入口）
  - `PROD`：时间驱动（定时任务：投标截止→待开标、公示期到期→下一态）+ 真实政府审批接口（替换 `GovernmentApprovalServiceImpl`，契约见 27）
- **「下一步」代替时间轴开关**：`bidding.flow.manual-advance-enabled`（缺省跟随模式：TEST=true / PROD=false；显式配置覆盖）。
  - false 时时间轴事件（BIDDING_STARTED/BIDDING_ENDED/EXPIRE，`FlowTransitionEventEnum.timeDriven=true`）手动执行报 `1060111007`，`next-actions` 自动过滤（前端按钮不渲染）；操作/审批事件不受影响。
  - PROD 联调期可配 true 临时允许手动推进，待定时任务就绪再关。
- **流转必留痕**（规范 §六-2）：操作人/操作 IP/变更前状态/变更后状态/事件/时间全量落 `bidding_flow_log`
- **新建默认草稿**：项目/招标项目/标段 `save*` 默认态由 ACTIVE 改为 DRAFT（存量 ACTIVE 数据兼容，可继续流转）

## 三、POST /bidding/flow/transition

### 请求体（FlowTransitionReqVO）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| bizType | string | 是 | PROJECT / TENDER_PROJECT / BID_SECTION（ANNOUNCEMENT 走既有公告服务） |
| bizCode | string | 是 | 业务编号（project_code / tender_project_code / bid_section_code，20~23 位层级编号） |
| event | string | 是 | 流转事件（FlowTransitionEventEnum code，见下） |
| remark | string | 否 | 流转说明/审批意见 |

### 响应（FlowTransitionRespVO）

`{ code, data: { bizType, bizCode, fromState, toState, event }, msg }`

### 事件 → 目标状态映射（测试模式「下一步」选项）

**PROJECT（ProjectStatusEnum）**

| 当前状态 | 事件 | 目标状态 |
| --- | --- | --- |
| DRAFT | SUBMIT_APPROVAL | APPROVING |
| DRAFT | CANCEL | CANCELLED |
| APPROVING | APPROVE_PASS | ACTIVE |
| APPROVING | APPROVE_REJECT | DRAFT |
| APPROVING | CANCEL | CANCELLED |
| ACTIVE | CONTRACT_SIGNED | COMPLETED（项目完结） |
| ACTIVE | CANCEL | CANCELLED |
| COMPLETED / CANCELLED | — | 终态不可流转 |

**TENDER_PROJECT（TenderStatusEnum，主链 12 态）**

| 当前状态 | 事件 | 目标状态 |
| --- | --- | --- |
| DRAFT | SUBMIT_APPROVAL | APPROVING |
| APPROVING | APPROVE_PASS | PREPARING |
| APPROVING | APPROVE_REJECT | DRAFT |
| PREPARING | PUBLISH_TENDER_NOTICE | ANNOUNCED |
| ANNOUNCED | BIDDING_STARTED | BIDDING |
| BIDDING | BIDDING_ENDED | PENDING_OPEN |
| PENDING_OPEN | BID_OPENED | EVALUATING |
| EVALUATING | EVALUATION_FINISHED | PUBLICIZING |
| PUBLICIZING | PUBLISH_RESULT_NOTICE | AWARDED |
| PUBLICIZING | OBJECTION_RECONSIDER | EVALUATING（异议复核） |
| AWARDED | ISSUE_AWARD_NOTICE | CONTRACTING |
| CONTRACTING | CONTRACT_SIGNED | COMPLETED |
| 任意非终态 | TERMINATE | TERMINATED（已归档除外） |

**BID_SECTION（BidSectionStatusEnum）**

| 当前状态 | 事件 | 目标状态 |
| --- | --- | --- |
| DRAFT | PUBLISH_TENDER_NOTICE | BIDDING（随招标公告） |
| BIDDING | BID_OPENED | EVALUATING |
| BIDDING | TERMINATE | FAILED（不足 3 家流标） |
| EVALUATING | PUBLISH_RESULT_NOTICE | AWARDED |
| EVALUATING | TERMINATE | FAILED（全部废标） |
| AWARDED | CONTRACT_SIGNED | COMPLETED |
| FAILED / COMPLETED | — | 终态不可流转 |

### 示例

```bash
# 项目立项审批通过
curl -X POST 'http://127.0.0.1:48110/admin-api/bidding/flow/transition' \
  -H 'tenant-id: 1' -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"bizType":"PROJECT","bizCode":"I6101002026000001","event":"APPROVE_PASS","remark":"同意立项"}'
# → { code: 0, data: { bizType: PROJECT, bizCode: ..., fromState: APPROVING, toState: ACTIVE, event: APPROVE_PASS } }
```

| 1060111005 FLOW_EVENT_INVALID | 事件在当前状态不可执行（含跳阶段） |
| 1060111006 FLOW_ENTITY_NOT_FOUND | 业务编号不存在 |

## 四、GET /bidding/flow/next-actions

- 入参：`bizType`、`bizCode`
- 响应：`[ { event, label, toState } ]`（当前状态可执行动作；`label` 为事件中文名，可直接渲染为「下一步」按钮）
- 前端流程：详情页 → 调本接口渲染按钮 → 点击调 transition；无动作即终态/无权限操作

## 五、GET /bidding/flow/logs

- 入参：`bizType`、`bizCode`
- 响应：`[ { bizType, bizCode, fromState, toState, event, operator, operatorIp, remark, createTime } ]`（按时间倒序）
- 用途：状态流转时间线（谁在什么时间把 X 从 A 流转到 B）；审计留痕

## 六、与既有功能的关系

- **公告**：`bidding_notice` 状态仍由既有 `NoticeService.publish/unpublish` 管理（含发布门/索引/关注扇出），本服务不直接改公告状态；招标项目在 PREPARING 执行 `PUBLISH_TENDER_NOTICE` 发布招标公告 → ANNOUNCED，**下属 DRAFT 标段自动联动 → BIDDING**（留痕备注「随招标公告发布自动联动」）
- **政府审批**：27 号契约的审批 stub 返回通过/驳回后，由调用方按本契约执行对应流转事件（APPROVE_PASS / APPROVE_REJECT / SUBMIT_APPROVAL）；PROD 接入真实审批后同样只负责结果回填，状态推进仍走本服务
- **存量数据**：已有 ACTIVE/CLOSED 裸字符串状态可继续流转（`of()` 兼容解析）；列表查询不受影响
