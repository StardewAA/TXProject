# 自营公告 PDF 预览代理请求（T 轨 notice）——前端请求 + 验收口径（2026-09-25）

## 一、问题（用户实测：点开公告 PDF 是空白）

外部公告（internalFlag=false 的采集域）**已有**字节流代理：

```
GET /bidding/notice-external/pdf?id={noticeId}      // @PermitAll @TenantIgnore
```
后端注释明确其存在理由：**"避免前端直连 infra 文件 URL（内网 host 不可达）"**。

自营公告（T 轨 notice，企业前台发布）**没有对应端点**，详情出参也没有可访问 URL：

| 项 | 现状（代码证据） |
|---|---|
| `NoticeDetailRespVO` | 只有 `pdfFileId` / `pdfSha256` / `pdfSize`，**无 `pdfDownloadUrl`**（外部域 `NoticeExternalDetailRespVO` 有该字段） |
| `NoticeController` 端点 | page / public-list / get / public-detail / create / update / publish / meta-types / reindex(-all) / unpublish / delete / exchange-deadline / exchange-gather-sync —— **无 pdf 字节流端点** |
| 前端唯一退路 | `GET /infra/file/get?id=` 取 `url`；**该接口需权限 `infra:file:query`，业务账号通常没有**（前端组件注释已写明） |
| 拿到 URL 也可能不可用 | 文件服务直连地址多为内网 host（浏览器不可达），或 http 地址在 https 页面被**混合内容拦截** ⇒ iframe 必然空白 |

**影响面（都用 pdfFileId 预览）**：门户「本平台公告详情」、门户标段公告页「版式文件」按钮、
管理端公告详情 `NoticeHtmlView` 的 L1 版式文件（查阅/下载链接）、发布工作台表单内的 PDF 预览。

**前端已做的降级（本次）**：不再给用户一块无解释的空白 iframe —— 命中"必然失败"的两类地址
（https 页面 + http 文件地址；内网/容器 host）时改为说明原因并给出"新窗口打开 / 下载"，
其余情况照常渲染并保留说明；拿不到 URL 时文案改为准确归因（不再甩锅"归档未回填"）。

## 二、请求（按推荐顺序，任选其一即可解决）

1. **参照外部域实现字节流代理（推荐）**
   `GET /bidding/notice/pdf?id={noticeId}`：后端读 `pdf_file_id` → 转发文件字节流。
   可见性分层建议（与公告可见性一致，避免越权）：
   - `PUBLISHED` + `publicLevel=SOCIAL` + `internalFlag=false` → **匿名可读**（大厅用户）；
   - `GOVERNMENT` / `internalFlag=true` → **仅本租户登录用户**（`@TenantIgnore` 慎用，需按租户校验）；
   - `DRAFT` → 仅创建者/本租户内有 query 权限者；
   - 其余（UNPUBLISHED/ARCHIVED）按"留痕只读、不对外"处理。
2. **或在 `NoticeDetailRespVO` 回传 `pdfDownloadUrl`**（FileApi 签名地址，字段名与外部域对齐）——
   前端零改动即可用（组件已支持 `url` 优先）。
3. 放开 `infra:file:query` 给业务账号（**不推荐**）：等于放开文件服务全量读面，且仍受"内网 host 不可达"限制，治不了本。

## 三、验收口径

1. 门户「本平台公告详情」/ 标段公告页点「版式文件」→ **PDF 内嵌可读**（不再是空白、不再只显示说明）；
2. 管理端公告详情 L1 版式文件出现可用的"查阅/下载"；
3. 可见性：未发布/受限公告的 PDF 对无权用户**不可读**（403 或代理不下发），且前端据此显示"不可查看"而非空白；
4. 前端确认后删除各处"需后端提供字节流代理端点"的说明性注释与降级提示。

## 四、边界（复述）

- 前端**不改后端代码、不写后端 SQL**；本文件即全部交付形态。
- 本请求与契约 12（字典读面）、13（字典注册）无关，是文件读取面的独立缺口。
