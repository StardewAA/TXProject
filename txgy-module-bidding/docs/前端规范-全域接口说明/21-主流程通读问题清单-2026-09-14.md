## 一、口径落地后的第一处硬冲突（P0）

**前台存在一整套"企业数据生产"动线，且能创建/删除企业级数据。**

| 前台路由 | 页面 | 能做的写操作 | 证据 |
|---|---|---|---|
| `/portal/bidding/projects` | `views/portal/bidding/project/index.vue` | **创建/删除项目** | 调用 `saveProject` / `deleteProject`（`api/bidding/project`） |
| `/portal/bidding/projects/:projectCode/tender-projects` | `.../project/tenderProjects.vue` | **创建/删除招标项目** | `saveTenderProject` / `deleteTenderProject` |
| `.../tender-projects/:tenderProjectCode/sections` | `.../project/bidSections.vue` | **保存标段（包）** | `saveBidSection` |
| `/portal/bidding/sections/:bidSectionCode/notices` | `.../project/notices.vue` + `NoticeCreateModal.vue` | **创建公告** | `createNotice`（`api/bidding/notice`） |
| `/portal/bidding/publish` | `views/portal/bidding/publish.vue` | 公告发布工作台 | 路由注释："公告发布（**企业前台**）" |

路由文件自己的注释就写着："**项目公告管理（前台）**：项目 → 招标项目 → 标段（包） → 公告 四级层级导航。
创建入口逐级提供（创建项目/招标项目/标段），创建公告仅放在第三级进入的标段公告列表页。"
（`router/routes/core.ts` PortalBiddingProjects 段）

**与口径的冲突**：项目主档 / 招标项目 / 标段（包）/ 公告 都是**企业产出的数据**（公告发布还要过平台审核），
按"企业在后台、个人在前台"，这套生产端管理**应当在后台**；前台应只保留个人视角。
现状是**同一批管理功能在后台也有一份**（`views/bidding/project/index.vue` 等，后台用 `can()` 包按钮隐藏无权限动作）。

**对照：前台里符合口径的部分（说明前台不是整体错位）**
`index.vue`（公告大厅，**只读**：仅 ACTIVE+SOCIAL 公开数据）、`detail.vue`、`internalHall.vue`（本平台发布公告浏览）、
`subscription.vue`（我的关注）、`profile.vue`（个人中心-投标人）、`views/portal/training/learning/*`
（个人学习/签到/弹幕，走 `/training/portal/learner/*`，天然个人维度）。

**建议（需用户确认其一）**
① 把这条四级动线整体迁到后台，前台删除（前台菜单仅：公告大厅 / 本平台发布 / 我的关注 / 个人中心 / 我的学习）；
② 若业务上确实要企业在门户自助报项目，则须在口径里写成**例外**，并给门户**独立权限码**
（现状前台复用的是后台权限码 `bidding:project:create` / `bidding:bid-section:create` / `bidding:notice:create`，
见 `views/portal/bidding/access.ts` 注释），否则"企业高权限"与"个人前台"无法在校验层区分。
