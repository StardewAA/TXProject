# 契约/指引 23：招投标菜单"找不到入口"的核对与授权指引（属 DB 数据，前端无法代改）

- 提出方：前端
- 日期：2026-09-14
- 现象（用户）："找不到企业录入电子档案、个人录入档案、以及全部（企业+个人）证照的地方"。

## 1. 页面与菜单都在，问题在"看不看得见"

前端页面与菜单 SQL 均存在（本次核查）：

| 能力 | 页面组件 | 菜单位置（终态 60005000 段） | 权限点 |
|---|---|---|---|
| 企业电子证照录入 | `bidding/certificate/index` | 资质与证书管理 → **证照台账** → 「建档」 | `bidding:certificate:create` |
| 员工档案/证书录入 | `bidding/personnel/index` | 资质与证书管理 → **员工资质** → 「建档」「登记证书」 | `bidding:personnel:profile:create` / `cert:create` |
| 全部（企业+个人） | `bidding/certificate/lifecycle/index` | 资质与证书管理 → **证件全生命周期** | `bidding:certificate:lifecycle:query` |

⚠️ 注意：这些菜单挂在**独立顶层目录「资质与证书管理」**下，**不在「招投标」菜单里**（招投标下只有 外部公告审核/信息聚合任务/投标流程跟踪/项目与标段/公告公示管理/主体信息与授权）。

## 2. 三个可能原因（按概率）

① **角色未授权**：一键包 `sql/master-credential-sync.sql` 明确"**不包含角色授权（授权属业务决策）**：超管默认放行，其他角色见包尾「授权指引」按需授权" ⇒ 非超管且未授权时菜单不显示。
② **菜单号段迁移未跑完**：本域号段经历 `60002xxx → 60004xxx → 60005xxx` 三次变更；且 **`60002000` 这个 id 后来被爬虫域复用为「外部公告采集管理」**（同名不同物）。库里若停在中间态，会看到错位/过期菜单。
③ 顶层目录折叠：见 §1 的⚠️。

## 3. 只读核对 SQL（先诊断，再动手）

```sql
-- ① 证书域菜单是否存在/挂在谁下面（含旧号段）
SELECT id, name, parent_id, path, component, visible, status, deleted
FROM system_menu
WHERE (id BETWEEN 60005000 AND 60005599) OR (id BETWEEN 60004000 AND 60004599) OR id IN (60002000, 60002110)
ORDER BY id;

-- ② 是否"同名多个目录"并存（旧号段没清干净就会出现）
SELECT id, name, path, deleted FROM system_menu WHERE name = '资质与证书管理' ORDER BY id;

-- ③ 当前角色被授予了哪些证书域菜单（空 = 看不到就是没授权）
SELECT r.id, r.name AS role_name, m.id AS menu_id, m.name AS menu_name
FROM system_role r
JOIN system_role_menu rm ON rm.role_id = r.id
JOIN system_menu m ON m.id = rm.menu_id
WHERE m.id BETWEEN 60005000 AND 60005599;
```

## 4. 授权做法（二选一，均属 DB 操作，需 DBA/后端执行）

- **A. 按包尾「授权指引」**：把 `60005000~60005599` 的菜单行授予相应角色（`system_role_menu` 插入）；权限点的**按钮级**授权同理按 role_menu 关联 `type=3` 行。
- **B. 超管账号验证**：先用超管登录确认菜单是否出现——出现即"问题①（授权）"，不出现即"问题②（号段/未执行最新包）"。

## 5. 前端的边界（如实说明）

菜单/角色/授权都是 **DB 数据**；按本项目约束，前端**只能改前端页面**、DB/后端只能提契约。
故本文只提供诊断与指引，**不代改**。前端侧已做的相邻工作：把"全部证照"做成了证照台账页内的**范围切换**
（企业证照／员工证书／全部），因此即便菜单暂时不可见，"一处看全"的能力也已在前端就位。
