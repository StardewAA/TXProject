## 三、本次修正明细

### 3.1 招标情形 `BIDDING_SITUATION`

```
修正前：1 依法必须招标 / 2 自愿招标 / 9 其他
修正后：1 国有资金控股或占主导地位的依法招标 / 2 其他情形的依法招标 / 3 自愿招标
```

原口径的三处偏差：① 代码 `2` **语义错位**——前端把「自愿招标」挂在 `2` 上，规范里 `2` 是「其他情形的依法招标」；
② 规范里的「自愿招标」是 `3`，前端缺失；③ 前端多出 `9 其他`，规范该表无此档。

佐证：后端 `api/enums/ShaanxiBiddingSituationEnum.java` 已照录规范（`CODE_1`/`CODE_2`/`CODE_3`，三档均带注释），
字典 key `bidding_bidding_situation`（`DictTypeConstants` 标注「招标情形（陕西1）」）也已注册，
**仅前端这一份与之冲突**。

危害程度：该字段 dtype 为 `C1`，`1`/`2`/`9` 均满足 1 位长度，**校验层不会报错**，只在语义层静默出错；
且该字段 `pub=政务公开`（上报政务平台），等于把「自愿招标」上报为「其他情形的依法招标」。

### 3.2 项目交易分类 `PROJECT_TRADE_TYPE`

```
修正前：1 工程建设 / 2 政府采购 / 3 国有产权交易 / 4 土地使用权和矿业权出让 / 9 其他
修正后：A 房屋建筑工程 / B 市政基础设施工程 / GD 轨道交通工程 / F 水利工程 / L 电力工程 / E 公路工程
        / D 园林绿化 / Y 其他工程 / TL 铁路工程 / TX 通讯工程 / GLYH 公路养护 / WZB 外资办
```

原口径与规范陕西代码集毫无交集。此前留的余地（字段备注引用「1.10.14 项目交易分类」而该表正文未收录）已可定案：
后端 `DictTypeConstants.PROJECT_TRADE_CATEGORY` 明确标注「**项目交易分类（陕西1）**」，
且 README §1.1 定「**取值以陕西 V2.0 为准**」、§关键约定定「**国家、陕西都有的概念以陕西为准**」，
故取第十章陕西代码集。修正后代码长度（1~4 位）与字段 dtype `C..4` 相容。

## 五、数据迁移注意

- 修正前若有项目已存 `PROJECT_TRADE_TYPE` = `1`/`2`/`3`/`4`/`9`，修正后该值不在新选项表中，
  页面会**原样回显为裸代码**（`codeLabel` 对未知代码原样展示），但**不会丢值**：
  `codeOptions(code, current)` 会把当前值并入选项，保证仍可选中/可回填。
- 建议上线前查一次库，确认是否存在这类历史值，如有需业务侧判定如何转换：
  `SELECT id, project_code, project_trade_type FROM bidding_project WHERE project_trade_type IS NOT NULL AND project_trade_type NOT IN ('A','B','GD','F','L','E','D','Y','TL','TX','GLYH','WZB');`
- `BIDDING_SITUATION` 的历史值若存过 `9`，同样会原样回显。

## 六、遗留与后续方向

根因是**存在第二份硬编码代码集**：规范、后端 `api/enums` 常量类、前端 `codeTables.ts` 各维护一份，天然会漂移
（本次即前端这一份落后）。治本方向是按既有约定，让这类选择字段改走后端统一候选接口
（`GET /bidding/meta/options?type=<OptionType>`，见 `24-统一候选接口-options-契约-2026-09-15.md`），
或读字典元数据（见 `12-字典元数据读取权限契约-2026-09-14.md`），前端不再自建代码集。
本清单可作为该改造的输入。

## 八、关联：本次验证暴露的两条前端口径（2026-09-18 补）

改完实测时出现「保存失败」，倒查出两条与代码集无关、但前端必须对齐的口径，一并记在此处：

1. **17/20/23 位内部编号由后端生成，前端不传、不显示**；`INVEST_PROJECT_CODE`（24 位投资项目统一代码）
   是**唯一需要用户输入的编号，必填**。依据：《后端变更请求-编号体系归位》§二/§六（用户裁定 + 后端已落地）。
   前端已在 `voFieldRules.ts` 的 `REQUIRED_OVERRIDES` 覆盖为必填，并加 placeholder「24 位，来自投资项目在线审批监管平台」。
   ⚠️ 规范 ProjectVO 序号 5 该字段标 `required=false`（仅在"是否固定资产 = 1"时必填），与此处口径不同——**以契约为准**。
2. **保存失败不要自己拼 toast**：请求层 `#/api/request` 已统一弹后端 msg；自己再拼一次会重复提示，
   且错误对象是 `{code,msg,data}` 而非 `Error`，`(e as Error).message` 为空、`String(e)` 会得到 `[object Object]`。

> **排查锚点**：项目登记/保存报「请求参数不正确:项目编号不能为空」→ 基本可断定 bidding-server 是**旧构建**
