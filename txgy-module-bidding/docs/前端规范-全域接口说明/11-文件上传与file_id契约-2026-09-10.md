# 文件上传与 file_id 契约（bidding）——接口规范 + 前端改造规范（2026-09-10）

> 规范依据：《招投标模块开发规范》§4.7 段位表（101=公告与文件）、§5 三-5（文件经 FileApi，
> 库内只记 `file_id` + `sha256` + `size`，**URL 非一致性依据**）、红线 8（附件/版式文件三件套）。
> 用户口径 2026-09-10：上传成功必须在响应体返回全局唯一 file_id；前端禁止"让用户手填文件 ID"；
> 上传成功但响应缺 file_id 时必须明确报错（"文件注册失败，请重试"）。

---

## 一、根因（证据）

平台既有上传接口 `POST /admin-api/infra/file/upload` 的响应体是**字符串 URL**（`CommonResult<String>`，见
`txgy-module-infra-server .../FileController#uploadFile`），**不含 file_id**。而 bidding 业务表以 file_id 关联文件：

| 业务列 | 表 | 说明 |
|---|---|---|
| `pdf_file_id` | `bidding_notice` | 公告版式文件（发布前必填，错误码 `NOTICE_PDF_REQUIRED`） |
| `file_id` | `bidding_notice_external_attachment` | 外部公告附件 |
| `file_id` | `bidding_cert_file_version`（证照线，非本次范围） | 电子证照文件版本 |

前端因此出现退化交互（实测位置，`txgy-ui-admin-vben/apps/web-antd/src/views/bidding/`）：

| 文件 | 现状（问题） |
|---|---|
| `vo/attachmentUpload.ts` | 链路 2「后端上传兜底」只回 URL ⇒ `UploadedFile.fileId` 为 `undefined` |
| `notice/index.vue:109-114` | `fileId` 为空时只 `warning('…需后端支持…')`，`form.pdfFileId` 仍为空 ⇒ 发布时必填校验必然失败 |
| `vo/AttachmentsPanel.vue:62,129,131` | 提示"（仅 URL，未取到 file_id）"，并提供**手填 URL 输入框**（同类退化交互） |
| `vo/PdfPreview.vue:35-44` | 仅给 fileId 时依赖 `/infra/file/get`（需 `infra:file:query` 权限，业务账号通常没有）⇒ 预览失败 |

**结论**：不是前端"想"手填，而是上传链路没有 file_id 可用。修复必须从后端补出 file_id（本次已实现），
前端随后删除所有手工兜底。

---

## 二、后端接口契约（已实现，编译通过）

在 bidding 侧新增统一上传入口（不改 infra 公共接口，避免影响全平台调用方）：

### 2.1 `POST /admin-api/bidding/file/upload`（multipart/form-data）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | file | 是 | 上传文件 |
| `directory` | string | 否 | 归档目录，缺省 `bidding/attachment` |

**响应（成功）**：
```json
{
  "code": 0,
  "data": {
    "fileId": 1024,
    "url": "http://127.0.0.1:48080/admin-api/infra/file/4/get/bidding/attachment/xxx.pdf",
    "name": "招标公告.pdf",
    "type": "application/pdf",
    "size": 204800,
    "sha256": "9f2c…"
  },
  "msg": ""
}
```

**响应（失败，明确报错，不返回半成品）**：

| code | 场景 |
|---|---|
| `1_060_101_013` 上传文件为空，请重新选择文件 | `file` 缺失或空文件 |
| `1_060_101_014` **文件注册失败，请重试（文件服务未返回 file_id）** | 上传成功但回查元数据取不到 file_id |
| `1_060_101_015` 文件地址无效或不属于本平台文件服务 | 补登记入参非法 |

**鉴权**：登录即可（`@PreAuthorize("isAuthenticated()")` + `@Idempotent`）。理由：与平台 `/infra/file/upload` 口径一致
（该接口无权限码、仅要求登录），避免为工具型接口绑定业务权限码导致前端 403。

### 2.2 `POST /admin-api/bidding/file/register-by-url?url=<平台文件地址>`

历史"只有 URL 没有 file_id"的数据修复通道：按 URL 回查元数据补出 `fileId`。
**注意**：元数据不含文件内容，故 `sha256` 返回 `null`；需要三件套齐备请走上传接口重新上传。

### 2.3 实现要点（为什么这样做）

1. file_id 由 infra 落库时生成，唯一可靠取法是上传后 `FileApi.getMetadataByUrl(url)` 回查（`serves/file/BiddingFileServiceImpl`）；
2. 查不到 file_id ⇒ 抛 `FILE_REGISTER_FAILED`，**绝不返回只有 URL 的成功响应**（否则脏数据会带到发布/审核环节）；
3. 上传同时计算 SHA-256（红线 8 三件套），前端落库无需二次请求；
4. 返回 `url` 仅为上传后即时预览，业务落库以 `fileId` 为准；
5. `@Idempotent` 幂等键按「文件名 + 大小」取（`ExpressionIdempotentKeyResolver`）：框架默认解析器会忽略
   `MultipartFile` 参数（`StrUtils.joinMethodArgs` 排除 `org.springframework.web.*`），
   同目录下 1 秒内上传**不同**文件会被误判为"重复请求"（批量选文件必现），故显式改为按文件指纹取键。

## 三、前端改造规范（待授权执行）

> ⚠️ 本次会话约定「前端只读」（前端代码位于模块外的 `txgy-ui-admin-vben/`），故本节仅给出可直接套用的规范与代码；
> 取得授权后可一次性落地。

### 3.1 新增 API 模块 `src/api/bidding/file/index.ts`

```ts
import { requestClient } from '#/api/request';

export interface BiddingFileResp {
  fileId: number;
  url: string;
  name?: string;
  type?: string;
  size?: number;
  sha256?: string;
}

/** 上传文件（响应体必带 fileId；缺失时后端已返回「文件注册失败，请重试」） */
export function uploadBiddingFile(data: { file: File; directory?: string }) {
  return requestClient.upload<BiddingFileResp>('/bidding/file/upload', data);
}

/** 按已上传地址补登记 file_id（历史数据修复） */
export function registerBiddingFileByUrl(url: string) {
  return requestClient.post<BiddingFileResp>('/bidding/file/register-by-url', null, { params: { url } });
}
```

### 3.2 改造 `src/views/bidding/vo/attachmentUpload.ts`——单一链路，禁止"仅 URL"回退

```ts
import { uploadBiddingFile } from '#/api/bidding/file';

export interface UploadedFile {
  url: string;
  fileId: number;        // ← 由可选改为必填：拿不到就抛错，类型上杜绝"没有 fileId 也算成功"
  name: string;
  type: string;
  size: number;
  sha256?: string;
}

export async function uploadAttachment(file: File, directory: string): Promise<UploadedFile> {
  const res = await uploadBiddingFile({ file, directory });
  if (res?.fileId === undefined || res?.fileId === null) {
    // 容错要求：上传成功但缺 file_id —— 明确报错，绝不回退到让用户手填 ID
    throw new Error('文件注册失败，请重试');
  }
  return {
    url: res.url,
    fileId: res.fileId,
    name: res.name ?? file.name,
    type: res.type ?? file.type ?? 'application/octet-stream',
    size: res.size ?? file.size,
    sha256: res.sha256,
  };
}
```

> 原「预签名直传 + `/infra/file/create`」链路可作为可选降级保留，但**同样必须先拿到 file_id 才允许返回**；
> 两条链路都拿不到时统一抛 `文件注册失败，请重试`。

### 3.3 改造 `src/views/bidding/notice/index.vue`（`onPdfBeforeUpload` 附近）

```ts
const up = await uploadAttachment(file, 'bidding/notice');
pdfUrl.value = up.url;
pdfFileName.value = file.name;
pdfSize.value = up.size;
form.pdfFileId = up.fileId;                     // ← 必存在；删除 "if (up.fileId === undefined) warning(…需后端支持…)"
createMessage.success('版式文件已上传：file_id=' + up.fileId);
```

### 3.4 改造 `src/views/bidding/vo/AttachmentsPanel.vue`——移除手填 URL 输入

- 删除 `<Input :value="a.url" placeholder="URL（附件URL地址，规范必填）" …>` 手工输入行；
- URL 由上传结果自动写入（`makeAttachment(item.code, up)` 已带），页面只读展示：文件名 · 大小 · `file_id`（可选） · 预览/下载；
- 删除 `up.fileId === undefined ? '（仅 URL，未取到 file_id）'` 的提示分支（该状态已不可能出现）。

### 3.5 `PdfPreview.vue`

上传成功后已有 `url`，直接用它预览即可（`fileId` 分支仅用于历史数据）；
历史数据可先用 `registerBiddingFileByUrl` 补 file_id，再回落到 `/infra/file/get`。

## 四、验证清单（Docker 恢复后执行）

```bash
# 1) 登录取 token（admin/admin123，tenant-id: 1）
TOKEN=$(curl -s -X POST http://127.0.0.1:48080/admin-api/system/auth/login \
  -H 'Content-Type: application/json' -H 'tenant-id: 1' \
  -d '{"username":"admin","password":"admin123"}' | sed -n 's/.*"accessToken":"\([^"]*\)".*/\1/p')

# 2) 上传：必须返回 fileId（非空数字）
curl -s -X POST "http://127.0.0.1:48080/admin-api/bidding/file/upload" \
  -H "Authorization: Bearer $TOKEN" -H "tenant-id: 1" \
  -F "file=@./some.pdf" -F "directory=bidding/notice"

# 3) 补登记：用上一步的 url 换 fileId（应与第 2 步一致）
curl -s -X POST "http://127.0.0.1:48080/admin-api/bidding/file/register-by-url?url=<上一步 url>" \
  -H "Authorization: Bearer $TOKEN" -H "tenant-id: 1"

# 4) 空文件：应返回 code=1_060_101_013（不得 200 成功）
curl -s -X POST "http://127.0.0.1:48080/admin-api/bidding/file/upload" \
  -H "Authorization: Bearer $TOKEN" -H "tenant-id: 1" -F "file=@/dev/null;filename=empty.pdf"
```

页面侧（前端改造后）：
1. 公告新建 → 上传 PDF → 表单 `pdfFileId` 自动有值，**无任何手填框**；
2. 断网/后端异常 → 提示"文件注册失败，请重试"，且**不出现**"请手动输入文件 ID"字样；
3. 外部公告附件 → 上传后可直接预览/下载，无需手填 URL。
