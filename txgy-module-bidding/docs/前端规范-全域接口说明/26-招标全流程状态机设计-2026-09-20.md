# 26. 招标全流程状态机设计（项目/招标项目/标段/公告）——2026-09-20

## 1. 背景与用户裁定

用户裁定：以**招标方为主**设计招投标系统，核心在于理清四个核心实体（项目、招标项目、标段、公告）的生命周期与联动关系；
**配置分为「测试中 / 实战」两种**：测试中靠招标方/平台方/政府审批方点击「下一步」或「审批通过」手动驱动状态流转；
实战靠时间（投标截止/公示期到期）与实际审批接口驱动。**政府审批接口暂未建设，先预留接口**（见契约 27），当前 stub 直接返回通过。

## 2. 核心实体关系

| 实体 | 说明 | 关系 |
|---|---|---|
| 项目 (Project) | 立项层面概念 | 1 项目 → N 招标项目 |
| 招标项目 (Tender) | 具体的一次招标活动 | 1 招标项目 → N 标段 |
| 标段 (BidSection) | 最小投标单元 | 1 标段 → N 投标人/投标文件 |
| 公告 (Announcement) | 贯穿全流程的公告/公示文件 | 绑定招标项目或标段 |

## 3. 状态枚举与流转规则（枚举类：enums/flow/）

### 3.1 项目 ProjectStatusEnum（5 态）

| 枚举 | 中文名 | 说明 |
|---|---|---|
| DRAFT | 草稿 | 项目信息编制中 |
| APPROVING | 审批中 | 提交立项审批 |
| ACTIVE | 已立项 | 审批通过，可创建招标项目 |
| COMPLETED | 已完结 | 所有下属招标项目均已归档 |
| CANCELLED | 已取消 | 项目取消 |

流转：DRAFT→APPROVING（提交审批）；APPROVING→ACTIVE（通过）/CANCELLED（取消）；ACTIVE→COMPLETED（全归档）/CANCELLED。终态：COMPLETED/CANCELLED。

### 3.2 招标项目 TenderStatusEnum（12 态，最核心）

| 枚举 | 中文名 | 阶段归属 |
|---|---|---|
| DRAFT | 草稿 | 前期准备 |
| APPROVING | 审批中 | 前期准备 |
| PREPARING | 待发公告 | 前期准备 |
| ANNOUNCED | 公告中/获取文件中 | 投标阶段 |
| BIDDING | 投标中 | 投标阶段 |
| PENDING_OPEN | 待开标 | 开标评标 |
| EVALUATING | 评标中 | 开标评标 |
| PUBLICIZING | 公示中 | 定标阶段 |
| AWARDED | 已定标 | 定标阶段 |
| CONTRACTING | 合同签订中 | 收尾阶段 |
| COMPLETED | 已归档 | 收尾阶段 |
| TERMINATED | 已终止/流标 | 异常状态 |

主链路：DRAFT→APPROVING→PREPARING→ANNOUNCED→BIDDING→PENDING_OPEN→EVALUATING→PUBLICIZING→AWARDED→CONTRACTING→COMPLETED
特殊：APPROVING→DRAFT（审批驳回）；PUBLICIZING→EVALUATING（异议成立复核）；**任意非终态→TERMINATED**（主动终止/全部流标；已归档除外）。

### 3.3 标段 BidSectionStatusEnum（6 态，独立设置）

| 枚举 | 中文名 | 说明 |
|---|---|---|
| DRAFT | 草稿 | 标段信息编制中 |
| BIDDING | 招标中 | 涵盖公告、投标、开标阶段 |
| EVALUATING | 评标中 | 专家正在评审该标段 |
| AWARDED | 已定标 | 已确定中标人 |
| FAILED | 流标 | 投标不足 3 家或全部废标 |
| COMPLETED | 已完结 | 合同签订并归档 |

流转：DRAFT→BIDDING→EVALUATING→AWARDED→COMPLETED；BIDDING/EVALUATING→FAILED（流标）。终态：FAILED/COMPLETED。
独立设置的原因：支持部分标段流标、部分标段正常定标。流标后重新招标 = 新建招标项目（FAILED 为终态）。

### 3.4 公告 AnnouncementStatusEnum（5 态，规范版）

| 枚举 | 中文名 | 说明 |
|---|---|---|
| DRAFT | 草稿 | 编制中，可任意修改 |
| REVIEWING | 审核中 | 提交内部或监管审核 |
| PUBLISHED | 已发布 | 已对外公开发布 |
| WITHDRAWN | 已撤回 | 发布后发现错误撤回（需留痕） |
| EXPIRED | 已过期 | 公告有效期已过（如报名截止） |

流转：DRAFT→REVIEWING（提交审核）/PUBLISHED（测试模式免审直发）；REVIEWING→PUBLISHED（通过）/DRAFT（驳回退回）；PUBLISHED→WITHDRAWN（撤回）/EXPIRED（到期）；WITHDRAWN→DRAFT（撤回后修改重发）。EXPIRED 终态。

### 3.5 公告类型 AnnouncementTypeEnum（5 类）

| 枚举 | 中文名 | 发布时机（联动） |
|---|---|---|
| TENDER_NOTICE | 招标公告 | 招标项目 PREPARING→ANNOUNCED |
| CHANGE_NOTICE | 变更/澄清公告 | 投标截止前修改招标文件（状态不变，截止可延期） |
| CANDIDATE_PUBLICITY | 中标候选人公示 | 评标结束 EVALUATING→PUBLICIZING（公示期≥3日） |
| RESULT_NOTICE | 中标结果公告 | 公示期满无异议 PUBLICIZING→AWARDED |
| TERMINATION_NOTICE | 终止/流标公告 | 招标项目→TERMINATED 或标段 FAILED |

与既有 NoticeTypeEnum（4 个工程域数据集）映射见枚举注释：TENDER_NOTICE/CHANGE_NOTICE 同名；CANDIDATE_PUBLICITY↔WIN_CANDIDATE_PUBLICITY、RESULT_NOTICE↔WIN_RESULT_PUBLICITY；TERMINATION_NOTICE 数据集未登记（扩展补 VO）。

## 4. 运转模式（测试中 / 实战，bidding.flow.mode）

| 模式 | 配置 | 状态流转驱动 | 说明 |
|---|---|---|---|
| 测试中 | TEST（缺省） | 招标方/平台方/政府审批方点击「下一步」或「审批通过」 | 每个流转动作暴露为接口；政府审批走预留 stub（直接返回通过） |
| 实战 | PROD | 时间驱动 + 真实审批接口 | 定时任务：投标截止→待开标、公示期到期→下一态；审批调用真实政府审批系统 |

配置类：BiddingFlowProperties（yaml bidding.flow.mode）；流转事件清单：FlowTransitionEventEnum。

**「下一步」代替时间轴流转开关（bidding.flow.manual-advance-enabled，2026-09-21 新增）**：

| 配置 | 说明 |
| --- | --- |
| 缺省 | 跟随模式：TEST 默认 true（可手动点下一步），PROD 默认 false（时间轴事件走定时任务） |
| true | 允许手动执行时间轴事件（投标开始/截止、公示期到期等），即用「下一步」代替时间轴流转（PROD 联调期临时开启） |
| false | 禁止——时间轴事件（BIDDING_STARTED/BIDDING_ENDED/EXPIRE，事件枚举 timeDriven=true）只能由定时任务触发，手动执行报 1060111007；`next-actions` 也会过滤掉这些事件，前端「下一步」按钮自然不渲染 |

操作/审批事件（提交审批、审批通过/驳回、发布公告、开标、终止等）始终允许手动执行，不受该开关影响。

## 5. 事件驱动与联动（服务层落地原则）

1. 状态变更必须通过动作方法（如 tenderService.publish(id)），不直接 setStatus——动作方法内部：状态机校验（canTransit）→ 状态变更 → 联动（公告创建/通知/索引）→ 留痕（操作人/时间/前后状态/IP）。
2. 公告与状态双向绑定：发布公告的动作是状态流转的触发器——「发布招标公告」成功 → 招标项目自动推进 ANNOUNCED；「发布中标结果公告」→ PUBLICIZING→AWARDED；「终止公告」→ TERMINATED。
3. 时间窗口控制（PROD）：定时任务/延迟队列，投标截止、公示期到期自动推进或提醒。
4. 异常流程：投标截止后不足 3 家 → 标段 FAILED（发布流标公告）；所有标段流标 → 招标项目 TERMINATED；公示期异议成立 → 回退 EVALUATING 复核。
5. 联动图：项目(ACTIVE) → 招标项目(DRAFT→…→COMPLETED) ├─ 标段1(…→COMPLETED) ├─ 标段2(…→FAILED 部分流标) └─ 公告：招标公告@PREPARING→ANNOUNCED、变更公告@ANNOUNCED/BIDDING、候选人公示@EVALUATING→PUBLICIZING、中标结果公告@PUBLICIZING→AWARDED、终止公告@任意→TERMINATED。

## 6. 与既有状态体系的关系

- 项目/招标项目/标段：原 DO 裸字符串 state: ACTIVE/CLOSED。新枚举为标准模型；存量 ACTIVE 语义对齐 ProjectStatusEnum.ACTIVE（已立项），CLOSED 视场景映射 COMPLETED/TERMINATED。
- 公告：既有 NoticeStatusEnum（DRAFT/PUBLISHED/UNPUBLISHED/ARCHIVED）被 NoticeServiceImpl 使用；新 AnnouncementStatusEnum 为全流程标准模型，映射 DRAFT↔DRAFT、PUBLISHED↔PUBLISHED、WITHDRAWN↔UNPUBLISHED、EXPIRED≈ARCHIVED、REVIEWING 为新增审核态。存量读写保留旧枚举兼容。
- 状态字典：四类状态尚未登记 bidding_dict_data，前端回显/筛选下拉需后端补字典（下一步）。

| 1-060-111-000 | FLOW_STATUS_TRANSITION_INVALID | 状态流转不允许（实体：from → to） |

| 1-060-111-002 | GOV_APPROVAL_BIZ_ID_REQUIRED | 审批对象业务标识（bizId）不能为空 |
