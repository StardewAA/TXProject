## 九、运维、联调与配置机制

### 9.1 Nacos 命名空间机制（关键）

- 本机工作区用 `public`（空值），远端 `origin/master` 为 `dev`；
- 两侧靠 **git `skip-worktree`** 隔离，涉及 3 个文件：`deploy/docker-compose.yml`、`deploy-bidding-local.override.yml`、`application-local.yaml`；
- 若标记丢失或命名空间写错 → 网关找不到 `bidding-server`（`Unable to find instance for bidding-server`），前端 `/admin-api/bidding/**` 全线 503；
- **守卫脚本**：`deploy/guard-nacos-config.ps1`（可 `-Fix` 自愈）+ `deploy/commit-nacos-protection.ps1` + `.githooks/pre-commit` 中的 ns-guard 段（快速失败，`NO_NS_GUARD=1` 可跳过）。

### 9.2 服务与端口

模块 README 记载完整服务清单与从零启动流程；本地联调时 bidding 用 `run-local.cmd` / `bidding-dev.cmd`，Feign 指向 `127.0.0.1:48087`(system) / `48088`(infra)。

### 9.3 模块自检与守护

- `BiddingSchemaHealthCheck`：启动时库表自检，缺表打 ERROR 并给修复命令；**缺爬虫关键表则自动停爬虫调度**；
