# 公告创建接口与类型字段模板说明（notice 域）

> 适用范围：平台内部公告/公示（T 轨，bidding_notice）的新建与发布链路。
> 文档性质：仅说明各接口的**调用方法与参数传递格式**；不指示前端执行任何具体业务任务。
> 提醒：前端在选用/展示字段时，应从**终端用户角度**评估各公告类型表单的实际应用场景（见文末 §6）。

## 1. 接口清单（管理端，经网关前缀 /admin-api）

| 接口 | 方法 | 权限码 | 说明 |
| --- | --- | --- | --- |
| /bidding/notice/create | POST | bidding:notice:create | 新建公告（落 DRAFT 草稿） |
| /bidding/notice/update | POST | bidding:notice:update | 修改（部分更新：提交什么改什么） |
| /bidding/notice/publish | POST | bidding:notice:publish | 发布（DRAFT→PUBLISHED；招标人资格门 + 正文/PDF 校验） |
| /bidding/notice/unpublish | POST | bidding:notice:update | 撤下（PUBLISHED→UNPUBLISHED） |
| /bidding/notice/delete | POST | bidding:notice:delete | 删除（仅 DRAFT/UNPUBLISHED 可删） |
| /bidding/notice/meta/types | GET | bidding:notice:query | **类型字段模板元数据**（见 §3） |
| /bidding/notice/reindex | POST | bidding:notice:update | 本租户公告 ES 索引全量重建 |
| /bidding/notice/reindex-all | POST | bidding:notice:update | 平台级全租户索引补偿（仅平台租户） |

大厅公开读侧另有 /bidding/notice/public/list、/public/detail、/public/…（均 @PermitAll）。

## 2. POST /bidding/notice/create 请求参数

Content-Type: application/json；请求体（NoticeSaveReqVO）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| noticeType | string | 是 | 公告类型 code（§3 四种之一）；null 时 update 沿用原类型 |
| title | string | 是 | 公告/公示名称 |
| content | string | 创建时建议 | 正文全文（发布前必填，服务端校验） |
| id | number | update 必填 | 修改时传公告 id；create 不传 |
| noticeCode | string | 否 | 内部编号（空=系统生成） |
| projectCode / projectName | string | 否 | 关联招标项目编号/名称快照 |
| publisherName | string | 否 | 发布单位名称快照 |
| publishTime | string(datetime) | 否 | 发布时未填取当前时间 |
| internalFlag | boolean | 否 | true=企业内部公告（仅本租户可见） |
| publicLevel | string | 否 | SOCIAL/GOVERNMENT（默认 SOCIAL） |
| pdfFileId / pdfSha256 / pdfSize | number/string | 发布前必填 | 版式 PDF（file_id 需先经平台文件服务上传取得） |
| payload | object | 视类型 | 权威数据集字段（**键=规范英文名**，见 §3 字段模板）；create 会按类型校验"必填=是"的键 |

校验规则：公告类型未登记 / 必填字段缺失 / payload 格式非法分别返回 1-060-101-xxx 段错误；
缺失提示格式：`公告必填字段缺失（依据VO数据规范 必填=是，按类型"招标公告"）：TENDER_PROJECT_CODE（招标项目编号）、NOTICE_NAME（公告/公示名称）、…`。

## 3. 公告类型与字段模板（GET /bidding/notice/meta/types）

返回 4 种登记类型（与《VO数据规范》工程域数据集一一对应）：

| type | name | 数据集 | 必填数/全集 |
| --- | --- | --- | --- |
| TENDER_NOTICE | 招标公告 | TenderNoticeVO | 28 / 40 |
| CHANGE_NOTICE | 变更公告 | TenderChangeNoticeVO | 15 / 18 |
| WIN_CANDIDATE_PUBLICITY | 中标候选人公示 | WinCandidatePublicityVO | 28 / 40 |
| WIN_RESULT_PUBLICITY | 中标结果公示 | WinResultPublicityVO | 22 / 33 |

响应结构（data 为数组）：

```json
[
  {
    "type": "CHANGE_NOTICE",
    "name": "变更公告",
    "dataset": "TenderChangeNoticeVO",
    "fields": [
      { "code": "NOTICE_NAME",      "label": "公告/公示名称", "required": true },
      { "code": "CHANGE_CONTENT",   "label": "变更内容",      "required": true },
      { "code": "BID_END_TIME",     "label": "投标截止时间",  "required": true },
      { "code": "BID_OPEN_TIME",    "label": "开标时间",      "required": false }
    ]
  }
]
```

- `fields` 顺序：必填在前、其余按数据集字段序；`code` 即 payload 键（照录规范英文名）；
- `label` 为中文展示名（未登记字段回退 code）；`required=true` 表示该键在 create 校验时为"必填=是"；
- 前端按所选 type 取对应模板渲染表单即可；字段值类型以规范定义为准（多为 string，时间字段按 yyyy-MM-ddTHH:mm:ss）。

## 4. payload 提交样例（TENDER_NOTICE 节选）

```json
{ "payload": {
    "TENDER_PROJECT_CODE": "E610000000000001001001",
    "NOTICE_BID_NUM": "0866-26E1SXQY0885",
    "BID_SECTION_CODES": "0866-26E1SXQY0885",
    "UNIFIED_DEAL_CODES": "E610000000000001001001",
    "NOTICE_NAME": "某项目施工招标公告",
    "NOTICE_CONTENT": "（正文 HTML/纯文本）",
    "NOTICE_MEDIA": "陕西省公共资源交易平台",
    "URL": "https://…",
    "DOC_GET_START_TIME": "2026-09-10T09:00:00",
    "DOC_GET_END_TIME": "2026-09-15T17:00:00",
    "BULLETIN_DUTY": "招标人名称",
    "SUBMIT_TIMESTAMP": "2026-09-09T10:00:00",
    "DATA_TIMESTAMP": "2026-09-09T10:00:00"
}}
```

（字段全集以 meta/types 为准；其中含 `PUB_SERVICE_PLAT` 等平台口径字段，取值应与平台登记一致。）

## 5. 类型→页面场景对照（供字段选用参考，非业务指令）

| 场景 | 对应类型 | 表单主体字段方向 |
| --- | --- | --- |
| 项目发包（招标公告/资格预审） | TENDER_NOTICE | 项目/标段/文件获取与递交时间/联系方式 |
| 已发公告的更正补充 | CHANGE_NOTICE | 原标段编号 + 变更内容（BID_END_TIME 等） |
| 评审后候选名单公示 | WIN_CANDIDATE_PUBLICITY | 公示期 + 1~3 名候选人名称/代码/中标价 |
| 确定中标人结果公布 | WIN_RESULT_PUBLICITY | 中标人名称/代码/价格形式 |

## 6. 提醒（终端用户视角）

- 各类型"必填=是"来自《VO数据规范》数据集口径，面向公共资源交易对外报送；若业务上仅站内发布（无报送诉求），可不填 payload 直接以 title/content 建公告——两种用法都受支持，具体采用哪种由业务场景决定；
- 时间类字段请按规范格式（yyyy-MM-ddTHH:mm:ss）提交，展示统一按 epoch 毫秒由前端 dayjs 格式化；
- 公示类（候选人/结果）涉及敏感评审信息，请先确认终端用户在该场景下确实需要/允许展示再开放录入。
