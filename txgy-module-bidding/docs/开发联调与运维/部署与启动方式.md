# 招投标模块（bidding-server）部署与启动方式

> 适用范围：本地开发联调 + 测试/部署。仓库：招投标模块仓库（内嵌于全项目 `txgycloud/txgy-module-bidding`，独立 git）。
> 更新：2026-09-08。所有命令以 Windows + Docker Desktop 为前提；模块以 **JDK 25 + Maven** 构建。

---

## 0. 一句话架构（先看这个，避免配置错觉）

- **中间件 & 兄弟服务**跑在 Docker（compose 项目名 `txgy`）：MySQL / Redis / Nacos / Gateway / System / Infra / AI / ES。
- **bidding-server 本身以宿主机 JVM 运行**（端口 48110），目前不进容器。
- 注册与配置中心统一用 **Nacos `public` 命名空间（namespace id 为空串）**，与其它服务同一列表。
- 容器里的 gateway / system / infra 通过一个 **override 文件**把自身注册指到 public，并把 system/infra 的宿主端口映射出来（48087 / 48088）供宿主机上的 bidding **用 openfeign 直连**（绕过容器内网）。
- 网关已加 `bidding-admin-api` 路由：`/admin-api/bidding/**` → `grayLb://bidding-server`（靠 Nacos public 里 bidding 的实例）。

```
浏览器(管理端 5666 / 门户)
   │  /admin-api/bidding/** 或 /bidding-api
   ▼
Gateway 容器  48080 ──grayLb(public: bidding-server)──►  bidding-server(JVM, 48110)
   ▲  (transparent 加 login-user)
System 容器 48087 / Infra 容器 48088  ◄── bidding 内部 feign 直连 127.0.0.1:48087/48088
```

## 1. 配置文件清单（"哪些文件是干嘛的"整理）

| 文件 | 位置 | 作用 / 归属 |
|---|---|---|
| `pom.xml` / `txgy-module-bidding-api|server/pom.xml` | 模块 | Maven 工程定义（父依赖在 `txgy-dependencies`） |
| `application.yaml` | `txgy-module-bidding-server/src/main/resources/` | 主配置：应用名 `bidding-server`、`profiles.active=local`、端口、日志路径 `${user.home}/logs/bidding-server.log`、数据源模板、ES、AI 入口等 |
| `application-local.yaml` | 同上 | **本地 profile**：nacos 地址/命名空间、MySQL/Redis 直连、feign/字典等 |
| `application-dev.yaml` | 同上 | dev 环境 profile（本机一般不用） |
| `bidding-dev.cmd` | `txgy-module-bidding-server/` | **本地一键启动/重启**（杀端口→mvn 打包→java 启动→等就绪）。含本机路径，已 gitignore |
| `run-local.cmd` | 同上 | 纯启动（不打包不杀进程），等价参数；已 gitignore |
| `deploy-bidding-local.override.yml` | 模块根 | **本地联调 override**：把容器 gateway/system/infra 注册指到 public + system/infra 宿主端口映射 48087/48088 |
| `deploy/docker-compose.yml` | 全项目 | 平台中间件与兄弟服务编排（配合下一条 override 使用） |
| `txgycloud/txgy-gateway/src/main/resources/application.yaml` | 全项目 | 网关路由：已含 `bidding-admin-api`（bidding）与 knife4j |
| `docs/…/03-本地运行与联调说明.md`、`docs/开发联调与运维/爬虫开发-会话状态与断点.md` | 模块 | 历史联调/断点说明，可交叉参考 |

> ⚠️ `application-local.yaml` 里 `spring.cloud.nacos.discovery/config.namespace` 默认写的是 `dev`；**运行时**由启动脚本用 java 参数覆盖为空（=public）。若想彻底避免"本地又落到 dev"的混淆，可把这两处默认直接改成空串（见 §5，属后端配置改动，需评估后由维护者执行）。

## 3. 前置条件（首次）

1. 启动 Docker Desktop；JDK 25 与 Maven 已安装（`bidding-dev.cmd` 默认找 `D:\Java\jdk-25`，找不到则回退 `JAVA_HOME`）。
2. 先把平台跑起来（见 §4）。
3. 首次需 `mvn package -DskipTests`（`bidding-dev.cmd` 默认会打，或用 `-s` 跳过）。**打包前先确认 48110 无占用**（Windows 下运行中的 jar 会锁文件）。
4. 数据库已导入（平台启动脚本 `deploy/local/start.ps1` 内含安全导入；表如 `bidding_notice_external`、`bidding_crawl_*` 需存在）。

## 4. 启动方式 A：全平台（中间件 + 兄弟服务，Docker）

在**全项目**目录执行（override 在模块目录内）：

```bash
cd D:\Code\IDEA\txgy\txgycloud\deploy
docker compose -f docker-compose.yml \
  -f ..\txgy-module-bidding\deploy-bidding-local.override.yml \
  -p txgy up -d gateway system infra
# 中间件（mysql/redis/nacos/es 若未起）：
docker compose -f docker-compose.yml -p txgy up -d mysql redis nacos
```

- override 的作用：gateway/system/infra 注册指到 **public**；system→`127.0.0.1:48087`、infra→`127.0.0.1:48088`。
- 健康自检：
```bash
docker ps --format '{{.Names}}\t{{.Status}}' | grep -E 'mysql|redis|nacos|gateway|system|infra'
```

> 全平台一键备选：`deploy/local/start.ps1`（用 `docker-compose.local.yml`，会起中间件→导库→建 dev 命名空间→起服务）。注意它与上面 override 方案是**两套不同编排**，日常联调以 override 方案为准。

## 5. 启动方式 B：bidding-server（宿主机 JVM）

### B-1 一键（推荐）
```bat
cd /d D:\Code\IDEA\txgy\txgycloud\txgy-module-bidding\txgy-module-bidding-server
bidding-dev.cmd          :: 杀旧进程 → mvn package → 启动 → 等 48110 就绪
bidding-dev.cmd -s       :: 跳过打包（代码没变时更快）
```
启动日志：`%USERPROFILE%\logs\bidding-server.log`（Spring 主日志）、`target\bidding-dev.log`（脚本 stdout）。

### B-2 实际运行参数（等价于 IDEA 需配的项）
```text
--server.port=48110
--spring.profiles.active=local
--spring.cloud.nacos.discovery.namespace=     （空=public）
--spring.cloud.nacos.config.namespace=        （空=public）
--spring.cloud.nacos.discovery.ip=host.docker.internal
   （本机 WLAN / 供容器内网关可达；换网段时改）
--spring.cloud.openfeign.client.config.system-server.url=http://127.0.0.1:48087
--spring.cloud.openfeign.client.config.infra-server.url=http://127.0.0.1:48088
```
> ⚠️ 两条硬经验（曾导致反复踩坑）：
> 1. **`namespace=` 空值必须走 java 参数**。cmd 里 `set "VAR="` 是"删除变量"而非置空，写环境变量等于没设，会回落成 `application-local.yaml` 的 `dev`。
> 2. **不要加 `--spring.main.lazy-initialization=true`**。它会让框架的 `WebFrameworkUtils` Bean 不提前创建，凡带 `login-user` 头（网关透传）的请求解析登录即 NPE（`系统异常`）。

### B-3 在 IDEA 里跑（调试用，等价配置）
在 `BiddingServerApplication` Run/Debug Configuration：
- VM options 填（namespace 留空即 public）：
```text
-Dspring.cloud.nacos.discovery.namespace= -Dspring.cloud.nacos.config.namespace= -Dspring.cloud.nacos.discovery.ip=host.docker.internal -Dspring.cloud.openfeign.client.config.system-server.url=http://127.0.0.1:48087 -Dspring.cloud.openfeign.client.config.infra-server.url=http://127.0.0.1:48088
```
- Active profiles: `local`；端口 48110。**保存为正式配置**（临时配置重启会丢）。
- 直接右键 main 不加覆盖 = 会落 `dev`，属已知坑，别用那个裸配置跑联调。

## 6. 部署/发布到远端（git 层面）

招投标模块是独立仓库（远端 `master`(名称) = `gitee.com/Sqbsy/txgy_bidding`）。本地专用脚本（`run-local.cmd`、`bidding-dev.cmd`）含本机路径/IP，已 **gitignore**，不入库；新成员 clone 后看不到，需要时按本文档自行生成。团队联调用的 override 与文档保留入库。

常用：
```bash
git -C txgy-module-bidding push master notice        # notice 分支
```
（`master` 是该远程的**名字**，别和分支名混淆。）

## 8. 常见问题排查

| 现象 | 原因 / 处理 |
|---|---|
| Nacos public 里看不到 bidding | 实例注册到了 dev：核对 §5 的 `--...namespace=` 空参数是否真的在启动命令里（cmd `set VAR=` 会删变量） |
| 实例 IP 是 `172.17.x.x` | 没设 `discovery.ip`，客户端挑到 Docker/WSL 虚拟网卡；设成 `host.docker.internal`（LAN） |
| 走网关的请求 500 NPE（WebFrameworkUtils.properties is null） | 开了 `lazy-initialization`，去掉该参数重启 |
| 大批接口同时 500/超时 | 多为 bidding 重启空窗的偶发；稳定期重试；仍复现则按时间查 `bidding-server.log` 对应 URL 后的异常栈 |
| `CrawlParserController /test` 缺 parserCode | 该接口参数走 multipart/form（`@RequestParam`），不要把参数放 JSON body |
| 打包失败/提示文件被占用 | 48110 的 java 进程未停；`bidding-dev.cmd` 会先杀，手动也可 `netstat -ano \| findstr :48110` |
| Nacos 容器反复被 OOMKilled（ExitCode=137, OOMKilled=true） | Nacos 3.x 镜像默认堆较大（-Xmx2g），而 compose 给容器的 cgroup 限额只有 768MB → 启动约 6 分钟后被内核杀掉，随后 infra/system/gateway 因"连不上 nacos"接连退出。修法：`deploy-bidding-local.override.yml` 里给 nacos 固定小堆 `JVM_XMS=256m / JVM_XMX=512m / JVM_XMN=128m`（2026-09-11 实测有效） |
| 起不来：`ES 集群健康检查 HTTP 401 -> security_exception` | 本机 ES 容器开了安全认证，缺凭据时 `EsStartupHealthCheck` fail-fast 中止启动。修法：本地 profile `application-local.yaml` 的 `bidding.es.username/password` 填实际凭据（已补 `elastic / ww0qPgaEbSyT6oMMeART`）；换集群时改这里或用 `-Dbidding.es.password=xxx` 覆盖 |
| 启动报 `required a bean of type 'XxxMapper' that could not be found` | 框架 `@MapperScan` 是 **按注解扫描**（`annotationClass = Mapper.class`，见 `TxgyMybatisAutoConfiguration`）：新加的 Mapper 漏写 `@Mapper` 不会编译报错，只会在启动时找不到 bean。修法：所有 Mapper 显式加 `@Mapper` |
| 编译报 `程序包 cn.iocoder.txgy.module.bidding.api.* 不存在` | 本地 `.m2` 里的 `txgy-module-bidding-api` 快照过期（api 模块源码有、jar 里没有）。修法：`mvn -o -pl txgy-module-bidding-api install -DskipTests` 后重新编译 server（2026-09-11 实测一次修掉 46 个错误） |
| 任务全部失败且提示 `HTTP 请求失败: null` | 任务的 `rawFileUrl` 指向 `http://127.0.0.1:48080/admin-api/infra/file/...`（平台归档原文），**网关容器没起** → 19ms 内连接被拒。修法：`docker start txgy-gateway`（或让 rawFileUrl 走 infra 直连 48088）。另：该类 message=null 的包装异常已改为输出 class + cause 链（`FetchException.describe`），不再出现无法诊断的 "null" |
| 只起了 MySQL，想跑爬虫够不够 | 不够。爬虫链路还依赖 Nacos（注册/配置）、Redis（Stream 轻信号+布隆）、ES（fail-fast 健康检查），以及 **网关 48080**（平台归档原文下载）。最小集：mysql + redis + nacos + elasticsearch + gateway(+infra 提供文件归档/存储校验) |
| `UnknownHostException: nacos`（容器） | 容器掉出 `txgy-dev` 网络：`docker network connect --alias nacos txgy-dev txgy-nacos-1`（重建过则 `docker compose up -d nacos`） |
