# 外部公告：建议页面结构与数据映射（仅供参考，UI 以设计稿为准）

> 对应"招投标门户/大厅"与"管理后台"，均只读展示 + 审核操作，无本模块自身的内容录入表单（内容来自外站采集）。

## 1. 大厅-外部公告列表页
- 数据源：`GET /bidding/notice-external/page`。
- 筛选条：来源站（sourceCode，可选）、类型（contentType 或 noticeTypeRaw）、行业（industryFlag 切"防腐保温相关"）、发布时间区间；搜索框传 keyword（全文检索，命中标题/项目名/编号/正文；后端未启用 ES 时接口报 1-060-106-015，前端给提示）。
- 列表卡片/行：title、sourceName（"来源：xx平台"）、noticeTypeRaw 标签、industryFlag 命中标"相关"、issuerName、publishTime。
- 空态/加载/分页：PageResult 标准；公告量大时按 publishTime 游标分页。

## 2. 大厅-外部公告详情页
- 数据源：`GET /bidding/notice-external/detail?id=`。
- 头部：title、issuerName、publishTime、来源链接（"查看原文" → go 端点跳 origUrl）。
- 正文按 contentType 分支：
  - HTML → v-html **contentHtmlSafe**；
  - PDF → pdfDownloadUrl 内嵌预览（无内嵌能力就"下载 PDF 后查看"按钮）；
  - ATTACHMENT/含附件 → 附件区。
- 附件区：文件名+大小+下载按钮（downloadUrl）；virusStatus=INFECTED 显示"已拦截"；外站溯源展示 origDownloadUrl 文本。
- 详情无数据（已下架/非公开）时按错误码给"公告不存在或已下线"。

## 3. 管理端-外部公告列表/审核
- 数据源：**管理分页 `GET /bidding/notice-external/manage/page`（N1 已落地，见 01 §2.0）**——覆盖 NEW/ACTIVE/INACTIVE/ARCHIVED × 全部审核态，入参 status/auditStatus/来源/类型/时间，权限=bidding:notice-external:update。**不要用公开 page 做管理列表**（公开只出 ACTIVE+SOCIAL）。
- 行操作：审核通过（approve）/ 驳回（reject）/ 下线（take-down）/ AI 抽取（ai-extract）/ 正文结构化（body-structure），均二次确认 + 按钮 loading（@Idempotent）。
- 关注提醒联动：approve 后关注该维度的用户会收到"新到公告"动态（本模块关注域，见 01 §3）。

## 4. 我的关注（门户-个人中心）
- 关注操作：公告详情页/项目详情页放"关注"按钮 → follow/unfollow（targetType+targetKey 幂等）。
- 我的关注列表：item/page → 每行显示项目/标段名、阶段 stageName、最近动态时间、未读数角标；点进时间线 item/{itemId}/timeline（含 EXTERNAL_ACTIVE 事件，即外部公告到达提醒）；"全部已读"或行内已读调 item/{itemId}/read。
- 时间线上的外部公告事件 → 跳外部公告详情（noticeId）或原文 go 链接。

## 5. 联调检查单（冒烟用例）
1. page：不带任何参数能列出 ACTIVE 公告，INACTIVE 记录不出现。
2. detail：HTML 记录 contentHtmlSafe 不含 script；PDF 记录返回 pdf 字段组。
3. go：白名单源域名 URL 302；非白名单域名 400/拒绝。
4. detail 的 INFECTED 附件（若有测试数据）downloadUrl 为空/已过滤。
5. 关注：follow → item/page 出现 → timeline 有 EXTERNAL_ACTIVE（approve 一条外部公告后）→ read 清零未读数。
## 5. 主体信息完善页与授权管理页（Task2 新增；接口见 全域文档 §6）

### 5.1 企业侧 - 主体信息完善页（投标人/招标人共用表单）
- 数据源：GET /bidding/subject/profile/get?subjectType=（未建档返回 null → 走新建）；保存 POST /bidding/subject/profile/save。
- 表单字段（7 个必填 + 可选）：单位名称、统一社会信用代码（保存时 GB 32100-2015 强校验，前端可先做 18 位/字符集提示）、
  法定代表人姓名、法人机构类别、行政区划（GB/T 2260）、联系人、联系电话；可选：行业代码/注册资本/币种/营业执照影像/扩展 JSON。
- 完善度交互：get 返回 complete=false 时展示 missingRequiredNames 缺失项清单；保存后再次 get 校验 complete=true。
- 资格展示：GET /bidding/subject/profile/eligibility?subjectType= 显示 授权状态/授权时间/完善度/资格（投标或发布）/
  不满足原因（未授权→“联系平台管理端授权”；未完善→列出缺失项并直达本页）。

### 5.2 管理端 - 已授权主体管理页（平台）
- 列表：GET /bidding/subject-auth/page（可按 tenantName 模糊/状态/类型过滤；行内含 profileComplete 与缺失项，前端可本地筛选“已授权未完善”）。
- 授权：POST /bidding/subject-auth/authorize（tenantId+subjectType+企业名称快照）；停用/复用：PUT /bidding/subject-auth/status。
- 经办用户：GET /bidding/subject-auth/user/page（按租户）；绑定 POST /user/bind（userRole=OPERATOR/CONTACT）；解绑 DELETE /user/unbind。
- 资格查询（任意租户）：GET /bidding/subject-auth/eligibility?tenantId=&subjectType=，用于授权后核对企业是否已完善。

### 5.3 投标/发布入口的门交互（关键动线）
- 点击“投标/报名”或“发布公告/提交备案”前：
  1. 调资格接口（6.1.3 或 6.2.4）→ eligible=true 直接放行；
  2. eligible=false 且 reasonCodes 含 NOT_AUTHORIZED/AUTH_DISABLED → 提示“联系平台管理端授权”，按钮置灰；
  3. 含 PROFILE_MISSING/PROFILE_INCOMPLETE → 弹窗列 missingRequiredNames，提供“去完善信息”跳转（5.1 页）；
  4. 后端兜底：发布/备案接口仍会返回 1-060-106-031/034（多端并发或直连时保证不绕过）。

### 编写原因
页面结构建议需随业务需求更新：Task2 新增“主体信息完善页”与“管理端授权管理页”，并定义投标/发布入口的资格门交互动线，前端按此搭建页面与跳转。

### 编写依据
- 接口事实：docs/前端规范-全域接口说明/01-接口逐一说明与设计依据.md（§6/§7）、01-接口契约.md、02-字段枚举与展示约定.md（§7）；
- 业务需求：Task2（完善信息、管理端授权+管理用户、资格门双条件）；
- 法规/规范：招标投标法 第25/26条、电子招标投标办法 第24条、GB 32100-2015。

### 所满足的业务需求内容及其实现方式
- 「完善投标人、招标人的信息」→ 5.1 完善页（必填清单+缺失项+保存后复核）；
- 「管理端显示已授权投标人并支持管理用户」→ 5.2 管理页（授权/启停/经办用户/资格核验）；
- 「未完善不能投标，但可关注/订阅」→ 5.3 入口门交互（仅拦投标/发布动作，关注页不受影响）。
