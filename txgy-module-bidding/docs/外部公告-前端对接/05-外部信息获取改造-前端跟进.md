# 05-爬虫模块重构为外部信息获取：前端跟进说明（2026-09-10）

> 用途：告知前端本轮后端改造的**对外可见变化**。核心结论：**接口 URL、权限码、请求/响应结构兼容**，
> 前端现有 crawlExternal 页面**无需改动即可继续工作**；新增字段为增量（编辑表单可后补）。
> 参考：本目录 01-接口契约.md（汇总）、04-采集窗口契约（run 语义）；后端代码见 `service/externalfetch`。

## 三、新增字段说明（CrawlSource）

```typescript
// 源列表/详情/保存新增（均可选）
fetchType?: string      // 获取方式：CRAWLER=爬虫(列表HTML) / API=接口直取(JSON)；不传= CRAWLER（存量兼容）
apiConfigJson?: string  // API 源配置 JSON（fetchType=API 时后端必填校验）：
                        //   { method, url, headers?, bodyTemplate?, rowsPath?, totalPath?,
                        //     pageSize?, mapping?: {title?,url?,date?,category?,contentHtml?},
                        //     urlPrefix? }
// 说明：
// - 字段映射 mapping 让对方平台字段名对齐本模块（title/url/date/category/contentHtml）；
// - urlPrefix 用于相对 URL 绝对化；headers 支持静态鉴权头（X-Client-Id 等，动态签名平台另扩展）；
// - API 源样板已落地：QYZB 源 fetchType=API（三栏目配置化直取 JSON 全文），真跑与旧路径等价。
```

## 四、新增字段说明（CrawlTask 任务）

```typescript
// 任务行新增（只读，排查用）
payloadJson?: string  // 列表阶段任务快照 JSON：{title,url,date,category,rawFileUrl?,rawSha256?,rawSize?}
// - 大文本（HTML 全文/PDF）不落库不落 Redis：生产端先归档平台文件服务，task 只存 rawFileUrl 引用
// - 该字段供管理端下钻看"这个任务抓的是哪条公告/哪个文件"，无业务必读
```

## 五、任务状态机（信息获取任务，与旧采集任务一致）

| 状态 | 含义 | 管理动作 |
|---|---|---|
| PENDING | 在队（待下载） | 无 |
| RUNNING | 执行中（worker 归属） | 无 |
| SUCCESS | 已落库 | 无 |
| FAILED | 重试耗尽/死信 | 可 retry（→PENDING 新一轮） |
| SKIPPED | 跳过 | 无 |

## 六、批次语义（run 返回与 job 查询，不变）

- `POST /bidding/crawl-source/run` 同步返回本轮汇总（categories/fetched/ingested/failed），批次落 `bidding_fetch_job`；
- `GET /bidding/crawl-job/page|get` 查批次历史；jobId 过滤下钻 `crawl-task/page` 看任务明细（含 payloadJson）；
- 异步化已落地（配置 `bidding.crawl.runner.async-mode=true` 启用，默认关）：run 返回时机=投递完成即返回（totalIngested=已入队数），下载/落库由消费者异步执行；批次 job 保持 RUNNING 至 task 全部终态后收尾（job 详情 summaryJson 含 `"async":true`），进度看 job/任务列表即可；
- 批次语义补充：job 有 `produced`（投递完成）内部标志，summary 的 totalEnqueued=入队数、totalIngested=消费成功数（异步模式下可能暂少于入队数，job RUNNING 期间轮询可见）。
