# 招投标系统模块化拆分总览与依据

## 一、总体结论

本系统按《电子招标投标办法》第 3 条的法定划分拆成三个独立系统：

| 系统 | 对应法定平台 | 使用人 | 公开级别 |
|---|---|---|---|
| 企业后台管理系统 | 交易平台 | 招标人、投标人、代理机构 | 政务级公开（后台数据） |
| 监管系统 | 行政监督平台 | 行政监督部门、监察机关 | 政务级公开 |
| 公共服务大厅 | 公共服务平台 | 社会公众 | 公众级公开 |

> 依据：《电子招标投标办法》（国家发展改革委等八部委令第 20 号）第 3 条：电子招标投标系统根据功能的不同，分为交易平台、公共服务平台和行政监督平台。
> 公开级别依据：《公共资源交易平台系统数据规范（V2.0）》（发改办法规〔2018〕1156 号）将每个数据集字段标注"公开范围"，分"社会公开、政务公开"两级。本设计中，**公众级公开 = 社会公开**（公共服务大厅对外展示），**政务级公开 = 政务公开**（企业后台与监管系统之间共享）。

## 三、拆分原则（最小模块、最低耦合）

1. **一个模块只干一件事**：招标、投标、开标、评标等每个业务步骤独立成模块，互不包含。
2. **模块之间只通过接口打交道**：任何模块不得直接读写另一个模块的数据表；需要数据时调用对方接口（输入/输出均为值对象 VO，格式按数据规范 V2.0 数据集）。
3. **单向依赖**：依赖方向固定为"业务步骤下游依赖上游"（如开标依赖投标递交），禁止反向依赖，杜绝循环。
4. **公开范围即模块边界**：一个模块产出的字段按规范标注"社会公开/政务公开"，公开字段才能进入公共服务大厅，政务字段只在企业后台与监管系统间流转。
5. **最简设计模式**：每个模块内部只用"接口-实现-存储"三层，不用事件溯源、CQRS、共享数据库等复杂机制；跨系统交换用接口调用，不用中间件编排。

## 四、拆分依据汇总

### 国家层面

| 文件 | 用于 |
|---|---|
| 《中华人民共和国招标投标法》（2017 修正） | 招标、投标、开标、评标、中标各步骤的法定行为边界 |
| 《招标投标法实施条例》（2019 修订） | 公示、异议、投诉、保证金等细化规则 |
| 《电子招标投标办法》（八部委令第 20 号） | 三平台划分、电子文件效力、系统安全 |
| 《公共资源交易平台管理暂行办法》（十四部委令第 39 号） | 平台体系、目录管理、进场交易 |
| 《公共资源交易平台系统数据规范（V2.0）》（发改办法规〔2018〕1156 号） | 数据集、统一交易标识码、社会公开/政务公开两级公开范围 |
| 《招标公告和公示信息发布管理办法》（发改委令第 10 号） | 公告与公示公开规则 |
| 《必须招标的工程项目规定》（发改委令第 16 号） | 依法必招范围判定 |
| 《政府采购法》第 42 条 | 档案保存期限（≥15 年） |

### 陕西省层面

| 文件 | 用于 |
|---|---|
| 《陕西省实施〈中华人民共和国招标投标法〉办法》（陕西省人大常委会） | 省内招标投标活动细化要求、监督职责分工 |
| 《陕西省公共资源交易平台管理办法》（陕西省发展和改革委员会印发） | 省内公共资源交易平台建设与运行管理 |

| 《陕西省公共资源交易电子监管系统数据规范变更记录》（2024-05-28） | 新增/更新/删除三类共 63 项变更清单，作为各模块"陕西省 V2.0 增补"章节的依据 |

> 说明：陕西文件的引用均以文件整体为依据（不标注具体条文号，避免版本差异），国家文件仅标注本次已核对的条文。

## 五、各模块文件说明

每个模块一个文件，统一包含：定位、依据、功能、视图（功能视图/流程视图）、接口、VO 映射、技术支持。模块文件均为值对象（VO）层面的设计。
