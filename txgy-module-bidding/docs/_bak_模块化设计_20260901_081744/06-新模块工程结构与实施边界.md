# 06 新模块工程结构与实施边界

> 目标：全部系统实现在**新模块组**内完成，既有平台（yudao-* 各模块）**零改动**。本文件给出工程结构、依赖关系与实施顺序，供开发照做。

## 一、工程结构（全部新建）

在仓库根目录新增 Maven 聚合模块组：

- yudao-module-bidding（聚合 pom）
  - yudao-module-bidding-api：跨模块接口与 VO 定义（仅依赖 yudao-common，无业务实现）
  - yudao-module-bidding-ent（企业后台管理系统，19 模块中的后台-01~08）
  - yudao-module-bidding-sup（监管系统，监管-01~06）
  - yudao-module-bidding-hall（公共服务大厅，大厅-01~05）
  - yudao-module-bidding-es（ES 同步服务：公开文档写入、同步队列表消费）
  - yudao-bidding-server（独立启动模块，聚合以上各系统，独立打成可执行 jar）

## 二、依赖规则（只复用，不改动）

1. 可依赖（作为库使用，不改其任何代码）：yudao-common、yudao-framework 各 starter（web/security/mybatis/redis/tenant/job/mq 等）、yudao-dependencies BOM 的版本管理。
2. 禁止：修改既有模块源码、向 yudao-server 注入本组模块、在既有表中加字段。本组独立启动（yudao-bidding-server），与既有平台通过接口互通。
4. ES：独立集群或独立索引前缀，不与既有系统共用索引命名空间。

## 三、模块内目录约定（每个模块一致，遵循 07-项目框架对应约定.md）

模块目录按 01 文件的接口-服务-存储三层组织（接口层+VO、服务层、存储层），VO 字段一律对应 02 文件的映射表；不引入除平台 starter 以外的框架。

## 四、实施顺序（照做）

1. 先建 yudao-module-bidding-api：把 02 文件的全部 VO 与 05 文件的接口定义（签名与文档）落成接口层，作为三系统共同契约；
2. 建企业后台（后台-01→08 按顺序），每个模块完成接口、服务、存储与单元校验；
3. 建监管系统（监管-05 专家库、监管-01 备案先做，再 02 投诉、03 检查、04 信用、06 归集与 ES 同步服务）；
4. 建公共服务大厅（大厅-01/02/03/04 读 ES，大厅-05 投诉入口对接监管-02）；
5. 联调三条主线：备案链路（后台→监管）、公开链路（后台/监管→归集→ES→大厅）、投诉链路（大厅→监管→回推大厅）；
6. 验收清单：租户隔离抽查、公开级别字段白名单抽查、幂等重放测试、时限锁定测试（20/15/3/5/30 日）、ES 不可用降级测试、归档只读测试。

## 五、与其他交付文件的关系

- 00：系统与模块边界；01：接口与交换总约定；02：VO 字段来源（表设计2映射）；04：ES 与公开文档；05：接口清单与规则；本文件：落地工程边界。五个文件配合即为可照做的完整设计。
