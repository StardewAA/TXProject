# 04 公开文档与 ES 搜索引擎设计

> 原则：**所有公开文档（公众级公开）都由 ES 处理**——公共服务大厅的展示、检索、订阅全部以 ES 为数据源；企业后台与监管系统的公开字段经"数据归集→ES 同步服务"写入 ES。本文件不含代码，只给索引、文档、同步与检索设计。

## 一、总体结构

公开文档流向：企业后台/监管系统发布公开数据 → 监管-06 数据归集校验 → ES 同步服务写索引 → 大厅检索查询模块读索引 → 公众浏览/检索/订阅。

- ES 集群：3 节点起步（1 主 2 从），内网部署，只对"大厅检索服务"和"ES 同步服务"开放；
- 业务系统禁止直连 ES：写由同步服务代理，读由大厅检索模块代理；
- 公开级别控制：**只同步"社会公开"字段**；政务公开字段在任何情况下不得进入 ES。

| tbd_result | 中标/成交结果、合同公开信息 | 表22/48/49、表23 社会公开子集 | 项目编号、中标人、中标价格、签订时间、合同主要信息 |
| tbd_credit | 黑名单、违法违规、奖励公示（社会公开部分） | 表128~133 社会公开字段 | 主体编号、类型、内容、起止时间、状态 |

- 文档 ID：统一用业务编号（公告编号/公示编号/统一交易标识码），保证重复同步幂等覆盖。

## 三、文档结构（以公告文档为例）

| 字段 | 类型 | 说明 |
|---|---|---|
| notice_code | keyword | 公告编号（文档 ID） |
| title | text (ik_max_word) | 标题，检索权重最高 |
| content | text (ik_max_word) | 正文 |
| notice_type | keyword | 公告类型（表33） |
| project_code / section_code | keyword | 项目/标段编号 |
| region_code / region_name | keyword | 地区 |
| industry / trade_class | keyword | 行业、交易分类（表2） |
| publish_time | date | 发布时间 |
| deadline | date | 截止时间（公告用） |
| source_platform | keyword | 来源系统标识 |
| public_fields | object | 仅社会公开字段 |

## 四、同步设计（只描述机制，不写代码）

1. 发布即同步：企业后台"公告与文件/中标与合同"、监管"信用监管"发布公开数据时，调监管-06 的公开同步接口；监管-06 校验后写入 ES 同步队列（文档类型、业务编号、状态、重试次数）。
2. 同步服务按队列消费：成功置"已同步"；失败按 1/5/30 分钟三次重试，仍失败转人工，业务库数据不受影响（最终一致）。
3. 更正公告：发布新文档并更新原文档的"更正关联"字段，原文档保留（法律要求历史可查）。
4. 黑名单撤销：不删文档，更新状态字段为"已撤销"并追加撤销文档。
5. 订阅推送：大厅订阅由同步服务定时比对新增文档生成推送任务。

## 五、检索设计（大厅-02 检索查询）

| 检索场景 | 检索方式 | 排序 |
|---|---|---|
| 公告全文检索 | 关键字（标题加权 > 正文）+ 过滤器（类型/地区/行业/时间） | 发布时间倒序 |
| 公示/结果检索 | 关键字 + 公示类型 + 中标人 + 价格区间 | 公示结束时间倒序 |
| 信用检索 | 主体名称/统一社会信用代码精确 + 类型过滤 | 列入时间倒序 |
| 法规检索 | 全文 + 层级 + 机关 + 关联主题（同义词：政采/政府采购） | 发布时间倒序 |
| 主体/专家检索 | 名称/代码/资质/专业 | 相关度 |

- 中文分词 ik_max_word（索引）/ik_smart（查询）；高亮返回标题与正文片段；
- 查询日志只记条件与结果数量，不记个人敏感信息，且不写入 ES；
- ES 不可用时，大厅公告/公示页降级为"查询失败提示"，不提供其他存储兜底读（避免双源不一致）。

## 六、安全与合规

1. ES 只存社会公开字段，公开级别在写入前由同步服务做字段白名单校验，多字段即拒绝该文档同步。
2. 政务服务数据（投诉、备案意见、评标报告）绝不入 ES。
3. 索引快照每日备份；索引不可由业务侧删除，删除须走运营双人审批。
