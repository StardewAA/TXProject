# 07 项目框架对应约定（已按《招投标模块开发规范》对齐）

> ⚠️ 对齐说明（2026-09-03）：本文为早期设计稿，工程落地以《招投标模块开发规范》为**唯一权威**，冲突处一律以规范为准。包名已由 yudao 时代改为 txgy 现行值；错误码段、时间字段、文件口径等一律按规范章节执行。

## 一、模块包结构（全部在 txgy-module-bidding 模块组内）

每个业务域（如公告、投标递交）统一按平台既有业务模块（txgy-module-system/fms 等）的目录规范组织：

```
cn.iocoder.txgy.module.bidding.{域}
├── controller/admin/<domain>/    管理端接口（@PreAuthorize("bidding:xxx:yyy")）
│   └── {业务}/vo/                请求/响应 VO（XxxSaveReqVO、XxxRespVO、XxxPageReqVO，见规范 3.1）
├── service/<domain>/             业务接口 + ServiceImpl（事务、转换、TDD 测试同包）
├── dal/dataobject/<domain>/      XxxDO（继承 BaseDO 或 TenantBaseDO，规范五章四/五）
├── dal/mysql/<domain>/           XxxMapper（继承 BaseMapperX）
├── enums/                        枚举 + ErrorCodeConstants（错误码段 1_060_YYY_ZZZ，见规范 4.7）
└── framework/                    本模块自身的配置（Security/Rpc/Web 等）
```

- 公共服务大厅的**公众只读接口**放在同一 server：标注 `@PermitAll`（在本模块 SecurityConfiguration 白名单注册），跨租户读取用 `TenantUtils.executeIgnore` 或方法级 `@TenantIgnore`，出参只外发社会公开字段（规范 4.4/4.8、五章五第 3 款）。
- 跨模块调用契约（XxxApi/DTO）放 api 模块的 `api/<domain>/dto`（规范 3.1），不落在 server。

## 二、类命名与框架基类对应

| 设计元素 | 框架对应 | 说明 |
| --- | --- | --- |
| 数据表 | dal/dataobject 的 XxxDO，`@TableName` 与规范第五章命名一致 | 业务表 `bidding_<域>_<实体>`（域清单先登记，资质域例外成文）；T 轨 DO 继承 TenantBaseDO（tenant_id bigint），G 轨继承 BaseDO |
| 增删改查 | XxxService / XxxServiceImpl | 事务、幂等（`@Idempotent`，写接口必标）、乐观锁/分布式锁按规范 4.5 |
| 数据访问 | XxxMapper extends BaseMapperX\<XxxDO\> | 分页入参 PageParam/PageReqVO，返回 PageResult |
| REST 接口 | Controller + CommonResult 返回 | 管理端 `@PreAuthorize("@ss.hasPermission('bidding:xxx:yyy')")`；公开接口 `@PermitAll` |
| 权限码 | 菜单权限码前缀 `bidding:` | 同步 sql/ 菜单脚本 |
| 错误码 | ErrorCodeConstants，`new ErrorCode(1_060_YYY_ZZZ, "中文提示")` | 段位先在规范 4.7 表登记、再登记进规约测试段位集合 |
| 时间字段 | 业务时间 `datetime`，审计字段用 BaseDO 自带 | 与 V2.0 数据时间戳的转换在 Service 层；仅 `bidding_std_*` 镜像表存 `yyyyMMddHHmmss` 字符串（规范五章三第 6 款） |
| 文件/附件 | 复用文件服务（FileApi），表里存 `file_id + sha256(+size)` | 不存裸 url、不存二进制（规范五章三第 5 款、红线 8） |
| 正文类内容 | `bidding_<域>_content` 版本化 | 内容表结构、唯一键与追加规则见规范五章三第 2 款 |
| 全量 VO | `api/vo` 的 record | 字段名照录规范英文名称、全 String、逐字段 `@PublicLevel`（规范二章） |

## 三、框架 starter 复用（只依赖不改动）

| 能力 | 复用 | 用在哪 |
| --- | --- | --- |
| Web/Security | txgy-spring-boot-starter-web / -security | 全部 Controller、登录态、`@ss.hasPermission`、白名单 |
| 缓存 | txgy-spring-boot-starter-redis | 字典、时限、幂等缓存（key 前缀 `bidding:`） |
| 多租户 | txgy-spring-boot-starter-biz-tenant | T 轨租户隔离（TenantBaseDO + 拦截器），G 轨免租户（规范五章五） |
| 定时任务 | txgy-spring-boot-starter-job | 保存期提醒、检索同步重试、公示到期 |
| 消息 | txgy-spring-boot-starter-mq | 公开同步、备案推送、订阅通知（异步解耦，规范 4.6） |
| 数据权限 | txgy-spring-boot-starter-biz-data-permission | 监管按辖区（如 region_code）的数据权限 |
| 幂等/并发 | txgy-spring-boot-starter-protection | `@Idempotent`、分布式锁（规范 4.5） |
| 校验/测试 | txgy-spring-boot-starter-test、validation | 单元与接口校验、ArchUnit 规约测试 |

## 四、ES 落点（收敛在 bidding server 检索组件）

平台框架无 ES starter，因此 ES 客户端依赖与索引管理**收敛在 bidding server 的检索组件**（如 `service/notice/search`），实现 04 文件的公开文档同步与索引/查询；对外只暴露公开检索接口给大厅类只读接口使用（规范 4.6：本地写库 + 消息/事务后置驱动索引，最终一致）。除该组件外，任何代码不直接依赖 ES；启用/降级由配置控制（未启用时走数据库兜底查询，不允许在业务表上做全文 LIKE——见规范五章三第 3 款）。
